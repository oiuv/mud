# Design

## Context

动机与范围见 [proposal.md](proposal.md)，源码核对依据见 [analysis.md](analysis.md)。后者保留修订前的核对记录，其中三名持锤 NPC 及全金发的待定项已由本设计第 4 节确定。现有武器通过 `init_*` 设置技能类型、标志和默认攻击动作；普通品种由独立类别处理程序和数据表创建，特殊兵器仍有专用代码。中平枪法、圣骑士戟和三种斧法的历史错类已经传播到学习、NPC 与绝招。

现有主规范描述的是忠实数据迁移，本次用户明确批准分类纠正及无必要细微差异归并。新增验收必须列明这种语义变化，不把旧测试全部失效或删除快照当作解决办法。玩家技能不迁移、物品路径要正确、棍杖不合并均已确认。

## Goals / Non-Goals

**Goals:** 用现有继承、虚拟品种和武学机制，使类别、路径、教学和实际使用一致；保持一类一个明确入口、一种普通物品一份规范数据。玩家可自行学会基本枪法/斧法并使用原有特殊武学，也可按既有教学资格学习新增的撼山锤法。

**Non-Goals:** 不设计通用类别注册框架、不保留旧 FORK 或路径转发、不自动整理玩家技能、不合并棍杖；除已确认的共用撼山锤法外，不为模糊兵器或单个 NPC 新造武学，也不顺带运行正式存档转换。

## Decisions

### 1. 正式枪类替代叉类

沿用 `include/weapon.h`、武器继承类和基本技能的组织：新增 `.lpc` 的 SPEAR、F_SPEAR、基本 spear，删除已经替换的旧叉接口。枪系长兵器使用刺击为主的默认动作和与形制相符的标志；长枪的 LONG、尖刺兵器的 POINTED 及已有双手等标志逐项记录验收，不通过分类迁移重做专属招式伤害。

钢叉保持名称及物品输入别名，归属枪系。棍和杖保留各自 `skill_type`、基本技能和专属武学；不新增“棍必定更重、杖必定更快”等未经设计的属性规则。

不采用 FORK 宏别名或双类别可用方案：新代码及实际调用统一到新接口，历史资料中的旧符号作为审计记录保留。

### 2. 正确类别同时决定普通品种路径

新增 `/d/items/spear` 及其就近数据表，迁入钢叉、镔铁长枪及核定的枪系长兵器；开山斧、玉斧迁入既有 axe 表。删除旧表条目和空掉的 fork 处理程序。实体特殊武器改继承与相关回调；没有错误类别前缀的实体路径无需一并改名。

保持现有虚拟对象初始化契约、蓝图/实例差异、唯一规范身份及未知品种拒绝。实际调用、商店货表、刷新清单、随机生成池、存取资格检查一起更新。不能把旧品种留在 hammer/club 数据表中再加入跨类分派，也不扩宽仓库对任意路径的授权。

### 3. 同名重复品种按用途归并

对已迁移普通武器表按名称聚合候选，逐项比较用途、取得方式、属性、限制和行为。没有设计价值的细微数值差异可以归一；“曾经不同”本身不是保留理由。合并后选简洁规范 ID；不因表排序重编号、不保留重复入口。

优先选符合用途和现有装备档次的代表版本，目标值及依据写入实施清单；不将所有品种的最高伤害、最低重量等拼成新的强化装备。明显档次、任务、稀有身份、特殊效果和门派限制不是噪声。没有查清必要性的差异先保留并说明，而非按名称自动合并。

同步全部创建、比较和交易引用；货表键合并不得覆盖库存数量，随机池重复项若表示概率权重则保留权重。各商店可保留自己的显式售价；如一个货表的两个价格无法共存，记录并确认统一售价，不由 mapping 后写覆盖决定。玩家物品实例仍各自独立。

### 4. 武学、师父与 NPC 成套调整

中平枪法的 `valid_enable`、学习门槛、练习持器、有效等级及绝招 `ding`（现有名称“定岳七方”）检查改用 spear。`clone/weapon/qishiji.c` 是银制长戟，`kungfu/skill/qishi-ji.c` 以刺挑为主，同属已核定的枪戟类；武器、武学、绝招及 `kungfu/class/generate/english.c` 的基本技能、激发和战斗调用一并由 club 改为 spear，保留挑战者原等级缩放与其他能力，不顺带数据化实体兵器。

三种斧法由 hammer 改为 axe，特殊武器命中回调同步。盘古七式专属斧系，保留招架用途，不接受锤系激发或持锤练习、施展绝招。明确斧类的招式、默认动作及伤害类型体现利器劈砍，锤类体现钝击；复用现有伤害类型，不新建伤害机制，也不借此修改伤害数值和其他平衡参数。

师父按实际所教武学配置基本技能和教学白名单：仅教枪法的以枪法替换其旧棍法；同时教授真正棍法的保留棍法并增设枪法。新增基本技能沿用对应原教学等级，不凭此提高师父实力或取消门派资格。斧法师父同理，不误删其真正锤法或棍法。

NPC 的技能声明、激发、招架、战斗口令和持器组合一起核查；普通持枪兵丁只换基础类别，不额外赋予特殊枪法。常金鹏的西瓜锤、童百熊的铜锤、赵鹤的雷震挡均保留锤系，三人改用下述共用锤法，不更换特色武器。全金发保留杆秤并改用现有棍系武学，具体安排如下；不通过全局放开跨类技能遮掩配装问题。

补齐技能命令与中文名称登记。基础枪法必须存在可到达、可学习的教学入口，不能仅创建一个玩家无法学习的技能对象。

#### 基本枪法的公共学习途径

陈有德的基本枪法教学等级为 80。对原经验限制之外的老玩家（`combat_exp >= 3500`），允许缴纳 500 铜钱补学基本枪法；此项缴费资格只开放 `spear`，不能借此解锁其他基本功。沿用既有临时教学资格与正常 `learn` 机制，不自动增加等级、熟练度或绝招；新手原缴费资格、其他教学规则和已获资格的原有行为保持不变。

新增 `clone/book/basic-spear.lpc`，名称为《枪法入门》，输入别名为 `spear book`、`book`，继承既有 BOOK。参数与《剑法入门》《杖法入门》一致：重量 600、基础价值 200、纸质，学习技能 `spear`、经验要求 1000、`jing_cost` 20、难度 20、`max_skill` 19。研读条件、实际精神消耗和等级判断均复用 `study`，不另写研读回调或调整其他秘籍。

陈有德创建时备货五本《枪法入门》，与其他入门秘籍共用现货买卖规则；基础价值不等于最终售价，原现货加价及适用优惠仍由商人机制决定，不改成无限供货。玩家通过正常购买和研读学习基本枪法，不因此获得特殊枪法、绝招或旧技能转换。玩家帮助说明购买、研读和向陈有德补学的入口；隔离回归覆盖收费与教学范围、秘籍参数、真实购买和研读条件。

#### 共用撼山锤法

新增 `kungfu/skill/hanshan-chuifa.lpc` 及对应绝招，沿用现有 SKILL/PERFORM 机制。允许 `hammer`、`parry` 激发，学习使用基本锤法，练习与绝招要求锤类持器及对应有效激发，不接受斧类武器。三人共用一套武学，不按 NPC 复制实现，也不与盘古七式建立双系别名或运行期转发。

以调整前盘古七式的招式、绝招数值及相关门槛为设计起点，文案体现抡、砸、撞、横扫等锤法特点，伤害采用钝击语义，不描述斧刃劈砍。保留三人原基本锤法和特殊武学等级，以原盘古七式等级配置撼山锤法，替换相关招架与战斗调用；不额外叠加一套可用武学，不借此提高 NPC 等级。数值基线和实际表现分别验证，不以同等级或编译成功推断战力必然相同。

沿用三人各自已有的教学资格和入口，逐一同步技能白名单、询问及相关绝招传授配置；没有教学能力的 NPC 不因此变为师父。贡献、身份、内力等无关条件不变，玩家须正常学习和取得新绝招，不从旧 `can_perform/pangu-qishi` 记录自动转授。回归覆盖教学、练习、激发、招架、普通攻击、NPC 主动绝招及错类持器拒绝。

绝招教学由赵鹤的询问“撼山震岳”接入：要求日月神教、师承任我行，沿用原“开天辟地”的贡献 1200、邪气至少 120000（`shen <= -120000`）、有效内功 300、特殊武学 180 门槛，并保留赵鹤膂力 32 的教学资格。成功时扣贡献 1200，学习奖励沿用原数值但归入基本锤法与撼山锤法；已领悟时不重复扣费。常金鹏、童百熊不新增教学能力，旧盘古七式领悟记录不转授。

#### 全金发使用棍系武学

`d/guiyun/npc/quanjinfa.c` 保留 `/d/items/club/gancheng`、65 级基本棍法和杆秤原属性，将 65 级中平枪法替换为 65 级采燕功 `caiyan-gong`，同步 `club`、`parry` 激发。采燕功已有点、撩、扫等棍系动作，直接复用现有实现，不为杆秤增加新武学或枪类兼容。

保持全金发原 `dodge -> lingxu-bu`、内功、徒手技能及其他等级，不因为采燕功也能用于轻功就替换其轻功配置。不增加主动绝招或绝招传授入口；既有师父机制中的可教技能随配置更新，教学资格不放宽。验证杆秤持用、棍系攻击与招架、正常学习条件和原其他能力，记录更换武学带来的表现差异，不以保留等级声称战斗数值完全等价。

### 5. 玩家旧技能保持原样

不增加登录补偿、技能等级继承、激发键迁移或离线技能转换器。旧 club/hammer 等级、熟练度、特殊武学和绝招领悟记录不写改；玩家主动学习新基本功或撼山锤法并按对应类别激发，不自动获得新锤法及绝招。

旧激发记录不自动改写，但消费激发的代码必须遵守当前武学允许的类别：旧 `club -> zhongping-qiang` 不应继续提供枪法的棍类攻击。采用正常适用性校验，不建立旧技能专用兼容表、不删除玩家记录；合法基本棍法和其他棍系激发仍正常。回归覆盖有效等级计算、动作选择及 perform，不只验证新 enable 命令。

### 6. 变更依据与验证分离

保留原普通物品迁移快照和已完成报告；新增“分类/合并差异清单”作为当前预期。只允许清单中的类别、路径、必要展示及合并目标值变化，其他价格、属性、特殊行为仍比较。现有生成/审计工具的当前输出应对应新规范，不重新生成旧错误分类。

维护 `docs/architecture/` 的分类说明和现有物品台账，AGENTS 简短引用分类规范；玩家学习方式与变化写入 `help/`、`help/changelog`，不让玩家阅读技术迁移清单。

## Risks / Trade-offs

- 旧仓库、商店和 NPC 装备存档可能保存将删除的物品路径 → 记录完整去向及可能无法恢复的风险；本轮不读取、转换正式记录，不将代码通过等同于旧物品数据无损升级。上线前由管理员另行决定存量处置，不暗中丢弃物品或增加兼容壳。
- 不转换技能会使既有玩家暂时不能按旧基本功施展改类武学 → 保留旧修为、提供新教学入口和明确帮助；这是用户确认的策略，不自动补偿。
- 同名合并可能影响伤害、负重、商店收入或兑换条件 → 逐组核查实际用途和引用，列出原值/目标值，测试交易与任务识别，不按数值比例盲合。
- 特殊 NPC 的武学和标志性武器相互矛盾 → 按具体对象确认修正，不自动把特色物品换成通用枪斧，不宣称全局替换即可完成。
- 热更新遗留旧蓝图及已有运行中装备 → 隔离驱动验证完整启动；部署采用维护时段重启，不仅依靠重载一个数据表。正式重启须单独授权。

## Migration Plan

1. 实施时补齐分类与归并清单，完成代码、教学、调用及帮助；不接触正式存档。
2. 运行修改文件格式化及 `--check`，静态引用检查、既有物品回归和隔离真实驱动的学习/练习/激发/战斗/交易回归；记录尚未完成的实服验收。
3. 交付明确的删除路径清单及玩家重新学习说明。旧物品记录是否需处理尚未查验，不能给出“直接 pull 重启即可无损”的结论；任何正式记录处置另行授权，不属于本轮自动动作。
4. 管理员确定部署窗口与存量处理后再上线；回退使用匹配的代码和维护备份，不能保证只撤销代码就恢复更新期间的新物品、新技能记录。不得清除玩家旧技能作为回退手段。
