# Design

## Context

动机与六项缺陷对应关系见 [proposal.md](proposal.md)。当前实现基线为 `b85d40ff`；此前归档及审查文档尚在工作区，本变更不改写其历史验收结论。

- `put.c` 在调用 `do_put()` 前减少原堆叠数量；后者多个拒绝分支直接返回，未处理候选物。命令返回 `1` 既可能表示提示已处理，也可能表示交付成功，不能据它恢复数量。
- `auctiond.c` 只保存拍品对象引用，物品没有托管；买家对象定义在循环外。买家款、卖家佣金、货款和拍品移动依次发生，但没有完整失败补偿，成交广播还早于扣款。
- `moneyd.c` 的 `player_pay()` 拒绝非正金额，返回 `1` 才是付款成功，`2` 也是未付款；`pay_player()` 没有成功返回值，发钱的强制移动可能把钱落在地上。原佣金表达式实际为成交价乘 4 再除 100，不是恒等于零。
- `eventd.c` 使用年/月/日/时排序，到期先删除登记再调用事件；`at_after()` 没有进位。无量山触发后仍注册本月已过去的十五日二十三时。
- `NATURE_D` 的游戏日期来自 `TIME_D`。宿主 `timed.c` 设置游戏速率和纪年，mudcore 时间层从内部时间戳解析月日后重设显示年份；不能直接把当前游戏年交给现实日期转换或据它推断闰年。
- `test_commerce_audit.mjs` 已通过临时目录和本机连接测试真实命令及玩家对象；`test_gameplay.mjs` 汇总五组检查。新回归沿用这一方式，不依赖线上角色。

## Goals / Non-Goals

**Goals:** 在业务边界维持钱物数量与归属，显式区分命令处理和业务成功；按游戏历法安排活动；以旧代码失败、新代码通过的隔离证据验收。

**Non-Goals:** 不新增交易框架、持久拍卖、托管房间、奖励账本或通用时间框架；不更改佣金比例、银票使用门槛、活动奖励与其他活动的固定时刻；不保证进程崩溃后的交易恢复，不处理旧损失或玩家存档。宿主时钟连续性经维护者确认补入；其余八项缺陷和兵器平衡不混入本批。

## Decisions

### 1. 拆分操作由调用方统一负责收尾

将容器、容量件数及物品禁放等无副作用检查前移，并供单件、部分数量和 `all` 路径复用。先成功创建并设置候选，再扣原数量；创建失败不能先吞掉原堆叠。部分放入失败时由一个明确的收尾路径恢复原数量、清理尚未交付的候选。

移动前缓存显示所需信息；移动后按实际结果判断，兼顾普通堆叠合并会销毁同类旧对象，不能对失效引用继续发消息或据其消失重复补发。已有 `move()` 可能返回负值表示移动时对象被销毁，不把任意非零值无条件解释为资产已经交付；回归分别验证正常合并和拒绝。

不采用“给每个提前 return 补一份放回代码”，避免拒绝分支再次漏掉补偿。也不修改全部物品的移动协议或扩展实例存档功能。

### 2. 保持卖家持有，集中复核记录有效性

上架、竞价和到期结算共用拍品有效性检查：对象存在、直接环境为卖家、仍满足原 `check_auction()` 条件。展示清单时同步剔除失效记录，不把“对象仍存在”当作售权。物品移给第三人后仅取消记录，不追回。

每次循环从本记录重新解析买家，先清空临时状态。继续保留现有轮次、十秒推进、卖家退出撤单与无人竞价取消行为。不引入额外托管或冻结物品状态，因为当前没有持久拍卖恢复协议，修复归属不需要建设它。

### 3. 同步结算内预检、扣款、交付与补偿

把单笔结算组织成一个边界明确的同步过程：

1. 复核参与者、当前拍品、有效金额与持有条件；预检双方实际付款能力及交付容量，预检不得修改资产。
2. 按原规则扣买家款和卖家佣金，记录哪些扣款已经成功。佣金为零直接跳过；佣金计算使用与 `floor(price * 4 / 100)` 等价且不会中间溢出的整数运算。
3. 执行拍品交付，核对普通对象落点或堆叠数量变化。拒绝时退还本笔已扣款，不向卖家发成交货款。
4. 成功交付并完成卖家收款后才清理成交记录、广播成功；失败清理本笔记录并给出失败反馈，不能再次自动扣款。

如需提取付款预检，则与 `player_pay()` 共用币种、银票门槛及溢出判断，避免复制一套与真实扣款不一致的 `can_afford()`。不放宽公共付款对零、负数的拒绝。

退款不能只凭调用 `pay_player()` 宣称成功；验证金额与归属，覆盖负重变化及已有钱币合并。对正常可预判的收款/交付失败尽量在扣款前拒绝，保留扣款后物品明确拒绝移动的补偿测试。不用强制把拍品扔地上来绕过交付失败，不把“从成交收入抵扣佣金”当作本次修 BUG 的附带规则变更。

### 4. 日期进位属于调度器，周期推进属于活动

`at_after()` 保留参数语义，先组合目标分量，再规范化小时、月日及年份。日期依据当前 `TIME_D` 内部时间戳对应的历法与游戏纪年映射计算，测试与实际 `query_game_time()` 的月末结果对照；不硬编码每月三十天，不用现实 `time()` 直接代替游戏时间，也不重设游戏纪元或速率。

`at_when()` 保留 ROOT_UID 调用者约束、既有记录形状及参数传递。一般登记不擅自推断周期：有意登记过去时点仍只消费一次，不统一改成自动“下个月”。

无量山活动自行选择最近的未来十五日二十三时；本月目标已到或已过则进到下月。触发结束重新计算，避免落后多个周期后连续补发；奖励代码不变。同步纠正“凌晨”与实际二十三时不符的注释。

保留当前到期先删除、再调用事件的顺序；小时级检查可能晚于精确时刻，验收要求不提前、不重复，不承诺精确到秒。钱塘潮既有“下一年指定日期”规则不改为今年，日出和天池保持原定小时。

### 5. 回归验证边界结果，而非仅验证辅助函数

- 扩充交易隔离套件：真实玩家入口的拒收和成功放入；多卖家/买家的拍卖，包括调整记录遍历次序、退出、换主、佣金不足、零佣金、交付拒绝和堆叠合并。断言双方金额、数量、实际归属及成交消息，不只断言返回码。
- 新增 `tools/tests/test_world_events.mjs` 及对应 `.lpc` 夹具，运行生产调度器和事件代码。时间快进只在临时副本的时钟/测试替身实现，不给正式代码增加玩家可调用的调时入口。检查日/月/年界、二月、月中重登记和连续检查；断言奖励调用次数，不靠随机中奖证明是否重复。
- 针对本批缺陷明确保存 `b85d40ff` 负对照；不覆盖原交易套件 `d43c418f` 的历史负对照含义。新增用例须能在旧实现定位失败原因，不能只是夹具未能启动。
- 新活动套件接入统一入口并同步入口自身测试，原五组保留；测试目录、端口与日志继续隔离，不读正式玩家存档，也不启动正式服务。

### 6. 宿主时钟保存锚点，按经过时间连续推进

实施中已复现：宿主将 `set_scale()` 的纪年设为负数，内部日历跨年时显示年固定；启动又按现实日余数重建月日。这不是调度器分量进位能修复的问题。维护者确认纳入本批，只调整 LIB 的 `timed.c`，不修改 mudcore 通用接口。

首次遇到没有锚点的旧时钟记录时，按旧公式计算升级时起始日期，记录现实时间、内部游戏时间与正纪年偏移。之后当前游戏时间等于锚点游戏时间加现实经过秒数乘 `DATE_SCALE`；保持 1∶60 速率、实际公历月长及现有时区。显示年由内部完整年份加偏移得出，不再固定。宿主心跳仍处理原现实／游戏计划任务，但不靠累计心跳次数推算时钟。

锚点复用既有公共数据库的宿主对象记录保存，初次建立后落盘；重启恢复同一锚点并计入停服经过时间，不重新按现实日期取模，不迁移玩家存档。没有锚点的旧记录走一次初始化，而非猜测它保存于何时。开发测试只使用隔离数据库；部署前按正常流程备份公共数据库。

回归以临时输入的现实秒数驱动生产 `timed.c`，验证升级初始显示、固定速率、跨日／月／年、宿主调度触发、保存／恢复与重启停服时间衔接。既有负对照保留旧宿主以证明缺陷；无量山仍只安排下一场，不补发停服期间奖励。不得仅以正常纪年的测试替身通过代替宿主连续性通过。

## Risks / Trade-offs

- **任意物品钩子可有副作用** → 先覆盖当前普通物品与真实拒绝分支，组合移动按实际数量核验；不声称能自动撤销任意脚本破坏或进程崩溃。若修复必须改变特殊物品语义，另行记录并确认。
- **退款和收款与重量、找零有关** → 不能照搬旧 `pay_player()` 调用而省略结果验证；用真实货币对象及接近负重上限的角色回归，禁止静默落地或重复发钱。
- **游戏显示年与内部日历不同** → 日期测试覆盖宿主时间接口与可控月末夹具。固定纪年问题已经单独复现并获准补入第 6 节；保存锚点而不是重做通用时间系统。
- **历史文档描述超出实现** → 按验收后的实际取消、退款和调度行为更新文档，不复制“托管归还”“拍卖继续”等旧错误说明。

## Migration Plan

本批不迁移玩家存档；宿主时间记录新增锚点字段，首次升级建立并保存，已有有效锚点直接恢复。完成格式化、真实驱动隔离回归和统一入口后交付维护者部署；不操作正式服。拍卖记录只在内存，部署时应先结束或取消正在进行的拍卖，再按正常维护流程更新，避免热更新中丢失活动记录。

新事件调度须随守护进程重新收集事件；不为历史漏发或重复发放自动追补/扣回。回退使用对应代码版本，明确旧缺陷也会恢复；旧测试和审查证据继续保留。实现及验证完成前任务保持未勾选。
