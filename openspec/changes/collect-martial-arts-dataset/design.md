# Design

## Context

动机及授权边界见 [proposal.md](proposal.md)。源码基线为 `275580a6`。2026-10-08 只读清点得到：`kungfu/skill` 有 721 个顶层 LPC 文件、730 个下级 LPC 文件及 1 个头文件；`kungfu/class` 有 42 个分组、418 个 LPC 文件及 52 个头文件。它们是覆盖分母，不代表 721 门战斗武学、730 个绝招或 42 个正式门派。

现有 `bench_weapon_balance.mjs` 固定七个配置、六门武学及三组交锋，不能通过 CLI 更换武学。`valid_enable()` 同时存在直接比较与 `usage_skills` 列表方式；师父通过 `set_skill/map_skill/prepare_skill/create_family`、公共头文件及条件分支配置。正则命中只能定位候选，不能证明最终映射或可学资格。

本轮需要设计是因为采集跨越兵器、教学和所有技能，且长期运行必须保留可信样本与覆盖状态；不因此建立通用测试平台。

## Goals / Non-Goals

**Goals:** 每个源码条目有可追溯身份与采集状态；每类能力使用合适的观察方法；所有实测附带条件和原始证据。结果允许强弱、成本和玩法定位不同。

**Non-Goals:** 不修正式错误，不改游戏源码或存档，不平衡数值，不设计克制表，不穷举所有玩家配装与全部武学两两对战，不宣称实验角色等于线上可获得角色。

## Decisions

### 1. 一个数据清单，三个阶段视图

新增独立采集入口与 `tools/tests/` 夹具，不改正在运行的旧固定基线。按以下顺序执行：

1. 十二类兵器各选已核对可使用的代表武学，记录普通攻击、合法绝招及适用的短时交锋；不足类别补齐，不拿剑的结果冒充针和箫的实测。
2. 遍历 `kungfu/class`，按真实 `create_family`、公共继承/头文件和教学配置归并门派。保留目录分组视图；`generate/misc/none/ultra` 等不自动命名为门派。区分 NPC 自用、明确传授和仅有引用。
3. 遍历 `kungfu/skill` 全部条目及依赖，覆盖基本功、特殊武学、perform、exert、回调和辅助技能。文件和入口去重，但多类适用、多门派共用关系保留。

名称来自公开字典与源码，有差异时同时保留并标注来源，不静默改名。建立包括源码路径、hash、函数/行号、声明类别、运行期类别、师承、依赖与测试用例的可查询 JSON 索引；Markdown 提供分组说明和摘要，不堆砌所有原始日志。

### 2. 先发现，再运行原有接口

使用本地 FluffOS tokenizer 辅助识别真实代码与注释/字符串，提取入口、静态声明和定位依据；不能把扫描器当编译器，宏、继承与动态条件须借助真实驱动核验。数据中区分静态声明与实际返回。

测试角色、装备和学习记录仅在临时 MUDLIB 创建；保持 `userp/playerp`、持器、映射、领悟、门派和资源检查。为实验准备资格须记录依据及赋值，不替换资格函数，不用 NPC 豁免代替玩家成功。NPC 配装另列，不能等同玩家可学集合。

通用观察覆盖普通动作、资格、扣费和状态；个别武学需要特殊目标、道具、队友或场所时补小型显式配置，不引入推测性自动条件求解器。初次拒绝是有效的条件数据，但不是该效果已测；持续补齐合法配置直到实际覆盖。源码本身异常的入口记录复现及阻塞影响，不为让测试通过而修改它。

### 3. 标准对照和门派组合分开

兵器第一轮沿用现有 200 级特殊武学、统一属性与装备档次，保留零加力和加力 50；不合资格的高阶武学另列满足原门槛的配置，不混入 200 级均值。随后用 400、800 级观察成长，等级不是最高上限证明；特殊门槛超出时另列实际条件。

各门派从实际教学和映射中选择有依据的组合，逐一覆盖其武学集合，分别记录完整组合与单项效果。共用固定中性对手作为横向参考，并保留现有镜像/三组对战作为单独系列；不能混算不同对手、防具、内功、属性及资源预算。

针仍保留针物品与剑法归属；箫使用真实箫初始化与对应技巧；暗器按原手持、弹药和绝招入口测试，不强制当可 wield 的剑。棍杖分开。没有伤害的控制、轻功、招架、内功恢复、知识和辅助技分别观察对应行为，不填零 DPS 作为强弱结论。

### 4. 分段保存，完整覆盖不等于全排列

以 `源码快照＋条件＋技能/入口＋重复编号` 标识样本，完成一个独立条件即保存并验证，允许续跑缺项；失败样本不覆盖、不混入成功分母。记录驱动 hash、源码/mudcore 提交及依赖文件 hash，续跑前核对，变化则新建系列。不能修改旧运行清单使指纹相符。

随机效果每条件先采 100 次；纯确定性查询另列实际检查次数。实际持续效果沿用原时钟和回调，短时交锋沿用每条件 20 场、30 秒、交替先手，未决不计胜利。单次统计与交锋统计独立，烟雾不能替代完整样本。默认顺序执行长时驱动批次，避免负载改变时序；单任务看门狗只判断执行故障，不代表战斗失败。

完成口径是：全量目录清单闭合、全部实际门派有来源及采集资料、每个独立能力入口有实测或确认不适用的依据。尚未找到合法配置、条件缺失和异常阻塞仍列未完成效果，不能用“已扫描全部文件”宣布全部武学测试完成。不要求无限等级、所有随机分支和所有武学两两组合穷举。

覆盖表分别统计“采集处置”和“正常效果”：已复现的源码错误可以完成该项错误数据采集，但不能记为正常效果通过。用户要求错误留待后续统一修复，因此不将修复这些错误作为本轮交付前提；未调查清楚或仅因夹具缺条件而拒绝的入口仍需继续调查。

### 5. 观察、统计与缺陷记录

复用现有观测思路，优先由测试对象转调原接口；如使用既有临时副本探针，记录精确插入点和前后 hash，验证移除可还原，禁止改变原公式、随机、返回值或业务分支。仓库游戏 `.c/.lpc/.h` 始终不改。

记录攻击者/目标、实际基础/有效等级、装备/弹药、发动与拒绝、普通命中/闪避/招架、直接结算、连击数、气血/有效气血、精神/有效精神、内力总支出及恢复、双方忙乱、增益/减益、解除时间、缴械、昏迷与死亡。间接或未观察的量用未知/不适用，不填零。伤害不与创伤相加，持续输出注明是否含恢复。

汇总保留均值、中位数、分位数、样本量和概率区间；控制和恢复单列。只陈述观察差异与适用配置，不给所有门派排统一强弱榜，也不自动建议拉齐数值。

明确错误保存到开发缺陷台账：编号、文件与行号/hash、预期依据、最小触发条件、实际结果、复现目录、影响的样本范围及待处理状态。怀疑问题单列，不与确认错误混淆。发现错误后继续不受影响的数据收集，相关结果明确受影响；修复留给后续独立批次。

### 6. 交付与权限

原始数据与临时源码副本只写仓库外的新证据目录，禁止读取正式配置、账号、存档、私有 `u/` 和 AI 密钥。只使用回环端口，无正式服、模型或其他外部服务调用。

提交可复跑工具、人工用例配置、静态索引、分兵器/门派/全武学摘要及覆盖/缺陷台账；大量随机原始样本不进入 Git。报告保留证据目录及校验摘要，缺失原始证据不能宣称可复核。纯数据采集无玩家可见更新，不修改 `help/changelog`。

## Risks / Trade-offs

- [门派目录不等于真实师承] → 保留两种视图及依据，动态关系显式复核。
- [高阶或特殊条件被标准档拒绝] → 单独合法配置采样；不降低正式门槛，不把拒绝计成效果完成。
- [大规模运行耗时与中断] → 条件级保存、验证和续跑；先完成当前类别/门派，再进入下一层，不因提交中断已有隔离驱动。
- [源码错误影响数据] → 只记录复现和污染范围，后续修复；不得静默过滤异常得出强弱结论。
- [人工配置不等同养成成本] → 分别报告发动资格、师承路径与实验赋值；不声称线上可直接获得。

## Migration Plan

无正式部署或数据迁移。按上述三个阶段扩展和运行，每阶段先小样本验证夹具再完整采集；最后核对覆盖清单及所有原始记录引用。撤回工具或文档不影响游戏和玩家数据，旧评测记录保持不变。
