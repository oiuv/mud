# Proposal

## Why

mudcore 已经支持新 MUD 和老 MUD 的选择性接入，但默认组合、组件依赖及局部策略扩展的边界不够一致：命令分发固定串接可选服务，玩家组合默认携带战斗/任务/GMCP，角色创建规则与认证流程相邻。需要把“可以覆盖”完善为有文档、有兼容保证、有组合测试的公共契约，同时保留现有完整功能和默认行为。

## What Changes

- 增加明确的最小角色组合，与现有完整默认组合并存；梳理移动、命令、存取等组件的必需接口和可选协作，不让未选用的玩法或协议阻断基础流程。
- 为命令处理增加可覆盖的阶段列表和局部处理钩子；保持默认顺序，允许宿主关闭表情、频道、parser，禁用后不加载相应服务或调用相应 efun。
- 为默认角色创建增加名称规则、性别选项等策略钩子；保留中文 RPG 默认值、`CHAR_D` 入口，以及既有认证、UID、连接交接防护。
- 增加宿主权限策略诊断，明确开发默认 master 与宿主生产策略的区别；诊断只读、按需调用，不自动修改权限，不声称可认证一个宿主“安全”。
- 在 mudcore 中新增架构与模块契约文档，并同步 AGENTS、接入指南、相关 API 手册、测试说明和未发布变更记录。
- 扩展隔离回归，覆盖默认组合、宿主覆盖、最小组合、可选服务缺席及拒绝授权等场景。

## Capabilities

### New Capabilities

- `mudcore/module-contracts`: 公共组件依赖、可替换接口、最小角色组合及其与现有默认组合的兼容保证。
- `mudcore/command-pipeline`: 可选择和重排的命令处理阶段，以及 parser/表情/频道禁用时的隔离行为。
- `mudcore/character-creation-policy`: 不绕过认证流程的角色名称、性别和初始属性策略扩展。
- `mudcore/host-policy-diagnostics`: 对默认与宿主覆盖权限实现的按需、只读诊断。

### Modified Capabilities

无。当前主仓库尚无已建立的 OpenSpec capability；以上为首次建立相关行为规范，不表示框架此前没有这些功能。

## Impact

- 实施目标为 `mudcore/`：`include/mudcore.h`、角色/命令/移动组件、登录 daemon、master 策略诊断、`tests/` 及相关文档。实施时保留现有公共路径、签名、存档字段与宿主别名覆盖。
- OpenSpec 规划保存在主仓库现有 `openspec/`；长期使用规范保存在 mudcore，子模块独立检出不依赖主仓库 OpenSpec 或运行时 Node.js。
- 不改当前老 MUD 的接入策略，不改外部 minimud/MyMud 工作区，不访问实际玩家数据或具体外部服务。测试仅使用临时宿主与回环网络。
- 不删除或禁用 Socket、HTTP、TLS、DB、external、Intermud、GMCP、TUI 等合理通用能力；不引入 DI 容器、通用事件总线或第三方运行依赖。
- 不自动提交、推送、发布、打标签或迁移现有存档。若实施发现必须破坏兼容，停止对应任务，先修订设计并取得用户确认。

## Non-goals

不重写整个玩家/战斗/任务系统，不建设新的认证提供商或任意角色创建表单引擎，不制定适用于所有 MUD 的生产 ACL，不以本次临时宿主回归替代三个实际游戏的集成验收。
