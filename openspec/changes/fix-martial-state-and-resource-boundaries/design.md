# Design

## Context

动机和范围见 [proposal.md](proposal.md)。当前源码确认：

- `yuxiao-jian.c` 的共享 `action` 初始化读取 `this_player()` 并固定五项随机数值；`query_action(me, weapon)` 仅返回数组元素。
- `hujia-daofa/cang.c` 检查 200 内力，施招直接扣 220；`luoyan-jian.c` 练习检查 30 内力和 35 气血，实际扣 50 和 40。
- `feature/attack.c` 与 `combatd.c` 已把针的攻击武学映射为剑；`cmds/skill/perform.c` 的省略类别分支没有对应处理。
- 现有武学回归使用真实角色/技能对象及战斗调用记录夹具；公共战斗回归执行真实命令、战斗和忙乱流程。两者均由统一玩法入口运行，无需另建框架。

## Goals / Non-Goals

**Goals:** 将动态状态归还本次施招者；先验证完整成本再产生效果；让默认绝招遵守既有武学映射；用修复前后同一组断言证明差异。

**Non-Goals:** 不重新选择公式中的技能来源，不修改随机分布、招式资格或实际成本；不把 12 类武器合并，不赋予兵器标志新被动，不迁移存档，不做全武学重写。

## Decisions

### 1. 只在选中“极意”时生成独立动作

保留原 `level > action[i - 1]["lvl"]` 和 `NewRandom(i, 20, level / 5)` 选择方式。选中“极意”后复制该动作 mapping，按参数 `me` 计算五项数值再返回；共享定义只保留静态内容。普通动作沿用原数据，不增加角色缓存或新守护进程。

以下公式中的技能均保持原有效等级语义及 LPC 整数运算：

| 数值 | 原公式，改为读取当前 `me` |
| --- | --- |
| force | force / 2 + random(force) |
| attack | sword / 4 + random(sword / 2) |
| dodge | dodge / 4 + random(force / 3) |
| parry | parry / 4 + random(parry / 3) |
| damage | force / 3 + random(sword / 3) |

不把 dodge 公式中的 force 擅自“纠正”为 dodge，也不改动 `hit_ob()`。选择独立 mapping 而非覆盖共享数组，是为了防止交替施招污染其他角色和已经返回的动作。

### 2. 门槛与现有成本对齐，不降低扣费

八方藏刀势的前置内力改为至少 220，其余分支不变。回风落雁剑练习同时要求至少 50 内力、40 气血，所有检查完成后才扣费。

不采用事后钳零或只扣剩余资源，避免不足者得到完整效果。也不额外要求保留 1 点气血：现有 `receive_damage()` 允许准确扣至 0，角色心跳在气血小于 0 时才判定昏迷；40 气血足够支付原练习成本。

### 3. 只修正默认类别推断

在 `do_perform()` 未解析到显式 `<类别>.<招式>` 时，把当前主武器的 `pin` 映射为 `sword`。不修改物品类别、显式输入或公共战斗映射，不引入通用类别转换层。

保留原技能映射、特殊/基本武学后备分发、领悟及各绝招资格检查。继续通过现有 `main()` 验证左右互搏；不绕过较长忙乱的保存/恢复逻辑。

### 4. 文案修订与功能修订分别验证

限定于相关文件中已确认的问题：玉萧→玉箫、重复的“的”、内力不足误称体力、回风落雁剑“剑峰”→“剑锋”及攻击对象 `$N`→`$n`、绝招提示“低档”→“抵挡”、“或则”→“或者”。不借描述修订增加控制效果、音攻限制或收益。

### 5. 复用两套真实驱动回归

- 武学套件新增 WB-01～03：无玩家冷加载；不同角色交替和技能升级后取值；普通动作与 200/201 等级边界；220 内力及 50/40 练习成本两侧；拒绝无副作用、成功增幅清理及重复练习。
- 公共战斗套件新增 WB-04：经真实 `perform` 命令比较持针的默认和显式剑法分发，覆盖实际接受针/剑的葵花绝招、缺少资格、其他类别、换持及左右互搏回归。
- 控制随机输入只发生在临时源码副本，并记录替换位置；断言计算结果和原随机参数，不以碰巧选中某招作为通过依据。八方藏刀势使用现有战斗记录夹具隔离“本招直接扣 220”与普通攻击附带消耗；真实公共战斗仍单独回归。
- 为四项新增负对照冻结修复前提交 `8aee0828`，仅替换相应目标源码。原武学 `--before` 分组及 `d43c418f` 基线保持，不覆盖旧历史。负对照必须因预期缺陷失败，不能以缺文件或编译失败充当复现。

## Risks / Trade-offs

- [动态随机数由首次加载改为每次极意] → 这是解除跨角色冻结的必要变化；保留原公式和范围，不承诺修复前后的随机序列逐值相同。
- [共享技能已在正式服加载] → 验收与部署需加载新程序；不能仅凭源文件更新或保持旧状态的热更新认定初始化缺陷已消失。
- [过度依赖夹具] → 分别报告受控随机、战斗记录边界和真实命令覆盖；不将检查数当成全部武学正确的证明。
- [资源门槛修复改变不足资源者的可用性] → 玩家更新说明明确实际成本未涨，只是不再允许透支；伤害与平衡另行处理。

## Migration Plan

1. 在源码隔离副本完成四项负对照和修复后定向回归，按仓库要求格式化并检查所有本次 LPC 改动。
2. 执行统一玩法回归和 OpenSpec 校验，记录检查数、失败数、证据目录及限制；修复通过后再更新审查跟踪与 `help/changelog`。
3. 无存档转换。由维护者在维护窗口更新并重启驱动，再执行 `updateall /`；不得在战斗中直接销毁共享技能对象。`reload` 保留状态不作为本次共享初始化重建的替代。
4. 如需回退，由维护者恢复上一代码版本并重启。回退会重新带回已知缺陷，不修改玩家资产或补发历史收益；本批开发不操作正式服。
