# Design

## Context

审查定位见 proposal。工作区已有属性修复、334 项武器回归和文档归档，必须保留。修复使用当前源码，不回退到 HEAD；测试运行于临时 MUDLIB，不读取正式存档。

## Goals / Non-Goals

- 覆盖 17 组明确缺陷、AI 重连、四处内力透支和疗伤残留；包括碧焰共享反噬回调。
- 不改变未列入问题的数值平衡、不重构所有技能、不新增通用事务或调度框架、不迁移已存负数字段。

## Decisions

- 交易入口与公共付款双层验证正值；乘法前判断溢出。商铺/摆摊按现有基本单位库存交付，显式设置数量。
- 背包先验证原对象，再拆分。拒绝返回失败；取出交付成功后才扣账，失败清理候选而保留记录。复用双扩展名存在性检查，不扩大虚拟对象准入。
- 反击现取临时主武器；远程/近程加力在分支汇合后入账。忙乱通过现有行动接口保存/恢复原始状态，不能重新应用减免。
- 错字段和错对象按现有公共契约修正；参合使用实际 victim、真实等级，太玄修实际分发文件与空手准备检查；恢复使用 receive_heal。
- 摄心按目标保存独立恢复任务/身份，重复施展更新当前目标而不影响别人。碧焰反噬不得取消另一人的回调。采用已有 call_out，不另建效果引擎。
- 内力：神行/碧云主动增益均要求 100；袈裟额外 500 必须与基础 300 一并可支付才触发；参合命中特效要求至少 80。保留成本而非钳零。两种轻功练习扣 neili，疗伤完成清自身状态。
- AI 请求捕获发起时 link_ob，交付及续约同时核验仍为同一有效连接；不让网络载荷决定身份。
- 真实驱动执行生产函数，通过临时源副本控制 RNG/异步等待等测试输入；不以测试重写业务逻辑。逐项保留失败与成功分支，运行旧有回归防止倒退。

## Risks / Trade-offs

- 动态 API 拼写不会被编译发现 → 必须断言实际资源/属性/输出。
- 堆叠移动可能合并并销毁候选 → 交付前保存展示信息，成功判据不依赖候选仍存活。
- 回调顺序和连接身份存在时序 → 多目标、重复效果、连接替换及迟到回包均纳入测试。
- 格式化可能扩大差异 → 只格式化修改文件，核对语义 token 检查与 diff。

## Migration Plan

隔离验收后交付更新清单；正式部署由用户操作并重启相关对象/服务以消除旧内存状态。不自动写正式数据、重启或提交。回退使用原代码版本，测试不产生正式数据迁移。
