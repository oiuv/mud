# Tasks

本轮只提交计划，以下工作仍待实施。先由维护者选定类别，再使用本清单处理该批；北京五把剑是首个建议评估样本。后续类别是复核机会，不是必须迁移的任务。

**任一步发现需要增加系统复杂度，就停止该项改造并记录保留理由。** 不新增基础设施任务来绕过此门槛，不把“暂缓”改成未来必做。条件任务只有适用时才实施；不适用时记录原因，不声称功能已实现。

## 1. 选定一类并判断是否值得改

- [ ] 1.1 记录选定小组及原属性/行为，以北京 sword1..5 作为首次对照建议；逐项核对 create、继承与头文件，形成可复核基线。
- [ ] 1.2 核对该组的创建、蓝图、路径、交易、合堆、存取与所有可达出口；交付简短调用清单，明确能否直接参数化或必须保留路径。
- [ ] 1.3 对照 design.md 的复杂度门槛选择直接参数化、局部提取或保持原样；列出前后维护步骤与改动边界，证明没有新增身份、公共适配、存档或运行服务。
- [ ] 1.4 若该组不值得改，保留原代码并记录具体理由，结束本组；若值得改，记录实际需要执行的后续项，不把所有候选默认纳入实施。

## 2. 仅实现通过门槛的小组

- [ ] 2.1 对路径依赖类，仅在现有行为族内提取真实重复步骤，必要参数/数据就近维护；核对原具体路径、蓝图、set_default_object 和创建调用均不变，完整差异确实更易维护。
- [ ] 2.2 对获准直接参数化的独立类，使用原生 new/create 和最少必要参数或局部 mapping；验证合法/错误参数、多品种与多实例、无参蓝图，不新增全局注册或构造工厂。
- [ ] 2.3 核对 set_name 缓存、初始化顺序、0/未设置、随机时机及嵌套状态隔离；用受影响对象对照验证，不因提取而新增 setup、重抽随机或全量复制蓝图默认值。

## 3. 验证与本批结论

- [ ] 3.1 在真实驱动的隔离环境中对照创建与所属类核心行为，同时抽查未改代表对象；记录原始/改造后结果，特殊回调、数值、文案和权限保持一致。
- [ ] 3.2 对实际可达通路验证刷新/归位、装备或消费、交易、拆分及存取，存档仅使用临时旧格式夹具；确认无需公共机制适配且原记录直接可读，发现不成立则撤回本组改造。
- [ ] 3.3 对存在频繁创建/重置的本组做同量耗时与内存对照；记录环境和差值，若明显退化且只能靠额外机制补救，则恢复原实现，不新增性能平台。
- [ ] 3.4 对本批修改的 LPC/头文件执行项目 formatter、--check、差异审查和受影响编译；核对结果，不以格式化或编译代替游戏行为验证。
- [ ] 3.5 记录本批采用/保留清单、验证范围及代码回退方式；仅为实际新增接口补必要用法，确认没有新存档格式、资产转换或旧路径删除计划。

## 4. 后续类别按需复核

- [ ] 4.1 按维护者选择，从防具/普通兵器/书籍或食物/饮具中取下一小组，重复第 1–3 节；用前后对照证明局部收益，未选择的类别明确保持原样。
- [ ] 4.2 按需复核药材/药品/宝石/刺青已有父类，或动物/NPC 的真实重复；交付该组选用现有抽象、局部简化或保留结论，不为了推广增加叠加与角色管理层。
- [ ] 4.3 只有维护者选定时才评估容器/公告板/普通任务物；以原业务身份、历史内容及生命周期无需适配为准，不满足就记录保留并结束，不扩展为全库迁移。
