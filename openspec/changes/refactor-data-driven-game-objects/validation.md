日期：2026-10-04。旧源码基线 `ed10c535`；Windows 本地驱动报告 `fluffos 20260929-5270e7d6-795eb371`，Node.js v24.21.0。全部测试使用隔离临时目录，不读取、改写或迁移正式玩家数据，不重启正式游戏，不调用外部 AI/业务服务。

**阅读说明：下面“实现范围”至“后续类别建议”为第一版一对一数据化的历史记录，202 个独立 ID 与不合并库存的规则已替代。当前交付结果见文末“规范品种归并验收”；两轮检查数量及性能不混算。**

## 实现范围

202 个普通 CLOTH 源文件已删除，改为 `d/items/cloth.lpc` + `cloth_data.h` 中的 202 个独立品种。新品种保持 Domain UID、原名称/颜色/别名/重量/属性/初始化次序；共用类不作为商品，未知品种和外部直接参数构造被拒绝。可变复合默认值在实例间隔离。

744 个实际调用文件完成迁移：769 处静态表达式、2 处动态铁背心分支；另 5 处动态拼接白名单不涉及本批，保留原样。映射及源 SHA-256 在 `tools/tests/cloth/baseline.json`，不会因本 OpenSpec 归档失效。没有逐品种新文件、旧路径转发壳或运行期别名。

背包实体文件检查只增加已登记虚拟服装例外。旧乾坤袋已禁用的操作、其他虚拟对象资格、普通服装 autoload、mudcore、FluffOS 和 AI 服务均未改动。

## 性能与内存

每次独立启动驱动；旧/新顺序交替，三轮。先加载相同的 202 个品种蓝图，再保留每品种 20 个实例，共 4,040 个；不计 Node 准备副本、Git 读取及启动耗时。时间单位为毫秒；`memory_info()` 是驱动估算，不是 OS RSS。

| 指标 | 旧源码，三轮 | 数据化后，三轮 |
| --- | --- | --- |
| 冷加载蓝图 ms | 231.800 / 197.563 / 194.322 | 64.462 / 43.223 / 42.938 |
| 已有蓝图后创建 4,040 实例 ms | 32.426 / 31.299 / 32.258 | 308.742 / 287.502 / 282.429 |
| 蓝图新增估算内存 byte | 782,581（每轮相同） | 557,424（每轮相同） |
| 实例新增估算内存 byte | 3,225,360（每轮相同） | 5,442,920（每轮相同） |

结论：本负载冷加载中位数约降低 78%，蓝图估算内存约降低 29%；但实例创建中位数约为旧版 **8.9 倍**，实例估算内存约增加 **69%**。绝对值为每实例约 0.071 ms（旧版约 0.008 ms），4,040 实例多约 2.11 MiB。不能宣称总体运行更快或更省内存。虚拟构造和独立可变状态有成本；没有增加缓存/工厂框架来掩盖取舍。后续类别应结合实际负载评估收益，而非只看删除文件数量。

## 部署和回退

操作说明见 [数据化物品文档](../../../docs/architecture/data-driven-items.md)。离线工具仅转换显式清单中的背包 `my_depot/itemN/file`、商店两项库存映射路径键、指定旧袋记录；不会替换玩家描述或未选对象。商店新旧键冲突失败，不合并不同价格和数量。

正式切换须先停服保存、备份代码/记录，核对预览与转换报告，再部署代码及转换副本并冷启动。回退同时恢复旧代码和同批原始备份，不能仅回滚代码。开发阶段未执行这项生产操作。

## 后续类别建议

优先选择固定初始化、无独有回调的其他普通防具或兵器；单独核对 ARMOR/EQUIP/CLOTH 等父类差异。食物、饮具和书籍再按消耗、容量、阅读行为拆分。不把独有剧情、F_NOCLONE、自制装备或所有同名物品自动并入，本批不扩大到其他类别。

## 规范品种归并验收（当前，2026-10-04）

### 实现与数据边界

202 份历史定义归并为 **148 个规范品种**；19 个多来源组共去除 54 个重复定义，其余真实差异独立保留。所有 ID 均使用描述物品本身的命名，不只重命名重复组；744 个调用文件的 769 处静态引用及 2 个动态分支使用最终规范路径。同文件不同旧路径未出现归并后的配置键冲突，没有用 mapping 覆盖来吞并刷新数量或价格。

原 baseline.json、源码哈希及上面的报告原样保留。canonical_ids.json 与 cloth_canonical.mjs 构成离线对应资料：202 个实体路径和 202 个中间虚拟路径直接指向最终品种；游戏运行不加载此映射，不接受已移除 ID。

普通布衣归并兼容 `cloth/linen/c/l` 输入；主 ID 统一为 cloth，所以原 linen 的显示括号随之变更。只有这一组按核对后的数值语义统一 `value=0` 与未设置。颜色、描述、重量、价格和 `shaolin` 等实际差异均保留。原 28 份提前设置的固定 `long` 统一进入蓝图 `properties`，删除 `instance` 字段和初始化分支；实例通过默认对象读取，可独立覆盖和删除覆盖，可变复合属性隔离不变。

### 归并后性能（重新实测）

相同 202 个历史来源的加载请求、每来源 20 件、共 4,040 件；旧版实际加载 202 个独立蓝图，新版实际加载 148 个规范蓝图。每轮独立进程，顺序交替，三轮；构造函数未改写，计时不含 Node 准备与启动。

| 指标 | 旧源码，三轮 | 当前归并版，三轮 |
| --- | --- | --- |
| 加载蓝图 ms | 255.219 / 216.699 / 212.005 | 57.623 / 41.119 / 36.078 |
| 创建 4,040 实例 ms | 32.484 / 30.382 / 28.088 | 324.022 / 331.978 / 292.661 |
| 蓝图新增估算内存 byte | 782,581（每轮相同） | 420,156（每轮相同） |
| 实例新增估算内存 byte | 3,225,360（每轮相同） | 5,398,920（每轮相同） |

本机中位数：加载时间减少约 81%，蓝图估算内存减少约 46%；实例创建约为旧版 10.7 倍，绝对值约 0.080 ms/件，4,040 件的实例估算内存多约 2.07 MiB。收益主要是定义和身份统一、文件减少及维护成本降低，不宣称所有运行指标改善。计时会受本机负载影响，不把与第一版测量的比值差异解释为确定的性能退化或提升。
