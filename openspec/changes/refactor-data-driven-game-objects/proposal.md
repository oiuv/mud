# Proposal

## Why

游戏已有 ITEM/EQUIP/SWORD 等行为类，大量具体物品仍重复填写属性与初始化代码。按相同行为抽取共用类，用数据表达品种，能让新增内容和修改公共逻辑更直接。

**底线是物品功能不变、长期维护更简单。旧文件路径不是保留目标，修改调用文件的数量也不是复杂度指标。** 每批迁移完成必须删除全部被替代的旧物品源码，共用类和同类品种数据取代逐物品文件；不保留转发壳、旧路径别名或两套正式入口。

## What Changes

- 先按全局行为分类，再逐类实施；优先处理 `/d` 使用的普通服装，不能只按同名物品寻找重复。
- 品种使用新的虚拟路径作为正式入口：`new("/类路径/品种键")`。现有虚拟对象机制内部调用参数化公共类，复用 LPC 原生 `new/create`，不新增物品工厂。
- 不同时承诺直接带参创建与虚拟路径创建是两种可互换的商品入口；商店、刷新、仓库继续使用单个路径字符串识别品种。
- 同步迁移创建、比较、商店和刷新配置中的引用，处理实际阻止虚拟物品工作的实体文件检查；保持原玩法和存取资格。
- 旧持久记录若引用已删除路径，以受控的一次性路径转换处理，不建立运行期兼容别名。不改记录结构、不顺带读取或改写正式玩家数据。
- 复用已有继承体系；共有特殊行为可形成子类，真正独有的行为保留专用实现。默认数据采用就近 LPC mapping，不增加数据库、目录服务或缓存服务。

## Capabilities

### New Capabilities

- `game-object-definitions`：公共类、品种数据与统一虚拟创建入口，包含初始化和实例隔离约束。
- `game-object-lifecycle`：品种可区分、可按路径重建，迁移后生成、交易、存取功能不变。
- `game-object-families`：按共同的实际行为分类，保持原属性和特殊功能，逐类接入。

### Modified Capabilities

无。本次不要求 mudcore 或 FluffOS 增加游戏专用能力。

## Impact

首批为 `/d` 的普通 CLOTH 服装候选及实际引用它们的代码。直接继承 EQUIP 的服装、兵器、食物、饮具等属于后续行为族，不为了统一名称改变其父类功能。原北京五把剑的分析保留作历史基线，其“必须保留旧路径”的评估条件已被本次决策替代。

新虚拟品种路径保持现有路径式接口；实体 `.c` 文件存在性检查、品种蓝图、初始化次序及历史记录迁移必须单独验证，不能只因驱动支持虚拟对象就宣布整条业务链完全兼容。详见 [design.md](design.md) 与 [tasks.md](tasks.md)。
