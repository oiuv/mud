# Design

## Context

动机和范围见 [proposal.md](proposal.md)。已检查的实现与约束：

- `tools/tests/test_weapon_combat.mjs` 已提供临时源码副本、独立驱动、回环随机端口和日志检查，但会替换攻击、招架等随机决策；其百万气血测试角色也不适合直接衡量生存。
- 盘古 `kai` 与撼山 `zhen` 当前核心公式相同；中平 `ding` 是七次普通攻击，胡家 `cang` 是至多八击并有临时命中加成及忙乱；打狗 `chan` 只有控制，缠魂 `duo` 同时涉及伤害、毒技及白绸额外控制。不能用单个伤害字段统一排名。
- `feature/action.c` 的忙乱会受性格和互搏影响，数值忙乱不是固定秒数；默认针类按剑法分发，但物品仍为针，不是新增独立基本功。本批六类样本不包含针。
- 御剑飞升的共享对象中仍有按函数名删除 `perform2` 回调的写法；普通玩家可达性和多施术者影响尚待独立复现。本批不调用它，也不将其标为已修复。

## Goals / Non-Goals

**Goals:** 得到可追溯、可重复运行的同条件机制基线；区分单击、绝招和短时交锋，发现值得后续调查的差异。

**Non-Goals:** 不模拟玩家最优操作或全门派配装，不宣称人工角色等同线上可获得角色；不做十二类排行榜、自动调参、通用克制表或战斗框架重写。此次为工具与文档变更，按 `skip_specs: true` 跳过增量规范。

## Decisions

### 1. 独立入口，沿用已有隔离方式

新增 `tools/bench_weapon_balance.mjs` 与 `tools/tests/weapon_balance/`，保留现有七组功能回归原样；不为此次复用抽取通用测试平台。入口提供 `--help`、`--driver`、`--smoke`、`--samples`、`--bouts`、`--duration` 和可选 `--output`。默认完整参数为每条件 100 次独立单次采样、每对照 20 场交锋、每场最多 30 秒；烟雾模式仅验证链路，不用来宣称强弱。

源码复制排除正式配置、日志、账号与私有数据，仅按现有测试方式复制公开字典。驱动仅在临时 MUDLIB 和回环随机端口启动；拒绝将输出目录指向源码仓库、其子模块或其符号链接等价路径，不覆盖已有结果。无须管理员提供测试账号。

### 2. 明确一个标准档，不一次铺开大型矩阵

首版标准档初值：双方经验 1000 万，四项基础属性各 30，基础兵器及待测特殊武学各 200；基础内功、轻功、招架各 600，不激发额外内功、轻功及招架特效；气血及有效上限 10000，精及有效上限 10000，最大及当前内力 6000，武学修养 200，毒技默认 0，不开互搏、性格减忙、药物或临时增益。有效技能通过真实接口读取并写入报告，不把原始等级当有效等级。

武器夹具继承对应真实兵器，统一初始化伤害 50、重量 3000；基础防具加成统一 100。实际标志、材质、刚性及所有最终属性都写入配置，不增加物品专属命中钩子。它们是用于拆分机制的标准样品，不是同价商店装备，也不作为上线物品。先预检六招的原资格、映射和资源；配置不成立应报告错误，不能在采样中跳过检查或悄悄加属性。

零加力与加力 50 单列。缠魂额外提供一个明确标记的扩展配置：毒技 200、白绸武器，其余相同；与自身中性配置比较，不与其他武学混成同成本排名。首版不声称搜索过最佳配装，也不把这个较高培养投入算成免费的类别优势。

### 3. 分三层测，避免把控制武学判成零收益

| 模式 | 执行方式 | 可以回答什么 |
| --- | --- | --- |
| 普通攻击 | 各武学已激发，单次真实普通攻击；每次重建状态 | 动作与命中回调在同属性下的气血、创伤和资源变化 |
| 单次绝招 | 真实命令入口，保留本招与公共战斗全部结算；每次重建状态 | 发动、命中、连击、实际总成本和双方初始忙乱 |
| 短时交锋 | 三组配对，在原生心跳/回调时序内执行预定策略 | 控制后续收益、自忙机会成本、资源耗尽与生存 |

为两侧提供独立临时交互角色，沿用本地连接夹具；确认 `userp()`、`interactive()` 及既有 `playerp()` 的实际结果，合法设置测试领悟，不用 NPC 豁免证明玩家资格。每次命令使用对应玩家上下文，双方交换先行动顺序。

短时策略固定为：不忙且满足条件时尝试本组唯一绝招，否则按真实普攻路径行动；打狗不在对方已忙时重复请求缠字诀。不得每轮恢复内力、清除忙乱或复活。每组分别做纯普攻和“普攻＋指定绝招”对照，零/正加力分批，避免把不同策略混成一个结果。不声称这是玩家最优策略。

保持真实心跳、忙乱减计和 call_out 时间，记录驱动时钟配置与实际观测时长；不以手动调用若干次攻击冒充持续 30 秒。昏迷、死亡或时间到即记录对应终态，保留失去兵器等真实影响。超时未分胜负就是截尾/未决，不能计为胜利或填一个虚假的死亡时间。

### 4. 测量真实变化，不改变采样随机分布

不得复用回归中的强制命中、固定随机或模拟战斗守护精灵。角色继承中的观测回调先后转调原实现，只增加计数，不覆盖返回值或成本；必要的临时源码探针只能观察原结果，位置和前后 hash 随报告记录。所有生产公式、随机调用和分支必须保持。单次模式可暂停夹具自动心跳以隔离一次调用，但这一限制明确列出，不用于计量持续战斗。

每条样本记录：条件 ID、模式、角色/武器配置、发动成功或拒绝原因、普通攻击次数及真实命中/招架/闪避、实际 `qi` 与 `eff_qi` 损失、攻击者及目标资源变化、双方忙乱，以及异常/终态。反击与追加攻击有独立方向标记；直接伤害绝招的成功率与普通攻击命中率使用不同分母，不从伤害为零反推闪避或招架。

单次忙乱报告真实计数/状态，不换算秒；短时控制占比按观测时间内的实际忙乱时长计算，注明采样分辨率。报告内力总消耗（含公共加力/钩子），若存在恢复则分别记消耗与恢复；效率分母为零时标为不适用，不写无限或编造零成本。统计气血损失与创伤分别输出，不能相加当作总伤害。

### 5. 统计结果不是平衡通过条件

保留每次原始数据和实际样本数，汇总均值、中位数、分位数；概率类附样本数和区间。完整基线以相同配置独立运行两批，比较方向是否稳定；记录模型之外的随机来源为驱动原生随机，不承诺跨运行逐值重放。源码及 mudcore 提交、工作区相关文件 hash、驱动版本/hash、完整参数与观测探针组成运行清单，变化时不混算。

工具通过标准是完整、真实、可追溯，不是胜率接近 50% 或某技能必须更强。自检覆盖汇总算术、零分母、截尾、缺样本、角色顺序、进程失败和状态残留；真采样数据禁止注入预期结果。结果波动大时明确“证据不足”，后续可追加样本，不自动调数值。

## Risks / Trade-offs

- [人工标准属性不代表获得成本] → 报告只比较固定配置，列出贡献、门派资格、毒技/材质等未建模差异；真实门派配装是后续阶段。
- [伤害路径不同] → 同时保留真实普通攻击与直接伤害入口，不用同一个命中率分母或纯公式代算覆盖它们。
- [观测夹具改变行为] → 转调原实现并用少量无探针对照校验状态；不接管战斗规则，夹具错误阻止发布报告。
- [时序受进程负载影响] → 保留原时钟配置和实际耗时，先顺序隔离运行，不用加速时钟提升样本量；实际运行较慢是可接受的离线成本。
- [新发现确定缺陷] → 保留复现证据，标注受影响结果，另立修复，不拿错误数据调平衡；无关待核风险不阻断全部样本。
- [御剑回调尚未验证] → 独立待办，需多施术者、销毁和重新施展复现；首批六门样本不依赖它，不提前宣布全武学无 BUG。

## Migration Plan

1. 先完成隔离入口和工具自检，再运行六门武学的小样本烟雾，核对资格、成本、记录分母及状态重置。
2. 再执行两批同条件完整采样及现有功能回归，实际运行后才填写分析报告、证据目录与限制；不预写“平衡通过”。
3. 由报告提出下一批最小差异化候选及理由，具体修改另行确认。本批无需正式部署或存档迁移；回退只撤销新增评测工具和文档，不操作服务。
