# Design

## Context

动机及影响范围见 [proposal.md](proposal.md)。代码基线 `57f106f8` 已提供四类数据物品、精确存取、统一离线转换与隔离驱动测试；本批直接复用。

2026-10-05 只读扫描 `/d` 的 15 份 NECK 定义，均只有 `create()`。用既有词法解析器在内存中核对名称、重量、固定属性，得到 10 组。随后隔离真实驱动的旧对象基线通过 64 项检查，四个代表品种通过 511 项检查；最终全批回归通过 2481 项，详细范围及原有缺陷见 [validation.md](validation.md)。CodeGraph 未完整收录这些物品，范围以当前源码和既有引用扫描器为准。

## Goals / Non-Goals

**Goals:** 复用现有构造与迁移约定，统一等价身份；保持蓝图、克隆的有效属性、颈部穿戴和实际调用；新增与旧四类混合的可恢复记录转换。品种 ID 简短、稳定，字段仍只有名称、输入别名、实际重量和单层固定属性。

兼容性以旧代码的实际行为为准，不以名称、注释或推测的设计意图代替。可疑或不合直觉的表现不直接认定为 BUG；只有明确确认的 BUG 才作为独立修复记录依据、范围和验证，其余功能保持原样。测试预期与旧行为不符时，应纠正测试预期，而不是改动游戏规则迎合测试。

**Non-Goals:** 不建通用装备工厂，不增加实例属性层、运行期别名或新的转换 CLI；不修正历史数值、输入名、材质、文字、剧情时序或领取资格；不改公共装备父类、mudcore、AI 和驱动，不操作正式服务或存档。

## Decisions

### 1. NECK 独立程序，复用既有生命周期

新增 `d/items/neck.lpc`、`neck_data.h`，直接继承 NECK，正式入口 `/d/items/neck/<id>`。内部返回新克隆，由驱动赋予虚拟身份后通过 `virtual_start()` 初始化一次，同品种蓝图作为默认对象，复合状态独立复制。无参 provider 不交付，未知品种拒绝；不借 CLOTH 父类新增撕布、洗涤能力。

数据按 ID 自然升序排列，已有编号不重分配；只保留 `name/ids/weight/properties`。玄铁令和赏善罚恶簿的固定 long 原位于分支外，迁入蓝图属性，由实例正常覆盖和回退，不恢复单独的 instance 表。以可见属性和游戏行为验收，不保留无效的历史源码排列。

### 2. 区分普通属性与实际重量

白金项圈和两份荆州金项链使用 `set("weight", ...)`，不是 `set_weight()`。先在隔离真实驱动记录旧蓝图、克隆的普通属性、实际重量及派生值，再填数据；旧对象基线已核验实际重量均为 0，普通属性分别为 200、500。解析器只在内存适配已核对写法，冻结原文/哈希，不改原历史。

三份其他金项链用 `set_weight(500)`，因此保留 `jinxianglian` 与 `jinxianglian2` 两个真实品种；不能因同名同价合并，也不“修复”零重量。其余属性未设置仍不设置，原 neck、steel、玉 等材质不规范化。

### 3. 调用迁移保留领取与剧情识别

引用扫描定位 15 个文件、15 处静态引用，均相对 `d/`：`changan/npc/{jinfuhuan,yuanwai}.c`、`city/npc/{yang,yuhuan}.c`、`dali/npc/datusi.c`、`fuzhou/npc/chen.c`、`jingzhou/npc/shuanghua.c`、`luoyang/npc/{xiao,zhou,zhu}.c`、`quanzhou/npc/chen.c`、`wudang/npc/xiaocui.c`、`xiangyang/npc/gaoli.c`、`yanziwu/npc/{abi,azhu}.c`。原表达式在实施时冻结，检查相对路径、宏和商品键碰撞。

- 武修文和道相各有 `weibo` 动态领取分支，统一到 `/d/items/neck/shaolin_weibo`，保留各自身份条件、原 `present(name, player)` 检查及共享库存。原输入别名是 `wei bo` / `bo`，本批不新增 `weibo` 别名或顺手修正原持有检查；新旧实际表现须对照。手套、指套、鞋靴和其他护具分支仍有效。
- 萧员外 `send_to_fight()` 改创建路径；`present("yu pei", who)` 及湘湘 `check_rescure()` 的人物阻挡、领队和跟随逻辑保持。验证玉佩发放、识别、随行状态、归还消耗，以及原书籍奖励入口，不替换任务为新协议。
- 玉佩回归在隔离夹具运行实际相关函数，区分物品迁移效果和旧剧情本身。若旧版也存在无关回调错误，单列原有缺陷，不顺带修复，也不把局部测试称为完整剧情验收。
- 扫描中副将和道尘的同目录拼接仅发武器，保持现状。玄铁令、赏善罚恶簿目前未命中创建引用，仍保留品种和旧记录映射；不根据未命中认定无历史数据，不新增获取入口。

### 4. 五类统一存取与离线迁移

背包仅增加 NECK 表已登记路径，未知虚拟对象、穿戴中、临时状态、禁存和独特物品仍拒绝。原四类及实体物品继续可用，不开启自动加载或旧袋功能。

既有 `tools/migrate_item_records.mjs` 增加 15 条映射，合计预期 584 条历史路径。临时五类玩家、商店和显式选定旧袋记录共用默认预览与新目录输出；玩家分立记录不合并，同品同价商店库存合计，价格冲突整批拒绝，无关字段及未选物品保持，原字节可恢复，重复转换零变更。

### 5. 复用现有测试，不新增框架

先冻结原文、哈希、分组和引用，选择两种金项链、少林围脖和龙凤玉佩接入，再扩展全批。测试真实创建、交易/禁售、存取、状态隔离与身份重建；可穿戴品种验证穿戴/卸除和槽位互斥，不因继承 NECK 就假设所有品种可穿戴。

- 玄铁令保留 `female_only=1`。`cmds/std/wear.c` 的旧判断仅拒绝 `gender == "男性"`；分别验证女性、男性和无性角色，新旧结果一致，不改成所有非女性均拒绝。
- 赏善罚恶簿原本没有 `armor_prop`，`feature/equip.c` 的 `wear()` 返回 0。验证新旧均不能穿戴且不占用颈部槽位，不补护甲属性，也不修改公共穿戴逻辑。这不是已经确认的 BUG。

复用旧四类审计与隔离驱动测试，其调用审计只允许本批精确替换，不放宽历史属性断言。性能用旧/新各至少三次独立进程，对相同 15 个来源、相同实例数测量冷加载、热创建和驱动内存，报告绝对值及文件减少，不要求必须更快、不外推整服性能。

## Risks / Trade-offs

- [同名金项链误合并、零重量被覆盖] → 普通属性和实际重量分开实测，保留两种品种。
- [固定描述或实例复合值泄漏] → 测试原描述、覆盖回退、两实例及后续创建互不污染。
- [换路径破坏玉佩剧情或围脖领取] → 保留输入名、各自条件和原函数，按上述实际分支对照。
- [旧记录加载失败] → 字段级转换、冲突拒绝、备份与代码/记录联合回退，不加运行期兼容壳。
- [虚拟创建增加开销] → 独立实测本批绝对耗时和内存，收益为品种唯一和净减少 13 个游戏定义文件。

## Migration Plan

1. 冻结基线，记录旧对象运行数据，完成代表品种及业务边界验证。
2. 接入全部品种、调用、背包与离线映射；核对后删除本批 15 个旧定义。
3. 格式化、编译全部实际调用，运行五类回归、离线记录、审计与性能测试；同步维护说明，实际通过后勾选。
4. 维护者在停服备份预览并按需转换，核对副本后联合切换代码与记录；零变更只对已检查范围有效。
5. 回退同时恢复对应代码和原字节记录。开发验收不代表正式部署，不在此流程自动推送、重启或发布。
