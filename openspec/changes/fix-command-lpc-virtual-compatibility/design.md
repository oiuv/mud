# Design

## Context

动机见 `proposal.md`。本次审查覆盖 `/cmds/` 的 335 个源文件/头文件，定位的是扩展名、对象加载、目录扫描及源码展示问题，不代表已验证全部指令的所有玩法。已修复的 `clone` 隔离回归为 51 项通过；其余问题尚待本变更实施。

实现依据：

- `mudcore/system/kernel/simul_efun/file.c` 已提供 `lpc_file()`、`lpc_object_path()`、`lpc_source_files()`；显式源码后缀精确匹配，无后缀优先 `.lpc`。
- `adm/daemons/virtuald.c` 按 `/provider/key` 调用处理程序；处理程序可以返回另一程序的克隆，虚拟身份不等于实现源码。
- `cmds/adm/updateall.c` 已识别双扩展名并排除隐藏路径、tests 和若干非游戏目录；`loadall` 尚未同步。
- 真实驱动隔离验证：冷加载不存在的实体 `.c` 可返回 `0` 而不抛错；同名 `.lpc` 可正常无后缀加载。虚拟路径附 `.c` 可能仍被驱动接受，不能把所有字符串拼接都报告为加载失败。`children()` 能处理对象名的扩展名，`function_exists()` 的程序名则不带源码扩展名。

### 已确认修复清单

以下共 28 个指令文件，每组必须有对应回归，不以统一文本替换代替语义判断。

| --- | --- | --- |

| `std/special.c`、`std/team.c`、`std/vote.c` | 特技或固定子命令路径检查仅认 `.c` | 双扩展名，保留原固定目录与分派规则 |

| `wiz/info.c`、`arch/data.c`、`arch/sa.c`、`wiz/ff.c` | 将对象身份、环境或函数来源误标成 `.c` | 对象身份按原生名称显示，存在的源码显示真实扩展名 |

不计为本轮缺陷：`goto` 的补 `.c` 为注释；`clear` 有原生加载后备；`summon` 的查找在已验证驱动中仍可解析；`info` 的实例统计并非因 `.c` 后缀而失效。`update`、命令索引、`which`、`rehash` 已具备相关加载能力。上述入口纳入必要回归，不能为了减少 `.c` 搜索命中而机械改写。

## Goals / Non-Goals

**Goals:**

- 修复清单内全部已确认问题，旧 `.c` 的业务行为保持不变；新格式与旧格式应用同样的资格和权限。
- 原生驱动负责创建与虚拟身份；指令负责正确选择文件操作或对象操作，检查失败并提供准确反馈。
- 用真实驱动执行实际指令代码覆盖冷加载、热加载、成功与拒绝路径。

**Non-Goals:**

- 不修改装备属性、技能数值、配方、物品发放资格或玩家持久数据，不开展下一类物品迁移。
- 不新增虚拟类型注册表、任意品种枚举协议、热更新事务框架或旧路径兼容壳。
- 不让 `cat`、编辑/复制文件等纯文件工具读取不存在的虚拟文件；不扩展 `hotupdate` 已声明的实体蓝图边界。
- 不自动更新克隆/玩家对象，也不声称更新处理程序就能刷新所有现存虚拟实例。

## Decisions

### 1. 复用文件辅助函数，按用途解析

读取、编译、扫描或改写实体源码使用 `lpc_file()` / `lpc_source_files()`，明确后缀按精确文件处理；用于比较、`children()` 等的对象身份使用 `lpc_object_path()`。无后缀对象加载保留驱动的 `.lpc` 优先级；不维护第二套后缀表和加载优先级。

虚拟路径不能要求 `lpc_file()` 成功。对象操作按原命令约束解析路径后使用原生加载/创建，分别检查异常与 `objectp()`；调用失败不报告成功。显式实体后缀不能被悄悄改为另一扩展名。只查询已加载实例的 `child` 不增加加载副作用，无实例时明确报告为空。

拒绝“全局去掉所有 `file_size`”方案：技能、子命令、源码读取仍有真实文件边界，不能借兼容性扩大可调用路径。

### 2. 保留原规则，修正存在性检查

发放类命令先验证物品可用再进入原接收者循环，保持数量、合并物品、落点与各自资格筛选；后续构造失败须明确报告实际结果，不虚报全员成功。`home` 保留无工作室时的原后备位置。`rideto`、`whistle` 和 `make` 只修正既有配置/配方目标的解析，不新增可任意指定目标的玩家入口。

技能与子命令属于实体代码。双扩展名接入必须覆盖“拒绝”路径：尤其 `learn` 不能因为已学技能为 `.lpc` 就跳过 `valid_force`。绝招/内功列表按逻辑名称去重，不把 `.lpc` 截成错误名称；`team`、`vote` 保留固定分派目录，不启用任意虚拟子命令。

### 3. 批量工具扫描源码，不猜测虚拟品种

`loadall` 支持 `.lpc` 与 `.c`，沿用原有 `u`、`event`、`simul_efun` 等排除，并补齐 `updateall` 已采用的隐藏路径、tests 和非游戏目录保护；直接指定被排除目录也不能绕过。利用现有单层源码发现函数，不重复加载同名对象；失败日志和汇总区分成功、失败与跳过，不能有错误仍笼统声称目录全成功。

`guilei` 继续按实际源码归类房间/NPC/普通物品；读取房间物品表、NPC 装备和货表时使用原对象路径，允许其中的虚拟品种。扫描到提供 `create_virtual_object` 的处理程序，不把其无参克隆当商品，不自动枚举全部 key；明确区分处理程序与已归类物品。构造失败可定位，归类失败/跳过不计为成功；临时创建的 NPC 和物品在失败分支也必须释放。

`fcrypt` 仅增加 `.lpc` 文件识别，保留 `.h`、原授权及版本处理逻辑，不接受虚拟身份替代文件。

### 4. `updatei` 使用更新清单，失败不误报

- 根输入仍为可解析的实体继承源码；虚拟路径不是一个新的源码根。仅有选项而没有路径时给出用法，不对 `0` 执行字符串操作。
- 在销毁前记录已选对象的身份、真实源码及直接继承关系，以无后缀身份比较；保持排除玩家、克隆、VOID/TEMP 对象的既有规则。
- 实体蓝图按依赖顺序更新；同一依赖在列表中只处理一次，多重继承不能在尚未更新另一父程序时重建子对象。
- 已加载且符合原继承筛选的虚拟蓝图仍在范围内，不因没有同名源码而丢弃。先完成选中的实体程序，再按各虚拟身份重建；不枚举未知 key、不修改现存克隆、不绕过处理程序归属校验。
- 无 `-c` 只预览；超过原阈值且未指定 `-f` 时不进行更新。该保护已有帮助声明，修复实现漏掉的停止分支。
- 保留原有房间内容临时迁出行为；迁出失败或仍有玩家留在旧对象中，不销毁旧对象。加载抛错或返回非对象都停止并说明失败路径，不增加成功数，不再对无效对象调用环境或移动方法。
- 重建失败后，已迁出的内容留在原安全临时地点，明确说明未恢复；不承诺恢复已销毁对象及其原运行状态，不新增自动回滚系统。成功时才恢复原位置/房间内容，恢复失败也单独报告。

不采用“仅把 `.c` 替成 `.lpc`”或忽略加载失败继续执行的方案；也不把虚拟蓝图直接当实体文件更新。

### 5. 信息展示不伪造源码路径

`info`、`data`、`sa` 区分对象身份与实际文件；克隆名可以保留 `#编号` 作为运行身份，但不在其后伪造 `.c`。`ff` 将驱动返回的函数定义程序解析为现存源码；不存在时如实显示程序身份，而不是编造文件。

`more <文件>` 保持文件阅读语义；按身上/房间对象查阅时，实体对象定位其真实源码。虚拟对象没有同名源码时可按 `/provider/key` 定位处理程序，明确提示“查看处理程序源码”，不能声称这一定是对象实际执行的程序；处理程序可能创建另一程序。找不到可读文件时给出清楚提示。最终目标仍须通过原 `valid_read` 检查，不通过加载对象探测权限、不解析驱动调试文本推断源码。

### 6. 隔离回归覆盖每个问题文件

沿用 `tools/tests/` 的 Node 启动临时 MUDLIB + 实际驱动模式，增加专用指令测试入口和最小 LPC 夹具，直接加载/调用仓库指令，替换角色、安全守护和游戏周边依赖，不复制被测逻辑。LPC 新夹具使用 `.lpc`，全部测试数据在临时目录。

覆盖矩阵包括 `.c`、`.lpc`、无后缀、合法虚拟品种、错误 key、构造抛错、加载返回 `0`、权限拒绝及冷/热加载。按业务用途选择矩阵，纯源码工具不强行要求接受虚拟路径。技能互斥、三层/多重继承、虚拟蓝图、安全迁出失败、测试目录排除以及虚拟处理程序返回另一程序均有专门用例。

每个清单文件至少编译并触发被修正分支；静态扫描用于检查遗漏，不替代运行结果。复跑既有 `clone` 与普通物品/幻境协议回归，防止兼容修复改变创建行为。统一格式化只处理本次修改的 LPC 文件，随后 `--check`、差异审查和实际驱动验证。

## Risks / Trade-offs

- [对象加载会执行 `create`/`virtual_start`] → 仅在原本执行对象操作的命令中加载；源码阅读与实例列举不为探测而创建对象，测试不连接正式服。
- [更新失败无法复活旧对象] → 事前解析并检查更新顺序；销毁前确认玩家迁出，失败诚实停止并保留安全位置，不把“无异常”当成功。
- [扩大源码扫描会触达处理程序或测试夹具] → 明确排除策略和处理程序跳过规则；覆盖直接指定排除目录的用例。
- [加载能力被误当作授权] → 保留原命令、路径、玩家资格与处理程序校验，对拒绝路径单独验收。
- [隔离夹具无法复刻全服状态] → 报告实际编译/分支覆盖，不宣称已验证全部玩法；部署后由维护者在维护窗口做全量编译和抽查。

## Migration Plan

本变更不调整虚拟路径、物品 ID 或存档格式，无数据转换。实施完成后记录全部修改文件与测试结果；部署时更新这些指令对象，已有程序依赖需要刷新时安排正常维护重启，不以此替代物品迁移本身的存档流程。回退恢复本变更代码并重新加载，正式数据不随本变更迁移。未经另行授权不提交、推送或操作正式服务。
