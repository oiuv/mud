# 普通鞭类数据化设计

## Context

动机与范围见 [proposal.md](proposal.md)，候选和消费者证据见 [analysis.md](analysis.md)。基线为 `da7027046add7e68a2ca38f04611c3c0cd745498`，已有十三类采用同一虚拟对象生命周期、精确存取检查及离线转换流程。本批沿用这些结构，不改变主规范。

WHIP 的 `init_whip()` 仅处理蓝图，设置伤害、传入 flag、whip 技能类型以及默认动作和动词；不同于 STAFF，它不添加 LONG。三渡的独特黑索及备用普通长鞭有分支关系，不能按一般无条件携物语句处理。

## Goals / Non-Goals

**Goals：**以唯一规范品种数据替代同类重复文件；保持实际属性、输入、交易、刷新、配装、发放及存取行为；通过原物品真实驱动观测和原消费者方法对照验证，而非只验证可克隆。

**Non-Goals：**不抽取万能武器工厂、不新增缓存或存储框架；不改公共父类、虚拟分派、驱动或 mudcore；不迁移独特黑索、赤金鞭或其他物品类别，不依据名称推测新增效果。不顺带修正九节鞭材质拼写等历史数据，不读写正式存档或自行部署。

## Decisions

### 1. 复用分类 provider，保留 WHIP 原行为

使用 `d/items/whip.lpc` 与就近的 `whip_data.h`，直接继承 WHIP，沿用 `create_virtual_object(key)` 返回新克隆、`virtual_start()` 按最终虚拟身份初始化的模式。无参 provider 只持有登记表，未知品种不创建，外部调用使用唯一 `/d/items/whip/<id>` 路径。

蓝图设置名称、重量和固定属性后调用原 `init_whip()`；克隆绑定规范蓝图并复制必须隔离的复合默认属性，两者各执行一次原 `setup()`。保留驱动的身份、UID/EUID、clonep 和 virtualp 语义，不手动赋权或重命名。

不抽取跨类别新工厂：现有结构已经能满足本批。所有候选当前 flag 参数均省略，实际零标志以驱动观测为准，不能从上一批复制 LONG，也不补上名称暗示的属性。流星锤、钓杆继续使用鞭类技能和动作。

### 2. 冻结旧观测，核实等价后确定短 ID

在任何旧定义删除前，冻结 32 份源码、完整消费者原文、排除对象 hash 和旧蓝图/克隆观测。扩展已有严格解析器识别 WHIP/init_whip，拒绝额外继承、回调、动态表达式及未支持副作用；既有十三类基线不重写。

按完整有效名称、属性、重量、伤害、标志及行为核实静态预分的 25 组。六份拂尘与三份长鞭经确认等价才合并，别名去重但保持原输入可用；三种拂尘、两种长鞭等真实差异分品种。25 是预测，不以少一个或多一个品种判定失败。

规范 ID 使用 `shebian`、`fuchen`、`fuchen2` 等短名称和稳定编号，神蛟丝系列也可使用有意义名称加稳定编号；最终映射随基线固定。数据按 ID 自然排序，不重新编号，不在名称中堆叠历史地区、目录或每个属性限定词。拒绝保留重复来源 ID 的方案。

### 3. 迁移精确引用，分支单独验收

将 29 处已识别静态引用迁至规范路径，再复扫整个游戏源码的绝对/相对路径、宏与常量拼接。三个动态入口各增加明确映射：钱正伦 `whip`、副将 `changbian`、道尘 `changbian`；不改变原选择、门派、持有检查、配额、库存及实例覆盖。

王方平按原完整货表顺序执行实际 F_DEALER 查询/购买/支付/交付与冷却，核对十一件本批商品及其他货品身份不变。两处房间保留原 objects 语句、数量和顺序，执行 ROOM 刷新、携走与销毁补刷。十三处普通 NPC 携物语句按原顺序实际执行，其中李莫愁仍只携带不持用。

三渡分别执行原构造中独特黑索可取、已被占用两条分支：前者仍取得各自独特黑索，后者创建并持用普通长鞭。只替换长鞭路径，HEISUO 常量、其他独特装备和获取条件不变。可用隔离替身承载无关 NPC/独特装备设施，但实际分支、移动和持用须运行；报告不得将该验证扩大为独特兵器或完整战斗验收。

武修文、道相的防具入口和王方平 weapon2/weapon3 前缀不新增分支。完成后删除 32 份旧定义，不保留壳或运行期别名；赤金鞭保持原 hash。累计审计增加本批精确替换层，旧测试需要的鞭源码仅从冻结快照恢复到临时副本。

### 4. 继续精确存取与离线转换

`feature/user_storage.c` 只增加 WHIP 的注册品种路径检查，其他资格和序列化保持原样。`migrate_item_records.mjs` 增加 32 条历史路径，预计累计 1,145 条，目标是一次直接转换到最终规范路径。

仅处理显式备份中的既有字段：玩家背包、商店、明确选择的旧袋、精确 `npc/meng-zhu.o` 的 weapon/armor。测试十四类混合记录、同品同价数量合并、不同价格整批拒绝、独立实例数据保留、输入不覆盖、幂等及原字节恢复。不得新增运行期旧身份解析或扩大存档字段范围。存在真实冲突就报告，不通过重复 ID 回避。

### 5. 复用验收入口，独立测性能

为现有审计、`compile_cloth_callers.mjs`、`test_cloth_objects.mjs` 增加 `--whip` 及就近夹具；不另建运行器。验证全部旧/新蓝图和克隆、虚拟身份、一次初始化、复合属性隔离、持用/卸下、动作、耐久、存取、交易和前述消费者。保留 `/d/village` 与虚拟 clone 回归，运行十四类累计检查。

正确性测试结束后再执行三组新旧交替、每次独立驱动的性能对照。每组按 32 个历史来源各创建 20 次，共 640 实例，新实现按同一来源映射计数；分别记录冷加载、热创建中位数、内存估算及程序数。报告实际绝对值，不套用杖类数据、不将内存估算当 OS RSS，也不把冷加载节省与未知线上创建次数直接合成总收益。

## Risks / Trade-offs

- 同名误合并 → 全量旧蓝图/克隆观测先行，保留完整有效数据差异。
- 照搬 STAFF 引入 LONG → 直接调用 WHIP 原初始化并检查实际零标志、动作和技能类型。
- 只验证普通携物漏掉三渡条件 → 三个 NPC 分别覆盖独特黑索可取和被占用两条实际分支。
- 旧累计夹具仍引用待删除长鞭或商品 → 在临时副本恢复原源码并按批次映射对照，不污染运行期或重写旧快照。
- 旧存档恢复失败 → 显式备份预览、字段级转换、无损恢复测试，代码与记录配套上线/回退。
- 热创建与实例内存可能增加 → 独立实测并如实报告，不为少量开销新增框架。

## Migration Plan

1. 冻结旧定义与消费者，采集真实驱动观测，固定短 ID 和映射；再实现 provider、调用和离线转换。
2. 完成类别/累计回归、存档恢复、格式化、编译与独立性能测试后同步开发文档和验证报告；只有玩家可见变化才更新 `help/changelog`。
3. 正式部署另行执行：备份代码与相关记录，对备份预览；有旧身份才生成独立转换副本并核对数量/价格，再在维护窗口配套部署并冷启动。没有受影响记录则不改写。
4. 回退须停止写入并成对恢复旧代码、转换前记录，再冷启动；不只撤销代码，也不添加运行期兼容壳。本计划不授权开发过程操作正式服务。
