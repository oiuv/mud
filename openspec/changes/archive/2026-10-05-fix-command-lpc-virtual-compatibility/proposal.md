# Proposal

## Why

本库已支持 `.lpc` 源码和数据化虚拟物品，但 `/cmds/` 的部分指令仍以实体 `.c` 文件判断对象存在、发现技能或显示源码，导致合法对象被拒绝、技能检查漏执行，以及 `updatei` 销毁对象后加载失败。先修复本轮审查确认的问题，再推进普通食物迁移，避免迁移继续扩大指令兼容性缺口。

## What Changes

- 区分实体源码路径与运行期对象身份：文件工具解析真实扩展名，对象工具接受原生虚拟路径，不再统一拼接 `.c`。
- 修复发放物品、查找实例、移动、召回与制药相关入口；保留现有资格、数量、归属、配方和权限规则。
- 修复技能存在性检查、绝招/内功子指令扫描及 `team`、`vote` 分派；`.lpc` 内功不得绕过 `learn` 的互斥检查。
- 修复 `loadall`、`guilei`、`fcrypt` 的源码发现；批量加载避开非游戏源码、隐藏目录与测试夹具，归类不把虚拟处理程序当成商品。
- 修复 `updatei` 的双扩展名、继承依赖和失败判断，落实已在帮助中声明的 `-f` 确认保护；不把加载返回 `0` 算作成功。
- 修复对象与函数信息的伪 `.c` 显示，以及 `more` 按对象查看源码的定位；明确虚拟身份与处理程序源码不同。
- 添加隔离真实驱动回归，覆盖本轮 28 个问题文件及已有 `clone` 等兼容入口，同步指令帮助和开发说明。

## Capabilities

### New Capabilities

- `command-object-compatibility`：LIB 指令对 `.c` / `.lpc`、实体源码与虚拟对象的正确识别、发现、操作及失败处理。

### Modified Capabilities

无。沿用 `virtual-object-creation` 和 `game-object-lifecycle` 已规定的创建、身份与玩法约束；本变更不修改 mudcore 命令流水线或虚拟对象协议。

## Impact

- 问题文件位于 `cmds/adm/`、`cmds/arch/`、`cmds/imm/`、`cmds/wiz/`、`cmds/skill/`、`cmds/std/` 和 `cmds/usr/`，完整清单见 `design.md`。
- 优先复用现有 `lpc_file()`、`lpc_object_path()`、`lpc_source_files()` 和驱动加载接口；不引入对象注册框架、历史路径别名或新依赖，不计划修改 mudcore。
- 测试使用临时 MUDLIB、假角色和实际驱动，不向正式玩家发物品、不操作正式存档、不重启正式服务；本次修复本身不需要数据迁移。
- 食物迁移保持独立；尚未实施的功能不计为修复完成，也不以源码格式检查代替实际指令回归。
