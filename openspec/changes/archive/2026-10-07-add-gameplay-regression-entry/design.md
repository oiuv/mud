# Design

## Context

动机见 [proposal.md](proposal.md)。五个脚本都通过 Node 启动临时 FluffOS，支持驱动位置参数；`ai/scripts/verify_lpc.mjs` 还接受第二个 Python 位置参数，用本机 UDP 替身而非真实模型。它们各自创建系统临时目录、随机本机端口并输出日志路径，已有失败退出与驱动等待超时。

前三组输出 `<前缀> CHECKS: N FAILURES: M` 并另报 PASS/FAIL；AI LPC 相同。NPC 重连由 Node 输出 `AI NPC RECONNECT PASS: N checks`。因此可复用现有输出，不必修改五组脚本或 LPC 夹具。

## Goals / Non-Goals

**Goals:** 给既有五组正向回归提供统一启动、参数、可核查汇总及可靠失败状态；原脚本仍可单独运行。

**Non-Goals:** 不成为全库测试覆盖工具；不纳入全量编译、付费 AI 评测、旧代码负对照、格式化、自动构建、部署或 CI 服务配置；不修改玩法、测试断言或运行期接口。

## Decisions

### 1. 固定清单、顺序运行

在 `tools/test_gameplay.mjs` 内维护五组名称、路径和摘要匹配规则，使用当前 `process.execPath` 启动原脚本。工作目录固定为入口文件推导出的仓库根目录，不依赖调用者的目录；不使用 Shell 拼接命令。

选择顺序而非并行：避免多份源码复制和多个驱动争抢资源，日志也能按组阅读。选择显式清单而非扫描所有 `test_*`：不能把带负对照、性能、写数据或外部服务行为的其他脚本自动纳入。

### 2. 最少参数与依赖检查

对外提供 `--driver <path>`、`--python <path>`、`--help`。默认驱动为 Windows 的 `bin/driver.exe` 或其他平台的 `bin/driver`；Python 沿用 `ai/.venv` 的平台路径。显式相对路径相对调用者当前目录解析后传绝对路径，支持包含空格的路径。

运行前检查五组脚本、mudcore 必要文件、驱动/Python 路径和 Git 可用性，缺失时显示修复指引并非零退出；不自动安装、编译或修改环境。Python 使用现有 AI 环境，依赖导入失败由原脚本报告，不另建自动修复机制。未知选项拒绝，`--help` 不启动测试或要求驱动存在。

### 3. 保留日志，按实际结果汇总

每组展示名称与执行命令，转发 stdout/stderr，并提取其检查数、失败数和既有临时证据路径。结束时列出每组状态、检查数、失败数及耗时，列出总结果和总耗时。

退出码与摘要共同判定成功：子脚本必须退出 0，且有该组有效的成功摘要和零失败。摘要缺失、冲突或进程启动失败显示失败/不完整，未知检查数显示未知，不能算作零项通过；汇总区分已知检查数与不完整组。计数动态提取，不把历史 788 硬编码为当前结果。

普通单组失败仍继续剩余组，最终统一非零退出。用户中断则不启动下一组、不报告全通过。复用原脚本的临时目录、诊断保存与驱动超时，不重写驱动执行器或新增任务级超时。初版不增加 JSON 报告协议和新的日志数据库。

### 4. 验证编排，不复制业务测试

采用 Node 内置 `node:test`，围绕参数和结果解析、顺序调度、失败继续、非零退出进行小型测试；用测试侧可控进程或函数替身验证失败与缺摘要，不给正式 CLI 增加任意脚本执行/伪造结果参数。

随后用真实驱动运行统一入口，逐组核对原摘要及总数。单元测试通过不代替五组真实回归；Windows 路径实测，未运行的平台只说明参数/路径分支已检查，不宣称实机通过。

## Risks / Trade-offs

- [原脚本摘要将来改名] → 匹配规则集中维护且有单元测试；缺摘要失败，避免静默漏计。
- [某组失败导致无法给出完整总数] → 保留原错误与证据路径，显示已知计数及不完整组，不把已启动当成已通过。
- [各组复制源码耗时] → 初版保留隔离与可独立复跑，不为提速共用可变 MUDLIB。
- [测试结束后临时日志占空间] → 沿用现有保留策略和路径提示，不新增自动删除行为。

## Migration Plan

无需游戏停服或数据迁移。实施后开发者可直接运行新入口，原五条命令继续可用；移除新入口也不影响原回归或游戏。同步贡献规范及现有开发说明，不修改 README 项目介绍或 `help/changelog`。
