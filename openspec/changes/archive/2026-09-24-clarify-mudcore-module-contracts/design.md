# Design

## Context

动机见 [proposal.md](proposal.md)。源码基线为 mudcore `4df084e`，框架版本 `2.0.0-dev`；规划根目录为主仓库，实施目标为子模块。

已核实的约束：

- `include/mudcore.h` 已通过 `CORE_*` 与宿主别名分离原始实现和覆盖；不能绕开现有覆盖机制。
- `inherit/command.c` 的 `nomask command_hook()` 固定串接方向、action、表情、频道和 parser；`enable_living()` 无条件调用 `parse_init()`。
- `inherit/user.c` 组合 `_LIVING`、战斗记录、GMCP 和任务；`living.c` 又组合攻击、状态、组队等。现有组合是兼容入口，不应直接裁减。
- `inherit/move.c` 在交互对象移动后直接调用 `gmcp()`，`remove()` 使用可选持久化协作；最小组合必须处理这些隐式协作。
- `system/daemons/login_d.c` 的 `create()` 无条件重载 `VERB_D`；认证状态为私有 mapping，连接交接受路径、身份、交互状态和调用来源约束。
- 登录名称与性别规则在 `get_name()`、`get_gender()` 中；初始属性已有 `CHAR_D->init_player()` 扩展点，无需另建角色工厂。
- 默认 master 的文件读写和 Socket apply 比较宽松；UID、绑定和数据库已有独立授权规则，不应以诊断为名改变它们。
- `tests/run.mjs` 当前复制临时 mudlib，执行 default/overrides 两组全量与回环测试；`tests/lpc/master.lpc` 的网络、登录和结束流程依赖完整组件，最小组合不能直接复用它的全量执行路径。

## Goals / Non-Goals

**Goals:**

- 使用增量公共入口与 protected 钩子，实现明确且可验证的选择性接入。
- 未采用新选项的宿主保持现有默认组合、调用签名、字段和行为；新配置只影响主动采用它的宿主。
- 将依赖、错误、生命周期和覆盖约定固化为 mudcore 独立携带的规范。

**Non-Goals:**

- 不重排现有完整玩家的继承链，不删除原有组件，不进行存档格式迁移。
- 不做运行时热切换模块、不支持玩家登录中途更换认证策略、不建立任意插件注册总线。
- 不使最小组合自动兼容所有原有玩法命令；实际选用的命令仍须满足各自业务依赖。

## Decisions

### 1. 长期规范放在框架内，OpenSpec 仅记录本次变更

新增 `mudcore/docs/architecture.md` 和 `mudcore/docs/module-contracts.md`。前者说明驱动适配、基础能力、可选系统、默认组合、宿主策略之间的边界；后者提供所有 `docs/inherit.md` 公共组件的依赖矩阵，并对本轮关键组合给出完整契约。

矩阵至少包含原始路径与别名、必需组件/daemon/simul efun、可选协作、驱动包、生命周期入口和宿主责任。详细契约覆盖 DBASE/SAVE/DBSAVE、COMMAND、MOVE、ROOM、默认/最小 USER、LOGIN/CHAR 和策略诊断；网络、DB、TUI 复用并链接现有详细手册，避免复制出第二份签名来源。

更新 `AGENTS.md`，要求新增公共组件明确上述边界，公共扩展测试同时覆盖默认实现、宿主覆盖和声明可选依赖的缺席。未具备隔离能力的组件必须如实列为组合依赖，不能只在文档中改称“完全独立”。

替代方案：只把审查报告存档不能约束后续开发；运行时模块注册中心会扩大依赖和生命周期复杂度，本次不采用。

### 2. 增加最小玩家组件，不改现有完整组合

新增 `inherit/user_base.c`，公开 `CORE_USER_BASE` 和可覆盖 `_USER_BASE`。它组合属性、名称、消息、移动、文件存档、命令及基础行动限制，提供与现有组合一致的 `is_living()` 约定，不继承攻击、状态、组队、战斗记录、任务或 GMCP。

保留现有 `CORE_LIVING`、`CORE_USER`、`_USER` 的默认值和继承结构。最小宿主显式将 `_USER` 指向 `_USER_BASE`，继续使用默认 `USER_OB` 的连接、存档及重连生命周期，并提供所需的命令配置和 `CHAR_D` 初始属性策略。`user_base` 是组件组合，不是独立的驱动连接对象。

文档给出可运行的最小宿主配置示例：选择 USER_BASE、关闭 parser、用宿主 COMMAND 别名仅保留方向/action 阶段，选用依赖满足的基础命令；不宣称只换一个宏就能自动消除所有服务依赖。

`move.c` 对 GMCP 和可选 `is_db_saved()` 协作先确认能力是否存在；存在时仍执行原路径，缺席时仅跳过该可选协作。必需的属性、移动和环境接口不作静默兜底。不能捕获并吞掉已提供组件的真实错误来制造“可选”。

替代方案：直接将原 `living/user` 改造成最小对象会破坏现有宿主；大量逐项预处理开关容易产生不可穷举组合。本次以一个明确的新增组合和现有宿主覆盖入口解决。

### 3. 保留受控命令入口，开放小粒度阶段钩子

保留 `nomask command_hook()`、`enable_living()`、`disable_living()` 的公共签名。增加 `protected string *query_command_handlers()`，默认阶段为 `exit`、`command`、`emote`、`channel`、`parser`；宿主可返回子集或调整顺序。

各阶段使用直接调用的 protected 局部钩子，例如 `handle_exit`、`handle_action_command`、`handle_emote`、`handle_channel`、`handle_parser`，参数明确包含 actor、verb、arg。通过固定阶段分发调用，不能把用户输入当作方法名，也不使用外部 `call_other` 绕过 protected 边界。

阶段返回约定：`0` 继续，`1` 已处理并停止，错误字符串交给现有失败提示机制并停止；parser 的原始返回值在对应钩子中按旧行为归一化。验证阶段列表为已知、不重复的名称；错误在启用命令前报告，不留下半初始化的 living 状态。公开文档说明钩子异常会传播，不会伪装为未处理。

新增宿主编译选项 `MUDCORE_ENABLE_PARSER`，默认 `1`。关闭时命令组件不编译/调用 parser efun，默认阶段列表不包含 parser，登录初始化不加载 `VERB_D`。同时使用驱动能力检测保护 efun 引用；显式选中不可用 parser 时报告明确的能力错误，不能静默改变默认路由。仅在阶段包含 parser 时执行 `parse_init()`。

表情与频道通过阶段列表控制：未选阶段完全不访问对应 daemon；已选而缺少实现则明确失败。parser 选项与阶段列表的生效时机为编译/对象初始化，不承诺热切换。

替代方案：移除 `nomask` 让宿主复制整个入口，会继续扩大定制面；新建通用事件总线对当前需求过重。

### 4. 从认证流程抽出角色策略，不开放认证状态

在默认登录 daemon 增加 protected 策略钩子：

- `query_name_prompt()`：角色名称提示；默认与现状一致。
- `validate_character_name(string name)`：合法返回 `0`，非法返回可显示的错误文本；默认保留中文、长度、禁用词及姓名查重规则。
- `query_gender_options()`：返回有序选项，包含输入键、显示标签和存储值；默认保持 m/f 与“男性/女性”的既有含义及顺序。
- `query_gender_prompt()`：默认由选项生成提示，宿主可覆盖。

非空选项根据声明的输入键匹配；默认 m/f 保留现有大小写及首字符接受行为。空选项表示主动省略性别步骤，不写入默认性别值。畸形或冲突的选项应在角色创建前报错；空输入和无效输入重新提示，不创建角色或转移连接。

提取内部角色创建收尾路径，供正常性别选择和省略性别共同使用；必须重新验证有效登录对象及认证状态，继续通过现有 `make_body()`、`init_new_player()` 和 `enter_world()` 完成创建。策略钩子不能创建已认证状态、绕过保留 ID、导出任意身份或替代 master 授权。失败时不留下可进入世界的半创建角色。

保留 `CHAR_D` 为初始属性与每次 setup 的定制入口，不新增第二套属性初始化机制。新增非中文名称、自定义性别、无性别、无等级/HP 属性的临时宿主示例，不把它们作为默认游戏策略。

替代方案：要求宿主覆盖整个 `get_name/get_gender` 会复制状态迁移代码；把账户认证也改成可插拔提供商超出本次需求。

### 5. 提供策略来源诊断，不提供通用生产 ACL

新增无自动启动行为的 `inherit/host_policy.c`，公开 `CORE_HOST_POLICY`/`_HOST_POLICY`，提供只读 `mapping inspect_host_policy(object masterObject)`。由宿主或管理工具显式传入已加载的 master 对象，不主动加载业务服务。

诊断文件读写、Socket、UID、绑定、数据库等 apply 的实现来源；逐项返回方法名、来源程序和 `framework-default` / `host-defined` / `unknown` 状态，以及说明性的 warnings。对文件读写和 Socket 的框架宽松默认明确提醒；无法确定来源时返回 unknown，不能假装通过。

只读检查方法来源，不实际发起文件写入、连接、数据库访问、UID 切换或调用权限 apply 来“试探”。宿主覆盖只表示实现来源不同，不代表安全；不输出凭据和实际玩家数据。不在默认 master 启动时强制执行或更改授权结果。

替代方案：框架无法正确推断所有游戏的路径/角色 ACL；默认改成拒绝所有会破坏现有宿主，因此生产策略由宿主显式提供。

### 6. 用独立的最小宿主验证组合契约

保留 `tests/run.mjs` 的 default/overrides 全量套件，新增可单独运行且纳入总入口的组合测试运行器和 LPC 夹具。最小宿主不得调用完整测试 master 的全量编译、TUI、网络或 Intermud 收尾流程。

测试矩阵：

| 组合 | 主要验证 |
| --- | --- |
| 原默认组合 | 默认命令顺序、中文角色创建、存档/重连及现有协议回归不变 |
| 宿主覆盖 | `_DBASE`、COMMAND 钩子、LOGIN/CHAR、UID 拒绝策略实际生效 |
| 最小组合 | 临时复制时排除战斗/任务/GMCP/状态/组队及关闭的表情/频道/parser 文件，仍可注册、执行选定命令、移动、存取和重连 |
| 自定义角色策略 | 非中文名称、自定义/无性别、无 RPG 初始字段，以及非法输入和未认证调用拒绝 |
| 权限诊断 | 框架默认、宿主覆盖、未知来源的分类，以及诊断无文件/网络/身份副作用 |

最小组合必须通过真实本机 Telnet 和持久化往返，不只直接调用钩子。已存在的安全拒绝测试继续执行；默认及有 GMCP 组件时也测试移动通知，防止把可选化实现成所有情况下都不通知。

使用完整驱动加编译关闭选项，可以验证关闭路径；不能把它宣称为已验证真实裁剪驱动。若提供无 parser 驱动，再记录该驱动的独立结果。无需为本变更重新构建驱动。

## Risks / Trade-offs

- [新基类改变继承冲突或存档布局] → 不修改现有完整继承链；最小组合显式采用，存档沿用相同属性接口；现有玩家切换组合需宿主单独评估，不自动迁移。
- [命令重排改变失败提示或执行次数] → 默认基线测试、短路顺序记录、参数传递及错误结果测试；拒绝重复阶段。
- [移出角色规则意外放松认证] → 保持私有认证状态与原授权入口，追加外部调用/伪造对象/UID 拒绝回归。
- [文档承诺强于实现] → 关键示例来自可运行夹具；缺席测试物理省略未选组件，不能仅用返回成功的桩掩盖依赖。
- [诊断被误认为安全审计] → 状态描述实现来源而非安全评级；文档和返回说明同时强调局限。
- [测试规模增大] → 复用现有默认/覆盖回归，新增小型组合套件，不把所有开关做无边界笛卡尔积。

## Migration Plan

1. 先建立默认行为回归和契约文档骨架，再实现可选入口与钩子；每批仅格式化本次修改的 LPC 文件并执行 `--check`。
2. 未采用新选项的宿主无须改配置；运行默认与覆盖套件，确认旧接口、默认值和存档行为不变。
3. 最小组合通过新增显式配置采用；重新编译受宏影响对象。不要在现有玩家运行中途切换组合，不自动删除存档字段。
4. 更新 `README.md`、`docs/README.md`、`docs/inherit.md`、`docs/integration.md`、相关命令/登录/角色手册、`docs/dependency-boundary.md`、`docs/maintenance.md`、`tests/README.md`、`AGENTS.md` 和 `CHANGELOG.md` 未发布条目。继续保留 `2.0.0-dev`，不打标签。
5. 记录所用驱动、格式化命令、各套件结果和未验证范围；真实老 MUD/minimud/MyMud 的接入验收另行授权执行。
6. 回退时由宿主撤销本轮显式新增配置并恢复先前验证过的框架提交；本轮不要求存档转换。不得用破坏性工作区重置丢弃用户修改。
