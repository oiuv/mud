# Design

## Context

动机与范围见 [proposal.md](proposal.md)，逐项源码、引用及保留项见 [analysis.md](analysis.md)。十七类已有 provider、精确存取、离线转换和真实驱动测试设施；本批不同点是 ITEM 研读数据与三种有限随机初始化，不是新的阅读系统。

现有四份主规范已要求保留随机时机、父类、实例隔离、交易和恢复行为；本次按 `skip_specs: true` 实现，不改变主规范或新增重复增量。

## Goals / Non-Goals

**Goals:**

- 将获准定义集中为小型 ITEM provider 与自然排序的数据表，让相同研读物共用规范身份。
- 保留原研读门槛、效果、随机值的归属和消费者结果；真实驱动对照是最终依据。
- 复用现有测试和备份转换流程，给后续维护留下完整的范围与保留项证据。

**Non-Goals:**

- 不添加通用表达式解释器、回调注册表、全局物品工厂或新的持久化层。
- 不修改 ITEM/BOOK、study/du、技能 valid_learn、F_DEALER、房间刷新或虚拟对象守护精灵。
- 不将所有“书”改为 BOOK，不给普通品种增加自动载入或专用阅读指令，不修正旧 sen_cost 字段。
- 不追求跨重构前后全游戏随机序列逐次一致，不新增实例快照以永久保存原本不持久化的随机结果。

## Decisions

### 1. 一个 ITEM provider，不照搬武器初始化

新增 `d/items/book.lpc` 和 `book_data.h`。使用既有 `create_virtual_object` / `virtual_start` 生命周期、精确 `valid_variety_path`、定义查询副本及重复初始化保护；只有驱动赋予最终虚拟身份后才初始化蓝图或克隆。

公共程序无参 create 仅保存定义，外部带参克隆、未知 ID 和伪造路径不能生成可流通物品。名称、别名、重量使用原接口；克隆绑定对应默认蓝图，独立复制复合属性。36 份旧定义都不主动 setup，新类也不额外调用 setup 或任何 init_weapon。

选择 ITEM 而不是 BOOK，是因为后者会新增 is_book/extra_long 等可观测行为；按玩家看到“书”就改父类不符合本次兼容目标。逐旧路径保留转发文件则继续保留冗余，也不采用。

### 2. 固定数据加三种明确的随机初始化

基础字段仍为 `name`、`ids`、`weight`、`properties`，不设空 instance 层。只有实际需要时才写以下可选数据：

- `name_choices`：原 titles 池，替代固定 name，按原位置在蓝图和每个克隆初始化时分别选择。保留单元素池、原候选顺序和重复权重。
- `skill_choices`：仅石板需要，在 create 对应的初始化阶段抽样；只将蓝图选定结果写入 `skill/name`，克隆有效值来自默认蓝图，不用它自己的抽样改写技能。
- `jing_cost_random`：仅道德经两卷需要，保存 random 的上界 10/20；蓝图应用固定 `skill/jing_cost=20` 后加抽样值，克隆沿用结果。

数据表只存候选数组、常量和固定属性，不在 `book_definitions()` 构造所有品种时执行 random。读书、query_definition、valid_variety_path 和重复 virtual_start 不重新抽样。蓝图卸载重载可重新抽样，与旧文件生命周期一致；存取仍按原路径式重建，不承诺保留从未保存的随机书名。

这三处短分支表达当前真实行为，不接受任意函数字符串、closure、嵌套策略配置或通用随机 DSL。实施测试先证明随机生命周期，再迁移全部定义，避免从某一次取样推导等价。

### 3. 归并按有效数据与随机规则，不按旧路径或一次抽样

采用 analysis 中 28 个预定 ID，最终以旧、新驱动观测确认。相同书名池、概率、技能参数及其他有效数据的定义归并；少林与峨嵋 skill/name 不同的佛经分别保留。技能、精力消耗、经验、最小/最大等级、嵌套 need 以及禁售限制全部核对。

原重复 set 保持最终有效值；未设置、零值、sen_cost 等不按“应该如此”归一。静态分组不忽略任意属性；描述纠错只应用 analysis 的精确白名单，冻结源码和驱动基线不改写。名称、别名和技能 ID 不在文字修正范围内。

### 4. 只改可达的创建路径，保持业务入口

19 处静态引用按 token 边界替换。四个藏经房间的七处动态路径换成明确的规范路径候选；同品种重复项只代表原选择权重，不凭归并改变刷新数量或新增可选品种。凌霄书房保留原两次随机选书与 mapping 键冲突结果，不顺便改成“必定两本”。

道尘、道相和武修文现有公开函数未限制 name 只能是 inquiry 中的词，能够创建 fojing10/11/20/21；为这四个原输入增加精确路径分支，分别保持原门派、present、库存扣减和交付。inquiry 不增加经书口令。副将的 weapon_file 只会取五种兵器名，保持源文件不变。

萧员外奖励、全真领书、油布包单次开包、五位天空 NPC 携带以及书痴售书都运行实际相关业务函数回归；不只检查替换后的字符串。可隔离 NPC 心跳等无关基础设施，但说明替身边界，不把片段回归说成完整任务/战斗验收。

### 5. 精确存取与离线转换延续现有协议

`feature/user_storage.c` 只增加 book provider 的合法品种检查，不放开任意虚拟对象，不改变 no_put/no_store、唯一物品、克隆或其他资格规则。普通品种没有 query_autoload，本轮不补上。

统一转换器追加 36 条旧路径映射及本批基线元数据，继续支持现有明确字段的玩家、商店和已选旧袋记录，不增加存档格式。规范品种合并时，同品同价库存合计、异价冲突拒绝、无关字段不变、重复转换零变更；原字节备份可恢复。测试包含随机品种恢复，按原语义核对范围与共享关系，不把随机书名变化误判为新缺陷或用迁移掩盖实际数据丢失。

### 6. 在已有测试入口增加本批，不另建框架

沿用 `test_cloth_objects.mjs`、`compile_cloth_callers.mjs`、引用/ID/记录审计，增加 `--book` 与本批小型夹具。冻结旧源码、调用方和五件保留项 hash；复用真实驱动的旧/新实例比较，并为随机品种分开检查固定属性、取值集合/范围、蓝图与克隆的关系。

真实 `cmds/skill/study.c` 检验成功、上下限、经验/识字/skill/need 拒绝以及精力扣减。只隔离与本批无关的角色或服务依赖，不能把直接读取 skill mapping 当作完整研读验收。保留现有十七类累计回归，并用 `check_lpc_warnings.mjs` 验证全量零 LPC 警告；新增代码不得破坏刚完成的驱动兼容清理。

## Risks / Trade-offs

- [随机值提前求值或克隆重抽] → 分别验证多蓝图、多实例、重复读取/初始化和重载；不在公共表生成时求值。
- [相似经书实际教不同技能] → 比较完整 skill、候选池及有效属性，保留 mahayana/buddhism、min_skill/need 差异。
- [随机名称与存档显示的历史差异] → 保留当前记录字段及恢复方式，不为本批新建实例持久化；仅声明已检查范围内的恢复结果。
- [动态路径漏改或新开领书入口] → 核对四个房间和三个公开函数，inquiry 不变，副将作为不修改的负例。
- [测试把旧疑似错误修掉] → sen_cost、无 setup、石板技能共享、紫盖克隆销毁等显式验收，不以符合直觉替代旧行为。
- [创建时间或内存增加] → 正确性通过后，至少三轮独立进程比较冷加载、热创建与内存的绝对值；不仅报倍数，不预先承诺性能提升。

## Migration Plan

1. 用户确认后，冻结分析基线中 36 个来源、20 个消费者与保留项，记录旧对象有效值和随机行为。
2. 实现 provider/数据及实际调用迁移、精确存取和 36 条离线映射；确认引用迁移后删除旧定义。
3. 完成本批和十八类累计回归、临时记录恢复、格式化及 --check、消费者编译和全量零警告检查，记录性能及实际结果后再勾选。
4. 同步数据维护说明、未迁移台账及必要的玩家文字纠错；记录保留项交叉归属，不改写历史报告。
5. 提交和正式上线另行确认。正式更新前仅对明确备份预览/按需转换，保留代码及原始记录；回退时恢复对应代码和数据，不只撤销代码。
