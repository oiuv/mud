# 普通杖类数据化设计

## Context

本批范围与动机见 [proposal.md](proposal.md)，37 份候选、8 份排除对象及调用依据见 [analysis.md](analysis.md)。以 `32f587a5c46c10193ad3974069ce76e07b91a2a3` 为冻结基线，复用已有十二类物品的数据化结构和离线工具，不改变主规范的行为契约。

STAFF 与上一批 HAMMER 的关键差异是 `init_staff()` 自动设置 `LONG` 长兵器标志。迁移还涉及货表、房间陈设、NPC 持用及三个动态发放/创建入口，不能只验证物品成功克隆。

## Goals / Non-Goals

### Goals

- 普通杖类共用一个程序与一张数据表，等价物品只有一个规范身份，真实差异继续保留。
- 保留旧对象的有效属性、显示、持用、交易、刷新及既有存储行为；调用统一使用 `/d/items/staff/<id>`。
- 在删除旧定义前取得可复核的原物品、消费者及记录转换基线，部署与回退均能配套处理代码和记录。

### Non-Goals

- 不迁移 8 份特殊对象，不补充从名称推测的玩法，不修正未经确认的历史数值或标记。
- 不新建万能武器工厂、存储框架或测试运行器，不改变公共父类、虚拟守护精灵、mudcore、FluffOS 或 AI。
- 不保留旧路径转发壳或运行期别名，不扩大背包准入和存档字段范围，不操作正式数据。

## Decisions

### 1. 沿用单类别虚拟对象生命周期，直接继承 STAFF

新增 `d/items/staff.lpc` 和 `d/items/staff_data.h`，沿用现有兵器 provider 的登记检查、`create_virtual_object()` 和 `virtual_start()` 结构。无参数加载 provider 仅建立登记表，不构造一个可用物品；非法或未登记 key 不创建对象。

虚拟蓝图设置固定名称、重量、属性并调用原 `init_staff()`，保留其默认动作、动词、`skill_type` 和 `flag | LONG`。克隆绑定最终虚拟蓝图，按现有方式隔离可变复合属性并完成一次 `setup()`；重复生命周期调用不得重复初始化。继续由驱动管理虚拟身份和权限，不手动重命名或赋权。

选择复用类别结构而非抽取跨武器工厂，是因为本批只增加数据类别；保留原 STAFF 父类可避免复制或重新解释长兵器规则。不能复制 HAMMER 的零标志假设，也不能套用 BLADE 的 EDGED。

### 2. 先冻结实际观测，再固定归并和简短 ID

复用既有严格解析逻辑，单独识别 STAFF 和 `init_staff()`；只接受固定初始化，遇到额外继承、函数、动态表达式或初始化副作用即排除，不能通过宽泛文本替换放宽语法。

静态预分组为 32 组，实施时对全部 37 份旧定义采集蓝图与克隆观测，再比较名称、有效属性、重量、伤害、标志及行为。输入别名可合并；其余显示、数据或行为有差异则分品种，不为达到预估数量强行归并。同名竹棒、禅杖和钢杖分别核查，不以同名或同伤害代替等价判断。

ID 使用简短物品名及必要的稳定编号，避免地区前缀或长限定词；最终映射一经确定即冻结，编号不随表内排序变动。数据按 ID 自然排序，来源路径只保留在测试基线和离线映射中。原 `shaolin` 等标记和所有文案照旧，不顺带纠错。

### 3. 精确迁移消费者，动态分支保持原业务

以冻结扫描得到的 49 处静态引用、41 个文件为起点；逐项处理宏、相对路径及常量拼接，完成后复扫。另迁移三个已核实的动态入口，共预计 44 个消费者：

- 钱正伦：为 `staff` 增加规范路径分支，保留门派、个人配额、总库存及实例上的 `value/no_sell` 覆盖。
- 副将：只将五选一中的 `gangzhang` 创建改到规范路径，保留分支选择、技能及其他四种兵器。
- 道尘：只迁移 `chanzhang` 分支，保留询问映射、少林资格、原持有检查、库存和交付。

王方平的 weapon1/weapon2 前缀命中不是本批动态入口；只改 weapon13 至 weapon21 的九处货表项。武修文和道相的防具询问不新增杖类领取。

保留货表顺序、房间陈设顺序与数量，以及 NPC 原持用语句。全部调用迁移后删除选定的 37 份源码，8 份排除对象的 hash 必须不变。原十二类冻结源码不改写，累计调用审计增加本批精确获准变更层，不能重建旧快照掩盖差异。

### 4. 记录转换仍是离线、精确且可恢复的

`feature/user_storage.c` 仅增加 STAFF provider 对已登记规范路径的验证，既有存放资格和状态规则不变。转换器新增 37 条历史映射，预计累计 1,113 条；不引入运行期旧路径解析。

仍只转换显式备份中的已支持字段：玩家背包、商店、明确选择的旧袋，以及精确 `npc/meng-zhu.o` 的 `dbase/weapon`、`dbase/armor`。同品同价记录合并数量，价格冲突明确报错而非覆盖；保留实例数据和无关字段，输入不覆盖，重复执行不重复转换，恢复应还原原字节。不得借本批迁移开放其他 NPC 存档或正式目录。

### 5. 复用现有验收入口，分开行为和性能结果

给既有 `test_cloth_objects.mjs`、`compile_cloth_callers.mjs` 增加 `--staff` 和就近夹具，冻结并比较全部 37 份定义。验证虚拟蓝图/克隆身份、未知路径拒绝、一次初始化、实例可变属性隔离、原 STAFF 标志与持用/解除持用效果。

对九件冥府商品及普通货郎实际交易、五处房间陈设与刷新、NPC 持用、三个动态入口执行对应业务回归；其他消费者至少编译实际函数体并通过逐处冻结差异审计。测试范围和未覆盖的实服状态分别报告，不把编译通过称为全部玩法实测。保留既有 `/d/village` 和虚拟 `clone` 回归，并运行十三类累计审计和记录恢复。

正确性验证结束后再测性能：三组新旧交替的独立驱动，每组覆盖 37 个旧来源各 20 次创建，共 740 实例；新实现也按相同来源映射和创建次数计量。分别报告冷加载、热创建中位数、驱动内存估算及程序数，不将冷加载节省与未知实际创建次数直接合为总收益，不套用锤类数值。

## Risks / Trade-offs

- **长兵器行为遗漏** → 直接继承 STAFF，真实驱动比较有效 `LONG` 标志、动作、持用条件及加成，不仅比较数据表。
- **归并误消除真实差异** → 全量原物品观测先行，比较完整有效属性；预计 32 个品种不是硬性目标。
- **动态发放或商品身份变化** → 三个动态入口单独执行，静态消费者做精确差异审计；同品同价库存合并，价格冲突阻止转换。
- **旧存档仍指向已删除文件** → 部署前对备份预览、按需离线转换并冷启动；旧代码与转换前记录成对回退。
- **热创建及内存开销增加** → 复用成熟实现并实测绝对值，不以文件减少代替性能结论，也不为小量开销新增缓存层。

## Migration Plan

1. 冻结旧定义、消费者、排除对象及真实驱动观测；确定最终规范 ID 与映射，再实现 provider、调用和离线转换。
2. 通过隔离驱动、十三类累计回归、转换/恢复、格式化检查和独立性能测量后，同步 `docs/architecture/data-driven-items.md`，记录实际结果；玩家可见变化才需同步 `help/changelog`。
3. 实际部署另行执行：备份代码版本和相关记录，对备份预览映射；有旧身份时转换到单独输出，核对数量、价格和差异，再在维护窗口配套部署并冷启动。无待转换记录不强行改写。
4. 回退时停止写入，恢复同一备份批次的旧代码与转换前记录，再冷启动；不把新规范路径的存档直接交给旧代码，也不以兼容壳代替记录恢复。本次实施不自行操作正式服务。
