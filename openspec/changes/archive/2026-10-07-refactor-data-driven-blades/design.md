# Design

## Context

动机与范围见 `proposal.md`，候选及调用证据见 `analysis.md`。现有九类物品已提供虚拟品种、精确存取识别、离线转换和驱动回归。刀类与剑类共享装备生命周期，但三份定义实际传入第二个初始化参数，且本批涉及特殊屠龙刀的产出路径，不能仅替换父类名称后默认全部行为相同。

## Goals / Non-Goals

**Goals:** 用一个继承 BLADE 的公共程序和一张就近品种表维护普通刀；以原蓝图、克隆及实际调用行为验证兼容，消除旧目录冗余。

**Non-Goals:** 不创建万能武器类、回调解释器、动态注册服务或第二套身份。不修改战斗、门派资格、概率、物品平衡、权限或存档格式；不修正尚未确认的旧行为，不新增自动保存和完整实例快照。

## Decisions

### 1. 复用剑类生命周期，显式保留刀的标志参数

新增 `d/items/blade.lpc` 与 `blade_data.h`。公共对象只保管定义；`create_virtual_object(key)` 校验品种并返回新克隆，驱动赋予最终身份后由 `virtual_start()` 初始化。外部使用 `/d/items/blade/<id>`，未知键及直接带参公共构造不作为商品入口。

数据保留 `name`、`ids`、`weight`、`damage`、`properties`，仅三份非默认定义增加 `flags: 110`，其余省略并按零传给 `init_blade()`。这里保存原参数，不把最终 `flag` 当作一般属性重复设置。字段是固定整数，不扩展为表达式、回调或权限配置。

最终蓝图先设置名称、重量和定义属性，再执行原 `init_blade(damage, flags)` 和一次 `setup()`；克隆绑定同品种蓝图，隔离可变复合默认值并执行一次原 setup。保留原 EDGED 合并、刀技能、动作闭包、攻击动词、重量修正、材质耐久及 UID/EUID。无需 instance 层。

不在临时克隆阶段调用武器初始化，因为父类对克隆直接返回；不改父类以免影响未迁移刀；不把整套 SWORD 公共程序抽成框架，因为本批沿用少量既有代码比增加间接层更清晰。

### 2. 先核对有效行为，再确定规范身份

固定 61 份旧源码、hash、初始化参数及旧蓝图/克隆观测；检查六份特殊对象不误选。归并依据包含显示、实际重量、伤害、完整标志、有效属性和行为，历史别名可合并。52 个静态组只是规划依据，最终以驱动观测判断，不要求语法写法逐字一致。

短 ID 以物品命名；同名真实品种用稳定编号，数据按现有自然排序维护。保留有实际意义的名称限定，不携带来源路径，也不强行拼接冗长修饰词。不同商店售价留在调用方，不复制品种。

例如 `unequip_msg` 与 `unwield_msg` 的原键保持；标志 110 的未命名位也原样保留。若发现疑似 BUG，记录并单独确认，不以迁移名义改变结果。

### 3. 定点迁移调用，不扩展全局分派

替换已定位 102 处静态引用并重新扫描。分别在钱正伦 `blade`、长安副将 `gangdao`、道尘 `jiedao` 的既有分支使用规范路径；保留门槛、持有判断、共享库存、个人限额、临时覆盖与随机选择。其他品种和前几批分支不变。

数组中的重复项若承担权重，不去重；mapping 归并发生键碰撞时核对并保留数量和有效价格，不能静默覆盖。王方平 `weapon4/weapon5` 是独立旧品，不作为 `weapon40..59` 的前缀替换。

特殊刀不进入普通表。屠龙刀源码只修改 `new("/d/tulong/obj/duan2")` 的目标及项目格式化；审计将该唯一替换归一后比较原 token。其他五份特殊源码 hash 不变。选择保留专用回调，而不是为少数命中/销毁逻辑增加通用行为开关。

### 4. 复用既有存取与离线记录工具

背包只加入本表精确品种判断，原持用中、临时状态、禁存和食物饮具拒存规则不变。不得因所有刀都变成虚拟对象就放宽任意虚拟路径，也不新增耐久/附魔快照。

离线工具加入本批 61 条映射，与现有 916 条一次处理。仍只操作管理员显式提供的备份：玩家 `my_depot`、商店货表与库存、显式旧袋及精确 `npc/meng-zhu.o` 的 weapon/armor。保留字段、数量和有效价格；同品同价库存合计，冲突整批拒绝，输入不覆盖，规范化后再次执行零变更。新旧代码对应各自记录，不以运行期别名掩盖部署问题。

### 5. 延用测试入口，重点执行真实消费者

给 `tools/tests/test_cloth_objects.mjs` 和 `compile_cloth_callers.mjs` 增加刀类选择，基线和专用夹具就近放 `tools/tests/blade/`，不另建执行器。解析器严格限定本批固定初始化，允许真实存在的常量第二参数；未知调用或回调应拒绝，不能用宽泛正则吞掉行为。

逐定义比较旧/新蓝图及实例，覆盖路径重建、独立复合状态、初始化幂等、默认动作、setup 次数、装备/卸下、主副手标志及耐久；动作闭包比较可执行效果，不比较地址或 JSON 序列化结果。所有调用编译之外，还执行实际供应方法、NPC 配刀、商店买卖、房间刷新与屠龙刀对砍方法，对照原结果。

剑类旧夹具目前复制即将删除的北京/长安刀文件，须调整为仅在临时副本恢复冻结原文；新版消费者加载当前规范路径。旧基线不改写，十类引用审计可分层核对后续迁移，避免把允许的路径升级误判为历史数据变化。

同条件性能测量使用 61 个来源请求、每来源创建 20 次，共 1,220 实例；至少三组旧/新独立进程，交替顺序，不与其他本轮回归并行。分别报告冷加载、热创建总计及每实例平均值、驱动内存和程序数，不承诺热创建更快或内存更小。

## Risks / Trade-offs

- [遗漏非默认标志或错误初始化时机] → 三份 110 参数单独回归，并逐品种核对最终 flag、装备槽和一次 setup。
- [特殊刀被误改或断刀产出中断] → 固定排除清单与 token 差异边界；真实对砍方法验证成功、失败和原物品销毁。
- [路径合并损失库存、权重或临时覆盖] → 原/新业务对照、同文件键碰撞检查，保存原数量和分布。
- [新批次破坏旧测试依赖] → 旧源只恢复到临时夹具，原九类回归和引用审计继续运行。
- [历史记录无法恢复] → 字段明确的备份预览、按需转换及成对回退，不默认操作正式数据。
- [热创建成本上升] → 报告实测绝对值，优先维护收益，不为亚毫秒开销添加额外缓存体系。

## Migration Plan

1. 固定当前基线与引用，采集原蓝图/克隆观测，确定归并及短 ID，新增公共程序、数据与测试。
2. 迁移静态和三处动态调用、屠龙刀产物引用，接入精确品种识别和离线映射，删除 61 份被替代定义。
3. 执行行为/消费者、调用编译、存档副本及旧类别回归，完成三组性能对照；格式化本次 LPC 并 `--check`，同步技术文档、玩家更新和验证记录后交付。
4. 正式部署另由维护者停服备份，预览并按需转换，在同一次维护中切换配套代码与记录、冷启动。`updateall` 不代替旧实例和临时订单清理。
5. 回退同时恢复旧代码和对应原始记录；上线后的新交易须单独核对，不反向替换任意文本或猜测归并前路径。
