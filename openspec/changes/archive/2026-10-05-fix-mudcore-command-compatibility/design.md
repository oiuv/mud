# Design

## Context

动机和修复范围见 proposal.md。现有 `lpc_file()`、`lpc_object_path()`、`lpc_source_files()` 与 `resolve_path()` 已提供基础能力，COMMAND_D、别名和批量扫描已有双扩展名支持，不重写它们。

审查确认：`update.c` 在校验克隆身份前销毁对象且只按字符串保护 VOID_OB；`which.c` 无条件回退 VERB_D；`loadall.c` 捕获错误后仍输出成功；`sa.c` 拼接 `.c`；`CRLF.c` 先检查再解析 cwd；五个检查/动作入口未完整处理目标加载异常或空对象。驱动对被销毁克隆路径的重新加载会拒绝；销毁环境还会调用内容对象的 `move_or_destruct()`，未移出的内容会被销毁。不能把直接 `destruct()` 当作安全房间更新。

`tests/run.mjs` 已在临时宿主运行 default/overrides 并接入 minimal/custom，`loadall_probe.lpc` 已验证扩展名及过滤。新增命令用例复用这些入口，不依赖本游戏物品、幻境或权限 daemon。

## Goals / Non-Goals

**Goals:** 在命令边界修复已知缺陷，保留原生加载语义和宿主可替换性；同时验证成功、拒绝、抛错及选择性接入。

**Non-Goals:** 不创建通用对象管理器、批处理任务平台或新的权限体系；不修改 sefun 的 efun 兼容语义、虚拟创建协议或框架最低驱动要求；不把批量加载改成全量强制重载，不承诺任意在线继承链与业务状态的原子热更新。

## Decisions

### 1. 在操作入口区分对象身份与文件路径

对象命令沿原生加载处理实体和虚拟对象，不加实体文件存在门槛。文件操作只使用解析后的实体路径，检查与读写保持同一目标。`sa` 保留运行期对象身份，实体源码通过已有辅助函数确定；虚拟身份明确标为虚拟对象，不把处理程序或公共父类当作该虚拟实例的独立源码。

不新增覆盖 `load_object()` 的全局包装。已有 `.c` 文件名不改，`eval` 实际生成 `.c` 临时程序的行为不动。

### 2. update 先检查，再安全安置，再重载

- 将路径按现有约定规范化，同时保留驱动显式扩展名的选择语义。`here` 没有环境时给出失败；克隆环境/显式克隆路径直接拒绝，不用 `base_name()` 静默改成更新蓝图。
- 在销毁前识别 VOID_OB 的规范对象身份与已加载对象，拒绝所有等价拼写；不得因目标不存在或路径错误先销毁其他对象。
- 对有内容的环境，使用现有 VOID_OB 暂时安置直接内容，保留对象引用。沿用框架/宿主移动接口及区域协作，不绕过必要移动限制；先核实安全环境可用，任一对象无法安全移出则中止销毁。
- 成功加载后，仅把仍存活、仍在本次暂存地点的内容移回新环境，保留实例字段和内部物品；重载或回迁失败明确报告，存活内容留在安全地点。移动钩子导致对象销毁或转移时按实际状态收尾，不声称回滚宿主副作用。
- 旧对象销毁后编译失败不能恢复旧程序，帮助须明确此边界。采用既有销毁/加载机制，不引入最低版本之后才提供的热编译 efun，也不自动重载虚拟提供程序或整个继承链。

### 3. 保持 loadall 轻量语义和兼容接口

仍按目录分批加载。每目录分别统计成功和失败，异常与非对象结果都记录目标并反馈；不在子目录尚待执行时报告全树成功。保留 `loadall(string)`、`skip_load_dir` / `skipLoadDir` 的兼容覆盖，`main()` 的命令已处理状态不作为编译成功证明。

保持现有隐藏目录及 CORE_DIR 内 docs、tests、master/sefun 源码片段过滤，不复制主库对宿主目录的排除规则。帮助明确 `updateall` 仅为别名，驻留程序不会自动重新编译。按目录报告即可，不新增全局批次数据库或队列管理器。

### 4. 尊重 parser 开关和命令层错误边界

`which` 先查询 COMMAND_D；仅在 parser 可用时查询 VERB_D，兼容宿主服务及新旧函数名。关闭时不引用会触发服务加载的路径，启用服务的真实异常不转成普通未找到。

检查命令和 go/look 只在目标加载及必要状态核验处处理失败，不用大范围 catch 吞掉后续业务错误。管理工具给出可定位失败；玩家提示不包含内部路径和异常原文，详细错误写宿主可控日志。提供程序拒绝/抛错后停止该操作，不重试旧协议、不把错误字符串当对象。

### 5. 在现有隔离运行器中执行实际命令

新增 `.lpc` 命令回归夹具及所需最小房间/物品/提供程序，接入 default/overrides；补强 loadall 失败输出断言。minimal/custom 物理省略谓词服务，实际执行 `which` 未命中，验证无意外加载。需要观察交互输出的断言复用本机连接或测试输出捕获，不仅断言源码包含某个条件。

用例覆盖 `.c`、`.lpc`、无扩展名、虚拟蓝图、克隆路径、拒绝和抛错，及 update 内部对象存活/位置、VOID 等价路径、CRLF cwd 同名文件。所有故障源码、转换文件和存档仅在临时目录生成；测试原生对象身份、返回结果与诊断，不以编译通过代替实际命令正确。

## Risks / Trade-offs

- [宿主移动钩子有副作用] → 检查实际对象状态，无法安全保全就不销毁环境；不引入通用事务系统。
- [使用较新驱动误引入新 efun] → 实施时核对本地驱动文档/源码及基线，记录实际测试版本，不提升最低要求来省略必要检查。
- [捕获错误遮蔽问题] → 仅在命令边界转换反馈并保留诊断；底层异常契约和虚拟拒绝不回退规则不变。
- [既有回归通过但命令仍错误] → 执行实际入口，断言副作用和失败文本，并运行四组原有回归防止宿主覆盖退化。

## Migration Plan

无数据迁移。实现后同步命令帮助、`docs/daemons/command_d.md`、`docs/module-contracts.md`、`tests/README.md` 及 CHANGELOG 未发布条目；框架修复未改变当前主 MUD 玩家入口时，不把它写成已上线的玩家新功能。

仅格式化本次修改的 LPC/头文件，再执行 `--check` 与真实驱动回归。用户授权提交时先提交 mudcore，再更新父仓库 gitlink 和计划记录；不自动推送或部署。宿主按自身维护流程更新受影响对象；回滚使用原框架提交，不执行批量物品或存档转换。
