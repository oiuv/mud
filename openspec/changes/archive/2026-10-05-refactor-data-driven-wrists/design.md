# Design

## Context

动机见 [proposal.md](proposal.md)。以 `61abfde332b86b286f2cf8ce44d5b502cfbec10e` 为源码基线，沿用五类物品的 provider、精确存取、离线转换及隔离驱动测试。

2026-10-05 只读检查 `/d` 下 7 份直接继承 WRISTS 的定义：6 份只有固定初始化，另 1 份绞金腕轮有死亡销毁回调。现有词法解析与引用扫描器在内存中确认 6 份候选、6 处静态引用及两条相关动态领取分支；本规划尚未运行护腕等价性测试。CodeGraph 用于父类定位，未完整收录的物品以当前源码为准。

### 迁移名单

来源相对 `d/`，省略 `.c`。正式路径为 `/d/items/wrists/<id>`，数据按 ID 自然升序排列。

| ID | 原来源 | 保留差异 |
| --- | --- | --- |
| `huwan` | `city/npc/obj/huwan`、`city/obj/huwan`、`jingzhou/obj/huwan` | 布护腕；重量 500、价值 1300、护甲 5，三份等价定义合并 |

`wanlian` 已足以识别物品，不为颜色或材质再拼长 ID。少林前缀表达真实属性，不表示历史目录归属。玩家名称与输入别名不因规范 ID 改变。

## Goals / Non-Goals

**Goals:** 以既有 WRISTS 行为承载四个品种，保持腕部槽位、默认对象、实际属性和旧领取/交易规则。合并等价定义并同步全部已确认调用，旧记录通过现有字段级流程转换。

**Non-Goals:** 不新增通用装备工厂、实例属性层、运行期别名、转换 CLI 或测试框架；不顺手纠正材质、重量、文字、NPC 权限或库存规则。绞金腕轮和所有非本批物品保持原路径与行为，不改公共装备父类、mudcore、驱动或 AI。

功能以旧代码实际行为为准。测试假设与旧对象不符时先纠正假设；只有明确确认的 BUG 才另列依据及修复范围，不通过改玩法让迁移测试通过。

## Decisions

### 1. 独立 WRISTS provider，复用现有生命周期

新增 `d/items/wrists.lpc`、`wrists_data.h`，直接继承 WRISTS，不借 HANDS 或 CLOTH 来节省文件，避免混淆槽位或增加撕布、洗涤能力。数据仍为 `name/ids/weight/properties`，不增加额外元数据层。

`create_virtual_object(key)` 校验品种并返回新克隆，驱动确定身份后由 `virtual_start()` 设置默认对象并完成一次初始化。同品种复合属性隔离，标量可覆盖和恢复默认；无参 provider 不是商品，未知 key 拒绝。`new(base_name(ob))` 与当前 `clone` 命令均走既有虚拟加载链，不改守护精灵或管理命令。

鎏金腕链的 `set("weight", 200)` 仅设置普通属性。沿用颈饰方法先在隔离真实驱动记录旧蓝图/克隆实际重量，再填写定义，不机械转换为 `set_weight(200)`。其余未设置属性、原材质和派生描述照旧。

### 2. 只替换已确认的物品创建引用

6 处静态引用分别位于 `d/changan/npc/jinfuhuan.c`、`d/city/npc/yang.c`、`d/luoyang/npc/{xiao,zhou,zhu}.c`、`d/xiangyang/npc/gaoli.c`。同店没有多条等价旧路径待合并；仍在替换后审计货表键与数量，不能依赖字符串替换掩盖覆盖。

两条动态分支位于武修文及道相的 `ask_me_1(name)`：仅将 `name == "huwan"` 路由到 `/d/items/wrists/shaolin_huwan`。保留原 `present(name, player)` 检查、共享 `huju_count` 和其他分支。道相要求少林身份；武修文此函数没有该门派检查，不替他补上。两者对已有匹配护腕、库存不足及成功领取的行为须新旧对照。

`d/changan/npc/fujiang.c` 和道尘的动态拼接目前提供武器，保持不变。`d/city/npc/obj/yang.c` 的 `__DIR__ "obj/huwan"` 实际指向 `/d/city/npc/obj/obj/huwan`，不是本批来源，不因名称相同改写。审计记录该线索，不把未确认旧路径顺手重定向。

### 3. 特殊腕轮留在既有实现

`d/luoyang/npc/obj/wanlun1.c` 的 `owner_is_killed()` 会销毁自身，不能放入只含初始化的普通表而丢掉回调。本批保留它及朱丹臣的相关引用，回归确认与数据化普通护腕共存。将来有多个相同死亡行为物品时可按共同语义归并，当前不为一个对象增加新层。

### 4. 精确存取和统一离线转换

`feature/user_storage.c` 仅增加四个已登记虚拟品种的资格判断，不放开任意 WRISTS 或虚拟对象。穿戴中、临时状态、禁存、独特物品等限制保持；不新增自动保存。

`tools/migrate_item_records.mjs` 增加 6 条原路径直达规范路径的映射，原五类 584 条继续有效，合计预期 590 条。仍处理背包、商店和显式选定旧袋的既有字段；同品同价库存合计，价格冲突整批拒绝，玩家分立记录和无关字段保持，重复转换零变更。冻结旧源码/哈希及映射仅用于离线测试，不进入游戏运行期。

## Risks / Trade-offs

- [腕链普通 weight 被误当作负重] → 用真实驱动分别核对普通属性、蓝图/克隆实际重量和派生说明，原值不“修正”。
- [两种铁护腕误合并或领取资格被统一] → 保留少林标记以及两位 NPC 各自原条件，按实际函数对照。
- [特殊腕轮回调丢失] → 留在原专用实现，审计该文件及引用不变。
- [旧路径删除导致存档失物] → 先完成六条离线映射、混合记录与原字节恢复测试，正式部署联合处理代码和记录。
- [虚拟创建增加耗时与内存] → 旧/新各三个独立驱动进程，同来源、同实例数，报告绝对值与净减文件数，不承诺必须更快。

## Migration Plan

1. 冻结六份原文、哈希、分组和引用，实测旧蓝图/克隆属性；沿用现有测试入口，不增框架。
2. 实现四个品种，迁移八个调用文件，补充背包资格与离线映射；通过后删除六个旧定义。
3. 运行属性/穿戴/克隆/交易/领取/存取和记录回归，复测已迁移五类及特殊腕轮；格式化、编译、审计和性能测试后同步维护说明及结果。
4. 维护者在停服备份中预览，按需转换；核对副本后部署代码与记录并冷启动，无受影响记录时无需转换。
5. 回退同样恢复配套代码和原字节记录。本轮规划不操作正式数据、不重启、不推送，未实测的任务保持未完成。
