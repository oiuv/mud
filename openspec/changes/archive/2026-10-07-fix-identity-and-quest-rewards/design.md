# Design

## Context

动机及范围见 proposal.md。源码基线为 `95cb63b1`，只读核对发现：

- `feature/command.c::enable_player()` 给旧巫师等级设置标记，普通玩家分支未撤销旧标记；`quest2` 的他人已解详情分支缺少其余他人查询已有的管理判断。
- mudcore `try_complete_quest()` 收集任务物品、检查条件后直接删待办、标已解并保存；调用方之后才执行返回值为 void 的 `reward()`。铁匠无收集物品需求，先发数值再尝试移动乾坤石。
- 宝镜 `do_return()` 已计数、发数值及银两、销毁交付物后才调用 `set_item()`；500 次的累计数在移动奖品前清除。
- 运送 `accept_object()` 消耗货物后将奖励按 ID 合并，延迟回调先删记录再检查对象与清醒状态。`GIFT_D->bonus()` 还按当前经验衰减并限制潜能，不能只把回调删除视为等价改动。
- 现有 `tools/tests/test_commerce_audit.mjs` 可复用隔离驱动构造方式；统一入口已有六组测试。CodeGraph 本次未加载索引，采用当前源码读取，不自动建库。

## Goals / Non-Goals

**Goals:** 在既有业务中设置明确的失败及成功边界，覆盖已确认四项缺陷，真实驱动验证正常完成、失败重试、身份撤销和生命周期。

**Non-Goals:** 不迁移六级权限；不处理 WB-01 至 WB-04；不构建事务框架、离线奖励数据库或历史补发工具；不保证任意业务回调异常及驱动崩溃的全局原子恢复；不改变其他任务的交物机制。

## Decisions

### 1. 在可信刷新和命令入口各修一处

身份刷新根据已有可信角色结果同步驱动标记，维持原命令路径。测试必须使用真实交互角色验证标记实际作用于被降级者，而非发起降级的管理员。保留 UID/EUID 和既有调用约束，不简化安全精灵或开放新授予入口。

`quest2` 先检查他人详情查询的管理身份再读取目标，保留自查语法。拒绝仅在显示层隐藏文本的替代方案，权限须在读取入口成立。

### 2. 任务框架提供单一可选 try_reward 回调

新增 `int try_reward(object player, object npc)`：有该接口时，在既有条件检查通过、完成状态变化之前调用。返回成功后才删待办、标完成并保存；该分支不再执行旧 `reward()`。返回 0 保留未完成状态；异常不回退、不冒充成功。未提供新接口者继续旧路径，保留现有 protected 覆盖和名称桥接。

铁匠改用此接口：先创建乾坤石并检查真实 `move()` 结果，失败销毁未交付临时对象、提示整理行囊并返回 0；成功才用原 `work_bonus()` 发数值。这样不用在资格判断里偷偷发奖，也不只凭负重估算声称交付成功。

本批仅将无收集物品需求的铁匠接入。公共收集步骤原本可能消耗物品，新增接口不承诺回滚该步骤；文档明确这一边界，不向其他收集型任务推广为通用原子提交。完整收集型任务重构另行立项。

### 3. 宝镜先验证并交奖，最后提交任务

将奖池选择与计数更新解耦，用“本次成功后的候选计数”判断里程碑。普通资格、轮次和实际携带检查都在数值变更与交付物销毁前完成；里程碑奖品成功移动后才统一计数、发数值及银两、销毁原物，并在第 500 次成功后清零累计数。

采用当前里程碑奖池的最大重量作保守预检，预检通过才随机选奖及尝试真实移动，避免玩家用剩余负重筛选轻奖品。不向玩家提前揭示未领取品种，不维护新的持久候选队列；预检按交付前负重，不借尚未销毁的交物重量提前放行。普通移动失败清理临时奖品，原任务、交物与数值不变。池成员、重复条目权重不变；普通非里程碑银两原有行为不在本批扩改。

拒绝落地或 raw 强塞奖品：用户已确认超重拒绝并保留任务。也不在失败后先加计数再反向扣回，以免漏掉轮次、500 次重置或数值副作用。

### 4. 运送逐次同步结算，回调只负责表现

有效交货同次处理中构造原每次奖额并调用现有 `GIFT_D->bonus()`，不再把未到账的资产放入 `bonus/id` 延迟表；之后销毁已接受货物。保留正常对白的延迟，不需要为奖励保留 `do_finish()` 等待条件。已同步结算的奖励由正常 quit 保存，不新增长久离线记录。

这不是“合并奖励时间不变”的重构：从 2–3 秒合并结算改为逐次结算，经验跨阈值及整数舍入可能有小差异。基础随机公式、公共衰减及潜能上限不改，测试并明确记录按每次交货当前状态计算的结果，不借此重平衡奖额或复制一套 GIFT_D 算法。替代方案保留延迟需增加离线/昏迷待领状态，本批不选。

### 5. 验证实际行为，不只编译

新增 `tools/tests/test_identity_quest_rewards.mjs` 及隔离 LPC 夹具并接入统一入口。真实连接验证在线降级、自查和越权；实际生产任务与移动/GIFT_D 链路验证负重、重复交付、里程碑循环、正常退出存档恢复、昏迷及最后一批货物。随机奖励用可复核条件覆盖每个池成员，不以低概率碰运气作为验收。旧基线负对照须复现四项缺陷；框架默认与宿主覆盖回归独立运行。

## Risks / Trade-offs

- [预检保守] → 里程碑要求能携带该池最重奖品，可能比实际抽中的轻奖品多预留空间；明确提示，换取不重抽筛奖且无候选存储。
- [旧任务完成顺序及宿主覆盖复杂] → 新回调显式选择，测试旧回调、覆盖、父实现和异常不回退；不将新契约强加给旧任务。
- [任意异常可能已有部分副作用] → 只承诺已核实普通负重/移动失败的无损重试；不声称驱动崩溃、任意 GIFT_D 异常可回滚，不吞异常返回成功。
- [保存时机与退出窗口] → 用真实正常退出和临时存档恢复验收同步到账；不读取正式存档、不承诺断电零丢失。

## Migration Plan

实施前记录宿主及子模块基线，测试只使用临时数据。按子模块修复、宿主接入、完整回归顺序交付；后续获准提交时先提交 mudcore，再提交宿主指针。部署使用匹配版本并按正常维护方式重启，避免旧运送任务的待发回调与新代码混用；上线操作另行授权。本批不转换玩家存档或自动补发历史奖励。回退恢复匹配代码及子模块，不反向扣除玩家已获奖励。
