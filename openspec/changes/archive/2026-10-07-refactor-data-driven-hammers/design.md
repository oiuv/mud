# 普通锤类迁移设计

## Context

动机及范围见 [proposal.md](proposal.md)，逐项源码和调用依据见 [analysis.md](analysis.md)。当前 SWORD、BLADE 等十一类已采用原生虚拟路径及离线迁移；本批同样以 `9553790649746e0b8b21ef2b9dcf818fd839f242` 为冻结源码基线，不引入新的对象工厂、存档格式或驱动能力。

## Goals / Non-Goals

**Goals:**

- 43 份旧定义集中管理，等价身份合并，并保持蓝图、克隆及原业务入口的有效行为。
- 名称简洁、数据自然排序；复用现有测试和离线转换入口，使下一批物品仍按相同方式维护。

**Non-Goals:**

- 不把全部武器塞入万能类，不为 HAMMER 增加其他类别的能力。
- 不改武器父类、耐久、价格、材质、文案或任务规则；未明确确认的旧问题保留原行为。
- 不扩大到本批清单外的复合食物、乐器、独特装备、其他目录定义或其他武器类别；不迁移权限体系，不操作正式存档或服务。

## Decisions

### 1. 复用原 HAMMER 与既有虚拟生命周期

新增 `d/items/hammer.lpc`，直接继承 HAMMER，配套 `hammer_data.h`；无参公共程序只持有定义，不作为商品进入游戏。`create_virtual_object(key)` 仅接受已登记品种并返回新克隆，`virtual_start()` 在驱动赋予最终身份后初始化。

最终虚拟蓝图设置名称、重量和属性后调用原 `init_hammer(damage, flags)`、一次 `setup()`；克隆绑定同品种蓝图、复制可变复合默认属性并保留自身名称缓存/重量及一次 setup，初始化须幂等。继续拒绝未知路径、外部直接带参构造和未绑定公共程序流通；保留 UID/EUID，不手动改名或赋权。

选择复用 BLADE 的生命周期方式而非复制它的兵器规则：HAMMER 的 flag、默认动作和伤害类型以原父类为准，不添加 EDGED。现有类已足够，本批不借机建立跨武器泛型框架。

### 2. 以真实效果归并，而非来源路径或源码排版

冻结 43 份原文、hash、别名、精确调用和 17 份排除定义；用原版隔离驱动采集所有蓝图/克隆的有效属性，再核对静态预分组的 40 个品种。等价物品共用规范身份并保留历史输入别名，有真实差异才使用稳定编号或简短限定。

`hammer_data.h` 只保存必要的蓝图定义、物理重量和伤害/flag；不新增普遍为空的实例数据分支。数据按规范 ID 自然排序，编号不因排序或插入改变；历史对应关系仅留在离线元数据中。

碧绿西瓜的两次连续 set_weight 最终为 20000；采集原蓝图及实例确认后只保留有效值。解析器仅识别已经核实的连续固定写入模式，并加入拒绝中间依赖/动态赋值的反例，不能靠宽泛删除语句掩盖额外行为。

### 3. 更新实际调用，不扩大玩法

先冻结 55 处静态引用和钱正伦的动态 hammer 分支，迁移 NPC 配装、房间刷新、货表、工具发放及替补武器创建。保留原数组顺序、数量、概率、领取条件、计数和实例覆盖；若合并造成 mapping 键碰撞，明确合计原数量，不覆盖丢失。

其余五条目录前缀线索按 analysis 中的可达性核对，不给副将、少林或襄阳入口新增原来没有的领取选项。黑白子/范松的独特武器身份与归还条件保持，只换普通替补品。骨头、水瓢、金火枪和铁琵琶仍只有原 HAMMER 能力。

删除全部 43 个旧源码，不使用转发壳或运行期路径别名。旧十一类的原始快照不重写，历史审计仅增加经过核验的本批调用变更层。

### 4. 复用精确存储接入和离线转换

`feature/user_storage.c` 只增加已登记 `/d/items/hammer/<id>` 检查；持用中、临时状态、禁存、独特物品等既有拒收条件不变，不新增实例状态持久机制。

`tools/migrate_item_records.mjs` 接入 43 条旧路径、锤类基线标识及报告，预计累计 1,076 条历史路径。沿用玩家/商店、显式旧袋、精确 `npc/meng-zhu.o` 的既有字段转换，输入不覆盖、默认预览、同品同价库存合计、价格冲突整批拒绝、重复转换为零变更。未选对象和无关字段保持原字节，不提供在线自动迁移。

### 5. 以原对象为验收基准

扩展现有 `test_cloth_objects.mjs`、`compile_cloth_callers.mjs` 的 `--hammer` 选择及就近夹具，不新增测试执行框架。所有原品种均对照名称、别名、实际重量、默认对象、属性、动作、主副手、耐久、持用/卸下、存取和交易重建；重点运行原钱正伦领取、两个商店、武馆工具以及替补武器相关分支。工具使用与归还仍按原输入 ID 验证。

编译全部受影响的真实函数体，并明确构造函数是否执行；回归旧十一类、村庄启动、虚拟 clone、累计 ID/引用和记录转换。三组新旧交替独立驱动性能对照均覆盖 43 个来源、860 个实例请求，分开报告冷加载、单实例热创建、内存估算和新增程序数，不与其他回归并发测量。

## Risks / Trade-offs

- 同名锤子有不同价格、伤害或文案 → 原始数据与真实驱动双重核对，不能为减少品种抹平差异。
- 静态骨头、任务工具或独特武器替补易被误分类 → 按继承和真实调用处理，不从名称推导新能力，排除定义保留 hash 审计。
- 虚拟初始化顺序改变默认动作/重量派生值 → 蓝图和克隆分别对照，不只测试能否创建；重复重量按最终有效值验证。
- 路径删除可能使旧存档无法恢复 → 复用完整预览、字段转换和对应代码/存档回退，不以全量编译通过替代迁移检查。
- 共享程序减少文件与冷加载，但热创建和实例内存可能增加 → 本批实测绝对值，不承诺运行性能必然更好。

## Migration Plan

1. 在隔离副本冻结基线、实现迁移并完成回归，发布范围、收益和未覆盖边界的真实报告；不改正式数据。
2. 维护者按既有部署说明停服保存并备份代码和相关记录，预览明确备份；确认受影响才生成和核对转换副本。
3. 配套部署新代码和需要转换的记录后冷启动，不以热更新旧实例代替切换。
4. 若需回退，恢复对应源码版本和同批原字节存档，不只回退代码。
