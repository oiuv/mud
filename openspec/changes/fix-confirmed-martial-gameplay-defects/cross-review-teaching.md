# NPC／教学改动只读交叉审查

## 结论与范围

在下述真实调用链及当前差异范围内，**未发现本批新增的确定逻辑错误或必须阻止集成的严重风险**。这不是对所有NPC、全部教学／物品领取路径或正式服行为的无缺陷保证；未决配招不当作已实现。本次只读源码与现有差异，不运行驱动、不改源码或夹具，也不复核本分工自己的fields修复来充当独立审查。

重点阅读了当前 `cmds/skill/apprentice.c`、`recruit.c`、`feature/apprentice.c`、`cmds/std/ask.c`、`adm/daemons/masterd.c` 的真实消费者；并交叉检查岳不群、达摩、玄慈、善勇、无崖子、梅庄四友、欧阳锋、欧阳克、商剑鸣、冯默风、小龙女以及本批改领悟键、奖学技能的教师差异。纯错字不以重新展开所有无关NPC函数作为审查前提。

## 2. 新默认startroom的实际影响

新增实现位于 `inherit/room/room.c::make_inventory`，真实调用来自同文件 `reset`（单个及多个对象两种情况）。它先调用 `mudcore/inherit/room.c::make_inventory` 创建／移动对象，再仅对真实character的缺失、空或非字符串startroom补出生房间路径；明确非空字符串路径不覆盖，普通物品不赋该字段，未修改mudcore。

这里的影响**不只是NPC定时归家**：

- `inherit/char/npc.c::return_home(home)` 实际接收宿主room参数，原逻辑已不依赖startroom；本次没有改变其战斗中不返、原环境无出口不返的判断。
- `feature/guarder.c::kill_enemy` 会比较当前环境与startroom，只有在家才召援；默认值会令原先因未配置startroom而无法援助的出生房守卫真正进入后续coagents调用。其后仍验证援助对象、`is_coagent`、非自身及原 `start_help`，没有因补路径跳过资格。
- 欧阳克送神蛇的出门／返程、部分峨嵋人物及其他带路／传书分支也使用该字段，所以这是宿主级行为修复，不能描述成仅影响玄冥／嵩山三名守卫。
- 狄修、鹤笔翁、乌旺阿普的援助目标路径改为实际存在且放置对应NPC的原房间；不是凭未知占位符随意造新NPC。现有定向夹具从原房间初始化取得守卫／援手并走原kill_enemy及start_help，还检查离家不援助；不以手工塞进角色的援手对象冒充原房间配置。

本次核对未见该默认值覆盖既有明确路径或改变玩家权限。**有限范围**：没有枚举全库所有character对startroom的动态读取，也没有逐个验证克隆实体房间／临时活动房间中该默认路径的长期行为。按本次批准的“出生地默认值”意图是合理实现；上线后应保留NPC归位与守卫援助的运营观察，不据此宣称所有NPC副作用都已排除。

冯默风两条带路分支另改为保存调用时真实 `environment()` 并返回该对象。其用途是回到本次出发地，不误回未初始化startroom或被默认值误导的其他房间。原学艺许可／拜师条件仍在；没有借此放宽桃花阵进入条件。

## 3. 教学领悟、奖励与交付

真实询问链是 `cmds/std/ask.main` → NPC inquiry／`accept_ask(me, topic)` → 既有 `MASTER_D->teach_pfm` 或NPC自己的授招函数。公共teach_pfm按传入perform键先判已学，再判门派、贡献、技能及有效force/dodge，成功才写该键、改善武学并扣贡献。因而只改NPC传入键必须同时核对招式真实读取者，不能只检查字符串“看起来相同”。

| 子项 | 核对结果 | 保留限制 |
|---|---|---|
| 裘千尺破甲推山、李莫愁冰魄资格、古墓赤练领悟、谁与争锋奖励 | 传入的tui许可及实际招式读取一致；冰魄资格使用真实bingpo-shenzhen；赤练规范许可与真实perform门槛一致；谁与争锋只改改善的实际倚天掌，既有领悟键／费用不漂移 | 未把其他待决策的裘千尺不存在绝招或NPC配武学一并宣称关闭。 |
| 达摩清心／乱气 | inquiry分别到原函数，各自重复检查和成功领悟键对应清心／乱气；消息名同源修正，未调贡献／神值门槛 | 原问两招先后顺序均应以现有教学回归证据为准，不从一条函数静态正确外推全部教学渠道。 |

## 4. 小龙女自动twice确实进入原互搏入口

核对链为 `inherit/char/npc.c::chat` 评估原chat_msg_combat闭包 → 小龙女 `command("perform whip.feng twice")` → 原命令分发 → `cmds/skill/perform.c::main` 解析twice → 两次原do_perform → 映射银索金铃的真实feng入口。

原 `perform_action("whip.feng twice")` 并不是命令级twice解析入口，因而这次改用已存在的command机制是必要且匹配的，未为NPC新增假绝招。命令本来就负责互搏等级、杂学冲突、战斗状态及随机失败；小龙女原zuoyou-hubo为200，原随机失败仍可能发生，不能将一次失败当成回归不稳定而改为必定互搏。她原有whip映射和持鞭初始化也仍在。

命令内部在首招后按原互搏规则暂挂数值busy再发动第二招；持续闭包busy不能再组合的保护也保留。现有NPC回归以原闭包、受控原随机输入观察两次feng共四次伤害边界，不是直接调用feng两次来绕过互搏资格。这里不对四次伤害的全概率／平衡数值另作结论。

- 未决NPC配招（如无名僧内功冲突、王剑杰八阵／八卦、其他没有唯一替代技能的配置）仍按最终矩阵分别记录，不从本报告“未见新增问题”变成已修。
- 本报告不代替主Agent正在串行执行的统一七组回归，不以此前通过数推定后续工作树自动通过；也不代替游戏内updateall／正式服日志。
- 本次没有发现需要另外修改源码的确定新问题，因此未越权做额外实现。默认startroom的宿主级影响已明示，不缩写为局部三NPC改动。
