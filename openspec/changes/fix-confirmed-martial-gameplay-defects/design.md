# Design

## Context

依据 `docs/architecture/martial-arts-data-findings.md` 的144组编号记录，含子项、历史状态及独立急修旁账。台账不是当前源码无条件补丁列表：证据跨多个源码快照，静态确认、驱动复现及意图待确认必须分开。当前教学由 `adm/daemons/masterd.c` 接收教师配置，武学经真实角色与战斗接口执行；已有 `tools/tests/test_martial_audit.mjs` 支持隔离副本和旧版本负对照。

已核对示例：三口神功调用不存在的 `die_protect` 导致玩家目标被全部跳过；神照经当前仅允许 force，旧徒手激发实现被注释，不能未经确认恢复整套徒手机制来消除“死代码”。

## Goals / Non-Goals

**Goals:** 全量核对编号及子项，只修正正确行为有依据的错误；每项具备对应测试和状态记录。

**Non-Goals:** 不做全局平衡重调，不迁移存档，不读真实 `/u/`，不修改历史原件或驱动/子模块。对已确认缺口仅做以下有界调整。

## Decisions

1. **逐项处置而非批量替换。** 新建本变更的修复矩阵，记录 MA 编号/子项、文件、当前现状、正确依据、测试、状态及待确认原因。状态包括待修、已验证修复、已由其他提交修复、重复、非缺陷、待决策；不把“有测试输出”当作修好。优先运行错误/奖励与资格、生命周期、普通配置、文案。
2. **最小改动、复用公共接口。** 对错拼字段逐处确认用途；资源检查与实际扣费一致，失败不靠事后钳零掩盖。不引入通用技能兼容层或历史错键别名。原待定冲突、缺失技能及保护差异按下文16组裁定处理，门规不因修复扩张。
3. **共享对象按实例或调用者处理。** 对 MA-135 等加载期动态动作取值按当前调用者计算；覆盖无玩家首载、交替角色和已返回数据不被后次改写。恢复记录使用施加时的真实增量，不重新按结束时等级算扣回值。
4. **测试修复语义而非旧错误预期。** 复用隔离真实驱动与原命令；夹具只设置必要输入和观察边界，不替换被修复逻辑。旧采集报告/契约保持冻结，修复测试另存；原错误条件须在修前失败、修后通过。每个修复写正向、拒绝/边界与相邻路径的可执行断言。
5. **文案与机制分账。** 明确错字可修，身份、输入别名、存档键不能当文案更改。帮助说明对照真实实现更新。`help/changelog` 描述玩家可见变化，不转贴内部编号堆砌。

## 原未决16组的裁定

- MA-004：保留裘千尺原教学与领悟钥匙。无影掌是初阶虚实单掌，空手、铁掌100、有效内功160，扣120内力、施招者忙乱2；轻功可避，命中按原始铁掌/2交给原公共伤害结算，比例30，不追加忙乱、不绕过防护。不借用嵩阳掌同名控制，也不取代铁掌龙影掌。
- MA-006：靛沧海仍需拳脚、内功、根骨与内力门槛；把不存在的玄混沌替换为已要求的基本内功，保留高10级的相对进阶差，避免强制跨门派。金晨曦的现有递进不变，不新增秘籍来源。
- MA-012/040/078：驱动测量三处当前生效值并原样保留；司徒焚只保留原警告与战斗，不安排无实现的移动；排云手未命名招式用门类名回退，选招不变。
- MA-031/049/044/057：黛绮丝和桑土公以原持杖武学招架；费彬补原映射的凌虚步，取门内同辈已有的140，不改其基本轻功200；王剑杰以已准备且门内传授神卦天印的八阵掌作为掌法，不把掌法激发成拳脚。
- MA-091/108/112/113：无名僧保留易筋经及如来掌普通招式/被动和授招，退出不合当前激发的自动万佛朝宗；周芷若保留有效夺命连环与摧心掌等，不补即死爪招、鞭或大伏魔拳；林朝英以现持长剑和已学的玉女素心剑使用连环剑术，不切兵器。删除无效自动槽位时按比例调整战斗闲聊机会，近似保留其余原招频率，不让其被动增频。
- MA-123/129/136：铁筝沿用铁琴同一死亡保护，不改无保护目标的伤害；密道9号北石门独立操作，密室南侧保留原单向回0号路线且不与另一门同步；神照经保留确立已久的内功定位，撤下两项无法合法施展的旧徒手代码，不改运劲、护体与存档。

## Risks / Trade-offs

- 旧记录已过时 → 对照当前源码及历史急修提交；已修项目补验证而非重复修改。
- 有意新增的无影掌和恢复可达的NPC招式必须断言施展门槛、效果与成本；局部实测不外推全服胜率和平衡。
- 多文件改动掩盖回归 → 按模块小批落地，记录每项文件及验证命令；全量编译不替代效果断言。
- 格式化差异 → 只格式化本批修改 LPC，运行项目格式化及 `--check`，审查 token/文案与无关数值不变。
- 实服旧对象持有状态 → 部署说明按每批实际生命周期要求给更新/重启建议，不承诺热重载能修复已残留的玩家状态。

## Migration Plan

不读写或转换玩家存档，不补发历史奖励、不自动转换历史错许可。完成全部明确修复及回归后提供文件范围、行为影响、剩余待决策列表和正式服验收步骤；部署由维护者另行授权。回滚按 Git 版本恢复代码，状态数据不在本次迁移范围。
