# 状态、资源及阵法交叉审查

范围为当前工作树 diff 与实际引用链的只读复核；本审查没有修改游戏代码，没有启动驱动，也没有以本报告代替主 Agent 的真实回归。重点核对宿主销毁入口、刀阵解除、如来掌固定与可选费用、低内力及公共加力。

## 结论

在下列限定正常路径中未发现新增的确定逻辑错误。必须保留两项边界说明：

1. 固定费用预扣会减少低余额时可支付的公共加力，这是杜绝负内力时的实际行为改变；不能声称与旧版低余额每一击效果完全相同。高余额原攻击次数、固定总费用和可支付加力规则保持。
2. 宿主 `destruct()` 包装可处理经该入口销毁的刀阵成员，不等于驱动所有对象回收方式都经过宿主包装；不能将这个修改称为驱动层全局析构钩子。

## 真实引用链与检查结果

### 宿主销毁到刀阵撤销

- `adm/single/simul_efun/object.c:destruct` 在对象尚有效时，若 `is_character()` 成立，先调用 `dismiss_martial_array()`，然后保留原 `remove()` 与 `efun::destruct()` 顺序。未改 UID/EUID、安全判断或对象删除机制。
- `feature/team.c:dismiss_martial_array` 仅在 `array/name == fanliangyi-dao` 时进入该武学；普通角色和其他阵名不会调用反两仪解除。
- `kungfu/skill/fanliangyi-dao.c:dismiss_array` 委派现有 `fanliangyi-dao/makearray.c:dismiss_array`，没有复制数值算法。
- 解除函数先保存成员快照，再逐成员读取自己的 `array/level`；删除阵标记并按该成员快照撤回攻击、伤害、防御、护甲。不会用退出者的等级替其他队员统一扣数值。
- 成员互含检查在原对象仍有效、尚未执行 `efun::destruct` 时进行；即使先清了发起者自身的 `array`，后续队友检查的是自己的成员快照是否包含发起对象，仍可正确撤销。没有发现“先清发起者导致第二人跳过”的错误。
- 重复解除因缺少本阵标记直接返回，不重复扣除；其他阵名或不含发起人的成员快照跳过，不影响独立队伍。

### `no_quit` 与队伍／移动钩子

- 成阵保存每人的原 `no_quit`；解除只在当前值仍为本阵写入的1时恢复原值。期间其他效果写成9等不同值会保留，不再无条件覆盖。
- 现有共享布尔字段不能区分其他效果也恰好写1的归属；这是当前字段模型的限制，未发现本批引入新的所有权框架，也不声称解决任意并发同值写入。
- `feature/move.c` 在 `move_object()` 后确认对象仍存在且实际换环境才撤阵；失败移动、不换环境不撤阵。
- `feature/team.c:set_team/dismiss_team` 仅在成员集合或领队实际变化、或有效解散/退出时撤阵，然后调用原框架方法。
- `CORE_TEAM.add_team_member` 虽先直接更新领队数组，再向每人 `set_team`，旧的另一名阵员仍能检测成员变化并解除两人阵；未发现正常加第三人导致整阵无法解除。
- 宿主扫描发现的 `adm/single/simul_efun/user.c` 旧 `efun::destruct` 位于一个各 switch 分支均已 return/error 后的历史段落，不能仅凭文本命中认定它是当前可达的绕过路径。显式调用驱动 efun 或驱动内部回收仍不属于新增包装的承诺范围。

### 如来掌固定200、可选80

- `adm/daemons/combatd.c` 普通攻击实际以三参数调用 `SKILL_D(martial_skill)->hit_ob(me, victim, damage)`；`kungfu/skill/rulai-zhang.c:hit_ob` 已改为匹配这三个参数，`i` 变为本地循环变量，传来的伤害不会再落入旧的第四参数空值。
- 原启动门槛仍为内力600、伤害参数至少150、佛学300、如来掌180，以及原忙乱、目标存活和动作标记条件；没有降低门槛补偿修复。
- 发动先 `start_busy`，再按原时点扣固定200，执行原四掌 `COMBAT_D->do_attack(...,0,20)`。该忙乱条件亦阻止同一施术者四掌中的本技能递归触发。
- 四掌之后才检查原体质比较；仅余额至少80时支付额外80并执行附加创伤。没有提前预留280挤占四掌的合法加力，也没有在余额不足时免费造成这项附加创伤。
- 伤害门槛保证 `(damage_bonus-120)/2` 在此分支非负。体质读取保留真实 `query_con()`，不能仅设置普通 `con` 属性就假定已进入创伤分支。
- 剩余79跳过可选创伤、80支付至0；高体质不触发可选创伤而保留原固定200成本。现有 `combat_cost_fixes.lpc` 已包含这些真实公共链边界断言；本审查没有自行运行它们。

### 断云、修罗与万毒的公共加力

- 断云：保留 `neili > 200`，额外要求可支付实际 `power`，并在普通连击前支付该固定费用；无鞭拒绝独立存在。高余额依旧执行原2—7击及原临时增益／撤销。
- 修罗：保留原1000启动门槛；普通固定总费600、豁免标记时300，先结算，再让原4—7击使用剩余内力。临时 `jiali` 与命中加成按原方式恢复，豁免标记按原意消费。
- 万毒：命中分支先支付目标对应的原直接费用，再进入真实 `combatd.do_damage`；未中分支不新增直接费用。公共直伤按当前余额判断可选加力，不会在已经花尽预算后再扣本招费用形成负数。
- 实际公共接口的规则并不完全相同：普通 `do_attack` 的内功命中钩子条件为 `neili > jiali`；`do_damage` 的附加加力结算使用 `neili >= jiali`。当前各修复没有改写这两条公共规则，也不能将两者混成统一严格/非严格比较。
- 因先支付固定费用，低余额时可触发的加力次数会少于旧的“先花加力、最后强扣固定费”路径；这是明确防透支后的资源约束，不应在玩家更新或报告中描述成完全零行为变化。现有真实 COMBAT 回归包含修罗1000与6000、加力450、豁免与正常费用，以及如来600/加力350等边界。

### 挪移键级清理

- `qiankun-danuoyi.c:valid_damage` 调度时捕获攻击者ID，`nuoyi(ob,me,attacker_id)` 首先确认承受者存在及对应标记，再只删除该ID子键。
- 攻击者已销毁或双方脱战也能消费该键，只有父 mapping 确实为空才删除父节点，不清除其他敌人待触发记录。
- 未发现本批将该键改成全局清空或重复回调双扣；真实异步与旧回调测试仍以主 Agent 所跑证据为准。

## 后续验收注意

应保留原件中的销毁成员、重复解除、独立队伍、期间新增 `no_quit`、失败移动、正常队伍变更以及真实 COMBAT 低余额测试。只验证 spy 传入费用，不能替代公共加力真实链；只调用解除函数，不能替代经宿主销毁入口撤阵。此报告只给出有限源码范围的交叉审查结论，不宣称整个状态／资源系统无缺陷。
