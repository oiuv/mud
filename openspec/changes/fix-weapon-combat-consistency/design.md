# Design

## Context

动机与范围见 [proposal.md](proposal.md)。分析基线为 `007a3953`，名称字典的工作区和 HEAD 都含 `spear: 基本枪法`、`hanshan-chuifa: 撼山锤法`。`data/e2c_dict.o`、`data/emoted.o` 已有本地变动，不纳入修复。

- `feature/equip.c` 只在新武器自身为双手武器时完整检查占用；新增副手没有反查已有主手的双手标记。主手为空的分支也未检查副手与手持物品已同时占用。
- 同文件 `unequip()` 删除主手后不处理副手；普通攻击仅取主手，副手没有属性加成。`wield()` 中原主手降为副手又会调用 `unequip()`，自动转主手必须避免在内部重排中递归或重复计数。
- `cmds/std/hand.c` 在新物品可用性检查前先移除旧手持物品；失败换持会丢失原手持状态。
- `feature/move.c` 的物品移动和正常销毁会调用 `unequip()`；主手切换不只发生于玩家命令。
- `combatd.c` 将伤害值作为第四参数传给 `post_action`；`weapond.c` 的 `bash_weapon` 却把同一参数当作 `RESULT_PARRY=-2`。当前运行期源码检索只发现默认钝击和暗器两组注册回调，实施前复核新增调用。
- 两份斧锤绝招均检查 400、命中扣 500；罗汉棍阵写入未被属性系统读取的键，且搭档状态为 `bunzhen`，检查/清理却使用 `gunzhen`。
- 既有 `test_weapon_startup.mjs` 已提供真实 NPC、装备和 COMBAT_D 的临时 MUDLIB；分类回归的部分战斗检查仍使用替身，不能替代本次真实招架/碰撞验收。

## Goals / Non-Goals

**Goals:** 在现有函数和状态上修复确定缺陷，新增可重复的真实驱动回归；玩家能看到的变化有对应日志，测试不接触正式数据。

**Non-Goals:** 不创建新装备管理器、状态机框架或兵器插件；不把副手升级为双持输出，不修改全局属性/伤害公式，不清理历史物品标记，也不把测试通过解释为类别平衡完成。

## Decisions

### 1. 装备校验先于状态写入

在既有 `wield()` 和 `hand` 入口内按目标状态检查，仍使用 `weapon`、`secondary_weapon`、`handing`：双手主武器独占；单手主武器只能与一个副手或一个手持物品共存；同一物品不占多个槽。新增副手必须检查现有主手标记。

换持或将手持物品转为武器时，把原占用视作本次转移的一部分，检查成功后才提交；拒绝时保留原装备、手持物品和属性，不先清槽再补救。保留现有耐久、物品资格和重量规则。

选择局部校验与现有属性加减，不引入独立事务框架。物品 `move()` 失败前已卸装等其他生命周期行为不在本轮通用重构范围。

### 2. 卸主手后合法副手自动转为主手

用户已确认此选项，而非同时卸下两把武器。完成原主手卸装和属性扣除后，将仍在角色身上、仍可持用且不违反占用规则的副手移到主手，清副手槽、加入其属性并刷新动作。该武器只计一次主手加成；反复持卸与原主手降为副手均不得残留加成。

副手不合法时不强行转持，也不阻止原主手正常移走；移除失效的副手装备状态，物品保留原归属，不销毁或丢弃。复用现有装备提示的武侠表述说明正常转持，不向玩家暴露槽位等术语。

覆盖命令卸装、掉落/移动、正常销毁、钝击脱手，以及双副手候选之间的主副重排。仅补齐关联链，不增加副手攻击、招架或额外属性收益。

### 3. 攻击结果与伤害分开传递

攻击结算保持第四个回调参数为实际伤害，增加独立的第五个结果参数；在真实闪避、招架、命中分支赋值，复用已有结果常量并按需明确普通命中常量。同步 `bash_weapon`、`throw_weapon` 签名及调用说明，不再用伤害负数表示结果，不建立两套兼容分派。

`bash_weapon` 只对真实招架且参与碰撞的兵器仍有效时运行原重量/刚性/力量比较。保持原概率、分支和自制兵器保护；命中零伤害、闪避或数值偶然等于 -2 都不能进入招架碰撞。暗器原数量消耗保持。

不把默认钝击回调强加到所有特殊武学；后者仍使用自身动作。选择显式结果参数而非直接将第四参数替换为负码，避免新接口继续混淆伤害与状态。

### 4. 绝招按最大消耗检查发动资格

两份绝招都以 500 内力为发动下限；命中扣 500、失败扣 300，保留原计算、忙乱、领悟与类别校验。不通过事后将负数钳为零减免实际费用，也不降低成功消耗来凑旧门槛。

既有分类验证记录保留历史“入口 400”结论；当前回归更新为显式批准差异并覆盖 399、400、499、500 及成功/失败分支，不改写冻结的旧武学数值快照。

### 5. 罗汉棍阵使用实际属性键并完整撤销

加成改写到 `apply/str`、`apply/dex`，双方统一使用 `gunzhen`；所有正常结束、脱战、离开、失去兵器或一方消失的清理分支同步。只撤销本阵实际加入的数值，保留其他效果，防止重复组阵、重复清理和遗留检查造成叠加或负加成。

复用当前阵法函数和临时状态，不新增通用 buff 框架；原增量公式、上限 20、资源消耗和目标忙乱不变。让错误字段对应的既有增益真正生效属于功能修复，但会增强实际表现，应明确告知玩家。

### 6. 用隔离驱动验证，不以编译代替机制测试

在 `tools/tests/` 新增本批测试入口和夹具，复用既有源码复制及测试 master；只复制源码、必要公共字典到 OS 临时目录，禁止外部服务和正式存档。装备、属性、技能与战斗结算用真实实现；需要稳定覆盖随机分支时仅在临时源码副本设置确定性随机输入，记录替换点，不改正式随机算法。

首选复现缺陷的断言，再修代码；至少验证真实 `do_attack` 产生招架后确实调用碰撞处理，不能只直接调用 `bash_weapon(-2)` 或只检查输出文字。另测闪避、命中零伤害和暗器数量作为负向对照。

## Risks / Trade-offs

- 恢复碰撞可能令装备脱手或损坏 → 保留既有自制保护，用可丢弃的临时物品回归，玩家日志明确说明；不在正式服试打或回放。
- 自动转主手与内部主副交换互相影响 → 核对切换前后加成差额和动作，覆盖两把副手候选、移动与销毁；不在同次交换反复调用公开入口形成递归。
- 棍阵真实增益会改变强度 → 先验收原设计数值能生效并完整撤销，不同时增加数值，也不宣称已经做过公平性评测。
- 旧测试把缺陷数值写成兼容要求 → 当前预期以本变更显式更新，历史快照和旧报告不覆盖；已完成分类变更不重新伪造验收日期。
- 热更新时旧对象可能仍持有旧装备/阵法状态 → 交付完整重载或维护重启要求，不宣称只更新某一个文件即可一致；正式操作仍由用户安排。

## Migration Plan

1. 完成新回归、相关旧分类与装备回归、修改文件格式化及 `--check`、完整继承链编译，记录真实结果。
2. 同步 `docs/architecture/weapon-classification.md`、相关帮助与 `help/changelog`，说明副手转持、两绝招 500 内力门槛及旧效果恢复。
3. 不迁移存档、物品路径或玩家武学；部署由用户按维护流程更新并重新加载完整依赖，避开旧战斗/阵法未结束时混用版本。本次不替用户停服。
4. 回退时回退本批完整代码并重新加载，清理旧临时战斗状态；代码回退不会逆转上线后已经发生的耗费或物品损坏，不能承诺玩法后果自动恢复。
