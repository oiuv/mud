# Proposal

## Why

现有 AI 服务已有公共通信和独立业务模块，但问答仍由代码固定检索文档，专业提示词与业务代码耦合，缺少可复用工具、技能加载和受限 Agent 调度。需要在继续扩展无限世界及其他 AI 玩法前，建立可长期维护的“直接代码路由 + 主 Agent 路由 + Tool + Skill + Hook”架构，同时保留既有数据、异步体验和权限边界。

## What Changes

- 明确 AI 服务独立于具体 MUDLIB，可由遵守协议的其他 MUD 接入。路径、角色、知识库和部署差异优先通过配置解决，允许保留本项目默认值；只有不同的业务语义需要可选模块或适配。通用执行层不导入游戏业务，不要求复制本库目录；不为可移植性增加多租户、微服务或新通信协议。
- 将所有业务 AI 能力定义为独立 Agent，首批覆盖 NPC 问答、对话摘要和世界描写；支持直接路由和主 Agent 委派同一个 Agent。独立指配置、输入输出、上下文与权限独立，不要求独立进程或每次都多轮推理。
- 建立轻量共享执行器：Agent 围绕目标维护已知事实、待查问题和证据，根据工具反馈持续决策、补查及验证，直到完成或遇到明确阻碍；不是一次检索后直接生成答案。主 Agent 可发现、委派和检查业务结果，直接路由只是跳过主 Agent，不削减业务 Agent 的多步能力。
- 将模型可调用能力封装为可发现、可复用的 Tool：知识检索、授权文本/源码读取与搜索、统一 Skill 加载、受限 Agent 委派。工具只从受信任部署包发现，发现与授权分离；新增合法插件无需修改中央分发分支。
- 为源码问答建立任务完成标准：自主定位相关代码、追踪入口及依赖、区分学习/解锁/施展及贡献门槛/实际扣除、解决证据冲突、核对答案。首次检索无结果不能直接视为任务结束；只有在授权范围内完成必要调查，或遇到权限、缺失信息、预算等明确阻碍后才返回终态。用人工核对的真实问题和多文件夹具验收，不用模型自称正确代替验证。
- 将专业提示词迁为中文维护的版本化 Skill 包；自动扫描配置目录，将已授权技能的名称和描述注入 Agent 系统提示词，正文及引用资料统一通过一个 `skill` 工具按需加载，明确路由可由程序经同一入口预加载。保留专业示例与回归样本，加载技能不授予新权限、不执行技能脚本。
- 增加模型、工具、委派、结果提交等生命周期 Hook，支持受限观察、脱敏、拒绝和取消。权限策略是不可绕过的运行时检查，Hook 不能扩权，策略 Hook 失败时关闭相关操作。
- 保留 NPC 人设、RAG 降级、历史/关系与原子去重，以及世界任务、日额度、正文快照和已生成内容；增加按业务开关的迁移与回退，不重建数据、不因 Skill 升级重做正文。
- 为现有及新增功能建立统一接入规范：业务 Agent 定义、输入输出与完成条件、授权工具、专业 Skill、资源预算、结果提交责任及回归样本缺一不可。先迁移现有功能，再以源码任务验证目标驱动能力；不为每个 NPC 复制执行器，不建立第二套模型调用或权限通道。

## Capabilities

### New Capabilities

- `ai-agent-runtime`：独立业务 Agent、双入口、目标驱动任务闭环、主 Agent 委派、统一权限/预算及新功能接入契约。
- `ai-tool-access`：受信任工具发现、类型契约、权限过滤、有界执行、授权只读文件访问及无写入/执行工具的边界。
- `ai-skill-runtime`：中文专业 Skill 包、自动目录发现、单一加载工具、按需上下文、版本与资源隔离。
- `ai-runtime-hooks`：生命周期事件、观测与干预、不可扩权策略、脱敏审计及故障处理。
- `ai-source-grounded-answers`：目标驱动源码调查、跨文件追踪、结论验证、证据与部署版本区分、玩家和管理视图隔离及准确性验收。

### Modified Capabilities

- `ai-service-modules`：在保留 NPC 行为、数据和配置的基础上，允许问答通过授权工具使用源码证据，并以独立 Agent/Skill 承载业务模型调用；明确可独立部署、路径可配置及可选游戏模块边界。
- `ai-request-transport`：增加显式 Agent 请求入口及双路由对应的可信权限绑定；保留旧请求、未知类型拒绝、容量及回调生命周期。

## Impact

- 主要影响 `ai/main.py`、`ai/src/llm.py`、`ai/src/udp_server.py`、`ai/src/npc/`、`ai/src/world/`、`ai/src/knowledge_*.py`；新增轻量运行时、Agent 定义、工具、`ai/skills/` 和中文架构/扩展文档，更新根 `AGENTS.md` 的 AI 接入规范。首期保持 Python 模块化单服务、现有模型提供方和同机部署，不要求新 Agent 框架、向量库或 MCP 服务；不建通用任务数据库、长期自治调度、插件市场或热安装平台。
- 本游戏继续经 `AI_CLIENT_D` 调用，其他 MUD 只需实现约定的客户端协议，不依赖该 LPC 对象名、FluffOS 或 mudcore。面向本游戏玩家的结果沿用武侠表达，不泄露源码路径、内部函数或异常；证据明细供受限管理诊断。源码授权同时包含是否允许发送给外部模型，不默认开放整个仓库、个人目录或玩家数据。
- 现有 `add-wuxia-infinite-world` 仍为独立、未完成变更；以已提交的 `2f8192a5` 为迁移基线，本变更先升级服务架构，不修改其地理/战斗规则或替它勾选验收。两项变更涉及 `ai/` 的实施须串行协调，旧世界的内容键、存档及创作开关保持。
- 不修改 `mudcore` 或 FluffOS，不增加模型可见的文件写入、删除、Shell、代码执行、任意网络访问或直接改游戏数值工具。服务自身必要的数据库/日志/正文写入仍由可信业务代码执行，不作为模型可调用工具。
- 本提案及配套设计、规范、任务只完成规划；实现、实际源码目录授权、真实模型额度和正式开放分别验收，不由规划创建动作隐式开启。
