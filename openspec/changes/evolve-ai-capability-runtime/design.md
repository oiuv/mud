## Goals / Non-Goals

**Goals:**

- 遵循 KISS：先保证正常条件下的任务完成与常见故障恢复，选择性借鉴其他 Agent 的成熟做法，不为假设中的边界场景增加框架、抽象或恢复分支。简化重复职责，不削弱权限、取消、证据可信性和业务提交保障。
- 建设面向 MUD 的通用 AI Agent，充分利用 LLM 自身的理解、推理和规划能力。默认让模型围绕目标自主规划、行动、观察和调整（ReAct）；仅对业务明确要求的场景由 Skill 指定工作流，对明确格式要求的输出使用 JSON Object。不把特定场景的固定步骤作为通用要求，不为单道评测题增加规则；测试检查答案和证据，不要求复现某条工具调用轨迹。
- 所有业务 AI 服务以独立 Agent 定义注册，直接与委派入口共用执行、工具、技能和策略。
- 新增受信任工具/技能可通过规范包被发现，权限过滤后供模型使用，不增长中央业务分支。
- 源码问答按目标自主调查、追踪依赖和验证结论，以任务是否完成衡量能力，不退化为检索片段后生成答案。
- 将权限、取消和用量账本置于模型之外，Hook 支持可审计的干预，任何嵌套路径不能提升权限、清零消耗或撤销取消；不以累计次数、消耗或总时长限制正常调查。
- 保留既有 NPC 和世界数据，支持逐项迁移、禁用及回退；自动测试不产生真实 API 消费。
- 服务可脱离本 MUDLIB 部署；路径和部署差异优先使用配置，通用执行层不依赖本游戏业务，可选模块承载真正不同的业务协议和语义。

**Non-Goals:**

- 不开放文件修改、任意文件系统访问、任意 Shell/脚本或代码执行、动态安装插件、网络浏览或游戏数值修改能力。授权 CLI 调用不构成这些能力的旁路。
- 不实现自治 NPC 社会、自动发奖、新任务系统、无限世界新地形或自动改写已发布正文。
- 不先拆微服务、不引入 Redis/新向量库，不把重型 Agent SDK 设为前置条件；未来可替换运行时适配器。
- 不建立通用任务数据库、长期自治调度、插件市场、独立 Hook 插件框架或完整 LPC 静态分析平台；完整 Agent 循环属于必要基础，不在精简范围内。
- 本轮不增加计划工具或计划执行框架；将来复杂任务确有需要时，可通过已有工具机制增加计划工具，由 Agent 自己维护并调整计划，不强制所有任务先列计划。

## Decisions

### 1. 统一 Agent 定义，两种路由共享执行器

采用模块化单服务和一个共享执行器。Agent 是负责业务目标的独立定义，不等于独立进程，也不等于必须执行固定轮数。定义包括稳定 ID、说明、输入/输出契约、完成条件、Skill 绑定、工具权限引用、模型配置引用、执行模式、上下文管理与单次操作故障策略。运行时保管任务状态和执行工具，模型根据反馈选择行动。

主 Agent 是服务 MUD 的通用智能体，理解目标、自主处理或委派，并判断整体结果；游戏答疑、无限世界生成等具体功能由专业子 Agent 承担，也可通过明确入口直接调用。Tool 提供可执行能力，Skill 提供专业知识、方法及明确场景的工作流，Hook 负责观测和必要干预；三者共同支持 Agent，不另建工作流执行框架。

```text
AI_CLIENT_D / Trusted CLI
          |
  Transport + Route Binding
          |
          +--> Direct Agent ------------------+
          |                                   |
          +--> Main Agent --------------------+--> Agent Runtime
                    |                                |
                    +--> agent.invoke --> Leaf Agent-+
                                                     |
                                      Skills + Tool Executor + Model Adapter
                                                     |
                                         Validated Business Result
                                                     |
                                           Trusted Domain Commit

              Policy / Usage / Cancellation / Hooks / Trace apply to every path
```

首批 Agent：主 Agent 沿用 `main_router` 注册 ID，但职责不限于路由；`npc_dialogue` 承担游戏答疑和 NPC 对话，`world_narration` 承担无限世界当前阶段的描写生成，`conversation_summary` 负责内部对话摘要。NPC 角色仍为数据配置，不为每个 NPC 复制代码；源码调查是游戏答疑使用的专业能力，不再额外套一个必经子 Agent。摘要默认不向主 Agent 公开，仅接受所属会话提供的材料。

直接路由绑定 Agent ID 和权限配置，经过同一个 `AgentRunner`；主 Agent 通过 `agent.list`、`agent.invoke` 使用相同定义，不能另建业务实现或通过 UDP 回调本服务。两种入口都先经过业务适配层的验证、容量和提交契约，不能委派时绕开它们直接调用模型。`memory/config/world_status` 等确定性操作保留原查询入口，不为架构形式额外调用模型。

执行模式为 `single` 或 `tool_loop`，共用模型、Skill、策略、Hook 和结果验证。世界描写和摘要是业务已明确的单次生成场景；NPC 问答和主 Agent 使用通用目标驱动循环，不预设调查工作流。模型选择下一步行动，运行时执行工具并反馈观察；简单问题可直接完成，复杂问题自主继续调查。直达 NPC Agent 同样具备完整多步能力，“直接路由”只表示不经主 Agent。

主 Agent 是协调目标的 Agent，不只是分类器：可选择业务、检查委派结果、根据缺口再次调用或请求澄清。首版顺序委派叶子 Agent，不引入递归 Agent 网络或并行讨论；这不限制叶子 Agent 内部持续查证。世界委派仍通过原持久任务受理入口，返回受理凭据时主 Agent 必须报告等待，不能把任务受理冒充文案完成，也不能抢占后台工作或重复发布。

对比：所有请求先经主 Agent 会增加延迟与路由失败面；只保留固定流水线则无法支持开放目标。本方案统一 Agent 抽象，不统一成同一种执行步骤。

#### 专业执行与上下文隔离

主 Agent 管“我要完成什么”，子 Agent 管“某个专业任务怎么完成”。主 Agent 负责整体目标、任务拆分、依赖协调和结果是否覆盖目标；专业 Agent 负责在授权范围内选择方法、加载 Skill、读取参考资料、使用工具及验证专业成果。采用“上下文隔离 + 专业任务封装 + 结果回传”，不将所有专业过程塞进主 Agent，也不要求主 Agent 重做子任务的完整调查。

简单任务直接处理，复杂任务按需要委派，不要求所有任务都经过子 Agent。这不仅指明确业务路由跳过主 Agent：已经进入主 Agent 的简单请求，也可由其使用自身已授权能力直接完成，子 Agent 调用次数为零。材料量较大、跨专业或需要独立调查/创作过程时，再将清晰的专业子目标委派出去；不以调用了工具或需要多轮处理为由强制拆分，不把主 Agent 限制为只能分发任务的路由器。

每次委派复用现有 Runner，创建独立消息历史和任务状态，只传入完成子目标必需的已授权事实与约束，不复制父运行全部历史。专业 Agent 使用声明的模型配置，并在自己的上下文中通过统一 `skill` 工具加载指导与参考资料，按 `single` 或 `tool_loop` 完成任务；模型选择仍受可信配置控制。一个 Agent 可使用多个 Skill，一个 Skill 也可由多个 Agent 复用，不为每个 Skill 编写执行器或强制创建子 Agent。

子任务只回传有界结果摘要、必要的业务结论、成果/证据引用、限制与未完成事项。技能正文、原始参考资料、检索列表、完整工具记录、中间草稿及提供方返回的思考内容不自动追加到父消息历史。思考内容可按模型协议保留在本 Agent 上下文，并在显式开启的受限开发诊断中记录，不属于父子业务交付。结果契约必须保留影响结论的条件、数值、例外和阻碍，不能为了缩短上下文把不确定结果压成“成功”。主 Agent 需要进一步核查时，可按原授权补查必要资料或继续委派，而不是默认回灌全部过程。

上下文隔离不等于权限或用量隔离：子调用仍受父子权限交集、根取消状态及调用方存活契约约束，使用既有业务容量与提交入口，用量分别记录并汇总到同一根账本。父子使用不同模型时各自按对应窗口管理上下文，不继承错误的容量。简单明确的任务继续直接执行；源码调查不额外套必经子 Agent，世界和摘要不因隔离增加路由、审稿或专门压缩交付结果的模型调用；达到窗口阈值的上下文维护另按第 3 节执行并独立计量。比较正确率、完成率、上下文规模、累计用量、延迟及每个成功任务的费用，不预先承诺固定节省比例。

### 2. 路由与可信调用身份

保留现有 `chat/memory/config/world_describe/world_status` 报文与回调字段；省略类型仍按现有聊天语义，未知类型继续报错，不成为主 Agent 的兜底输入。

新增显式、默认关闭的 `agent_run` 路由；请求仅包含业务目标、相关公开情境和关联编号，不接受调用方自报 `admin`、权限、文件根路径或额外工具定义。目标不清时允许返回澄清问题，不能靠猜测越权执行。明确的 NPC 和主 Agent 长任务使用在途状态与存活/取消契约，不受固定总等待期限截断；有独立持久业务生命周期的世界任务仍走原队列，不为通用调查新建任务数据库。

`RunContext` 由可信适配层创建：调用来源、受众、会话范围、Agent ID、根运行/父运行 ID、策略版本、共享用量账本及取消状态。操作超时、短请求期限和调用方存活期限与任务总时长分开表示，不再沿父子链传播一个固定的通用任务总截止时间。旧本机 UDP 不是管理员身份认证机制：网络入口至多获得服务端配置的固定玩家级策略；不得凭 payload 字段升级。管理员源码诊断先走受本机操作系统权限保护的 CLI/内部入口，不新增未认证管理 UDP 路由。

最终有效权限取部署策略、入口策略、当前 Agent、父调用授权范围及 NPC 知识范围的交集。注册定义、Skill、模型和 Hook 都不能自行扩大交集。委派默认只允许主 Agent 调用叶子 Agent；遇到祖先环或超出既定单层委派拓扑立即拒绝，不另外设置累计委派次数预算。单个玩家请求的资料、证据和上下文隔离，不把其他玩家记忆当作共享知识。

上述交集继续约束工具、知识库、会话及业务操作；源码资料统一使用第 5 节的仓库根目录和敏感排除，不再叠加 NPC、玩家/管理员或各 Agent 的源码目录清单。获得源码工具能力的 NPC 与主 Agent 共用这一边界，不因此给摘要或世界单次生成增加无关工具。

#### 长任务通信与取消

在现有 socket、请求编号及业务路由上扩展可识别的非终态在途状态、存活续约和取消，不更换传输协议。长任务模式须由客户端与服务端显式支持；普通短查询及世界受理/状态查询仍保留原有短响应期限，旧客户端不被隐式切换为无限等待。

长任务在调用方仍有效且通信存活时继续执行，不因累计运行超过 80/90 秒而结束。客户端与服务端按同一请求关联续约及在途状态；存活探测独立于模型输出，模型长时间思考不被误判为断线。非终态状态只维持等待，不消费至多一次终态回调，不触发新模型运行或成功缓存。同编号同内容的重传继续关联原任务，同编号不同内容仍拒绝；续约不能改变身份、权限或复活已经取消的请求。

玩家离线、NPC/回调宿主失效、显式取消、服务停止或通信失联后，撤销该运行的继续执行与提交资格，停止新操作。一次探测丢包不立即误判，重试/存活窗口是故障检测而非任务总时限；失联后不后台无限付费。服务端自身确认失联也应取消，不依赖最后一份取消报文必定送达。已发出的调用可能无法强制停止，迟到结果仍计已知用量，但不投递、保存成功对话或推进关系。玩家提示保持武侠语境，协议状态与诊断只供接入代码/管理员使用。

### 3. 结构化模型适配、用量观测与上下文管理

新增模型结果对象，区分业务文本、提供方实际返回的可选思考字段、工具调用及调用 ID、停止原因、用量和错误；现有 `complete_chat()` 保留为只接受最终文本的兼容包装，不拼入思考内容。模型工具能力及上下文容量通过提供方适配和配置声明，启动/离线契约测试检查；不支持时返回可诊断结果，不静默改模型或伪造工具执行。

思考字段（如 `reasoning_content`）与正文分开处理，不要求模型在正文中复述或补造思维链。按当前提供方/模型协议，在本 Agent 后续调用中保留需要的助手思考字段，包括工具调用后续行和候选校验失败后的继续处理；不把同一字段不加区分地发给不支持它的模型。未返回字段的模型沿用原流程，不增加模型调用或修改默认模型/思考开关。协议保留与诊断落盘相互独立：关闭诊断不应丢失下一轮推理所需字段，开启诊断也不改变消息、工具、权限或完成条件。

每轮合成授权工具定义和消息，检查上下文并在需要时压缩，再调用模型，严格解析参数与调用 ID，通过统一工具执行器取得结果，再继续或提交候选结果。初版顺序执行一批工具调用；每一个 Tool 完成独立鉴权。调用 ID 不能重复执行，非法/未知工具记入诊断但不消耗虚构的收费调用；工具失败按可恢复/不可恢复返回，允许 Agent 换关键词、追踪另一入口或修正参数。

可信任务状态保留目标、简短行动清单、已确认事实及证据 ID、未解决问题、工具结果和终态，不从思考内容提取授权、证据或完成状态。提供方返回的思考内容属于本 Agent 的模型上下文及可选诊断资料，不是事实依据或业务结果，不写入玩家响应、成功对话历史或业务响应缓存。模型根据观察更新待办，选择下一工具；运行时没有硬编码每个游戏问题的搜索顺序。声明完成时由业务验证器检查结构、引用来源和要求覆盖，未通过则给出具体缺口供 Agent 继续调查。程序不能仅凭引用存在或思考过程看似合理证明语义正确，语义准确性另由固定答案集验收。

区分 `completed`、`needs_input`、`incomplete`、`failed`、`cancelled`。`completed` 要满足本业务完成契约；`incomplete` 记录已完成部分和实际阻碍，如必要资料确实不可取得，不能因首次检索无结果或累计调用较多就结束。需要澄清、不可恢复故障和取消分别返回相应状态。工具拒绝后的重新规划只能在原授权范围内进行。任务状态随请求存在，不引入跨重启自主续跑；有副作用的结果只在业务确认完成后提交。

连续无进展检测改为策略反馈：根据工具身份、规范化参数、资料版本和有效结果识别等价行动；新的调用 ID、时间戳或模型自述不单独算作进展。重复取得相同事实、相同失败或反复提交相同完成缺口时，反馈具体原因并提示更换方法，不仅因达到固定次数阈值就返回 `incomplete`。新证据、相关资料变化或已验证缺口减少属于进展；首次无命中、多文件调查和合理重读不能单独触发停止。只在目标完成、实际不可解决的阻碍、需要澄清、不可恢复故障或取消时结束。反馈不自动重提有副作用的操作，也不新增进展审判模型。

不设置通用 Agent 累计模型/工具/委派次数、累计 token/费用、累计读写字节或任务总时长硬上限，移除“最后一次调用关闭工具并强制收尾”的逻辑。根账本仅负责并发安全地记录主/子 Agent、摘要、检索内向量/重排及 compact 的实际调用、失败和用量，不据累计值拒绝正常操作。记录输入、缓存命中和输出用量；提供方未返回的数据标为未知，不按零消费处理。费用按部署配置的单价估算并注明口径，不将调用次数冒充精确费用。权限、业务额度、并发容量、单次资料/报文规模和单次 I/O 故障处理不属于该累计预算，继续独立生效。

取消 NPC 的 80 秒任务总期限，与游戏端长任务存活机制一同迁移；摘要和子 Agent 共享取消状态，不自行续活已失效的根任务。模型与工具仍具有可配置的单次连接/操作故障超时，不能把一次可恢复工具超时等同于整个任务到期。世界默认单次生成、90 秒单次故障超时、最多三次持久业务尝试和日额度保持，世界/摘要不增加额外路由或审稿模型。HTTP 超时不是强制杀线程；超时操作的迟到结果不得混入后续步骤，取消后不再发起下一次调用或提交。

#### 原生 JSON Object 输出

默认使用自然语言输出；仅当业务接口明确要求 JSON 对象时，统一发送 `response_format={"type":"json_object"}`，提示词简短说明 JSON 输出及现有字段。字段、类型和必要业务条件继续由已有本地校验负责，不把普通推理、规划或对话强制包装成 JSON。只采用 JSON Object，不实现 JSON Schema 模式、提供方 Schema 转换、模式选择器或额外格式修复模型。纯文本摘要、compact 和普通文本调用不启用 JSON 模式。

沿用同一工具循环，保留工具调用和思考字段续行；JSON 模式不强制模型提前回答或增加单独的收尾调用。不支持所需能力时沿用明确失败，不静默降级或换模型。格式正确不代表事实正确，证据与业务提交检查保持原职责。

按[百炼结构化输出文档](https://help.aliyun.com/zh/model-studio/qwen-structured-output)，JSON 生成不发送 `max_tokens`；上下文管理按配置的模型最大输出容量预留空间，不能继续按较小的文本输出限制预留。本节为待实施方案，不代表现有调用已经启用原生 JSON。

#### 模型容量配置与 token 计量

上下文窗口以环境变量 `OPENAI_CONTEXT_WINDOW_TOKENS` 声明，与 `OPENAI_MODEL` 绑定；配置层默认值为 `1000000` token（1M），未设置时使用该默认值，运行时不硬编码容量。`OPENAI_MAX_TOKENS` 保留为纯文本调用的输出上限；原生 JSON 调用不发送该参数，另通过环境变量声明模型最大输出容量用于预留。窗口和输出容量不相加当作可用输入容量，也不要求每次输出最大长度。部署切换模型时同步核对窗口、输出配置及分词适配；进程环境变量优先于 `ai/.env`，示例与迁移说明使用中文。显式值为空、非整数、非正数或无法为输入与输出留出有效空间时明确报错，不静默回退。1M 是部署默认约定，不表示所有模型都支持该容量或服务已经自动识别提供方限制。

共用同一模型配置的 Agent 复用对应容量；声明独立模型的 Agent 必须绑定自己的容量环境变量及输出配置，不能套用主 Agent 的窗口。模型配置由可信部署提供，请求、Skill 或 Hook 不能改大窗口。启动日志只报告模型标识、容量与阈值等非敏感信息，不能声称仅凭配置即可证明提供方真实能力。

计量覆盖最终发送的系统/角色提示、技能目录与指导、历史、实际回传的思考字段、工具定义、工具返回、输出格式说明与配置及 Hook 追加内容，采用对应模型的 token 计量；无法精确计算时使用经验证的保守估算并标明，不以 UTF-8 字节数直接等同 token 数。提供方返回的输入用量用于核对估算偏差；思考 token 按提供方用量口径记账，不将已包含在输出总量中的细项重复相加，也不因关闭诊断而漏记。取消现有通用上下文 128 KiB 和累计字节阈值，模型原始响应解析也须匹配配置的输出容量，不能仍被旧 32 KiB 通用限制截断；最终业务响应、单个工具的分页/有界结果及数据报大小契约独立保留。

完整输入达到配置窗口的 80% 时触发 compact；输入加本次预留输出和适配安全余量必须能装入窗口，输出预留较大时可提前压缩。80% 是维护触发点，不是压缩成功或任务终止的硬界线；已有效缩短且能容纳完整请求与预留输出时，不仅因仍高于该比例而判失败。每次模型调用前最终复核，Hook 追加内容也必须计入，不能先检查后追加越限内容。父子 Agent 分别管理自己的上下文，不因子任务压缩而把其原始过程送给父 Agent。

#### Compact 的保留、提交与故障语义

compact 是共享运行时的内部上下文维护操作，由代码直接调度，复用统一模型适配、外发授权、用量观测和 Hook，不新建第二个 Agent 工具循环或模型可调用工具。压缩指导在独立提示词文件中维护，由运行时直接加载并固定内容 hash；它不是业务 Skill，不经过 Tool/Skill 加载或要求 Agent 具有 skill 权限。压缩调用不提供业务工具，不产生游戏副作用，也不递归触发自身压缩。短任务未达到阈值时不增加压缩调用，单次世界/摘要的普通样本仍维持原调用数。

上下文计量可用同一模型返回的实际输入用量校准已发送前缀，只对新增内容做保守增量估算；复用前核验模型绑定、窗口、工具定义和消息前缀。模型切换、提示改写或摘要替换后重建计量基准，未知用量不按零处理。缓存输入已计入输入用量，不重复相加；累计账本和压缩请求的消耗不是压缩后上下文大小。候选上下文须重新计量并预留继续执行空间。

保持系统安全约束、授权视图、当前目标和必要专业指导；压缩较早的调查过程，保留已确认事实及条件/数值、证据 ID 与快照信息、未决冲突、待办、已尝试而无效的方法和近期相关交互。不额外索取思维链，不将思考内容或来源资料的提示注入升级为指令。按完整交互组选择压缩范围，保留近期助手消息时同时保留其协议所需的思考字段及全部对应工具结果，不能按固定消息条数切出悬空调用 ID；未完成工具批次先完成或按取消语义结束，再在稳定边界压缩。较早思考字段随所属历史纳入容量与压缩处理，不要求在摘要中逐字保留，不从诊断文件回灌旧历史；可信证据及业务完成检查仍独立保管。

模型只生成供任务继续执行的文本工作摘要，不要求固定标题、严格 JSON 或完整复制 `evidence_ids`，删除相应格式修复与引用复述重试分支。运行时直接保留被压缩材料与原证据的关联，并将必要任务状态和证据信息与摘要一同组装；元数据无需由模型再生成一遍。提示词指导模型保留关键条件、数值和未决事项，正常任务及连续压缩后的效果通过回归样本验收，不以格式正确或 ID 复制齐全证明语义正确。

证据表、权限、根/父子关联、用量、取消、工具去重及待提交成果由可信运行时保存，不从模型摘要重建或覆盖。压缩摘要不能把未读材料变成证据、把未完成变成完成，引用交付和源码验证仍回查原记录；必要事实可按原授权补读。取得非空、未截断且无工具调用的文本摘要后，检查运行时证据关联与受保护状态未变、消息/工具组完整、完整请求容量合规且实际缩短，再原子替换本 Agent 的旧消息部分，继续同一目标与运行身份。

压缩失败、取消或校验不通过时保留原上下文与证据，不静默丢弃旧材料。常见连接失败、限流和暂时性服务错误沿用已有请求恢复机制，不新增恢复框架或改变业务提交重试语义。超大资料先按工具契约分页/缩小读取；输入已超出单次压缩窗口时按完整消息/工具组分段处理，单个不可再分的受保护内容装不下则明确报告上下文无法容纳的实际阻碍。不以丢弃关键约束或无限重复无效 compact 恢复运行；一次压缩没有减少容量时调整摘要目标或压缩范围，确实无法容纳才返回相应错误。压缩本身的输入也必须符合其模型窗口和输出预留要求。

根用量账本采用请求内共享计数器，轨迹沿用脱敏结构化日志，记录请求/父子关系、终态、策略/技能/模型版本、证据 ID、用量和错误类别，以及 compact 前后 token、原因、次数与结果，不新增通用运行数据库。已有 NPC 成功结果缓存保持；新 `agent_run` 复用持久请求结果缓存机制，以业务命名空间隔离键和完整请求指纹，旧 NPC 键保持可读。并发重传共享在途运行，已缓存成功结果重传不重新付费；中断但未落结果的通用请求不自动续跑，不承诺崩溃窗口中外部调用恰好一次。世界仍由原队列、租约和尝试额度恢复，调用统计与运行日志关联但不重复扣额度。

### 4. 可发现的 Tool 是注册能力，不是任意函数

定义受信任工具包协议：稳定 ID、说明、版本、参数/结果 schema、所需权限、资源类型、只读性、并发安全性、超时/取消语义、输出上限和成本类别；处理函数来自部署时固定的受信任 Python 包。启动时扫描受信任工具目录的声明，校验依赖与重名，建立注册表；未授权工具对模型不可见，猜测名称也不能调用。工具的新增发现无需编辑中央 `if/elif`，但包部署、启用和权限授予仍由开发者/管理员控制。元数据不能代替执行时授权；首版继续顺序执行工具，不因声明并发安全就增加并行调度器。

统一执行顺序为参数/身份/权限/取消及单次操作边界检查、前置 Hook、对变更参数重新验证及授权、执行、结果检查、后置 Hook 与结束记录。前置检查拒绝时记录未执行，实际进入执行的调用在成功、失败、超时或取消时均有可关联的结束状态。返回结果包含调用 ID、安全错误类别及可恢复性；无匹配、扫描截断、文件变化和未授权不能混为“没有资料”。可恢复问题反馈给 Agent 调整行动，取消或不可恢复的运行故障则结束，不能将取消转成普通工具错误继续调用。

超时与取消语义须说明底层操作是否支持协作停止；停止等待不等于线程或外部请求已被强制终止。不能丢弃实际用量或把迟到结果交付为成功。结果必须受 schema 和规模约束，需截断的搜索等工具明确返回部分结果状态，不静默截断结构化对象或必需指导。按职责复用工具入口：多个 Skill 共用 `skill`，管理员授权的 CLI 共用 `exec`；知识检索、源码读取及 Agent 委派仍保持各自契约。不为每个程序或子命令增加模型工具，也不把所有业务合并成一个可任意调用内部函数的万能入口。

首批工具：

| Tool | 行为 | 约束 |
| --- | --- | --- |
| `knowledge.search` | 复用 BM25/向量融合和重排，返回证据片段 | 查询、返回数量、提供方调用和受众有界；保留 BM25 回退 |
| `exec` | 以程序别名和参数数组调用授权 CLI，CodeGraph 为首个接入 | 管理员绑定程序、允许操作及工作目录；统一 Hook/取消；源码结果保留过滤和证据登记，不接受任意 Shell |
| `source.search` | CodeGraph 不可用、漏检或不适用时，在仓库源码中做有界词面/路径搜索 | 统一敏感排除，字面量搜索，无任意正则计算或 Shell 拼接 |
| `source.read` | 补读、核验或回退时按行读取仓库源码 | 仓库相对路径 + 行区间；返回内容 hash 和行号，不由模型选择根目录；不强制重复读取已取得的同版本证据 |
| `skill` | 按技能名加载指导，按技能名和可选资源路径读取引用资料 | 技能目录自动注入系统提示词；仅访问授权包，无逐技能入口或任意文件跳转 |
| `agent.list` / `agent.invoke` | 发现、委派业务 Agent | 参数校验、权限取交集、共享用量/取消及祖先检查 |

所有模型请求的外部能力通过此执行器，不允许业务 Agent 自行绕过 Tool 调知识库或读文件。普通业务代码也可直接调用同一工具入口，仍使用相同鉴权、用量观测、取消和结果契约；不必为了复用工具先调用模型。现有纯计算函数、持久提交和回调投递不是模型工具，不为“全部工具化”暴露内部运维函数。`knowledge.search` 复用当前算法和客户端，缓存键、内容过滤和诊断隔离受众/授权范围；不能在过滤前把越权候选送去远程重排。

加载 Python 插件是部署可信代码的一部分，不等于向模型提供代码执行工具。模型、玩家输入、Skill 不能指定动态 import 路径；不从运行数据目录、网络或聊天附件安装插件。首版注册表在启动时构建，新增部署后重启生效，不做未审计热安装。

#### 统一 CLI 调用与 CodeGraph 接入

复用现有 Tool 注册和执行器，仅提供一个 `exec(program, args)` 模型入口，替代原 `codegraph.explore`，不并列发布两个入口。`program` 是管理员配置的程序别名，`args` 是参数数组，不是 Shell 命令字符串。例如 `exec(program="codegraph", args=["explore", "query_skill"])` 和 `exec(program="codegraph", args=["callers", "query_skill"])` 使用同一工具。统一的是 CLI 调用，不是取消各能力的资料处理和结果契约；不接入 MCP、不新增执行框架或 Shell 语法解析器。

可信部署配置绑定程序入口、允许的操作、工作目录及简要用法，按有效权限向模型发布可用程序和操作说明，不增加单独的命令列举工具；详细用法可放在已有业务 Skill 中。模型根据任务自主选择已授权的程序和参数，不能指定任意可执行路径、另一个工作目录或新授权。发现、配置启用及 Skill 加载均不自动授予调用权。参数中影响仓库、访问目标或输出位置的选项仍须符合绑定范围，不能只检查程序名就允许绕过边界。

执行复用现有参数校验、工具授权、前后置 Hook、取消、单次故障超时和输出处理；Hook 改写参数后重新校验，调用前拒绝不启动程序。Hook 不替代操作系统隔离，也不负责解析并证明任意 Shell 脚本安全；本入口不接受模型编写的脚本、管道、重定向或命令拼接，不提供文件修改或游戏数值修改能力。取消和故障处理须准确报告进程结果，不将仅停止等待描述为外部程序已停止。

CodeGraph 作为首个适配，仓库仍绑定 `SOURCE_ROOT`，源码全局关闭或缺少调用授权时不能经 `exec` 读取。接入管理员允许的 `explore`、`query`、`callers`、`callees`、`impact`、`node`、`files` 查询，不为这些操作逐个增加 Tool；模型按问题选择操作，不规定固定调查顺序。`explore` 必须实际调用 CodeGraph 的 `explore`，不能继续用 `context` 包装冒充；符号关系和影响范围仍只是调查线索。原适配器及评测调用过的 `context` 与新入口分别记录，不混算效果。

支持正常 npm/pnpm Windows 安装提供的 `codegraph.cmd`，包括从 PATH 解析的入口及管理员显式配置的路径；原生可执行文件或可信 JSON argv 配置仍可用，不要求部署者寻找安装包内部的 Node/JS 文件。启动适配负责把查询完整作为参数传递，空格、中文及 Shell 元字符不得改变操作或执行额外命令；支持批处理启动器不等于给模型 Shell 权限，也不能仅凭 `shell=False` 宣称参数安全。用实际 Windows 安装验证查询、超时和取消，Linux 原入口及缺工具回退保持。

可用时优先用 CodeGraph 定位符号及调用关系；工具或索引不可用、查询漏检、中文字面量或未支持语法不适合索引定位时，允许模型改用 `source.search` / `source.read`，不强制反复尝试 CodeGraph，也不以无结果证明代码不存在。服务只调用授权接口，不干预工具自身的缓存维护等内部行为，不要求查询期间索引文件零写入，也不为此增加拦截或接管机制。显式建库、同步及配置变更由部署或隔离测试准备完成，不向模型暴露这些索引管理操作；“只读”约束模型可用能力及源码访问，不限制工具内部自维护。

统一调用层不解释 LPC 或业务规则，CodeGraph 的结果处理保留在其内部适配中：返回前过滤路径、符号和关系两端，源码正文复用现有安全读取和证据登记。CLI 输出的原文、统计和错误不能未经筛选直接送入模型，也不能因命令成功就成为已验证证据。同一次 `exec` 可返回必要当前源码、行号、hash 及证据关联，不要求模型为同一片段再调用一次 `source.read`。索引过期时不能按旧行号把其他内容标成目标符号，须核对定位或回退；提交前版本复查保持不变。一般 CLI 的调用配置与特殊结果适配分开，不要求为没有业务适配需求的程序复制一套模型工具。

CodeGraph 不是完整 LPC 语义分析器。实施时验证 `.c` / `.lpc` 的实际收录、扩展名配置、同名函数及继承/动态调用局限；即使将 `.lpc` 映射到 C 解析器，也不能宣称已支持全部 LPC 语法或可靠解析所有调用目标。关系帮助定位，确定规则仍以当前原文及模型分析为依据。

### 5. 单仓库源码读取与外发边界

初版只保留一个可信配置的仓库根目录和一个全局开关：`SOURCE_ENABLED` 默认启用，`SOURCE_ROOT` 默认指向服务目录 `ai/` 的父目录，即本项目仓库根目录；相对路径始终以服务目录解析，不随启动 cwd 变化。其他 MUD 可覆盖根目录，只有文档问答需求时可显式关闭。不要求部署者编写 scope、逐目录白名单或逐 Agent/角色的源码授权清单；旧 scope 配置须给出迁移说明，不保留两套并行权限矩阵或静默忽略旧配置。

默认可调查整个仓库的源码，包括跨 `kungfu/skill/`、授艺 NPC、公共检查、头文件及框架的依赖，而非仅预选几个目录。读取能力不等于整库加载：模型按问题搜索和读取必要片段，经现有统一模型边界发送给当前配置的 Qwen，不上传整个仓库，不增加任意外部地址。工具声明和调用仍走统一执行器，源码全局关闭时不能通过委派或 Skill 重新打开；知识库范围、会话隔离、主 Agent 入口开关及业务提交规则不变。

源码搜索和读取只接收仓库相对路径、查询及行区间，根目录由可信配置提供，玩家、模型或 Hook 不得覆盖。玩家和管理员使用相同的源码文件边界，区别仅在结果呈现：管理员诊断可查看证据位置，玩家回答保持游戏语境。需要保密的资料统一排除，不建立“管理员可读、玩家不可读”的另一套源码目录矩阵；普通源码不因属于管理命令目录而整目录禁读。

访问校验必须同时覆盖搜索枚举和读内容：规范化并验证根路径归属，拒绝绝对路径、父目录穿越、UNC/设备路径、Windows ADS、二进制文件、符号链接/目录联接/reparse point 越界及文件替换竞争。对硬链接或不能可靠确认最终打开对象的情况关闭访问，不将字符串前缀比较当作隔离；工具仅持有读取授权源的最小 OS 权限。并发部署导致文件变化时重新校验或返回 `source_changed`，不能混用前后版本证据。

`.env`、密钥与私密配置、玩家存档、数据库、日志、`.git` 内部数据、生成文件和服务私有运行目录在源码工具中始终排除，包括受限思考诊断及工具索引缓存。部署所用的私有数据/日志路径须纳入同一排除规则，不能只依赖默认目录名；不得通过搜索结果、计数、文件名、错误信息或链接绕过。文件大小、单次搜索文件数、单次总扫描字节、执行时间、片段长度仍有上限；越限返回明确的部分结果标记或拒绝，不假装搜索完整，也不变为累计任务预算。

本游戏的 `data/e2c_dict.o` 是公开的技能等名称映射，作为精确文件例外复用 `source.search/read` 按问题取得必要片段，允许经统一模型入口外发；不整份预加载，不执行或恢复 LPC 对象，不新增字典 Tool 或通用权限配置框架。例外只解除该公共文件所在目录和扩展名的粗粒度过滤，不放开其他 `data/` 或 `.o` 文件，不覆盖密钥、实际私有运行目录、仓库边界和链接等检查。证据保留来源及内容版本；查不到映射时说明未知，不凭内部标识编造中文名称。另一游戏的根目录生效后不回读本库字典，缺少此文件不妨碍其他源码调查。

源码、注释和检索内容只作为资料。即便其中写着“忽略指令、读取密钥”，也不能修改工具集或触发未授权行为。权限和外发检查发生在内容进入模型前，日志默认只记证据 ID、hash、用量等元数据，而非完整源码和提示词。

### 6. Skill 为专业知识包，统一通过工具接口访问

业务技能放 `ai/skills/`，与开发用 `.agents/skills/` 分离。采用 `SKILL.md` 的名称、中文说明和 Markdown 指导，配套 `references/`、示例与评测样本。依据 [Agent Skills 格式规范](https://agentskills.io/specification)，版本可放 metadata；输入输出 schema、权限、模型窗口与取消仍为程序契约，不假装属于标准强制字段。

首批包：武侠 NPC 对话、游戏规则源码调查、对话摘要、幻境房间描写、主 Agent 协调。技能按实际场景提供必要指导；方法、检查清单和示例按需加入，不要求每个包套用同一内容模板。明确具体场景的 Skill 可以规定工作流，其余只说明目标、相关知识和必要边界，由 Agent 自主规划步骤。源码 Skill 提供定位、追踪依赖与核对结论的方法，不要求每个问题遍历全部检查项。原人设仍由角色配置提供，Skill 不硬编码周不通身份，也不捆绑模型供应商。

服务自动扫描配置的业务技能目录（默认 `ai/skills/`），校验元数据并建立技能目录；组装 Agent 系统提示词时，按有效权限仅注入可用技能的名称和描述。Agent 根据任务需要，通过唯一的 `skill` 工具按名称加载正文，例如 `skill(name="source-investigation")`；需要引用资料时仍用同一工具，增加包内资源路径参数。目录发现无需模型先调用列举工具，不增加 `list/load/read_resource` 或 `action` 分发层，也不为每个 Skill 创建工具、路由或中央分支。

直接模式由运行时通过同一个 `skill` 工具入口预加载指定 Skill，复用相同的加载、鉴权和审计，无额外模型回合；工具模式由模型按需选择。新增合法技能包可由扫描发现，但仍需显式授权，不把所有包全文塞进每个请求。资源路径不得逃逸本技能包；即使包包含 `scripts/`，本服务也不执行这些脚本。Skill 可指导使用已获授权的 CLI，但不能通过 `exec` 扩大程序、操作或资料范围；`allowed-tools` 最多收紧已有范围，绝不构成授权。

技能目录、`skill` 工具可见性及实际加载使用同一有效授权视图；禁止工具时不能仍提示模型调用它，直接预加载也不得绕过该限制。技能正文及被要求完整加载的指导资源不能静默截断后标为加载成功；超限须明确拒绝，维护者将大篇资料拆为按需引用文件。目录摘要与按范围读取的普通参考资料不冒充完整指导。

一次运行固定注册表与技能版本，记录内容 hash、实际加载资源和模型配置；发现必需 Skill 缺失/损坏时拒绝该能力或走已有明确离线回退，不悄悄启用另一套硬编码专业提示词。运行时保留短的角色层级/安全协议和结构适配代码；上下文压缩的内部提示词单独维护，不作为业务 Skill 发布。

Skill 负责“专业方法与资料”，Agent 负责“执行专业任务”。`skill(name, path?)` 始终是唯一的业务指导/资源加载工具，不暗中启动模型或嵌套工具循环；需要隔离专业过程时由 `agent.invoke` 调用已注册的业务 Agent，后者通过相同 `skill` 入口加载指导并复用 Runner 执行。这样保留专业模型和工具循环的封装收益，不建立另一套 Skill 模型客户端、权限通道或用量计数，也不要求主 Agent 先加载子任务的全部技能材料。compact 不属于业务技能：运行时直接加载内部提示词并按第 3 节执行，不依赖模型主动调用技能。

迁移世界描写时先保持当前指导语义及内容键，不借架构升级重生成旧文案。专业样例扩充与质量提升另做对照评测：事实/结构正确率与文风评分分开，允许合理补白。新增相邻正文上下文要显式记录所用证据，不能读其他玩家私有状态。

### 7. 源码问答的证据链与呈现

问答首先服务 MUD 体验，允许不影响正确结论的题外展开、角色发挥、联想和建议，不以严格短答或毫无发散为目标。核心问题得到准确、有必要证据支持的回答，且补充内容不歪曲规则或误导玩家，即可通过；篇幅、联想或额外调查本身不是否决理由，耗时与调用数单独观测。创作和建议不冒充确定的玩法事实，错误门槛、扣费、虚构奖励或“局部条件满足即必然成功”等实质误导仍须判为失败。

确实缺少资料时，允许模型结合现有信息给出明确标注为推测或假设的解释，并说明哪些尚未核实；不要求一律拒答。已核实规则与推断须能被玩家区分，不能只在开头加一句“可能”却把后文未知数值当作确定门槛，也不能以标注推测掩盖与现有证据矛盾的结论。是否完成仍取决于原问题：附带推测不会自动补齐缺失的决定性证据或玩家实时状态。复用现有答案段落、未决事项和终态，不新增置信度字段、推断分类框架或审稿模型。

问答 Agent 将问题转为可验证的调查目标：武功/绝招实体、学习/解锁/施展/消耗类别、要回答的条件及数字。通过工具发现相关入口，沿函数调用、继承、头文件常量、配置及授艺 NPC 继续调查，维护待查依赖和证据；发现冲突、间接调用或搜索截断时补查，不能把一个片段当作完整结论。优先使用已配置可用的 CodeGraph，词面搜索与按行读取作为兜底和必要补查；不自建完整 LPC 分析平台，不执行或编译源码，也不规定每题必须复现同一工具顺序。

完成检查围绕原问题：目标主体、动作及入口匹配，影响所问结论的关键条件和依赖已查明，逐条确定结论关联已读证据，没有影响确定结论的未决问题。依赖、门槛、扣除、替代路径及冲突按与问题的相关性核查，不要求每个任务填满固定五类调查表，也不为不相关类别补写占位结论。精简的是内部填表要求，不是调查深度或正确性标准。以缠字诀为例，`perform()` 的技能和内力检查只能证明施展条件；若问学习条件，Agent 必须继续寻找传授/解锁逻辑。“内力至少 60”与“扣除 30”须分别回答。验证发现仍可补查的缺口时继续调查；真正无法取得资料时可按上述边界提供明确标注的推断，不用推测代替已有可行的查证。

每个确定结论关联证据记录：配置仓库身份、相对路径、行号区间、文件内容 hash、读取时刻；有可信部署 revision 时附上，没有则说明只代表当前源码快照。仓库身份可复用现有内部来源标识，不要求模型选择 scope 或部署者维护多范围配置。目录索引只是定位线索，回答以安全读取的当前文件为据；`exec` 的 CodeGraph 适配中已完成读取并登记的原文可直接复用，不要求模型重复读取，提交前仍复查版本。工作区源码不一定等于驱动已加载的版本。依赖仍在授权范围且有可行路径时继续追踪；实际不可访问、材料确实缺失、需要玩家澄清/实时状态、取消或不可恢复故障才返回对应状态，不把假设数值写成已核实规则。compact 后引用继续关联原始授权记录，不把摘要或推断当作新的源码证据。专用规则查询工具可后续提高效率，但不是源码调查的前提，更不能要求手写每个问题的答案。

内部完成契约保留主体/动作、入口、逐条结论与证据和未决事项；不再强制固定五类调查记录。程序继续校验本次原始授权读取、引用范围、文件版本及已知未决事项，并在业务提交前复查证据；结构合格、引用存在或模型自行填写“已检查”均不能证明语义正确。Agent 负责基于源码核查结论，实际效果按固定题的原质量标准验收，不新增审稿模型、执行框架或源码执行能力。取消、权限和业务提交保障保持不变。

NPC 与主 Agent 的规则答案采用单份内容：模型只生成带证据关联的玩家可读段落，不再分别撰写内部 `claims` 与玩家 `answer`。业务适配层按原顺序拼接玩家正文，并从同一段落提取受审查结论；仅隐藏证据元数据，不另行改写、概括或补充事实。角色描写、联想和建议可以保留，确定规则仍须关联证据，不能借角色表达省略关键条件或混入无依据的玩法承诺。这样消除两份答案重复生成造成的遗漏与矛盾，但不把同源或格式合格当作语义正确的证明。

该调整复用现有 JSON Object、完成验证及业务提交，不改变 socket 响应格式，也不增加模型调用、Tool 或执行器。主体/动作、入口及未决事项继续保留；已有成果引用仍由可信交付层解析原成果，不要求主 Agent 重写正文。NPC、主 Agent、玩家呈现及管理诊断同步适配，原条件、数值、证据、缺依赖和真实模型质量验收标准不变。

管理员诊断显示源码位置，玩家仍得到符合 NPC 身份的中文解答和游戏内条件，不显示路径、数据库或工具调用细节。敏感资料对两类请求统一在读入模型前排除，不能只靠最终隐藏引用；知识库原有受众过滤保持独立，不因源码范围简化而放宽。

保留至少 20 个固定问题的效果评测集，覆盖跨文件门派贡献、宏/继承、授艺与施展分离、多种学习路径、阈值与扣除、旧文档冲突、同名技能、无命中后的改查及确实不可完成的情况。完整质量验收仍要求每题有人工核对的预期结论、必要证据和终态，所有可回答核心题的条件/数值及证据正确，不可以“谨慎拒答”刷通过率；解释与细节齐全属于后续效果优化，不再作为本轮能力交付的统一门槛。假模型验证循环与权限，真实模型在用户授权范围内验证自主定位和回答，二者不能互相替代。分开报告正确率、完成率、无依据结论、延迟、调用数、累计用量及每个成功任务的估算费用；代表题只证明实际覆盖的能力，中断批次不冒充全题验收。有限题集用于控制测试范围，不另设固定模型总调用数截断正常调查；用户显式指定的测试消费边界仍须遵守。

### 8. Hook 可观测与干预，但不是安全隔离替代品

Hook 是固定注册的可信回调，由程序在边界自动触发，不是模型工具，也不单独建设插件引擎。事件覆盖 `run_start`、`before/after_model`、`before/after_tool`、`before_commit`、`run_end`、`run_error`，直接、委派和兼容包装路径一致覆盖。委派就是一种工具调用并携带父子运行 ID，不再另设委派专属生命周期；向量/重排请求产生模型边界事件并附 operation 类别。

实际进入模型或工具执行的调用，无论成功、失败、超时或取消，都必须发出一次关联的后置事件；操作状态与 Hook 干预结果分别记录，避免后置拒绝抹掉已发生的执行或用量。前置拒绝记录未执行的原因，不伪造实际执行或收费。`run_error` 用于错误诊断，`run_end` 是每次运行唯一的最终结束记录，携带最终状态；终态观测故障不得再次结束运行或改写已经确定的业务提交结果。

| Hook 类别 | 能力 | 失败处理 |
| --- | --- | --- |
| 观测回调 | 观察脱敏事件、指标、延迟、用量；不改上下文 | 隔离失败并计数，不能拖垮业务或递归触发自己 |
| 干预回调 | 允许/拒绝/取消，或修改声明允许的上下文字段 | 必需干预超时/异常即停止；修改后重新走 schema、大小、外发和权限检查 |

首版干预按事件限定，不提供任意状态对象改写接口：

| 事件 | 允许的干预 |
| --- | --- |
| `run_start` | 允许、拒绝或取消本次运行 |
| `before_model` | 允许、拒绝、取消或追加有界且通过外发检查的上下文；不得替换整份消息历史或系统安全协议 |
| `before_tool` | 允许、拒绝、取消或修改该工具契约允许的参数，修改后重新校验 |
| `after_model` / `after_tool` | 观察执行状态，拒绝继续使用结果或取消；不得覆盖模型原始响应、工具事实、证据及用量 |
| `before_commit` | 允许、拒绝或取消提交；不改写业务结果、证据或持久化目标 |
| `run_error` / `run_end` | 仅观测最终事实，不干预、重试或触发提交 |

同一事件按固定注册顺序处理，拒绝和取消优先于允许，不采用最后完成的回调覆盖前面决定的规则。输出格式转换及完成条件验证保留在明确的业务适配/验证器内，不通过通用 Hook 偷换答案；验证可补查的缺口仍返回 Agent 循环，不用新增 Hook Agent 替代它。

不可变字段包括身份、受众、权限上界、用量账本、关联 ID、模型容量与取消状态；Hook 不得扩权、清零用量、改大窗口或复活失效任务。单次操作故障期限也不能由 Hook 延长。处理顺序为基础校验/授权、受限 Hook、最终不可绕过的校验与授权，再执行操作。compact 不是 Hook 的任意历史替换权限：由专门的运行时步骤执行，经统一模型事件观测，记录压缩前后容量及结果，摘要不得替换可信账本或证据。模型后置拒绝不代表此前调用没有计费；`after_tool` 不能撤销已经发生的动作，所以危险副作用必须在调用前禁止。

Hook 不接收原始 SDK 客户端、数据库连接或完整密钥配置，只接收按目的最小化的数据。原始资料检查若确有必要，由明确授权的本地干预回调执行，普通观测端仍只拿脱敏元数据。提供方返回的思考内容允许进入下述显式开启的受限诊断，不因注册普通观测 Hook 就自动暴露。可信 Python 回调具有宿主进程能力，不能声称能安全容纳恶意第三方代码；部署审查和 OS 权限是另一层边界。

#### 开发与测试的思考诊断

通过可信本地配置或诊断命令显式开启思考记录，默认普通运行日志仍只有脱敏元数据；不接受玩家载荷、Skill 或模型输出开启记录、选择文件或获取记录。复用现有模型边界及诊断关联，按请求/父子运行/模型调用标识记录提供方实际返回的字段，关联模型参数指纹、Skill 版本、工具步骤、完成检查和最终结果。没有返回的内容标为不可用，不补造；记录可写入独立的受限本地文件，也可在明确启用的开发终端显示，不通过游戏通信回传，不新增工具、Skill、执行器或通用日志平台。

思考内容可能复述已授权源码或会话资料，因此按敏感运行数据管理：日志目录由部署 OS 权限保护，不放入公共网页、源码工具授权范围或源码提交；记录不转储 API 密钥、完整配置、原始 SDK 对象或异常正文。普通 Hook/日志仅得到元数据，专用诊断输出不广播给普通观察者；业务历史、成果引用及成功响应缓存仍只保存其原有业务契约内容。诊断写入故障按既有观测故障处理，留下安全错误提示，不改写业务结果、不为重建日志重跑收费请求。

开发者可据记录分析定位是否正确、工具结果是否被误读、提示是否干扰及上下文是否丢失，但思考不是可靠事实证据；最终结论仍对照原源码、标准答案和实际终态验收。不仅凭一次思考轨迹就断言质量问题已归因或修复，也不声称提供方返回字段等于其全部内部计算过程。

### 9. 数据提交与兼容迁移

“不提供写工具”不等于服务不能正常保存历史或生成正文。Agent 只产生结构化业务结果；经过输出验证、Hook 和会话/任务身份复核后，由现有业务层提交。模型不能选择数据库表、任意路径、发布目标或修改计数。

模型完成生成只是候选结果就绪，不是业务运行已成功。无需持久化的能力在完成验证后结束；需要提交的能力依次完成候选验证、`before_commit`、最终身份/调用方有效性/取消检查及可信业务提交，具有业务租约的任务另核验租约，提交结果确定后才记录 `run_end`。提交失败不得提前或补发 `completed`；成功提交后的观测故障不得回滚成功语义或再次提交。运行时提供统一边界，事务及世界发布仍由现有业务适配层负责，不把数据库实现导入通用 Runner，也不新增事务框架。

NPC 的历史、关系和去重仍在一个事务内提交；世界仍先落库再原子发布，来源元数据可添加 Agent/Skill/policy/trace 引用，不更改既有内容身份。不引入新运行库；确需添加的兼容字段必须可备份、可回退，旧库不删除、旧成功内容不重做。调查过程和未完成输出不冒充成功对话、不推进关系；澄清/部分结果由适配层以游戏语境反馈，不写入成功记录。

主 Agent 不绕过业务前置条件：世界开关关闭、世界/坐标非法、调用者无创作授权时，即使知道 `world_narration` 的名字也不能生成或发布。通过委派进入 NPC 业务同样不能无授权读取历史或推进其他会话关系。展示回调和提交职责不重复执行。

#### 已验证成果的引用交付

短结果可直接按契约返回；无需把每段文本都改成引用。较大或需要原样交付的成果，由可信运行时保留结果并生成不可由模型任意指定的 `result_ref`，子任务向主 Agent 返回有界摘要及引用。引用不是文件路径、任意下载地址或访问权限。首期仅使用请求内有界结果表；已持久的世界成果仍由原业务任务/内容标识关联，不新增通用成果数据库或跨重启 Agent 工作流。

主 Agent 可以在最终候选结果中选择本根请求下已授权的成果引用，由可信交付层解析原成果，无须让模型重新输出整篇正文。解析时核对根请求、会话/受众、有效权限、成果来源、内容完整性及业务完成状态；伪造、跨请求、失效或未完成引用不得交付。需要持久化的成果必须先完成其业务提交；世界受理凭据不是已完成正文。对多个成果的拼接或重新总结仍须检查是否覆盖整体目标，不能因子任务成功而直接宣布父目标完成。

引用交付不绕过输出 schema、大小上限、玩家表达、证据权限、取消及最终提交检查；不得用截断 JSON 或直接暴露内部引用处理超限。无需改写的原成果保持内容不变，必要的玩家/管理员视图转换仍由业务适配层完成。引用解析只取已存在结果，不再次生成或重复业务提交；持久成功请求缓存保存可重放的最终响应或既有业务凭据，不缓存只能在本次运行内解析的悬空引用。

### 10. 文件组织与验收重点

新增 `ai/src/runtime/`（定义/注册、任务循环、上下文/compact/用量、权限、Skill 加载及简易 Hook）、`ai/src/agents/`（业务 Agent 装配）、`ai/src/tools/`（共享工具）、`ai/skills/` 及中文样例配置。模型适配继续集中在 `ai/src/llm.py`。保留现有 `npc/`、`world/` 的业务状态归属和 `knowledge_*` 实现，不为目录美观批量移动源码或数据。只根据职责拆文件，不预设庞大类层次。

测试分三类：离线合约/安全测试、真实 FluffOS/UDP 假模型回归、单独授权的真实效果测试。安全样本必须覆盖恶意工具参数、资料提示注入、跨会话委派、路径绕过、Hook 扩权、同名插件、Skill 缺失、重复无进展反馈和提交前取消。补齐工具失败/取消的结束记录、前置拒绝未执行、Hook 改写后重验、技能目录与工具权限一致、指导不完整拒绝、提交失败不报成功及终态只记录一次的时序测试。源码问答用固定 LPC 多文件夹具精确核对门派贡献等数字，文风另行审读，不能让模型评审代替确定性权限测试。

委派验收检查实际发送给父、子模型的消息：大量子任务资料和工具过程不得自动出现在父后续上下文中，而必要条件、证据引用与阻碍仍完整可用。覆盖重复无进展反馈后调整策略、跨越旧调用/时长阈值仍继续、成果原样交付、伪造/跨请求/未提交引用拒绝，以及引用重放不重新生成。使用缩小的测试窗口验证 80% 阈值前/边界/之后、输出预留、工具与 Hook 开销、压缩失败原上下文保留、工具成对及父子不同容量；不必真实消费 80 万 token 才能验证机制。长任务测试覆盖续约、丢包、离线/取消、服务停止及迟到响应。成本对照记录主/子/压缩输入输出用量、上下文峰值、模型配置、延迟和质量；只有同等任务与完成质量下的数据才用于判断收益，假模型测试不冒充真实效果评测。

#### 分阶段验收与交付

- **本轮能力验收**：确认直接调用、按需委派、Tool/Skill/Hook、上下文续行及业务提交等实际链路可用，相关回归通过，并保留授权真实模型的代表性任务记录。只得到合法 JSON、工具启动成功或假模型通过，不足以证明自主调查能力；也不要求每个样本都穷尽所有补充解释。
- **后续效果优化**：保留完整固定题、同条件检索/路由对照及质量标准。核心结论准确、证据真实且不误导时，解释遗漏、非关键细节或表达不足可登记后续优化，不阻塞已验证能力的交付；这不把未通过的完整质量题改写成通过，也不把局部结果推算为整体准确率。
- **实质缺陷与安全边界**：错误数值、错误规则、遗漏会改变结论的关键条件、把未知说成确定或误导性承诺，仍记为缺陷，不能归入普通细节遗漏。权限、证据真实性与版本、取消、提交和隔离的失败仍阻塞对应能力验收；规划分阶段不改变运行时的完成契约，不用降低校验或增加逐题规则制造通过。
- **实服与状态记录**：隔离回归、代表性真实链路、完整效果评测和实际游戏验收分别记录。保留原报告及缺陷，任务按证据拆分；能力交付不自动开放玩家入口，不以隔离测试替代维护者的游戏记录，也不因阶段交付将尚未完成的质量任务全部勾选或归档。

### 11. 新功能的统一接入规范

实施时新增 `docs/architecture/ai-service.md`（长期架构与扩展指南），在根 `AGENTS.md`、`ai/README.md` 和业务文档链接；本变更的规范先作为实施合同，验收后同步正式 OpenSpec，不把尚未实现的目标写成当前能力。

每项新增 AI 功能交付七项内容：Agent 定义与目标/完成条件；业务输入输出和状态归属；工具及授权范围；中文 Skill 与样例；模型容量环境变量、compact、用量与故障/取消策略；直接/委派接入与受信任提交；离线测试、效果样本及运维说明。扩展复用统一模型和工具执行入口，不另建 SDK 客户端、权限分支或数据写入工具。以一个临时测试能力验证注册和扩展，无须新增实际游戏玩法。

新工具以受信任模块声明被启动注册表发现，新增 Skill 以包元数据被发现；部署启用和授予权限仍显式。业务模块在 `main.py` 装配并选择独立容量；注册的变化是正常接入，不要求为了“零改动”而扫描任意代码。架构验收检查现有全部业务入口也遵循这些规则，不能只给新例子接上运行时而遗留旧实现旁路。

### 12. 独立服务与 MUDLIB 的依赖边界

socket 带来进程和通信分离，可移植性还取决于服务是否依赖某个游戏的业务结构。目标是其他 MUD 按公开协议、配置和必要的业务适配接入，不承诺所有特色玩法无需适配即可复制运行；不要求对方使用本库、FluffOS、LPC 或 mudcore。

优先使用已有配置解决部署差异：`HELP_DIR`、`NPC_ROLES_FILE`、`DATA_DIR`、`WORLD_CONTENT_DIR` 等继续可配置；源码另用 `SOURCE_ROOT` 指定单一仓库，`SOURCE_ENABLED` 可显式关闭。保留本项目便捷默认值完全合理，不为每个目录建立接口或插件；要求是显式配置后不再隐式回读本库路径，关闭的能力不强制要求其目录存在。LPC 专业知识、中文武侠文风和 NPC 角色属于可替换的业务 Skill/配置，不写进通用运行时。

`ai/.env.example` 只列常用连接、模型及容量、服务接入和主要能力开关，按实际使用分组并用中文简要说明；高级检索、缓存、诊断、费用与并发调优移到使用文档按需查阅。不为缩短示例删除现有配置能力、改变默认行为或覆盖部署者的 `.env`；省略项由现有 `Settings` 默认值处理，进程环境优先级与服务目录相对路径规则保持。模型、上下文窗口与最大输出容量的联动说明必须保留，不能因精简而让换模型时继续误用旧容量。以清洁环境对比完整默认配置与精简示例的有效值，并验证显式覆盖。

依赖方向为装配入口选择业务模块，业务模块使用通用运行时/工具，socket 层只负责报文和路由契约；运行时、通用模型适配及基础工具不能反向导入 NPC、无限世界或游戏实现。现有本机 UDP 和旧字段保持兼容，不为解耦新增传输协议或笼统仓储框架。每个部署首期服务一个游戏，多游戏使用独立进程、端口、策略和数据目录，不宣称已有多租户隔离或远程认证。

游戏端负责在线对象、玩法规则、权限及数值变更；服务负责授权资料调查、AI 生成和服务自身的历史/任务/结果保存。调用方提供的角色或玩家标识是业务数据，不是管理员认证。当前世界清单校验、内容身份及原子 JSON 发布留在可选的无限世界模块，明确其共享目录集成要求；这是可替换的结果交付方式，不是所有 Agent 的必需依赖，也不把它伪装成纯 socket 集成。

验收将 `ai/` 单独部署到没有本 MUDLIB 的临时目录，使用另一套角色、知识和数据配置，以及普通 Python socket 客户端完成假模型请求。分别验证显式配置另一游戏的源码根目录、关闭源码后仅使用文档问答，不隐式回读本库。禁用无限世界后不应访问其清单或发布目录；启用该模块时再单独验证已公开的文件和报文契约。用导入边界测试防止公共运行时反向依赖游戏业务，不要求先拆独立 Git 仓库或发布安装包。

## Risks / Trade-offs

- [首次检索就结束或遗漏条件] → 目标/待查项/证据驱动循环，验证未通过继续调查；用人工答案集检验正确性和完成率，不以“可能不准确”削减能力。
- [只读也能泄密] → 单一仓库边界与统一敏感排除在搜索/读取前生效，模型仅取得所需片段；玩家资料永不进入源码工具，知识库受众和会话隔离保持。
- [自动发现等同任意执行] → 仅受信任部署包、启动校验与显式启用；不支持模型指定 import、脚本执行或热安装。
- [统一 CLI 入口绕过既有边界] → 管理员绑定程序、操作及工作目录，完整参数在 Hook 前后校验；源码结果继续过滤并登记证据，不将程序名许可或 Hook 放行等同于宿主沙箱。
- [多轮变慢或重复消耗] → 明确请求不经主 Agent；无进展反馈、工具去重、按需压缩、完整用量观测及可用取消入口，以可靠完成任务的成本衡量，不以固定低次数中断正常调查。
- [上下文溢出或压缩丢失关键事实] → 按绑定模型的可配置窗口计量，80% compact 并预留输出，保留可信证据/任务状态和近期工具组；压缩失败原上下文不丢失，容量确实无法容纳时明确报告。
- [游戏先超时而服务继续付费] → 长任务在途状态与双向存活/取消契约同步迁移，短请求期限不充当任务总期限，失效后停止新操作并拒绝迟到提交。
- [Hook 故障或扩权] → 区分观察与策略故障，修改后重新验证，所有执行路径使用同一不可绕过的策略边界。
- [与无限世界未完成改动重叠] → 固定当前 M2 基线，服务架构迁移优先，停止并行编辑重叠文件；两个变更分别记验收。
- [工具名统一但数据串线] → Agent 独立上下文，委派传必要任务资料而非全历史，工具与结果缓存纳入授权范围。
- [结果压缩丢掉关键条件或把引用当授权] → 有界结果契约保留条件、证据和阻碍，引用解析重新核验归属、权限和完成状态，不以摘要简短代替可靠交付。
- [为隔离而过度拆任务] → 保留直接入口与单层委派，简单任务不新增模型回合，比较真实质量、延迟和总用量后再调优。

## Migration Plan

1. 以 `2f8192a5` 保存的 NPC/世界回归和协议为基线，使用临时数据副本验证迁移，不提交生成数据。实际部署前另行备份运行数据。首先实现共享运行时、模型适配及权限测试；正式向玩家开放仍需单独确认，主 Agent 入口保持默认关闭。
2. 迁移 Skill、知识检索 Tool 和独立业务 Agent，保留旧路由及数据接口；逐业务开关验证，直接路由的单次世界生成不得增加模型调用。
3. 将源码配置与工具接入简化为默认启用的单仓库模式，保留全局关闭、统一敏感排除和根目录覆盖；先以临时夹具验证跨目录依赖、搜索/读取排除及边界，再在已授权的当前仓库读取必要源码并向当前配置 Qwen 发送相关片段。补齐旧 scope 配置迁移和独立部署说明。固定题前后对照仍使用原源码快照，不将新增全仓库调查结果混入历史对照或据此改写缺依赖题的标准结论。
4. 先按修订合同移除通用任务硬预算、接入容量环境变量与 compact，并同步游戏端长任务等待/取消，再接入主 Agent 的委派、结果检查与继续决策。复用既有 Hook；全链路检查共享用量、取消、重传、压缩和故障。主 Agent 默认关闭，验收时单独开启；不改变无限世界公共入口、业务日额度或自动创作默认值。
5. 更新中文架构/接入/运行/安全文档、根 `AGENTS.md`、配置示例和游戏端协议说明；运行 Python、LPC/UDP、Linux/Windows 路径与启动器回归，以及无本 MUDLIB 的独立部署和替代游戏配置测试。在用户授权范围内用代表性任务验证真实模型自主调查及直接/委派链路，记录用量和费用；按第 10 节交付已验证能力，完整题集的效果优化另行跟进，不沿用历史小额调用次数作为任务截止条件。缺少真实链路或实服记录的项目各自保留未完成，不因能力交付宣称全部回答正确或正式开放。
6. 回退时停止新调用、等待在途请求结束或标记中断，禁用新 Agent 路由/源码全局开关并切回已验证的业务装配；保留旧数据库、正文和新增审计记录。不得同时启动两个共享业务库的写入方，不通过删库恢复运行。
7. 部署修正先验证精简配置与正常 Windows CodeGraph 入口，再接入公共名称字典和推断表达。含字典的评测另存版本，保留原题、原源码 hash 和旧模型报告，原缺依赖题不额外补齐被排除的实现；同配置检索对照使用同一个新快照，不把资料增加后的结果混作旧版等质提速。旧回答可按明确标注推断的新口径另记复核，不能改写其原文、隐藏已知错误或提前勾选质量通过。
8. 将 CodeGraph 的模型入口迁为统一 `exec`，同步工具授权、命令说明、源码 Skill 及配置迁移文档，不通过迁移自动放宽已有部署授权。先验证各获准查询、真实 `explore`、Windows `.cmd` 与 Linux 启动、Hook 拒绝和改写后重验、取消/超时、敏感排除及证据回查，再用同版本题集和相同模型参数与词面检索比较。保留旧 `context` 包装的报告并标明实际命令，不将其当作新入口或真正 `explore` 的验收；不因统一入口提前勾选质量或实服任务。
