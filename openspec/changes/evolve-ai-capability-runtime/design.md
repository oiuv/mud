# Design

## Context

动机与范围见 [proposal.md](proposal.md)。本设计以已提交的 `2f8192a5` 为迁移基线，包含无限世界 M2 阶段实现；这是目标架构，不是已完成功能说明。

| 已核对位置 | 现状 | 演进约束 |
| --- | --- | --- |
| `ai/main.py:create_server`、`src/udp_server.py:register` | 显式业务路由、独立线程容量、期限和去重关联 | 保留旧协议，不把所有请求先交给主 Agent |
| `src/npc/service.py:handle_chat` | 会话锁、摘要、历史、关系及成功请求原子提交 | Agent 推理不能重复推进关系或混入其他玩家记忆 |
| `src/npc/manager.py:generate_response` | 直接调用混合检索，源码内拼接人设提示词 | 迁为独立 Agent + 可复用检索 Tool + Skill |
| `src/knowledge_qwen.py:hybrid_search` | BM25/向量融合、重排降级，具备独立于 NPC 的基础实现 | 复用已有算法、索引及客户端生命周期，不重建知识库 |
| `src/llm.py:complete_chat` | 单次文本响应，没有 tool_calls 执行循环 | 扩展结构化模型响应，保留旧文本包装及截止期限 |
| `src/world/service.py`、`store.py` | 持久任务、独立 worker、调用计数、原子发布 | Agent 化不替换内容键、重做正文或额外调用主 Agent |
| `src/world/generator.py` | v2 提示词在源码内，只发送当前房间事实 | 先做专业指导外置，文案质量改进与架构迁移分开评测 |
| `kungfu/skill/taiji-jian/chan.c:perform` | 检查已解锁、战斗、武器、技能等级、激发、内力 | 单个施展文件不能证明学习条件或门派贡献要求 |

现有正式规范为 `ai-service-modules` 和 `ai-request-transport`。无限世界的增量规范仍在另一变更中；本变更只引用其保持性约束，不将其当作已归档主规范修改。

## Goals / Non-Goals

**Goals:**

- 所有业务 AI 服务以独立 Agent 定义注册，直接与委派入口共用执行、工具、技能和策略。
- 新增受信任工具/技能可通过规范包被发现，权限过滤后供模型使用，不增长中央业务分支。
- 源码问答按目标自主调查、追踪依赖和验证结论，以任务是否完成衡量能力，不退化为检索片段后生成答案。
- 将权限与预算置于模型之外，Hook 支持可审计的干预，任何嵌套路径不能提升权限或重置预算。
- 保留既有 NPC 和世界数据，支持逐项迁移、禁用及回退；自动测试不产生真实 API 消费。
- 服务可脱离本 MUDLIB 部署；路径和部署差异优先使用配置，通用执行层不依赖本游戏业务，可选模块承载真正不同的业务协议和语义。

**Non-Goals:**

- 不开放任意文件系统、Shell、代码执行、动态安装插件、网络浏览或游戏数值修改工具。
- 不实现自治 NPC 社会、自动发奖、新任务系统、无限世界新地形或自动改写已发布正文。
- 不先拆微服务、不引入 Redis/新向量库，不把重型 Agent SDK 设为前置条件；未来可替换运行时适配器。
- 不建立通用任务数据库、长期自治调度、插件市场、独立 Hook 插件框架或完整 LPC 静态分析平台；完整 Agent 循环属于必要基础，不在精简范围内。

## Decisions

### 1. 统一 Agent 定义，两种路由共享执行器

采用模块化单服务和一个共享执行器。Agent 是负责业务目标的独立定义，不等于独立进程，也不等于必须执行固定轮数。定义包括稳定 ID、说明、输入/输出契约、完成条件、Skill 绑定、工具权限引用、模型配置引用、执行模式和资源限制。运行时保管任务状态和执行工具，模型根据反馈选择行动。

```text
AI_CLIENT_D / Trusted CLI
          |
  Transport + Route Binding
          |
          +--> Direct Agent ------------------+
          |                                   |
          +--> Main Agent --------------------+--> Agent Runtime
                    |                                |
                    +--> agent.invoke --> Leaf Agent-+
                                                     |
                                      Skills + Tool Executor + Model Adapter
                                                     |
                                         Validated Business Result
                                                     |
                                           Trusted Domain Commit

              Policy / Budget / Hooks / Trace apply to every path
```

首批 Agent：`npc_dialogue`、`conversation_summary`、`world_narration`、`main_router`。NPC 角色仍为数据配置，不为每个 NPC 复制代码；源码调查是 NPC/规则问答使用的专业能力，不再额外套一个必经子 Agent。摘要作为内部 Agent 定义复用执行器，默认不向主 Agent 公开；仅接受所属会话提供的材料，不给主 Agent 全部玩家历史读取能力。

直接路由绑定 Agent ID 和权限配置，经过同一个 `AgentRunner`；主 Agent 通过 `agent.list`、`agent.invoke` 使用相同定义，不能另建业务实现或通过 UDP 回调本服务。两种入口都先经过业务适配层的验证、容量和提交契约，不能委派时绕开它们直接调用模型。`memory/config/world_status` 等确定性操作保留原查询入口，不为架构形式额外调用模型。

执行模式为 `single` 或 `tool_loop`，共用模型、Skill、策略、Hook 和结果验证。世界描写和摘要保持默认单次生成；NPC 问答和主 Agent 支持目标驱动循环。简单问题可直接完成，复杂问题继续使用工具；不得将轮数固定成一次检索加一次回答。直达 NPC Agent 同样具备完整多步能力，“直接路由”只表示不经主 Agent。

主 Agent 是协调目标的 Agent，不只是分类器：可选择业务、检查委派结果、根据缺口再次调用或请求澄清。首版顺序委派叶子 Agent，不引入递归 Agent 网络或并行讨论；这不限制叶子 Agent 内部持续查证。世界委派仍通过原持久任务受理入口，返回受理凭据时主 Agent 必须报告等待，不能把任务受理冒充文案完成，也不能抢占后台工作或重复发布。

对比：所有请求先经主 Agent 会增加延迟与路由失败面；只保留固定流水线则无法支持开放目标。本方案统一 Agent 抽象，不统一成同一种执行步骤。

#### 专业执行与上下文隔离

主 Agent 管“我要完成什么”，子 Agent 管“某个专业任务怎么完成”。主 Agent 负责整体目标、任务拆分、依赖协调和结果是否覆盖目标；专业 Agent 负责在授权范围内选择方法、加载 Skill、读取参考资料、使用工具及验证专业成果。采用“上下文隔离 + 专业任务封装 + 结果回传”，不将所有专业过程塞进主 Agent，也不要求主 Agent 重做子任务的完整调查。

简单任务直接处理，复杂任务按需要委派，不要求所有任务都经过子 Agent。这不仅指明确业务路由跳过主 Agent：已经进入主 Agent 的简单请求，也可由其使用自身已授权能力直接完成，子 Agent 调用次数为零。材料量较大、跨专业或需要独立调查/创作过程时，再将清晰的专业子目标委派出去；不以调用了工具或需要多轮处理为由强制拆分，不把主 Agent 限制为只能分发任务的路由器。

每次委派复用现有 Runner，创建独立消息历史和任务状态，只传入完成子目标必需的已授权事实与约束，不复制父运行全部历史。专业 Agent 使用声明的模型配置，并在自己的上下文中通过统一 `skill` 工具加载指导与参考资料，按 `single` 或 `tool_loop` 完成任务；模型选择仍受可信配置控制。一个 Agent 可使用多个 Skill，一个 Skill 也可由多个 Agent 复用，不为每个 Skill 编写执行器或强制创建子 Agent。

子任务只回传有界结果摘要、必要的业务结论、成果/证据引用、限制与未完成事项。技能正文、原始参考资料、检索列表、完整工具记录和中间草稿不自动追加到父消息历史；不索取、保存或回传模型私有思维链。结果契约必须保留影响结论的条件、数值、例外和阻碍，不能为了缩短上下文把不确定结果压成“成功”。主 Agent 需要进一步核查时，可按原授权补查必要资料或继续委派，而不是默认回灌全部过程。

上下文隔离不等于权限或成本隔离：子调用仍受父子权限交集、同一根预算、截止时间和取消状态约束，使用既有业务容量与提交入口。简单明确的任务继续直接执行；源码调查不额外套必经子 Agent，世界和摘要不因这项设计增加路由、审稿或专门压缩结果的模型调用。主、子 Agent 的实际模型用量分别记录并汇总；比较上下文规模、总调用用量、延迟与完成质量，不预先承诺固定节省比例。

### 2. 路由与可信调用身份

保留现有 `chat/memory/config/world_describe/world_status` 报文与回调字段；省略类型仍按现有聊天语义，未知类型继续报错，不成为主 Agent 的兜底输入。

新增显式、默认关闭的 `agent_run` 路由，用于有界主 Agent 请求；请求仅包含业务目标、相关公开情境和关联编号，不接受调用方自报 `admin`、权限、文件根路径或额外工具定义。目标不清时允许返回澄清问题，不能靠猜测越权执行。首期主 Agent 请求受公共响应期限约束，耗时更长的工作应另建持久业务任务，不延长同步通道冒充无限期执行。

`RunContext` 由可信适配层创建：调用来源、受众、会话范围、Agent ID、根运行/父运行 ID、策略版本、截止时间、共享预算及取消状态。旧本机 UDP 不是管理员身份认证机制：网络入口至多获得服务端配置的固定玩家级策略；不得凭 payload 字段升级。管理员源码诊断先走受本机操作系统权限保护的 CLI/内部入口，不新增未认证管理 UDP 路由。

最终有效权限取部署策略、入口策略、当前 Agent、父调用授权范围及 NPC 知识范围的交集。注册定义、Skill、模型和 Hook 都不能自行扩大交集。委派默认只允许主 Agent 调用叶子 Agent；遇到祖先环、深度/次数上限立即拒绝。单个玩家请求的资料、证据和上下文隔离，不把其他玩家记忆当作共享知识。

### 3. 结构化模型适配与运行预算

新增模型结果对象，区分文本、工具调用及调用 ID、停止原因、用量和错误；现有 `complete_chat()` 保留为只接受最终文本的兼容包装。模型工具能力通过提供方适配和配置声明，启动/离线契约测试检查；不支持时返回可诊断结果，不静默改模型或伪造工具执行。

每轮先合成授权工具定义，调用模型，严格解析参数与调用 ID，通过统一工具执行器取得结果，再继续或提交候选结果。初版顺序执行一批工具调用；每一个 Tool 完成独立鉴权。调用 ID 不能重复执行，非法/未知工具也消耗步骤；工具失败按可恢复/不可恢复返回，允许 Agent 换关键词、追踪另一入口或修正参数，不无限自我修复。

任务状态只保留目标、简短行动清单、已确认事实及证据 ID、未解决问题、工具结果和终态，不索取或保存模型私有思维链。模型根据观察更新待办，选择下一工具；运行时没有硬编码每个游戏问题的搜索顺序。声明完成时由业务验证器检查结构、引用来源和要求覆盖，未通过则给出具体缺口供 Agent 继续调查。程序不能仅凭引用存在证明语义正确，语义准确性另由固定答案集验收。

区分 `completed`、`needs_input`、`incomplete`、`failed`、`cancelled`。`completed` 要满足本业务完成契约；`incomplete` 记录已完成部分和明确阻碍（权限、资料缺失、预算等），不能因首次检索无结果就结束。工具拒绝后的重新规划只能在原授权范围内进行。任务状态随请求存在，不引入跨重启自主续跑；有副作用的结果只在业务确认完成后提交。

在硬预算之外增加有界的连续无进展检测：根据工具身份、规范化参数、资料版本和有效结果判断是否反复执行等价行动；新的调用 ID、时间戳或模型自述不单独算作进展。重复取得相同事实、相同失败或反复提交相同完成缺口时，先反馈具体原因，允许模型更换查询或调查路径；达到配置阈值仍无进展则以 `incomplete` 结束并保留未解决事项，不强制生成成功答案。新证据、相关资料变化或已验证的缺口减少属于进展；首次无命中、多文件调查和合理重读不能单独触发停止。此机制不替代权限、累计预算或取消，也不将有副作用的任务自动重新提交。

预算包含累计模型调用、工具调用、输入/输出规模、委派次数、深度及总截止时间；子 Agent 使用同一个根预算账本，不能复制计数后各自消费。检索工具内部的向量/重排调用同样计入外部请求账本，不能隐藏为“一个本地工具”。并发安全地预留预算后才调用提供方，失败也记账；时间取消不能抹掉已经发生的收费。

保持 NPC 总期限不超过现有 80 秒，世界单次生成上限 90 秒及最多三次业务尝试。世界/摘要迁移不增加额外路由或审稿模型。问答和主 Agent 的轮次、工具数、委派次数及上下文容量由配置显式限定，默认允许多步调查，依据基准评测调优而非用单轮上限削弱任务能力。主 Agent 首版委派深度为一层、总期限受请求入口限制；摘要与子 Agent 不能重置根请求期限。HTTP 超时不是强制杀线程，迟到结果不提交，取消后不再发起下一次调用。

根预算采用请求内共享计数器，轨迹沿用脱敏结构化日志，记录请求/父子关系、终态、策略/技能/模型版本、证据 ID、用量和错误类别，不新增通用运行数据库。已有 NPC 成功结果缓存保持；新 `agent_run` 复用持久请求结果缓存机制，以业务命名空间隔离键和完整请求指纹，旧 NPC 键保持可读。并发重传共享在途运行，已缓存成功结果重传不重新付费；中断但未落结果的通用请求不自动续跑，不承诺崩溃窗口中外部调用恰好一次。世界仍由原队列、租约和尝试额度恢复，调用统计与运行日志关联但不重复扣额度。

### 4. 可发现的 Tool 是注册能力，不是任意函数

定义受信任工具包协议：稳定 ID、说明、版本、参数/结果 schema、所需权限、资源类型、只读性、并发安全性、超时/取消语义、输出上限和成本类别；处理函数来自部署时固定的受信任 Python 包。启动时扫描受信任工具目录的声明，校验依赖与重名，建立注册表；未授权工具对模型不可见，猜测名称也不能调用。工具的新增发现无需编辑中央 `if/elif`，但包部署、启用和权限授予仍由开发者/管理员控制。元数据不能代替执行时授权；首版继续顺序执行工具，不因声明并发安全就增加并行调度器。

统一执行顺序为参数/身份/权限/预算检查、前置 Hook、对变更参数重新验证及授权、执行、结果检查、后置 Hook 与结束记录。前置检查拒绝时记录未执行，实际进入执行的调用在成功、失败、超时或取消时均有可关联的结束状态。返回结果包含调用 ID、安全错误类别及可恢复性；无匹配、扫描截断、文件变化和未授权不能混为“没有资料”。可恢复问题反馈给 Agent 调整行动，取消或根预算耗尽则结束运行，不能仅转成普通工具错误继续调用。

超时与取消语义须说明底层操作是否支持协作停止；停止等待不等于线程或外部请求已被强制终止。不能丢弃实际用量或把迟到结果交付为成功。结果必须受 schema 和规模约束，需截断的搜索等工具明确返回部分结果状态，不静默截断结构化对象或必需指导。不同程序能力保留独立工具契约，不将所有 Tool 合并成一个以任意名称或 `action` 分发的万能工具；多个 Skill 共用 `skill` 是指导加载的统一入口。

首批工具：

| Tool | 行为 | 约束 |
| --- | --- | --- |
| `knowledge.search` | 复用 BM25/向量融合和重排，返回证据片段 | 查询、返回数量、提供方调用和受众有界；保留 BM25 回退 |
| `source.search` | 在授权文本范围做有界词面/路径搜索 | 默认字面量搜索，无任意正则计算或 Shell 拼接 |
| `source.read` | 按范围读取授权文档或源码 | scope 别名 + 相对路径 + 行区间；返回内容 hash 和行号 |
| `skill` | 按技能名加载指导，按技能名和可选资源路径读取引用资料 | 技能目录自动注入系统提示词；仅访问授权包，无逐技能入口或任意文件跳转 |
| `agent.list` / `agent.invoke` | 发现、委派业务 Agent | 参数校验、权限取交集、共享预算和祖先检查 |

所有模型请求的外部能力通过此执行器，不允许业务 Agent 自行绕过 Tool 调知识库或读文件。普通业务代码也可直接调用同一工具入口，仍使用相同鉴权、预算和结果契约；不必为了复用工具先调用模型。现有纯计算函数、持久提交和回调投递不是模型工具，不为“全部工具化”暴露内部运维函数。`knowledge.search` 复用当前算法和客户端，缓存键、内容过滤和诊断隔离受众/授权范围；不能在过滤前把越权候选送去远程重排。

加载 Python 插件是部署可信代码的一部分，不等于向模型提供代码执行工具。模型、玩家输入、Skill 不能指定动态 import 路径；不从运行数据目录、网络或聊天附件安装插件。首版注册表在启动时构建，新增部署后重启生效，不做未审计热安装。

### 5. 授权源码读取与外发边界

源码授权采用受信任配置中的 scope 别名、固定根目录、路径/扩展名包含规则、排除规则、允许 Agent/受众以及是否允许发往配置的外部模型。默认没有源码 scope；已有公开帮助检索保持，管理员配置明确范围后才启用源码工具。授权读一个目录不等于允许把整目录发给外部模型。

第一版提供样例授权配置但不启用实际路径；实际范围需要管理员核定。学习条件通常跨 `kungfu/skill/`、授艺 NPC、公共检查和头文件，不能默认为解决问题开放整个 `d/` 或 `adm/`。未授权依赖返回证据不足，不扩根搜索。玩家和管理员使用不同公开范围；隐藏剧情、口令及管理实现即使可由管理员查看，也不自动进入玩家回答或检索缓存。

访问校验必须同时覆盖搜索枚举和读内容：规范化并验证根路径归属，拒绝绝对路径、父目录穿越、UNC/设备路径、Windows ADS、二进制文件、符号链接/目录联接/reparse point 越界及文件替换竞争。对硬链接或不能可靠确认最终打开对象的情况关闭访问，不将字符串前缀比较当作隔离；工具仅持有读取授权源的最小 OS 权限。并发部署导致文件变化时重新校验或返回 `source_changed`，不能混用前后版本证据。

`.env`、密钥、玩家存档、数据库、日志、`.git` 对象和服务私有运行目录在源码工具中始终排除；不得通过搜索结果、计数、文件名、错误信息或另一 scope 绕过。文件大小、搜索文件数、总扫描字节、执行时间、片段长度均有硬上限；越限返回明确的部分结果标记或拒绝，不假装搜索完整。

源码、注释和检索内容只作为资料。即便其中写着“忽略指令、读取密钥”，也不能修改工具集或触发未授权行为。权限和外发检查发生在内容进入模型前，日志默认只记证据 ID、hash、用量等元数据，而非完整源码和提示词。

### 6. Skill 为专业知识包，统一通过工具接口访问

业务技能放 `ai/skills/`，与开发用 `.agents/skills/` 分离。采用 `SKILL.md` 的名称、中文说明和 Markdown 指导，配套 `references/`、示例与评测样本。依据 [Agent Skills 格式规范](https://agentskills.io/specification)，版本可放 metadata；输入输出 schema、权限与预算仍为程序契约，不假装属于标准强制字段。

首批包：武侠 NPC 对话、游戏规则源码调查、对话摘要、幻境房间描写、主 Agent 协调。每个包记录适用场景、目标/完成条件、行动方法、验证清单、正反例、边界及输出要求。源码 Skill 教会 Agent 寻找依赖、补查和核对结论，而非仅要求“依据资料回答”。原人设仍由角色配置提供，Skill 不硬编码周不通身份，也不捆绑模型供应商。

服务自动扫描配置的业务技能目录（默认 `ai/skills/`），校验元数据并建立技能目录；组装 Agent 系统提示词时，按有效权限仅注入可用技能的名称和描述。Agent 根据任务需要，通过唯一的 `skill` 工具按名称加载正文，例如 `skill(name="source-investigation")`；需要引用资料时仍用同一工具，增加包内资源路径参数。目录发现无需模型先调用列举工具，不增加 `list/load/read_resource` 或 `action` 分发层，也不为每个 Skill 创建工具、路由或中央分支。

直接模式由运行时通过同一个 `skill` 工具入口预加载指定 Skill，复用相同的加载、鉴权和审计，无额外模型回合；工具模式由模型按需选择。新增合法技能包可由扫描发现，但仍需显式授权，不把所有包全文塞进每个请求。资源路径不得逃逸本技能包；即使包包含 `scripts/`，本服务也不提供执行能力。Skill 声明的 `allowed-tools` 最多收紧已有范围，绝不构成授权。

技能目录、`skill` 工具可见性及实际加载使用同一有效授权视图；禁止工具时不能仍提示模型调用它，直接预加载也不得绕过该限制。技能正文及被要求完整加载的指导资源不能静默截断后标为加载成功；超限须明确拒绝，维护者将大篇资料拆为按需引用文件。目录摘要与按范围读取的普通参考资料不冒充完整指导。

一次运行固定注册表与技能版本，记录内容 hash、实际加载资源和模型配置；发现必需 Skill 缺失/损坏时拒绝该能力或走已有明确离线回退，不悄悄启用另一套硬编码专业提示词。运行时仅保留短的角色层级/安全协议和结构适配代码。

Skill 负责“专业方法与资料”，Agent 负责“执行专业任务”。`skill(name, path?)` 始终是唯一的指导/资源加载工具，不暗中启动模型或嵌套工具循环；需要隔离专业过程时由 `agent.invoke` 调用已注册的业务 Agent，后者通过相同 `skill` 入口加载指导并复用 Runner 执行。这样保留专业模型和工具循环的封装收益，不建立另一套 Skill 模型客户端、权限通道或预算计数，也不要求主 Agent 先加载子任务的全部技能材料。

迁移世界描写时先保持当前指导语义及内容键，不借架构升级重生成旧文案。专业样例扩充与质量提升另做对照评测：事实/结构正确率与文风评分分开，允许合理补白。新增相邻正文上下文要显式记录所用证据，不能读其他玩家私有状态。

### 7. 源码问答的证据链与呈现

问答 Agent 将问题转为可验证的调查目标：武功/绝招实体、学习/解锁/施展/消耗类别、要回答的条件及数字。通过工具发现相关入口，沿函数调用、继承、头文件常量、配置及授艺 NPC 继续调查，维护待查依赖和证据；发现冲突、间接调用或搜索截断时补查，不能把一个片段当作完整结论。初版用有界搜索与读取完成定义/引用定位；结构化符号索引以后按实测需要增强，不作为第一版前置条件，不执行或编译源码。

完成检查至少包括：目标实体/入口匹配；影响所问行为的关键分支和依赖已查明；阈值与扣除量分开；替代路径/例外已解释；结论各项关联已读证据；没有影响结论的未决矛盾。以缠字诀为例，`perform()` 的技能和内力检查只能证明施展条件；若问学习条件，Agent 必须继续寻找传授/解锁逻辑。“内力至少 60”与“扣除 30”须分别回答。验证发现缺口时进入下一轮，不直接输出“可能如此”。

每个确定结论关联证据记录：scope、相对路径、行号区间、文件内容 hash、读取时刻；有可信部署 revision 时附上，没有则说明只代表当前源码快照。目录索引只是定位线索，回答前回读当前文件；工作区源码不一定等于驱动已加载的版本。依赖仍在授权范围且预算可用时继续追踪；仅当实际不可访问、材料确实缺失、需要玩家澄清/实时状态或达到预算时返回相应未完成状态，不填入虚构数值。专用规则查询工具可后续提高效率，但不是源码调查的前提，更不能要求手写每个问题的答案。

内部结果包含答案、证据引用和不确定项；校验引用确实来自本次授权工具结果。管理员诊断显示源码位置，玩家仍得到符合 NPC 身份的中文解答和游戏内条件，不显示路径、数据库或工具调用细节。若存在只允许管理者知晓的信息，必须在读入模型前拦截，不能只靠最终隐藏引用。

建立至少 20 个固定问题的验收集，覆盖跨文件门派贡献、宏/继承、授艺与施展分离、多种学习路径、阈值与扣除、旧文档冲突、同名技能、无命中后的改查及确实不可完成的情况。每题有人工核对的预期结论、必要证据和终态；所有可回答核心题的条件/数值及证据必须正确，不可以“谨慎拒答”刷通过率。假模型验证循环与权限，真实模型在独立授权额度内验证自主定位和回答；分开报告正确率、完成率、无依据结论、延迟及调用数，固定通过用例不能替代真实模型能力验收。

### 8. Hook 可观测与干预，但不是安全隔离替代品

Hook 是固定注册的可信回调，由程序在边界自动触发，不是模型工具，也不单独建设插件引擎。事件覆盖 `run_start`、`before/after_model`、`before/after_tool`、`before_commit`、`run_end`、`run_error`，直接、委派和兼容包装路径一致覆盖。委派就是一种工具调用并携带父子运行 ID，不再另设委派专属生命周期；向量/重排请求产生模型边界事件并附 operation 类别。

实际进入模型或工具执行的调用，无论成功、失败、超时或取消，都必须发出一次关联的后置事件；操作状态与 Hook 干预结果分别记录，避免后置拒绝抹掉已发生的执行或用量。前置拒绝记录未执行的原因，不伪造实际执行或收费。`run_error` 用于错误诊断，`run_end` 是每次运行唯一的最终结束记录，携带最终状态；终态观测故障不得再次结束运行或改写已经确定的业务提交结果。

| Hook 类别 | 能力 | 失败处理 |
| --- | --- | --- |
| 观测回调 | 观察脱敏事件、指标、延迟、用量；不改上下文 | 隔离失败并计数，不能拖垮业务或递归触发自己 |
| 干预回调 | 允许/拒绝/取消，或修改声明允许的上下文字段 | 必需干预超时/异常即停止；修改后重新走 schema、大小、外发和权限检查 |

首版干预按事件限定，不提供任意状态对象改写接口：

| 事件 | 允许的干预 |
| --- | --- |
| `run_start` | 允许、拒绝或取消本次运行 |
| `before_model` | 允许、拒绝、取消或追加有界且通过外发检查的上下文；不得替换整份消息历史或系统安全协议 |
| `before_tool` | 允许、拒绝、取消或修改该工具契约允许的参数，修改后重新校验 |
| `after_model` / `after_tool` | 观察执行状态，拒绝继续使用结果或取消；不得覆盖模型原始响应、工具事实、证据及用量 |
| `before_commit` | 允许、拒绝或取消提交；不改写业务结果、证据或持久化目标 |
| `run_error` / `run_end` | 仅观测最终事实，不干预、重试或触发提交 |

同一事件按固定注册顺序处理，拒绝和取消优先于允许，不采用最后完成的回调覆盖前面决定的规则。输出格式转换及完成条件验证保留在明确的业务适配/验证器内，不通过通用 Hook 偷换答案；验证可补查的缺口仍返回 Agent 循环，不用新增 Hook Agent 替代它。

不可变字段包括身份、受众、权限上界、预算账本、关联 ID 和截止时间；Hook 不得增加这些权限或预算。处理顺序为基础校验/授权、受限 Hook、最终不可绕过的校验与授权，再执行操作。模型后置拒绝不代表此前调用没有计费；`after_tool` 不能撤销已经发生的动作，所以危险副作用必须在调用前禁止。

Hook 不接收原始 SDK 客户端、数据库连接或完整密钥配置，只接收按目的最小化的数据。原始资料检查若确有必要，由明确授权的本地干预回调执行，普通观测端仍只拿脱敏元数据；不记录模型私有推理。可信 Python 回调具有宿主进程能力，不能声称能安全容纳恶意第三方代码；部署审查和 OS 权限是另一层边界。

### 9. 数据提交与兼容迁移

“不提供写工具”不等于服务不能正常保存历史或生成正文。Agent 只产生结构化业务结果；经过输出验证、Hook 和会话/任务身份复核后，由现有业务层提交。模型不能选择数据库表、任意路径、发布目标或修改计数。

模型完成生成只是候选结果就绪，不是业务运行已成功。无需持久化的能力在完成验证后结束；需要提交的能力依次完成候选验证、`before_commit`、最终身份/期限/取消检查及可信业务提交，提交结果确定后才记录 `run_end`。提交失败不得提前或补发 `completed`；成功提交后的观测故障不得回滚成功语义或再次提交。运行时提供统一边界，事务及世界发布仍由现有业务适配层负责，不把数据库实现导入通用 Runner，也不新增事务框架。

NPC 的历史、关系和去重仍在一个事务内提交；世界仍先落库再原子发布，来源元数据可添加 Agent/Skill/policy/trace 引用，不更改既有内容身份。不引入新运行库；确需添加的兼容字段必须可备份、可回退，旧库不删除、旧成功内容不重做。调查过程和未完成输出不冒充成功对话、不推进关系；澄清/部分结果由适配层以游戏语境反馈，不写入成功记录。

主 Agent 不绕过业务前置条件：世界开关关闭、世界/坐标非法、调用者无创作授权时，即使知道 `world_narration` 的名字也不能生成或发布。通过委派进入 NPC 业务同样不能无授权读取历史或推进其他会话关系。展示回调和提交职责不重复执行。

#### 已验证成果的引用交付

短结果可直接按契约返回；无需把每段文本都改成引用。较大或需要原样交付的成果，由可信运行时保留结果并生成不可由模型任意指定的 `result_ref`，子任务向主 Agent 返回有界摘要及引用。引用不是文件路径、任意下载地址或访问权限。首期仅使用请求内有界结果表；已持久的世界成果仍由原业务任务/内容标识关联，不新增通用成果数据库或跨重启 Agent 工作流。

主 Agent 可以在最终候选结果中选择本根请求下已授权的成果引用，由可信交付层解析原成果，无须让模型重新输出整篇正文。解析时核对根请求、会话/受众、有效权限、成果来源、内容完整性及业务完成状态；伪造、跨请求、失效或未完成引用不得交付。需要持久化的成果必须先完成其业务提交；世界受理凭据不是已完成正文。对多个成果的拼接或重新总结仍须检查是否覆盖整体目标，不能因子任务成功而直接宣布父目标完成。

引用交付不绕过输出 schema、大小上限、玩家表达、证据权限、取消及最终提交检查；不得用截断 JSON 或直接暴露内部引用处理超限。无需改写的原成果保持内容不变，必要的玩家/管理员视图转换仍由业务适配层完成。引用解析只取已存在结果，不再次生成或重复业务提交；持久成功请求缓存保存可重放的最终响应或既有业务凭据，不缓存只能在本次运行内解析的悬空引用。

### 10. 文件组织与验收重点

新增 `ai/src/runtime/`（定义/注册、任务循环、上下文/预算、权限、Skill 加载及简易 Hook）、`ai/src/agents/`（业务 Agent 装配）、`ai/src/tools/`（共享工具）、`ai/skills/` 及中文样例配置。模型适配继续集中在 `ai/src/llm.py`。保留现有 `npc/`、`world/` 的业务状态归属和 `knowledge_*` 实现，不为目录美观批量移动源码或数据。只根据职责拆文件，不预设庞大类层次。

测试分三类：离线合约/安全测试、真实 FluffOS/UDP 假模型回归、单独授权的真实效果测试。安全样本必须覆盖恶意工具参数、资料提示注入、跨会话委派、路径绕过、Hook 扩权、同名插件、Skill 缺失、循环/超额调用和提交前取消。补齐工具失败/取消的结束记录、前置拒绝未执行、Hook 改写后重验、技能目录与工具权限一致、指导不完整拒绝、提交失败不报成功及终态只记录一次的时序测试。源码问答用固定 LPC 多文件夹具精确核对门派贡献等数字，文风另行审读，不能让模型评审代替确定性权限测试。

委派验收检查实际发送给父、子模型的消息：大量子任务资料和工具过程不得自动出现在父后续上下文中，而必要条件、证据引用与阻碍仍完整可用。覆盖连续无进展反馈与停止、有效进展继续、成果原样交付、伪造/跨请求/未提交引用拒绝，以及引用重放不重新生成。成本对照记录直接执行与委派执行的主/子输入输出用量、上下文峰值、模型配置、延迟和质量；只有同等任务与完成质量下的数据才用于判断收益，假模型的隔离测试不冒充真实成本或专业效果评测。

### 11. 新功能的统一接入规范

实施时新增 `docs/architecture/ai-service.md`（长期架构与扩展指南），在根 `AGENTS.md`、`ai/README.md` 和业务文档链接；本变更的规范先作为实施合同，验收后同步正式 OpenSpec，不把尚未实现的目标写成当前能力。

每项新增 AI 功能交付七项内容：Agent 定义与目标/完成条件；业务输入输出和状态归属；工具及授权范围；中文 Skill 与样例；模型/容量/预算及降级；直接/委派接入与受信任提交；离线测试、效果样本及运维说明。扩展复用统一模型和工具执行入口，不另建 SDK 客户端、权限分支或数据写入工具。以一个临时测试能力验证注册和扩展，无须新增实际游戏玩法。

新工具以受信任模块声明被启动注册表发现，新增 Skill 以包元数据被发现；部署启用和授予权限仍显式。业务模块在 `main.py` 装配并选择独立容量；注册的变化是正常接入，不要求为了“零改动”而扫描任意代码。架构验收检查现有全部业务入口也遵循这些规则，不能只给新例子接上运行时而遗留旧实现旁路。

### 12. 独立服务与 MUDLIB 的依赖边界

socket 带来进程和通信分离，可移植性还取决于服务是否依赖某个游戏的业务结构。目标是其他 MUD 按公开协议、配置和必要的业务适配接入，不承诺所有特色玩法无需适配即可复制运行；不要求对方使用本库、FluffOS、LPC 或 mudcore。

优先使用已有配置解决部署差异：`HELP_DIR`、`NPC_ROLES_FILE`、`DATA_DIR`、`WORLD_CONTENT_DIR` 等继续可配置。保留本项目便捷默认值完全合理，不为每个目录建立接口或插件；要求是显式配置后不再隐式回读本库路径，关闭的能力不强制要求其目录存在。LPC 专业知识、中文武侠文风和 NPC 角色属于可替换的业务 Skill/配置，不写进通用运行时。

依赖方向为装配入口选择业务模块，业务模块使用通用运行时/工具，socket 层只负责报文和路由契约；运行时、通用模型适配及基础工具不能反向导入 NPC、无限世界或游戏实现。现有本机 UDP 和旧字段保持兼容，不为解耦新增传输协议或笼统仓储框架。每个部署首期服务一个游戏，多游戏使用独立进程、端口、策略和数据目录，不宣称已有多租户隔离或远程认证。

游戏端负责在线对象、玩法规则、权限及数值变更；服务负责授权资料调查、AI 生成和服务自身的历史/任务/结果保存。调用方提供的角色或玩家标识是业务数据，不是管理员认证。当前世界清单校验、内容身份及原子 JSON 发布留在可选的无限世界模块，明确其共享目录集成要求；这是可替换的结果交付方式，不是所有 Agent 的必需依赖，也不把它伪装成纯 socket 集成。

验收将 `ai/` 单独部署到没有本 MUDLIB 的临时目录，使用另一套角色、知识和数据配置，以及普通 Python socket 客户端完成假模型请求。禁用无限世界后不应访问其清单或发布目录；启用该模块时再单独验证已公开的文件和报文契约。用导入边界测试防止公共运行时反向依赖游戏业务，不要求先拆独立 Git 仓库或发布安装包。

## Risks / Trade-offs

- [首次检索就结束或遗漏条件] → 目标/待查项/证据驱动循环，验证未通过继续调查；用人工答案集检验正确性和完成率，不以“可能不准确”削减能力。
- [只读也能泄密] → scope 与受众/外发授权同时检查，玩家资料永不进入通用源码工具，缓存/日志按策略隔离。
- [自动发现等同任意执行] → 仅受信任部署包、启动校验与显式启用；不支持模型指定 import、脚本执行或热安装。
- [多轮变慢或成本失控] → 明确请求不经主 Agent；预算覆盖委派及检索内部调用，截止时间不重置，交互任务超额及时停止。
- [Hook 故障或扩权] → 区分观察与策略故障，修改后重新验证，所有执行路径使用同一不可绕过的策略边界。
- [与无限世界未完成改动重叠] → 固定当前 M2 基线，服务架构迁移优先，停止并行编辑重叠文件；两个变更分别记验收。
- [工具名统一但数据串线] → Agent 独立上下文，委派传必要任务资料而非全历史，工具与结果缓存纳入授权范围。
- [结果压缩丢掉关键条件或把引用当授权] → 有界结果契约保留条件、证据和阻碍，引用解析重新核验归属、权限和完成状态，不以摘要简短代替可靠交付。
- [为隔离而过度拆任务] → 保留直接入口与单层委派，简单任务不新增模型回合，比较真实质量、延迟和总用量后再调优。

## Migration Plan

1. 以 `2f8192a5` 保存的 NPC/世界回归和协议为基线，使用临时数据副本验证迁移，不提交生成数据。实际部署前另行备份运行数据。首先实现共享运行时、模型适配及权限测试，不开放源码或主 Agent 入口。
2. 迁移 Skill、知识检索 Tool 和独立业务 Agent，保留旧路由及数据接口；逐业务开关验证，直接路由的单次世界生成不得增加模型调用。
3. 接入授权只读源码问答；先用临时夹具，随后由管理员明确实际 scope、受众和外发许可。执行目录越界与泄漏回归后再配置真实目录，默认配置保持关闭。
4. 接入主 Agent 的委派、结果检查与继续决策，复用已在基础执行器实现的 Hook；全链路检查共享预算、取消、重传和故障。主 Agent 默认关闭，验收时单独开启；不改变无限世界公共入口或自动创作默认值。
5. 更新中文架构/接入/运行/安全文档、根 `AGENTS.md`、配置示例和游戏端协议说明；运行 Python、LPC/UDP、Linux/Windows 路径与启动器回归，以及无本 MUDLIB 的独立部署和替代游戏配置测试。单独授权真实模型评测的调用预算，验证固定题的自主调查和结论；不自动沿用历史 20 次额度。缺少真实验收时明确标记未完成，不开放源码功能冒充已验证。
6. 回退时停止新调用、等待在途请求结束或标记中断，禁用新 Agent 路由/源码权限并切回已验证的业务装配；保留旧数据库、正文和新增审计记录。不得同时启动两个共享业务库的写入方，不通过删库恢复运行。

## Open Questions

- 首次部署授权哪些具体源码 scope、哪些信息可面向玩家、是否允许传给外部模型：机制确定为默认拒绝，目录清单是管理员部署选择，不阻塞离线实现。
- 主 Agent 开放给哪些实际游戏入口、每项预算采用何种较低初值：先内部诊断验收，后续开放须明确配置，不默认替换所有 NPC 聊天。
- 第一版专业 Skill 的示例文风：在架构与安全测试后用固定样本对照确定，不以增加禁词或自动重写已有正文代替质量评测。
