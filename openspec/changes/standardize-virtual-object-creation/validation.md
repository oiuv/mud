# 通用虚拟对象接口验收

日期：2026-10-04。基于主仓库 `ed10c535` 上已有、尚未提交的普通 CLOTH 数据化工作区；框架基线为 `d2f2b92`。本次不重置或提交此前变更。Windows 驱动为 `fluffos 20260929-5270e7d6-795eb371`，Node.js v24.21.0；未另行运行最低版本驱动。

## 实现与边界

- LIB 守护精灵改为 `/provider/key` → `create_virtual_object(key)`，不再猜测坐标或调用旧迷宫入口。服装、无限幻境、maze/workroom 接入；经 LIB VRM 包装器继承的迷宫使用 CORE_VRM 新接口。
- mudcore 的新接口可在世界/怪物目录之外使用；保留原路由顺序、宿主 VIRTUAL_D 和地区/怪物方法覆盖。未实现新接口的旧宿主在原目录范围继续兼容，不扩大隐式构造范围。新接口拒绝或抛错不回退。
- 返回值检查拒绝非对象、自身、蓝图和已虚拟命名对象。驱动保有命名、克隆标志、UID 和 virtual_start；未新增对象工厂、注册表、存档格式或服务依赖。
- LIB 仍使用自身 daemon。业务数值、服装品种路径、幻境实例身份及原构造逻辑未改；新坐标接口拒绝尾随垃圾字符串，负数和两参数默认 z=0 保留。

## 同负载时间和内存

沿用原 `--bench`：202 蓝图、每品种 20 实例，共 4040 实例；每次独立驱动进程，旧/新顺序交替，三轮。旧源码仍为 `ed10c535`，新版本是本次通用接口后的数据化实现。不计副本准备与启动；内存是 `memory_info()` 估算，不是 OS RSS。

| 指标 | 旧实体源码，三轮 | 数据化 + 新接口，三轮 |
| --- | --- | --- |
| 冷加载蓝图 ms | 250.857 / 206.543 / 214.808 | 65.910 / 45.434 / 44.833 |
| 创建 4040 实例 ms | 38.471 / 33.724 / 34.898 | 332.886 / 347.641 / 308.761 |
| 蓝图新增估算内存 byte | 782581（各轮相同） | 557468（各轮相同） |
| 实例新增估算内存 byte | 3225360（各轮相同） | 5442920（各轮相同） |

本次新版本冷加载中位数 45.434 ms，批量创建中位数 332.886 ms，即每实例约 0.082 ms；本轮旧实体约 0.009 ms。4040 个实例多约 2.11 MiB，与接口统一前相同；蓝图估算相比此前数据化结果增加 44 byte。

对照[上一份记录](../refactor-data-driven-game-objects/validation.md)，此前数据化中位数为冷加载 43.223 ms、批量创建 287.502 ms。本轮分别高约 5.1% 和 15.8%，但旧实体本轮也有波动，不能把跨轮差异全部归因于接口。未预设或宣称性能提升；绝对开销与维护收益分开评估，没有为基准增设缓存。

原始六组数据与日志保留在本机 Temp 的 `mud-cloth-IrjwT3/benchmark.json` 及 `benchmark-*.txt`；命令退出码 0。

## 部署与回退

所有验证均使用隔离目录，没有重启、降级正式游戏，没有读取/转换正式玩家记录或调用外部模型。接口本身不改变存储路径，不需新增数据转换。LIB 与新 CORE_VRM 须配套维护重启；回退同时恢复匹配的双方代码。

若将已有服装数据化一起部署，必须继续按[服装部署说明](../../../docs/architecture/data-driven-items.md)处理其存档转换和联合回退，不能把“接口无数据变化”理解为取消服装迁移要求。当前尚未提交、推送或部署。
