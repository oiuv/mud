# Design

## Context

动机见 proposal.md。当前 LIB 的 `adm/daemons/virtuald.c` 按末段 sscanf 出的整数数量执行 new，否则调用 query_maze_room；框架 `system/daemons/virtual_d.c` 还先按 WORLD_DIR/MOB_DIR/default area 路由。框架的目录分派通过 VIRTUAL_D 调宿主可覆盖的方法，不能直接绕过。

已核对的 LIB 新接口接入点是普通 CLOTH、无限幻境、`u/mudren/maze.c` 和 `workroom.c`。`d/death/heisenlin.c`、`u/mudren/migong.c` 经 `inherit/room/vrm.c` 使用 CORE_VRM；该中间程序会 replace_program，因此新入口应在框架迷宫组件提供，不堆叠宿主转发层。框架另有 `world/area/tower.c` 坐标示例；现有测试只直接调用 compile_area 和旧迷宫方法，尚不能证明真实驱动通用虚拟加载及宿主路由覆盖正确。

## Goals / Non-Goals

**Goals:** 一种对外创建回调；具体参数在业务程序解析；LIB 与独立框架均可验证；保留原对象身份、初始化与宿主边界。

**Non-Goals:** 不把 LIB 切换为使用框架 daemon；不新增跨仓库共享服务、注册表、参数解释器或统一对象父类；不改变 FluffOS、游戏数值、存档结构或已有最低驱动要求。只读方案阶段不实施代码或生产切换。

## Decisions

### 1. 单个不透明字符串回调

公开约定为 `object create_virtual_object(string key)`，路径为 `/provider/key`，对象引用不带源扩展名。按最后一个 `/` 拆出 provider 和 key；末段不能为空，不递归向上查找任意祖先，也不把 key 当代码执行。source 检查继续支持 `.lpc/.c`，遵循驱动的同名优先级，验证带/不带首斜杠的实际驱动调用形式。

回调可解析 key 为任意内部参数，返回供驱动接管的新对象；不能返回 provider 自身或复用已登记的游戏对象。未知键返回 0，真实构造异常传播。由驱动完成虚拟命名和 virtual_start，不在 daemon 手动改名、赋权或补调 setup。

选择字符串而非参数数组/JSON schema，是因为路径本来已承载业务身份，泛型转换会误判诸如 `1,2` 的普通键，也没有新增协议的需要。只改 query_maze_room 名称但仍在 daemon 猜坐标，不能真正统一职责。

### 2. LIB 全部转入新约定

LIB daemon 仅做路径/程序/接口检查与调用，不再保留坐标构造和旧迷宫名称分支。服装和无限幻境改回调名，保留各自校验及初始化；坐标房间自行解析原两/三整数形式，再沿用原参数构造和缺省 z 行为。CORE_VRM 提供新接口后，继承它的游戏迷宫自然接入。

原有效路径一律不改，不再迁移服装品种键，不动游戏入口或个人实例校验。测试应包含坐标负数、原两参数缺省值及非法字符串拒绝，避免用宽松部分匹配误收多余参数。更新活跃文档和测试；历史验收记录可以保留旧接口名称，不把它当作残留运行调用。

### 3. mudcore 的新约定与旧宿主边界

保留现有目录路由优先级及 `call_other(VIRTUAL_D, ...)` 扩展方式。匹配 WORLD_DIR、MOB_DIR 或默认框架地区时仍走原可覆盖入口；框架的 compile_area/compile_mob 默认实现先识别新回调，有则原样交付 key，接口不存在才执行原合法坐标/编号/迷宫兼容规则。新回调拒绝或抛错后绝不再回退。

未匹配旧目录时，只允许提供新回调的实体 provider 通用接入；不把旧的隐式数字构造扩大到全库。允许少量私有路径/回调辅助函数复用代码，但不新增服务、自动注册或配置开关。compile_mob 定位父程序也用最后一个斜杠，不继续全局替换末段文本。

CORE_VRM 提供新创建入口，保留公开 nomask query_maze_room 的同义入口，共享同一份迷宫逻辑，防止新旧方法互相递归。框架 tower 等示例采用新接口；旧协议只在文档的兼容章节及测试保留。

compile_object 对驱动只返回对象或 0；回调类型错误应给可诊断错误，不伪装为成功。旧 compile_mob 辅助入口已有字符串失败返回，直接调用的兼容结果不在本次顺手改变；经过驱动入口时不能把该文本交作对象。异常不通过 catch+旧式重试吞掉。

相比直接删除所有旧接口，这个小范围兼容层遵守框架现有公共契约，也避免要求独立 MUD 与本 LIB 同步发布；本游戏不必因此长期使用旧协议。

### 4. 测试与文档复用现有入口

- mudcore 的 `tests/run.mjs` 增加通用物品、坐标、迷宫及宿主路由覆盖夹具。既测方法直接调用，也通过测试 master 对真实 load_object/new 验证命名、clonep、UID 和 virtual_start 次数。保留原 default/overrides/minimal/custom 验证，不用本 LIB 通过结果代替框架验收。
- LIB 在 `tools/tests/` 增加或复用轻量隔离驱动检查，覆盖本机 daemon、CORE_VRM 继承链、坐标房间、新旧幻境关键校验。扩展已有服装回归入口，保持 202 品种行为对照，不访问正式数据或 AI。
- 同一 provider 同时有新旧方法、纯数字/逗号键、未知键、缺程序/缺回调及回调抛错是必要协议用例；不建立额外测试平台。
- 新建 LIB 虚拟对象说明并从 AGENTS/文档索引引用；同步服装文档。框架更新自身虚拟对象文档、组件依赖矩阵、include 宏注释、示例、README/CHANGELOG 未发布记录及必要贡献约定，不依赖父仓库文档才能接入。

## Risks / Trade-offs

- [框架宿主覆盖被绕过] → 保留路由入口，测试 override、父调用与 VIRTUAL_D 替换；新通用路径不接管原已匹配分支。
- [框架子模块与 LIB 更新不同步] → 先验证框架新接口，再迁移 LIB；交付说明要求配套版本。未获得授权不提交或发布。
- [virtual_start 初始化重复或身份提前使用] → 复用驱动时序与服装对照，不把业务 setup 搬到 daemon。
- [多一次回调的代价] → 重跑同条件服装基准并如实报告；目标是统一约定，不承诺性能改善或用缓存掩盖成本。
- [未提交服装重构被覆盖] → 仅修改它的新接口及相关文档/测试，保留基线和已有迁移改动；旧 13/13 记录不冒充本次测试结果。

## Migration Plan

框架通用分派与兼容 → CORE_VRM/示例与独立回归 → LIB 分派与处理程序 → 游戏隔离回归/基准 → 文档、格式和差异验收。运行对象继承链可能驻留旧程序，部署采用配套代码与子模块的维护重启，不承诺任意顺序热更。

本次不改虚拟路径，不需要新增存档转换；回退到紧邻的旧接口版本时同时恢复框架与 LIB 对应代码。若连同尚未部署的服装数据化一起上线或回退，仍须遵循该变更的代码/存档联合迁移说明，不能用本次“接口无存档变化”覆盖其要求。
