# AI 服务架构与接入规范

本服务提供 NPC 问答、摘要、无限世界描写及可选主 Agent。模型负责调查、判断和生成，程序负责权限、证据关联、取消、用量与提交状态。其他 MUD 通过路径、角色配置和业务 Skill 接入。

## 当前状态

主 Agent 可直接处理目标或按需委派专业 Agent。Tool 提供执行能力，Skill 提供专业指导，Hook 负责观测和干预。NPC、摘要和世界共用运行时，主 Agent 入口默认关闭。

外部 CLI 通过 `exec(program, args)` 调用，由管理员绑定程序、操作与工作目录。可选 CodeGraph 默认关闭，源码搜索与读取见[源码接入](ai-source-access.md)，配置见[授权 CLI](ai-cli-tools.md)。

问答须保证核心结论、数值及证据准确，允许符合情境的角色表达和建议。效果评测见[固定题评测指南](../../ai/evals/README.md)，历史验收记录见[运行时验证](ai-runtime-validation.md)。

## 依赖方向

- `main.py` 显式选择和装配业务；`udp_server.py` 只负责公共报文、请求关联和有界分发。
- `npc/`、`world/` 保留自己的输入校验、存储和结果提交责任。通用模型与运行时不能反向依赖这两个模块。
- 游戏端负责在线对象、玩家权限、玩法规则、数值变化和展示；服务生成内容并保存自身历史、任务与结果。模型不直接操作游戏对象或执行代码。
- 本游戏用 `AI_CLIENT_D` 接入；其他 MUD 只需实现相同协议，不依赖这个 LPC 对象名、FluffOS 或 mudcore。

## 配置

保留适合本库的默认值，显式配置覆盖默认值。所有相对路径均以 `ai/` 为基准，不以启动目录为基准。

| 配置 | 作用 |
| --- | --- |
| `ENABLED_MODULES=npc,world` | 默认注册旧有两类业务；设为 `npc` 可不加载世界模块 |
| `MAIN_AGENT_ENABLED=false` / `MAIN_AGENT_WORKERS=2` | 显式开启主 Agent 的 `agent_run` 路由及其独立容量，不改变旧请求 |
| `KNOWLEDGE_UPDATE_ENABLED=true` | 启动脚本同步知识；不需要检索的部署可关闭，不删除已有索引 |
| `HELP_DIR` | 本部署公开知识来源 |
| `NPC_ROLES_FILE` | 人物身份、说话风格和专属知识 |
| `SKILLS_DIR` | 独立业务技能包目录，默认 `ai/skills/`；NPC、摘要和世界必需技能从此加载 |
| `DATA_DIR` | AI 服务自己的索引、历史与任务数据 |
| `WORLD_CONTENT_DIR` | 可选无限世界模块的清单/正文共享目录 |

`ENABLED_MODULES` 为空时不自动加载 NPC 或世界，可由受信任程序入口调用现有 `register()` 装配自身业务。这不是从输入动态加载 Python 的机制。`WORLD_ENABLED=false` 与移除 `world` 不同：前者保留旧世界请求的停用响应，后者不注册该业务。

代码路由与主 Agent 路由不能绕过同一个业务契约。确定性状态查询不为了形式调用模型；明确生成请求也不必先交给主 Agent 分类。

## 独立部署边界

### 模型输出格式与容量

`Agent.json_output` 默认 `false`。仅接口明确消费 JSON 时设为 `true`，目前为 `npc_dialogue`、`main_router` 和 `world_narration`；统一适配发送 `response_format={"type":"json_object"}` 并保证请求含 JSON 格式说明，不向提供方发送本地契约 Schema。工具选择与调查顺序仍由模型决定，现有字段、证据、语义与提交检查不变；没有独立格式修复模型。内部摘要及运行时 compact 始终使用文本模式。

JSON 请求不发送 `max_tokens`。`OPENAI_MODEL_MAX_OUTPUT_TOKENS` 声明模型实际最大输出容量（默认 `131072`），与 `OPENAI_CONTEXT_WINDOW_TOKENS`（默认 `1000000`）共同决定完整请求是否有空间；格式参数也计入输入估算。纯文本沿用各业务输出上限，`OPENAI_MAX_TOKENS` 不再约束 JSON 结果。两者均为单次上下文容量，不限制累计轮数或用量。

部署更换模型时核对上述容量及 `CHAT_SUPPORTS_JSON_OBJECT`（默认 `true`）；能力不符时明确失败，不静默降级或换模型。`CHAT_EXTRA_BODY` 用于思考等提供方附加选项，不应覆盖运行时管理的 `response_format`、`max_tokens` 或 `max_completion_tokens`。参考[百炼结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)。

`python ai/scripts/verify_runtime.py --execute --model qwen3.8-flash` 可显式验证合成技能的 JSON 工具续行与单次预加载；切换 Max 或思考配置只影响本次进程。此链路测试不代表源码问答质量通过，业务单次生成仍由世界回归与 `verify_business_agents.py` 检查。

### 部署文件

可以单独复制 `ai/` 的源代码、`skills/` 和示例配置，按 `requirements.txt` 创建新的虚拟环境；不要复制原 `.env`、运行数据或跨平台虚拟环境。配置替代角色、公开知识和 Skill 目录后，普通 socket 客户端即可调用，见 [通信契约](../daemons/ai_client_d.md)。文风和专业方法由业务 Skill 调整；业务代码只保留短安全/结构协议、输入装配及结果校验。

每个服务实例面向一个游戏。多个游戏使用独立进程、端口、配置和数据目录；不要把当前本机 UDP 当作多租户或远程认证服务。玩家标识是业务数据，不是管理员凭证。

无限世界有明确的共享文件集成要求：该模块校验冻结清单并原子发布正文 JSON。路径可以配置，但文件格式属于其业务契约，不是整个服务的必需依赖。禁用该模块后不要求本库世界目录存在。

## 专业任务委派入口

`runtime/delegation.py` 的 `Delegations` 只接收可信业务绑定，`tools/agents.py` 将其注册为统一的 `agent.list` / `agent.invoke`；不从模型参数导入程序，也不绕回 socket。发现列表按当前权限、会话和调用拓扑过滤，实际调用及 Hook 改参后重新校验。仅允许单层、顺序子任务；内部摘要不注册为可委派能力。`agents/router.py` 装配可选 `main_router`，由显式 `agent_run` 调用；简单目标可直接完成，工具使用或多轮调查都不强制委派。

- `NPCService.delegation()` 的模型输入只接收子问题，角色与玩家由可信会话绑定，不能通过参数切换。主路由在业务绑定时另传原始 `goal` 与公开场景，作为子输入的 `situation.original_goal/scene`；不传父历史、世界事实或权限参数，也不允许模型改写该绑定。NPC Skill 区分原目标与子任务，compact 目标状态保留两者。复用 `process_request()`、NPC Runner 与原事务；成功须先提交，澄清/未完成不推进关系。内部摘要、检索和技能仍在独立子上下文中运行。
- `WorldService.delegation(payload, request_id=..., actor=..., audience=..., session=...)` 由宿主绑定已校验的冻结事实。模型仅选择 `describe` 或 `status`，不能提供新的事实、坐标、对象标识或文件路径。受理仍经过原持久队列，返回 `pending` 回执，不同步调用 Generator；未受理为 `incomplete`，只有已发布才确认就绪。取消在受理事务提交前生效；已经受理的持久作业仍按世界原有 worker/额度/尝试规则独立执行和记账，不冒充仍在父请求内运行的同步子任务。
- `capacity.py` 的业务容量由直接入口与委派共用；UDP 分发池继续限制收包压力，委派不能借另一个入口绕过业务容量，世界调度也识别正在运行的委派 NPC。
- 每个子任务拥有新状态和稳定的业务子请求号，保留根关联、玩家、受众和会话；权限取业务与父请求交集，用量及取消沿原账本共享。父任务不复制自己的全历史给子任务，也不自动接收子任务的完整参考资料或工具消息。父子各用声明的模型窗口，compact 不影响上述关联。
- `agent.invoke` 的 `timeout=None` 仅用于可协作取消的 Agent 任务；普通 Tool 仍要求有限 I/O 超时，旧短请求期限不会被延长。返回有界状态、正文摘要、必要结论/证据引用、限制、待办与可选成果引用或世界回执，不额外调用摘要模型。主 Agent 可继续补查、委派或澄清，不能把子任务成功当作整体目标完成。

主请求可以不带 NPC；提供 `npc_id` 时必须匹配已配置角色，沿用其知识限制、玩家会话及业务权限。主 Agent 和 NPC 使用同一 `SOURCE_ROOT` 与敏感排除，主 Agent 可直接调查或按需委派，不再配置逐 Agent 的源码目录清单。世界事实由可信调用方通过 `context.world` 绑定并经原业务校验，模型仅看到目标和情境，不能更换该绑定。主路由开关与源码开关独立；源码启用时允许发送必要片段，关闭时不暴露源码工具。

## 成果引用与主请求重放

`runtime/results.py` 保留请求内有界成果（默认最多 128 项、合计 1 MiB，单项 64 KiB；这是存储/单次输出边界，不是累计任务消耗上限）。只接受已验证且完成业务提交的终态；发布前复核候选摘要，避免提交后被修改。旧项可淘汰，根请求结束即失效，不增加通用成果数据库或模型写工具。

引用绑定根请求、玩家、会话、受众、来源 Agent、权限与外发策略。主 Agent 选择原样交付时，在结果中提供 `result_ref` 并设置 `parts: []`；可信交付层解析原成果，重验玩家表达、容量和取消，不再次调用模型或重复子业务提交。汇总多个成果时，模型生成带证据的玩家段落，并用已验证的成果引用关联结论，仍需核对目标覆盖和未完成事项。运行时只证明证据归属/提交状态，语义准确性还须实际效果验收。

NPC 和主 Agent 使用同一个单份答案转换：模型只写 `parts: [{text, evidence?}]`，规则段落的 `evidence` 非空；非规则描写可以省略。程序按顺序换行拼接 `answer`，从带证据段落提取同文 `claims`，不改写条件、数值或口吻，不新增模型调用。`answer/claims` 是内部派生结果，不再是模型双写字段；现有 socket 响应、成功历史、缓存及成果引用保持原格式。玩家不看到证据元数据，内部证据、入口、未决项和提交检查继续生效；同源只消除重复撰写引入的差异，不证明事实正确。

父上下文只接收摘要、结论、限制和引用；源码片段、参考材料、子工具历史不自动回灌。compact 保留引用与世界回执关联；后台凭据未到 `ready` 时拒绝主结果冒充完成。原样交付同样不能暴露内部引用，或绕过玩家输出与报文大小检查。

NPC 已提交成果的 `conclusions.evidence` 在回传时转换为该成果的 `result_ref`，首次交付与成功缓存重放一致；子任务私有证据 ID 保留在原成果中，不要求主 Agent 猜测或重建映射。原样交付要求 `answer: ""`、`claims: []`；需要综合时省略顶层 `result_ref`，在各结论中引用回传的成果。格式不符返回具体缺口，不放宽归属、提交或证据检查。

`request_cache.py` 在既有 `conversations.db` 中以 `capability_results(namespace, request_id)` 保存已解析的最终成功响应；指纹包含完整请求、身份、会话和有效权限。与旧 NPC `request_results` 隔离，按既有缓存 TTL/容量清理。取消、未完成和失败不写成功缓存；并发重传与重启后重放不再生成。NPC 委派成功另保存有界证据元数据侧表（不含源码正文），父失败重试时可从已提交缓存重新建立本次引用；旧缓存无此信息时不伪造成果证明。模型/Skill 改版不会重做仍有效的成功缓存，需要新任务时使用新编号。

运行 `python -m unittest ai.tests.test_delegation ai.tests.test_router ai.tests.test_results ai.tests.test_request_cache -v` 验证权限、上下文、协调、原样交付和持久重放。标准库客户端已覆盖显式主路由及旧短查询；测试使用假模型和本机临时数据。

## 运行与完成契约

`src/runtime/` 保留小型共享执行循环。Agent 定义包括输入/输出 JSON Schema、专业消息装配、允许工具和技能、资源限制、结果解析及完成检查。模型提出行动，运行时验证并执行工具；工具结果返回模型继续决策。直接路由仅省略主 Agent，并不限制多步调查。

- `single`：世界描写、摘要等明确生成目标，默认一次模型生成；结果不满足契约则报告未完成，不自动增加审稿模型。
- `tool_loop`：依据反馈搜索、读取及修正候选答案；证据充分即交付，需要澄清或存在真实阻碍时给出对应结果，不为凑次数继续调用。
- 终态区分 `completed`、`needs_input`、`incomplete`、`failed`、`cancelled`。持久化 Agent 声明 `requires_commit=True`，生成结果只是待提交候选；业务通过 `runner.commit(outcome, callback)` 提交，完成后才发唯一 `run_end`。提交失败只报告失败，不先记成功；重复提交被拒绝。回调仍需校验业务身份并使用原子事务，运行时不持有业务数据库。
- 通用运行状态只存在于本次请求内；已有业务继续负责去重和持久任务，不新增通用任务数据库或自动跨重启续跑。

完成验证回调为 `verify(result, context)`，通过 `context.state` 访问本轮证据；需要重新读取资料时，业务闭包持有统一工具入口并按原权限调用、共享计账。候选验证与 `before_commit` 之后均执行；验证中的期限或取消直接结算，不反馈成可无限重试的格式错误。公共运行时不导入源码调查或业务数据库。

`Budget` 现在是并发安全的用量账本：累计模型/外部/工具/委派次数和字节不再终止任务。失败、重复尝试及向量/重排请求仍计账，子过程计入所有祖先。权限、单次输入/输出契约、委派拓扑和世界业务额度仍有效，不是取消安全边界。

旧 `Limits` 计数字段和 `Budget.remaining()` 暂留作源码兼容，不再控制执行；不注入剩余次数提示，也不因累计次数禁用工具。支持工具的模型遇到显式空工具集仍传 `tool_choice=none`；不支持工具的纯文本模型不新增该参数。

每次实际派发的模型请求由 `runtime/usage.py` 独立结算，不以共享计数变化推测本次是否已记账。普通调用、内部摘要、compact、向量及重排都记录成功/失败/超时/取消；收到用量后发生截断、取消或后置拒绝仍保留消耗，出站前拒绝不算调用。子账本沿祖先链加总一次，按 Agent、主/子角色、operation、接口类别及模型分组；compact 自己的记录只累加本次压缩调用，不混入并发兄弟请求。

`snapshot().usage` 是各字段的已知小计，`usage_unknown` 是各字段缺失的调用数；`usage_incomplete_reports` 保留原有输入/输出/总量不完整计数，缓存缺失另看 `usage_unknown.cached_prompt_tokens`。服务商 `prompt_tokens_details.cached_tokens` 归一化为 `cached_prompt_tokens`，它是输入子集，不能再加到总 token。无文本输出的向量/重排接口按其输入用量归一化，缺少响应仍是未知。本地向量缓存和持久成功重放不产生新服务商调用，不伪造 provider cache token。

诊断费用由 `MODEL_PRICES_PER_MILLION`（JSON）与 `COST_CURRENCY` 配置。键为 `chat:模型名`、`embedding:模型名` 或 `rerank:模型名`；`input`、`cached_input`、`output` 单位均为每百万 token，不设置当前报价。显式配置缓存折扣时，按 `(输入-缓存输入)×input + 缓存输入×cached_input + 输出×output` 计算；不配 `cached_input` 表示统一输入价，不推测缓存折扣。缺少适用单价、输入/输出用量或折扣所需缓存数据，总费用为 `null`，只列可完整估算分组的已知小计。费用不是账单或消费限制；服务商阶梯/批量/其他收费须由部署者另行核对。

`usage_report()` 只能合并互不重叠的账本，不能同时加父账本和子账本。固定合成探针的“每个通过任务费用”包含失败尝试，按实际通过数作分母；待人工审读的源码探针只列用量/估算费用，不把运行结束当作答案正确。故障无返回用量时不声称精确总费用。用 `python -m unittest ai.tests.test_usage -v` 验证并发、父子、缓存、失败及价格配置。

在线生命周期：NPC 已与游戏端同步启用显式长请求，根上下文 `deadline=None`，摘要、调查和 compact 共享调用方存活检查及取消。socket 循环独立处理 5 秒续约与 30 秒失联窗口，无需等待模型输出；超出原 80/90 秒仍可继续。同编号重传不重跑，在途状态不是终态；终态短期重放缓存有数量、有效期及单包大小边界，持久成功去重仍由业务负责。离线、取消或服务停止后不再启动下一步或提交，迟到模型用量仍记录。短请求的固定期限与单次工具/模型 I/O 超时独立；工具超时可恢复，不把局部 deadline 传播成任务失败。协议见 [通信说明](../daemons/ai_client_d.md)。

模型工具能力由 `CHAT_SUPPORTS_TOOLS` 声明；不支持时明确失败，不自动换模型。旧 `complete_chat()` 仍只交付文本，工具请求不能误作答案。自动测试中的 `ScriptedModel` 验证循环行为，不证明真实模型已经具备预期调查质量。

`ModelResponse.reasoning_content` 单独保留提供方实际返回的思考字段，不要求模型在正文中补写思维链。`CHAT_REASONING_HISTORY=true`（默认）将该字段随完整助手消息留在本 Agent 的工具续行和候选退回历史中；没有字段时原流程不变。更换为不接受该历史字段的提供方时设为 `false`；这只控制本服务回传，不开启思考模式、不改变 `CHAT_EXTRA_BODY`。Qwen 支持型号的 `preserve_thinking` 参数和默认值仍以[提供方协议](https://help.aliyun.com/zh/model-studio/deep-thinking)为准，不自动给所有型号添加该参数。

实际回传的思考纳入上下文计量和 compact，近期完整助手/工具组保留原字段，较早过程随组压缩；压缩响应的思考不拼进工作摘要。用量沿用提供方输入/输出总量，不将已包含在输出中的 reasoning token 再加一次。思考不进入业务成功历史、响应缓存、玩家消息或父 Agent 交付，也不充当可信证据；旧文本包装只返回正文。

### 受限思考诊断

`REASONING_TRACE_FILE` 为空、`REASONING_TRACE_CONSOLE=false` 时不输出思考正文；`DEBUG` 不隐式开启。开发测试可显式设置文件路径（相对 `ai/`）或开启开发终端 stderr 输出，两者独立。普通 Hook 仍只见原元数据，模型历史保留也不依赖诊断开关。由可信环境配置控制目的地，游戏请求、Tool、Skill 和模型输出不能开启记录或选择路径。

每个合法返回的 Agent 模型响应生成一条 JSONL `model_reasoning` 记录，分开保存 `reasoning_content`、正文、工具调用及停止原因，关联根/父子运行 ID、模型 `call_id`、配置指纹、已加载 Skill 版本/hash 和用量。无思考字段时 `reasoning_available=false`，不补造。该事件不是业务完成声明：用 `run_id` / `call_id` 对照普通运行结束事件或评测的 `.events.jsonl`，结合工具结果和最终完成检查分析问题；不能把推理看似合理当作答案正确。

先创建受 OS 权限保护、仅开发者与服务账号可读的目录；建议 `ai/logs/` 下使用独立文件，该目录已被 Git 忽略。Linux 新文件为 `0600`，已有文件开放组/其他用户权限或是符号链接时拒绝写入；Windows 文件继承目录 ACL，须由部署者核对。不得放入公共网页或模型源码授权范围，思考可能复述源码和会话资料，不向不相干人员分发。已知配置密钥会脱敏，不转储完整配置、SDK 对象或异常正文。诊断失败只报安全的观测错误，不改业务结果或重跑收费调用；不从诊断文件恢复模型历史。

离线测试：`python -m unittest ai.tests.test_reasoning ai.tests.test_reasoning_trace -v`。源码效果探针使用同一模型边界，可以通过进程环境变量开启诊断，不需要为每个 Skill 增加入口；诊断记录不扩大源码外发授权。是否改善回答质量仍以真实题集及证据复核为准。

### 模型上下文窗口

`OPENAI_CONTEXT_WINDOW_TOKENS` 默认 `1000000`（十进制 1M），声明当前模型输入与输出的合计窗口；纯文本输出按业务上限预留，JSON 输出按 `OPENAI_MODEL_MAX_OUTPUT_TOKENS` 预留。没有自动模型规格查询，更换模型时须同时核对容量。未设置环境变量才使用默认值，显式空值/非法值不回退；进程环境优先于 `ai/.env`。`Settings` 校验容量、整数类型和输出可用空间，Agent 装配时再次校验其具体输出预留。

窗口从本次选定的模型适配器读取（`ChatModel.settings.context_window_tokens`），不是从根任务或全局环境重新读取。不同配置的父/子模型各用自己的窗口，但权限交集、共享计账和取消不变；本条不代表主 Agent 委派入口已经上线。

当前没有内置专用 tokenizer，`runtime/window.py` 使用明确标注的 `utf8_conservative_v1`：序列化完整 `messages` 和工具定义，取 UTF-8 字节数，加基础 64、每条消息 32、每个工具 64 的封装估算，再预留输出和窗口 1%（至少 64 tokens）的安全空间。覆盖系统/Skill 目录及正文、工具参数与结果、调用 ID 和 Hook 追加内容；中文不会按一字符一 token 低估。此估算通常偏大，不是服务商精确分词或实际计费，不能把样本通过视为所有模型的分词保证。更换服务商/模板时应重新运行合成计量探针，遇到低估应修正估算或接入匹配 tokenizer。

收到有效的服务商 `prompt_tokens` 后，请求内计量器可使用 `provider_anchor_utf8_delta_v1`：已发送且完全不变的消息前缀采用实际输入用量，新增部分仍按保守增量估算。只在模型实例/配置/窗口、工具定义和原消息前缀一致时复用；历史重写、系统提示变化或模型切换时重新估算。缓存命中已包含在输入用量中，不重复相加，也不把输出或累计账本当作当前上下文。缺少/非法用量退回保守估算。主子运行的校准记录彼此独立。

`after_model` 脱敏元数据记录 `context_tokens_estimated`、`context_window_tokens`、`reserved_output_tokens`、`token_estimation`，不记录原始消息；供应商 `usage` 单独计入账本。超过窗口时尚未出站的请求不会产生模型调用计数。模型上下文按配置窗口计算；文本生成使用相应输出上限，JSON 请求按模型最大输出容量预留。工具参数及最终业务输出须通过各自契约。`Limits.input_bytes` 仅限制业务入口载荷，不限制 Agent 累积历史；累计 `total_bytes` 只作观测。

### 自动 compact

`runtime/compaction.py` 在完整工具回合结束、下一次模型请求的 Hook 追加之后检查：估算输入达到窗口 80%，或输出预留不足时压缩较早历史。短请求和正常世界单次生成不增加调用。运行时直接加载 `runtime/prompts/compact.md`，同一运行固定其内容/hash；这不是业务 Skill，不需要 `skill` 权限，也不新增模型工具或递归 Agent 循环。

压缩沿用当前模型适配、外发检查和前后 Hook，`operation=compact`、工具集为空；用量与取消仍属于原请求。系统消息、当前目标、加载的 Skill 完整工具组和最新完整工作组保留，正常优先保留较多近期历史；容量不足时可将较早的近期组纳入压缩。材料按完整消息组分段，不拆开一个 assistant 工具批次与其结果。正常分段先预留本次摘要的输出空间，不能为了塞入更多历史而把输出挤到很小；只有单个不可拆组仍放不下时才缩小预留。保护部分确实无法容纳时明确失败。

模型只生成文本工作摘要，可使用段落或 Markdown 列表，不要求固定标题、JSON 或逐项复制证据 ID，也没有摘要格式修复分支。程序直接将被压缩材料的证据关联保存在请求内，后续再次压缩时继续携带；模型没有重复写出 ID 不会丢失关联，文本中声称的新引用也不能成为已读证据。

新摘要先进入临时候选：确认文本非空、未截断且没有工具请求；运行时核验状态指纹与原证据记录，重插受信任目标/事实/待办及证据 ID 索引，再计算完整候选容量。不机械复制全部含数字的源码片段或重复展示每条快照的校验 hash，避免这些内容随调查增长而成为无法压缩的负担；相关条件和数值由工作摘要保留。完整原始证据及 hash 仍在运行时账本中，摘要关联也不丢失，最终业务引用继续回查原记录。候选必须确实缩短且能预留输出和安全空间，才原子替换消息。权限、取消、调用去重、提交状态不从摘要重建；资料与摘要始终标为非指令。文本有效或 ID 存在不能证明语义无损，关键条件和数值另用任务续行回归验收。

80% 是整理触发线，不是第二个容量硬上限。“压缩不足”指摘要偏长或所选范围较小，导致完整候选仍接近/超过窗口；先根据原始材料降低摘要目标、调整输出预留或扩大完整组范围，不立即结束任务。若可压缩范围已处理、保留内容导致仍超过 80%，但候选确实变短且输入加输出仍可容纳，允许继续。真正装不下时明确报告，不截断必需指导或工具组。

日常恢复只针对无业务副作用的摘要：临时连接故障、超时及 HTTP 408/429/500/502/503/504 沿用退避与 `Retry-After`；持续故障使用 Agent 已配置的单次操作 timeout 作为恢复观察窗口，不设置累计任务调用上限。等待可取消，且不延长调用方寿命；每次尝试重新经过权限/Hook 并记账。空白或截断摘要明确失败并保留旧历史，不再通过 JSON 修复提示重新生成。持续故障、取消、Hook 拒绝或状态变化同样不覆盖历史，不假报业务成功。

摘要自身超窗缩小完整分段或输出预留，不误触发业务重试。仅服务商明确的普通业务上下文超窗允许一次压缩后的不同业务请求；普通业务 HTTP 400/超时/截断不走摘要恢复入口。恢复不重跑已执行工具、不重提世界任务、不重复提交。

每次压缩记录原因、提示词 hash、前后估算口径、结果、调用和服务商用量，不记录原历史。`usage` 是已知小计；`usage_incomplete_calls` 和账本 `usage_incomplete_reports` 标明缺失/不完整用量，不能把小计 0 当作免费。缓存数据和按配置估算的费用见上方账本说明，不以 token 估算器代替服务商用量。

离线回归：`python -m unittest ai.tests.test_context_window ai.tests.test_compaction -v`，覆盖多轮调查完成、连续三次文本压缩后的原证据/关键数值/待查项、短请求零额外调用及常见故障恢复。`verify_context_window.py` 默认预览三个合成计量样本，授权后 `--execute` 各请求一次，可用 `--case tool_history` 单独验证。`verify_compaction.py` 用本次进程的 24K 小窗口核对文本压缩后的业务答案与运行时证据关联，默认预览，`--execute` 才调用模型，不修改 `.env`。两者均不读取游戏/玩家资料，不自动重跑测试，不替代业务准确率评测。

### 连续无进展检测

`tool_loop` 使用请求内 `Progress` 检测反复等价行动，反馈改查路径或补齐缺口，不按固定轮数终止。旧 `Agent.no_progress_limit` 仅为定义兼容保留，不是执行上限；不额外调用评判模型，也不自动重提工具或提交业务结果。

工具比较使用 Hook 调整并通过验证后的实际参数，JSON 对象键顺序与排版不影响判断；证据记录的观察 ID、读取时间和列表顺序不算新事实。源码成功取证按 scope、路径、文件 hash/版本及每行内容保留指纹，跨查询累计已见行：换关键词重获已读内容、改变相同行的分块方式不算新证据；新增行、内容或版本变化仍算进展。搜索命中后的首次正式读取也算进展，搜索本身不能替代业务要求的读取；进展指纹不授予引用权、不改变原始证据校验。空结果、错误及其他工具仍比较实际参数/结果，第一次无命中不妨碍换词继续。反复改写候选答案但验证缺口不变不算进展，已验证缺口首次减少可继续。检测不保存私有推理，也不证明答案语义正确。

同一模型回合的工具批次全部按权限/取消规则处理后，再判断该轮进展。首次无命中、跨文件调查、合理重读不触发停止；模型仍须达到完成契约，或明确提出澄清/实际阻碍。成功完成检查后清除已解决待查项；取消或调用方失效仍优先终止。`single` 和无需工具的简单任务不因进展观测增加调用。

### 已接入的业务

- `npc_dialogue`：默认 `tool_loop`，角色来自配置，历史/关系限定当前 NPC 与玩家。模型按需调用共享 `knowledge.search`；源码默认启用，可按需加载源码 Skill 并调用 `source.search/read`，输出调查记录及实际读取的引用。候选和提交前均通过统一工具复查版本，学习/施展、门槛/消耗、依赖/替代路径由专业指导核对。只有完成并原子提交历史/关系/成功去重后才报告完成；澄清和未完成仍用旧 `response` 交付但不写成功记录。引用和记录检查不证明完整语义正确性，真实模型效果仍待固定题评测。
- `conversation_summary`：内部 `single`，正常样本一次模型调用；成功摘要经提交边界更新水位，失败保留原历史。与本轮问答共用根账本和取消，长请求不新建总期限；只载入摘要 Skill，无检索、源码或委派权限。
- NPC 不按累计模型调用次数或长请求总时长终止，摘要/问答/检索共享账本；`REQUEST_TIMEOUT` 仅保留旧短请求契约。未授权委派不开放。配置检索阈值是工具下限，模型不能调低，值为 1 禁用召回。
- `world_narration`：独立 `single`，每次队列尝试最多一个模型调用及一次 Skill 预加载，总期限至多 90 秒。仅发送规则事实，不发送 NPC 历史或玩家资料。候选经 `runner.commit()` 写库，提交时复核期限、停机、任务尝试/租约和冻结清单；失败不发布。持久队列、最多三次尝试、日额度与 JSON 原子发布仍由 `world/` 负责，429 的安全退避信息不会在运行时丢失。

### 可信入口与权限交集

入口策略由服务端组装，UDP 自报 `admin`、`scope` 或 `policy` 不授予权限。NPC 默认获得同一仓库的源码工具和公开知识；关闭源码后仍可文档问答。世界仅有描写 Skill，摘要无源码工具，主 Agent 默认关闭，递归委派不开放。UDP 是可信游戏进程的本机通道，不验证最终玩家身份，不应暴露到不可信网络；`player_id` 的真实性由游戏端保证。

- `Settings.runtime_policy` / `RUNTIME_POLICY` 提供部署上限，默认 `{}`。可收紧工具、Skill、scope、外发 scope、Agent 及知识文档路径；省略字段不额外限制，空数组拒绝全部，未知字段或非法值启动失败。不会因配置一个新工具名而注册或授权它。本地诊断同样遵守上限，索引构建仍是独立可信管理操作。
- `Policy.restrict()` 与 `intersect()` 只取交集。NPC 的可选 `knowledge_paths` 是公开索引相对文件名的通配白名单，各层之间 AND、单层模式之间 OR；`knowledge_base` 仍只是人设文本，不能充当授权。路径过滤在本地候选、向量匹配和外部重排前执行；始终排除的私密路径不因通配而放开。
- `bind_context()` 绑定请求、actor、固定受众及会话，NPC 会话为 `[npc_id, player_id]` 的 JSON。可信内部父调用在读历史/记忆前核对这些身份，保留父权限上限、根预算、取消和更短期限；Agent 进入时再取其定义的交集，并使用新状态。该入口不代替后续 `agent.invoke` 的业务容量、委派深度与完成契约。
- 工具重放、向量缓存使用包含全部权限和文档范围的指纹。NPC 成功缓存保留旧 `request_results` 四列格式与请求内容指纹，新增 `request_authorities` 附表原子保存会话/权限指纹，并随 TTL/容量回收。权限冲突拒绝旧结果，不自动重跑；无附表记录的旧缓存仅允许关闭源码且其余公开直接入口策略未变时重放。升级/回退备份须复制整个 SQLite 数据库，不能只复制单表；回退后新增的旧格式记录仍受上述兼容限制。

源码工具统一使用 `SOURCE_ENABLED=true` 与 `SOURCE_ROOT=..`，根目录相对于 `ai/`，可覆盖为另一游戏仓库；关闭时不要求源码目录存在。默认允许必要片段外发，始终排除敏感文件与实际配置的私有目录，不上传整个仓库。模型只指定相对路径/查询/行区间，不选 scope；NPC、主 Agent 与本机诊断共用一套边界，不按角色、Agent 或受众拆目录权限。保留工具许可、父子权限交集和知识/会话隔离。旧 `SOURCE_SCOPES_FILE` 和角色 `source_scopes` 必须显式迁移，否则报错；根目录/排除/策略版本纳入成功缓存指纹，普通闲谈不强制调查。详见 [源码只读范围配置](ai-source-access.md)，包括用量、证据复查与验证边界。

`scripts/debug_source.py` 提供 OS 身份保护的本机诊断，不注册网络路由，不靠报文授予 `admin`。复用 NPC 规则 Agent 与同一 Runner，只因不写业务数据而使用无提交回调的定义；正式 NPC/世界的持久化完成检查不变。玩家投影不发送路径/函数/内部记录，管理员投影再次核对授权并显示证据快照，不声称实服已加载。CLI 默认预览，显式执行需要范围及外发许可，报告独占新建于受保护目录；诊断成功仍需人工核对语义。

效果基准使用本游戏实际源码，开发者须先核对结论与依赖并记录位置；合成材料用于循环、安全和计分机制的自动回归。`evals/game-source-questions.json` 维护真实问题与固定公开文件清单，`scripts/eval_source.py` 默认只预览、本机可核对快照；真实测试需清单外发授权。源码改变须重新核对结论，不能自动刷新 hash 把旧答案当最新答案。

同一评测支持 `--route direct` 和 `--route coordinated`，分别经过 NPC 或真实主协调业务，不增加第二套模型循环。评测仍只复制固定题的允许文件，不因默认仓库访问而读取更多文件；协调者和 NPC 共用此临时仓库，主 Agent 可直接处理或委派，实际委派次数单独记录。报告用 `source_access` 标记范围模式与策略版本，不能和旧逐 Agent 授权或全仓库诊断混作同条件对照。逐运行报告保留模型/窗口/输出预留、上下文峰值、调用状态和用量，主账本已包含子调用，不重复累计。最终引用投影只展开被父答案采用的已提交成果，未引用子资料不能成为计分依据；语义关联仍须审核。`--compare` 只离线对照同题同模型报告，未完整人工验收不声明等质、节省比例或每个正确答案成本，操作步骤见 [固定题评测](../../ai/evals/README.md#直达与主-agent-对照)。

## Hook 与安全责任

工具输入不符合契约时，反馈错误代码及该授权工具原有的参数定义，让模型自行修正参数；不返回私密参数值或 SDK 异常正文，不替模型改写参数，也不放宽权限。

Hook 是部署代码中固定注册的受信任回调，不是模型安装的插件。事件覆盖运行、模型、工具和提交边界；普通观测只获取脱敏元数据，不接收原始 SDK 客户端或数据库连接。需检查原始内容的干预必须显式配置，并仅获得该事件需要的数据。

固定事件为 `run_start`、`before_model`、`after_model`、`before_tool`、`after_tool`、`before_commit`、`run_error`、`run_end`，按注册顺序处理。拒绝后不再运行后续干预，但观测仍继续；拒绝不能被后续允许覆盖。事件为递归只读视图，Hook 内递归触发本调度器会被拒绝。

| 干预时机 | 允许的作用 |
| --- | --- |
| `run_start` | 允许、拒绝或取消 |
| `before_model` | 仅追加 `additional_context=[{"text":"补充资料","scope":"已授权范围"}]`；合计至多 8 KiB，不能整体替换系统消息；阅读及外发许可均须通过 |
| `before_tool` | 仅修改 `arguments`，之后重新验证参数 schema 与实际资源权限 |
| `after_model`、`after_tool`、`before_commit` | 允许、拒绝或取消，不能偷换模型原文、证据或待提交结果 |
| `run_error`、`run_end` | 仅观测，不能回头改变终态或重复提交 |

模型和工具调用成功、失败、超时、取消都产生一次对应后置事件，前置拒绝记录 `executed=false`。后置事件描述该次操作的执行结果，不等于业务已经提交。实际模型用量在后置干预前计入共享预算，即使干预拒绝也不能抹去消费。

观察者失败被隔离；必需干预失败或超时关闭相关操作。身份、权限上界、受众、期限和预算不可由 Hook 修改。回调有并发和等待上限，取消后仍通知终态观察者；Python 超时不能强杀已经开始的可信回调。Hook 不是恶意代码沙箱，不应持有可变业务连接或承担外部写入职责。

默认轨迹只记录关联 ID、Agent/策略、阶段、用量与错误类别，不记录玩家原文、完整提示词、源码或私有推理。读取权限、资料外发与业务成功提交是不同检查点，最终隐藏路径不等于输入资料已经安全。

## Tool 接入

在受信任的 `src/tools/` 模块中提供 `build_tools(services)`，返回 `Tool` 声明；装配调用 `tools.discover("src.tools", services)`。新增部署工具无需增加中央名称分支；模型不能指定 Python 导入路径。启动发现不等于授权，Agent 仅看到有效策略允许的工具，并固定本次运行的注册表。

声明包括稳定名称/版本、说明、参数及结果 `Contract`、handler、authorize、`read_only`、`concurrent_safe`、`timeout`、`cancellation`、`max_bytes`、`resource` 和 `cost`。同一次运行中工具顺序执行；成本标记用于审计，内部模型请求仍必须经过共享计账边界。协议工具名把点号编码成双下划线，例如 `knowledge.search` 对模型为 `knowledge__search`；注册时拒绝别名冲突。

程序和模型均通过 `tools.execute(name, arguments, context, call_id)`，不直接调用 handler。成功返回 `ok/value/call_id`；可恢复失败返回安全错误码与 `recoverable`，供模型调整调查；取消或期限失败停止本次运行。相同 ID/参数可复用结果，不重复执行；参数、身份、会话、受众、策略或工具权限上界发生变化时，旧 ID 不能重放结果。

工具有有界等待及固定线程容量，超时不接纳迟到结果或证据，未结束的可信 handler 仍占用容量。`concurrent_safe=False` 的同名工具在同一注册表内跨请求串行化，超时后也须等实际 handler 退出才释放门控。handler 必须遵守传入的 deadline/cancellation 并保持只读，不把超时线程当作可安全强杀的沙箱。目前没有写文件、删除、Shell、任意联网或游戏数值修改工具。

## Skill 接入与版本

构造 `Skills(settings.skills_dir)` 扫描业务目录，并将其交给工具发现和 `Runner(..., skills=skills)`。每个包为 `<name>/SKILL.md`：YAML 元数据必需 `name`、`description`、`version`，可选 `resources` 和 `allowed-tools` 列表；正文按场景提供必要指导，不统一要求方法、检查清单或正反例。包名必须与目录名一致。新增包后重启装配以重新扫描；本次运行已经固定的正文不会因维护者编辑而改变。

模型提示词自动包含已授权技能的名称和说明，不预先注入全部正文，也不用调用列举工具。所有包只共用一个 `skill` 工具：

```json
{"name":"source-investigation"}
{"name":"source-investigation","path":"references/checklist.md"}
```

直接生成通过 `Agent(required_skills=("world-narration",), mode="single", ...)` 预加载，同样经过工具授权、预算和 Hook，不增加模型轮次。禁用 `skill` 时不显示可调用目录；必需技能也不能绕过限制预加载。

每次运行固定元数据、正文和声明资源的 hash，记录实际加载内容。尚未读取的资源若发生变更则返回 `skill_changed`；已安全读取的快照可在本次运行复用。损坏的可选包不影响其他包；必需包不可用时拒绝相关运行，不隐式回退源码内提示词。

`SKILL.md` 和单个资源至多 32 KiB，每包资源合计至多 64 KiB。超限明确失败，不发送截断的专业指导；大篇资料应拆分为按需参考文件。资源仅允许包内声明的 `references/`、`assets/` 下 `.md/.txt/.json` 文件，使用最终对象安全校验，不执行附带脚本，不读取开发用 `.agents/`、`.codex/` 或 `.claude/`。技能内容属于维护者批准外发的专业指导，不应混入玩家隐私或密钥；`allowed-tools` 只能缩小已有权限，不能授予能力。

维护 Skill 时优先给出目标及专业知识；只有明确场景才规定工作流，其余步骤由模型自行选择。语义变更须更新 `version`，同时检查运行日志中的 hash。NPC 指导负责角色与玩家表达，源码指导负责调查方法，不在多层重复完整调查流程，不为评测题添加特例。调查以回答原问题为完成标准，只有可能改变答案的缺口才继续追踪；单项检查和整个操作需要的依据不同，不将局部满足扩大为整体保证，也不因精简而省略关键依赖。

先用固定假模型测试加载、证据和提交合同，再以获准的固定真实源码题集检验自主调查。对照时固定模型及请求参数、题目和源码快照，通过 `SKILLS_DIR` 指向修改前后的独立技能快照，并核对报告中实际加载的版本/hash；脚本不得覆盖该目录。逐题审读答案与工具过程，区分格式、语义、调查范围和耗时，不能以离线测试或少数题改善代表全部效果通过。角色更换应修改配置而非提示词源码；世界合理补白、空间事实和玩法承诺边界见 `world-narration`。Skill 升级不改变内容键、不覆盖旧正文，也不重算已有聊天关系。

## 迁移与回退

先验证临时数据副本，再部署。保留 NPC 历史、关系及有效去重记录，保留世界内容键、任务状态、调用额度和成功正文；架构、模型或 Skill 升级不自动重生成已有内容。

部署切换前停止接收新请求并处理在途工作，按业务说明备份。回退保留原数据和必要审计，不删库、不用示例覆盖配置，也不同时启动两个共享业务库的写入方。源码默认启用；此前不使用源码的部署升级时须显式设置 `SOURCE_ENABLED=false`。主 Agent 入口仍默认关闭，实际目录、外发与付费效果测试须符合部署授权。

`python ai/scripts/verify_upgrade.py` 是离线兼容演练，不操作正式部署：从本地 Git 导出固定基线 `2f8192a5356af2e2306392132a7406715a85c44b`，复制当前服务源码和 Skill，在独立进程中依次执行旧版写入、当前版升级、旧版回退、再次升级。这四阶段显式保持源码关闭，以验证原业务能力边界下的数据兼容；另在旧版写入后插入独立阶段，验证默认开启源码时拒绝权限不明的旧缓存，不调用模型或改写对话/关系。不能把策略变化的缓存拒绝误判为数据丢失，也不能为兼容演练放宽检查。

每阶段退出后才复制临时数据；核对旧/新成功聊天重放、历史/关系/摘要、世界正文 hash、未完成任务租约与额度，以及取消后无迟到提交。演练已由 `ai/tests/test_upgrade.py` 纳入全量回归；测试环境须有 Git 及上述本地提交，全程使用假模型，不读取 `.env` 或玩家数据、不切换工作区、不自动下载缺失的历史提交。

演练通过只证明这份夹具的持久数据兼容，不证明旧版具有新版源码授权、主 Agent 或长任务能力。正式回退应同时停止新入口，并配套恢复已验证的游戏端短请求接入；依赖新版权限隔离的部署不能因旧版仍能读库就继续开放，无法保证原权限时应停用 AI。完整备份须使用 SQLite 一致性备份或在所有写入方退出后复制，不能在线只拷主 `.db` 而遗漏 WAL，也不能只恢复单表。新主路由缓存/授权附表可保留，但旧版不解释其新语义。

部署后检查 NPC 回复、断线旧回复处理、世界正文发布及服务不可用时的玩家提示。历史验证结果见[运行时验收记录](ai-runtime-validation.md)。

## 自动验证

```sh
python -m unittest ai.tests.test_portable ai.tests.test_lifecycle -v
python -m unittest discover -s ai/tests -v
python ai/scripts/verify_upgrade.py
python ai/scripts/verify_runtime.py
python ai/scripts/verify_business_agents.py
node ai/scripts/verify_lpc.mjs
node tools/tests/test_illusion_world.mjs
```

`test_portable` 将服务源码复制到无 MUDLIB 的临时目录，使用另一套人物/知识和假模型，通过真实本机 UDP 验证对话、摘要及数据归属。测试不消耗外部额度、不读取玩家存档；Linux/Windows 专属项必须在对应平台验收，跳过不代表通过。

`verify_runtime.py` 默认只显示计划。取得授权后执行 `python ai/scripts/verify_runtime.py --execute`，仅发送两个固定合成规则任务，不设累计调用/总时长截断，不自动重跑失败批次，不连接业务库或游戏。可用 `--model` 单次覆盖模型，不修改 `.env`，未配置该模型价格时费用为未知。报告列出结果、耗时、分组用量、费用口径和事件状态；这不是正式源码问答准确率评测。当前进度与实际验证记录见 [运行时验收记录](ai-runtime-validation.md)。

`verify_business_agents.py --execute` 仅使用临时角色、知识、历史、冻结清单和业务库，验证摘要、共享工具问答、重放和世界发布；默认仅预览，执行时不设累计调用次数上限。报告使用互不重叠的 NPC 请求账本与世界运行账本，包含失败消耗；输出含合成答案供人工审读，数值检查兼容中文数字，不把“二百”误判成缺少 `200`。

### 本地诊断与索引维护

`debug_chat.py` 使用单次 Runner；`debug_retrieval.py`、`bench_retrieval.py`、`bench_cache.py` 经 `src/diagnostics.py` 装配同一个 `knowledge.search` Tool。它们没有网络管理路由，不读取玩家历史；本地身份来自执行脚本的 OS 权限，不能由 UDP 载荷指定。查询共用权限、候选预过滤、用量、取消及 Hook；性能/缓存测试按有限题集共享父账本，不设隐式批次总期限。模型/工具单次 I/O 故障超时仍有效；可信调用者显式传入的 deadline 保留。诊断的分数与较高条数限制只属于 CLI 装配，不扩展普通 Agent 的工具契约。

连通性检查最多 1 次模型调用；混合检索每题最多 2 次外部请求，离线 BM25 为 0。工具上限 30 秒、64 KiB，诊断正文总计至多 16,000 字；超限明确标示部分资料，`--full` 不绕过限制。异常正文不直接输出，客户端在正常和失败路径均释放。

`ops_build_bm25.py`、`ops_build_vectors.py`、`ops_update_knowledge.py` 和启动器的知识更新属于受信任索引维护，不是 Agent 调查或模型可调用工具：可更新 BM25/文档向量，配置 `KNOWLEDGE_UPDATE_ENABLED` 控制启动更新，已有逐文档落库及断点重试保持。批量建索引不占某次玩家问答的预算，也不得被注册为模型工具；`HELP_DIR` 应只存放获准索引和外发的公开知识。`ops_world_content.py` 的生成仍经世界业务队列，备份/恢复/重发布由受限管理命令负责。静态回归禁止诊断脚本直接调用模型或检索内部接口，新增业务不得把维护入口用作执行旁路。
