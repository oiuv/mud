# 武器分类与同名品种核对

本清单对应 `normalize-weapon-classification`，基线为 `97858beb`。只核对源码与临时测试对象，不读取正式存档。实现与最终集成验收分开记录；本文件不表示已可无损更新旧物品记录。

## 范围与验证方式

覆盖已迁移的 axe、blade、club、dagger、fork、hammer、pin、staff、sword、throwing、whip 十一个原武器表，合计 293 份定义；归并 19 份后为 274 份，fork 的唯一品种移入 spear。普通 ITEM 乐器不是这批武器定义；特殊实体武器只按分类方案修正，不进行数据化归并。

- 28 组玩家同名候选逐组核对完整属性及当前引用。颜色、输入别名或地域来源本身不构成必须保留的品种差异。
- 归并沿用一个现有代表版本的整套属性，不组合最优数值。原输入别名及原首字母简称合并保留；`tiechui` 的“沈重／然後”统一为“沉重／然后”。
- 自动比较：`node tools/tests/audit_weapon_normalization.mjs`。以基线提交中的完整数据表为准，只接受 `tools/tests/weapon_classification/normalization.json` 列明的移类、归并、别名及上述文字差异；其他字段必须逐 token 相同。
- 历史 `tools/tests/*/baseline.json` 不改写。21 个历史物品静态审计及 21 组隔离驱动物品回归均已通过；剑、刀、锤、棍、鞭及斧枪针的数据生成器输出当前规范，`renderHistoricalDefinitions` 仅供核对旧阶段。归并预期使用冻结的目标代表物品核对全部属性、买卖及装备加成，原物品仍独立验证；只有清单中的移类、归并与文本修正可改变结果。具体范围、检查数及历史夹具警告见变更的 `verification.md`，不等于实服或旧存档验收。
- 引用审计同时比较 86 个文件中的物品路径顺序和出现次数，以及 13 处完整货表／随机池字面量；显式售价、数量、数组重复权重保持，归并没有造成 mapping 重键。该检查不读取既存商店存档，也不改变玩家手动重新标价的原有机制。

下列路径均省略 `/d/items/`。重量单位沿用代码，数值为 `weight / damage / value`；不是商店显式定价。

## 交付边界

删除路径清单以 `normalization.json` 的 moves 和 merges 键为准，共 25 条旧规范物品路径，不包含各批更早的实体来源路径。不存在运行期转发。隔离物品夹具将旧实体到品种的映射与本清单组合；历史元数据仍保留当时的目标，不代表这些旧目标现在仍有效。独立离线转换工具的当前目标适配尚未验收，不能直接用旧映射处理本批删除的路径，也不能为测试通过改写历史基线。

**正式仓库、商店和 NPC 装备存档没有查验或转换。** 例如武林盟主旧记录可能仍保存 `sword/changjian5`，不能将默认配装代码更新解释为已转换其存档。上线存量处置由管理员另行决定。
