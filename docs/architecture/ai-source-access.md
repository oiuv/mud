# AI 源码只读范围配置

源码访问使用 `source.search` / `source.read`，可配置通过统一 `exec` 调用 CodeGraph 做优先符号定位。默认读取当前仓库中的源码，允许将回答所需片段交给配置的模型，不上传整个仓库，不提供任意 Shell、执行 LPC、写入、删除或任意网络请求。模型只指定仓库相对路径、查询及片段范围，不能指定根目录或修改权限。

## 接入范围

NPC 和已启用的主 Agent 共用一个仓库边界，支持多文件调查、提交前证据复查及玩家正文投影。管理员证据视图仅通过本机诊断提供；世界和摘要没有源码工具。网络载荷中的 `admin` 或 `policy` 字段不能授予权限。

效果评测使用独立版本的真实源码题集，操作与审核规则见[固定题评测](../../ai/evals/README.md)。

## 部署配置

在 `ai/.env` 中配置：

```dotenv
SOURCE_ENABLED=true
SOURCE_ROOT=..
```

默认根目录是服务目录 `ai/` 的父目录。相对路径始终以服务目录为基准，与启动 cwd 无关；其他 MUD 可填写自己的仓库绝对路径，无需改代码。进程环境优先于 `.env`，修改后重启。根目录不存在、不是安全目录或配置非法时明确报错，不回退到其他目录。独立部署不需要源码时设置 `SOURCE_ENABLED=false`，此时不要求源码目录存在，文档问答仍可用。

统一排除隐藏文件/目录（含 `.env`、`.git/`、`.codegraph/`、`.zread/`）、密钥/凭据、玩家存档、数据库、日志、备份及构建/依赖/生成缓存。另按实际配置排除 `DATA_DIR`、`WORLD_CONTENT_DIR` 和思考诊断文件所在目录，避免将这些私有路径改名后读入。只读取允许的文本源码扩展名；不对文件内容自动识别秘密，开发者仍不能把凭据写进普通源码。

NPC、主 Agent 和本机诊断共用该边界；玩家/管理员仅影响结果展示，不改变可读文件。保留工具许可、知识库范围、父子权限交集及会话隔离，`RUNTIME_POLICY` 仍只能收紧能力，不能越过全局开关或敏感排除。内部证据的 `scope=repository` 是固定身份标记，不是模型选择项或部署权限矩阵。

### 从旧配置迁移

1. 移除环境中的 `SOURCE_SCOPES_FILE`，按新格式设置根目录及开关；旧 JSON 文件不再加载，也不自动删除。
2. 从角色配置移除 `source_scopes`，保留人设和 `knowledge_paths` 等文档配置。残留旧环境变量或角色字段会明确报错，避免悄悄扩大访问。
3. 检查已有 `RUNTIME_POLICY`：旧源码别名不再适用；取消针对旧别名的限制，用全局开关控制源码访问，保留需要的工具/知识限制。
4. 若此前关闭源码，升级时显式设置 `SOURCE_ENABLED=false`；不要直接用新默认值替代旧部署选择。原来的多范围权限矩阵不自动映射成新仓库配置。

根目录、统一排除及源码策略版本进入成功缓存指纹。权限改变拒绝旧缓存，不自动重新付费生成；无权限元数据的旧 NPC 缓存仅在关闭源码且其余公开直接入口策略未变时重放。同编号、同内容、同权限的重放返回原已提交回答，**不是重新调查当前源码**；重新查证须使用新请求编号。

因此，仅升级服务并保留原文档问答能力时应明确关闭源码；决定启用源码时，先按部署流程结束在途请求并备份，不把旧缓存拒绝自动改成新编号重试。该行为不删除旧对话、关系或缓存；恢复原兼容策略后，有效缓存仍可重放。离线升级演练同时检查两种情况，见[迁移与回退](ai-service.md#迁移与回退)。

普通角色和源码调查均不按累计调用次数或任务时长终止。保留单次 I/O 超时、取消、证据与提交检查；简单闲谈不强制调查或委派。固定题继续使用原源码/Skill 快照，临时仓库只放本题允许的文件；全仓库诊断单独标记范围及策略版本，不能混作原对照结果。

## 调用与证据

可信业务将 `load_sources(settings)` 传给工具发现入口的 `sources` 服务项，`settings` 服务项控制可选 CodeGraph 注册。模型调用及程序复查均通过 `Tools.execute()`，禁止绕过工具边界。调用示例：

```json
{"query":"contribution","limit":5}
{"query":"query_skill","path_glob":"feature/*"}
{"path":"skills/example.lpc","start":20,"end":70}
```

首次读取得到 `scope/path/start/end/content/hash/read_at/origin/revision`；继续读取同一文件时传回 `expected_hash`。内容变化返回 `source_changed`，应重新调查，不能拼接不同版本。`origin` 区分搜索线索和实际行读取。证据仅说明磁盘快照，不证明实服已加载该版本；源码注释中的指令仍是资料，不能提升权限。

搜索为区分大小写的字面量匹配（内容或相对路径），至多返回 10 条；每次最多扫描 4,096 个目录项、256 个可读文件、4 MiB 正文。单文件上限 256 KiB；读取最多 200 行、片段 24 KiB；单条搜索行至多 2 KiB，工具等待上限 5 秒。达到限制返回 `truncated:true` 或安全错误，不能解释为完整范围内无结果。空文件没有可引用行；非完整文件片段明确标记截断。

长行搜索返回命中附近原文及 `start_column/end_column`，而不是跳过整行；列为从 1 起、含两端的 Unicode 字符位置（不是 UTF-8 字节）。用 `source.read` 传回同一行、列范围和 `expected_hash` 可补读该片段，例如 `{"path":"data/e2c_dict.o","start":2,"end":2,"start_column":100,"end_column":200}`；实际位置以搜索结果为准。列参数须成对使用且限单行，普通行读取不变。片段仍带整文件 hash，提交前按同一行列回查；管理员证据及子任务引用保留列位置，评测不会把部分列当作已读整行。

`query` 是一个连续字面字符串，空格不是多关键词连接符；例如查 `query_skill`，而不是用 `query_skill force` 表示两词同时出现。可选 `path_glob` 是区分大小写的相对路径通配模式，使用 `/`，支持 `*`、`?`、`[]`，`*` 可跨目录。搜索从其固定目录前缀开始，例如 `feature/*` 不先扫描无关目录；过滤在读正文前生效，不绕过敏感排除。大范围查询仍可能截断，应根据线索缩小目录重查。文件内容有命中时只返回命中行；仅路径命中时每个文件只返回一条定位线索，避免同一文件占满结果。搜索线索仍须正式读取后才能用于结论。

### 公共技能名称字典

`data/e2c_dict.o` 是本游戏公开名称映射，作为精确文件例外接入现有工具。可按内部标识或中文名搜索，例如 `{"query":"mathematics","path_glob":"data/e2c_dict.o"}`，再按命中行列读取；必要片段可交给当前配置模型。服务不预加载整份字典、不执行或恢复 LPC 对象，也不枚举同目录的私密存档。

例外只解除这一文件的目录和扩展名过滤：其他 `data/`、`.o` 文件、实际配置的服务私有目录及链接仍不可读。`SOURCE_ENABLED=false` 同样关闭字典；替代仓库只使用自己的同路径文件，没有时不回读本项目，也不妨碍其他源码查询。新增公开文件范围进入权限指纹，旧成功缓存不会被误当作新权限下的调查结果。

专项回归：`python -m unittest ai.tests.test_public_dictionary ai.tests.test_source_investigation ai.tests.test_router ai.tests.test_source_evaluation -q`，使用临时数据和假模型验证搜索、读取、版本回查、业务交付及部分列证据覆盖，不代替真实问答效果评测。

### 可选 CodeGraph

`CODEGRAPH_ENABLED=true` 通过唯一 `exec` 注册 `codegraph` 程序，NPC、主 Agent、本机诊断复用；源码关闭或工具未授权时不可用。`CODEGRAPH_COMMAND` 保留管理员指定程序名、路径或 JSON argv 前缀，Windows 支持正常 `.cmd` 和带空格路径，不要求包内 Node/JS。`CODEGRAPH_OPERATIONS` 默认仅 `explore`，明确配置才开放其余 `query/callers/callees/impact/node/files`；每项执行同名 CLI 命令。旧工具上限需管理员明确迁移为 `exec`，不会自动扩权，详见[配置迁移](ai-cli-tools.md#codegraph-与迁移)。

索引须位于 `SOURCE_ROOT/.codegraph`。维护者可在自己的仓库配置 `codegraph.json` 的 `{"extensions":{".lpc":"c"}}` 后建库；不要覆盖已有配置。CodeGraph 1.6.0 实测默认不收录 `.lpc`，映射后可定位函数，但 C 解析器并不能完整理解 LPC，继承/动态调用存在漏边。中文正文也可能查不到；这些情况用文字搜索与读取补查，不反复强制查询索引。

工具过滤候选路径及关系两端，用现有安全读取返回当前片段、行号、hash 和证据 ID。索引范围仍为线索，检测到起始位置不匹配时标记 `index_outdated`，不把旧位置当成目标函数。缺索引、缺 CLI、未命中、超时分别反馈；单次结果有界，取消会清理本次进程组/进程树并回收直接子进程，不发送 stderr、索引统计或私密候选。最终答案继续按原证据校验与版本复查。

**职责边界：** 管理员配置和授权外部工具，Tool 提供调用功能，Hook 按部署策略控制风险操作是否执行；不干预外部工具自身的缓存维护等内部行为。CodeGraph 1.6.0 查询时可能修复自己的索引，这是工具内部行为，不要求索引零写入。适配器不强制设置 `CODEGRAPH_NO_DOWNLOAD`，保留管理员的 `CODEGRAPH_*` 进程配置；不向子进程传递 AI 服务密钥。模型仍不能选择程序或主动调用建库、同步等管理操作，返回内容仍须经过源码边界和证据校验。

### 调查结果与完成检查

NPC 通过唯一 `skill` 工具按需加载 `source-investigation`，自行选择搜索、入口、调用/继承/宏和替代路径，不执行源码，也不按题目硬编码搜索流程。模型输出采用单份答案契约：`parts` 按顺序包含玩家可读的 `text` 段落，已核实规则附非空 `evidence`，明确标注的推断及非规则描写另成段并省略该字段；`investigation` 只记录 `subject/phase/entry`（主体、动作阶段、入口引用），`pending` 保存未决事项。NPC 与主 Agent 共用 `ai/src/npc/agents.py:parse_reply`，将段落原样换行拼接为内部 `answer`，从带证据段落派生 `claims`，不要求模型另写两份事实。调查结构由 `ai/src/npc/investigation.py` 及业务结果 schema 校验，不输出 `checks` 分类表。

源码调查按原目标核对必要条件和依赖，查询顺序由模型选择。可用时使用 CodeGraph 定位，漏检或中文内容使用文字搜索补查；`origin: source.read` 已表示当前源码读取，无需重复。Skill 不授予权限，也不以累计调用次数、时长或首次未命中终止调查。

真正缺资料时允许有帮助的推测或条件假设，说明依据或假设及未核实部分；不强制拒答，也不将推断列入已核实规则。影响原目标的缺口仍留在 `pending`，按实际情况返回 `incomplete/needs_input`；已完成答案之外的无害联想不强制改变终态。仅标注“推测”不能豁免与已知证据矛盾或后文把假设肯定化。效果评测须审核完整正文、原证据及终态，不能只审核派生 `claims`。

逐段核对玩家文字与所附证据；程序仅拼接和隐藏元数据，不进行第二次事实改写。内部保留原入口引用与未决事项，玩家只看到游戏语境中的已知条件和具体疑点。正常路径的解释可明确其成立条件，不以题外分支未知拒答；直接决定计算结果的缺失定义则必须作为阻碍。路由不能证明绕过内部检查，真实调用点也不能证明尚未读取的计算公式。无进展反馈、原证据与提交检查保持不变；模型仍负责区分规则和角色描写，程序不能仅凭省略证据或格式合格判断语义正确。

题设明确给定的状态作为假设使用，不转成获取或配置流程的调查；发现矛盾时才说明。单项门槛问题只核对该项及必要依赖，不因此宣称整个动作必定成功；完整操作条件/消耗问题仍须查公共入口和相关分支。原始 `source.read` 记录、引用范围、候选与提交前文件版本复查、权限、取消和提交检查保持；`completed` 仍不能带未决事项或无证据结论。程序验证结构和证据关联，不据此证明语义正确；真实模型是否遵守仍须按[固定题结果](ai-source-eval-20260926.md)验收。

运行时识别跨关键词重复取得的同版源码行，而非把每个新查询都当作新证据。成功搜索但没有证据时，换关键词也不会重置“未增加可用证据”的反馈；空结果仍可指导下一次查询，并不证明实现不存在，截断结果尤其不能作此判断。命中后首次正式读取、新行或版本变化仍支持继续。反馈要求先核对原问题，资料充分时交付，仍有具体缺口时再补查；它不自动结束任务、不替模型判断规则，也不以引用数量证明语义正确。

完成时逐项检查必需记录、未决依赖与本轮真实证据。搜索线索不能直接作结论依据；实际行读取允许引用片段，但需覆盖相关条件和依赖。同文件引用不能混用 hash。候选验证和提交前各通过 `Tools.execute("source.read", ...)` 重新校验所引文件的 hash、范围和内容；使用新调用 ID，避免复用旧读取。Hook 拒绝、权限变化、文件变化、取消或期限到期均不能提交成功记录。compact 不重建证据账本，摘要中的引用仍须匹配实际读取记录。

这些检查验证引用真实性、读取时的版本一致性与调查记录完整性，**不证明模型已经找到所有相关分支或正确理解语义**；后续人工核对的固定评测集负责评估准确率。复查也不是跨文件原子快照锁或实服状态查询。

完成检查区分未知引用、部分检索证据和搜索线索，指出具体有问题的 ID。拒绝搜索引用时，若同一仓库身份、路径、hash 和版本已有覆盖该行的正式读取，则提示可替换的读取 ID，否则指出仍需读取的引用。未知 ID 不猜测对应文件，也不自动补成相似 ID；模型先核对已有工具结果，缺少原文时再读。本次请求内较早取得的 `source.read` 仍可引用已返回的行区间，不因片段带 `truncated` 标记就要求重读整个文件；不能跨请求复用。NPC 与主 Agent 共用这项反馈，原成果引用另按成果契约验证。程序不自动替换模型结论或降低校验标准；引用更正后仍须通过原有验证与提交前复查。

玩家投影只包含终态和角色正文，不返回调查记录；内部路径、证据 ID、明显函数调用和技术术语会退回模型重新表述，不用删除字符串来拼凑残缺答案。正常游戏命令和颜色保留。管理员投影仅展示已最终校验且当前仍获授权的引用、行片段、hash 与部署标签，并明确 `evidence_basis=source_snapshot`、`runtime_state_verified=false`；不能用输出脱敏替代读取及外发授权。

## 本机管理员诊断

`ai/scripts/debug_source.py` 复用 NPC 规则 Agent、同一 Runner、Skill 和只读工具，不需要正式 NPC 配置或业务数据库。默认只预览，不加载授权配置、不读源码、不调用模型：

```sh
python ai/scripts/debug_source.py "入门需要多少贡献，实际扣多少？"
```

实际目录、外发与模型调用均已获授权后，显式执行；报告父目录须事先创建并限制访问，每次使用新的文件名：

```sh
python ai/scripts/debug_source.py "入门需要多少贡献，实际扣多少？" --audience admin --execute --report <受保护目录>/source-answer-01.json
```

- 使用同一 `SOURCE_ROOT` 和统一排除，要求源码开关及工具能力可用。`--audience admin` 仅增加已核验的证据视图，不扩大可读范围；`--execute` 不绕过部署限制。普通游戏入口仍固定为玩家受众。
- **整个诊断报告只供本机维护者使用**：即使选择玩家受众，外层仍包含问题、用量和诊断状态；管理员报告还包含获准源码片段。不要将报告直接发送给玩家或放入公开日志、仓库、Web 目录。
- 新报告使用独占创建，不覆盖已有文件，不自动重提请求。POSIX 使用 `0600`；Windows 依赖父目录 NTFS ACL，须只允许服务维护者访问。CLI 的身份来自操作系统，不来自游戏玩家 ID。
- `Ctrl+C` 取消任务并保存已知/未知用量，不报成功；单次 I/O 超时仍有效，不设整项任务总期限。中断报告不是可自动恢复的任务存档。
- 报告的 `source_access` 标记全仓库模式、策略版本与配置指纹；文件 hash 只证明读取的磁盘快照，判断实服是否加载该对象仍需游戏端独立核查。`human_review_required:true` 表示运行成功不等于结论经人工验收。

## 安全与验证

- 私密配置、隐藏目录、玩家存档、日志、数据库、备份、密钥与非文本内容始终排除；不返回被拒绝对象的文件名、计数或异常原文。
- 每次访问核对最终打开对象，拒绝穿越、链接、junction/reparse point、硬链接、设备名、ADS 和替换竞争；不能可靠核验时关闭访问，禁止降级为普通 `open()`。
- 文件安全测试按平台覆盖符号链接、硬链接、文件及父目录替换竞争；junction 在 Windows 上验证。
