## 静态数据的含义

- 遍历实际 `kungfu/skill`、`kungfu/class` 中 `.c/.lpc/.h`，包含本地新文件；每项记录路径、SHA-256、函数原文/行列及声明候选。JSON 偏移为 JavaScript UTF-16 字符下标，不是 UTF-8 字节偏移。
- 使用本地 FluffOS tokenizer 识别注释、字符串和 heredoc，不执行源码。继承、include、函数调用与闭包引用分开记录。公共头文件保留原归属；不擅自将条件分支裁成一个“最终配置”。
- `set_skill/map_skill/prepare_skill` 首先表示 NPC 配置，不直接证明玩家能学；`create_family` 候选不等于入门资格。目录分组不是正式门派数。
- 宏、预处理条件及动态表达式保留原文待核验。词法未解析项是采集器限制，不是已确认的游戏错误；只有真实驱动和依赖调查能证明实际效果。
- 只有继承、没有本地函数的基本功也保留在清单，不当作“零伤害武学”。完整效果采集还须记录资格、目标、资源和状态变化。

`catalog.json` 提供十二类兵器定义、全部技能文件/本地函数、字典名及源码 `name()` 出处、NPC 配置/映射/师承/教学候选和公共头文件链接。`valid_enable` 的直接比较及数组成员是类别候选，尚未执行否定/组合条件或预处理；`runtime_unverified` 不能解释成“允许激发”。宏保留声明出处，未解析表达式保留原文。教学候选也可能属于 NPC 初始化或条件不可达分支，须连同调用者和资格函数核对；不自动折算成可学列表。

## 结果与缺陷边界

正常效果、明确资格拒绝、源码异常、尚缺条件和不适用须分别统计。扫描通过、样本已保存、技能能编译均不等于正常效果通过；辅助、恢复、防御、控制等不能只统计伤害。

发现明确代码错误时，先记录源码位置/hash、预期依据、最小复现、实际结果、证据目录及影响的数据。本轮不修复；怀疑问题与确认缺陷分开。正常强弱差异不能列成 BUG，受错误影响的样本也不能用于无条件强弱结论。

原始随机样本和日志不提交 Git。工具与资料可复跑，历史数据不覆盖；源码或条件变化必须建立新系列。

## 条件级台账

`tools/tests/martial_data/ledger.mjs` 供隔离夹具调用；一个系列只允许一个写入进程。`series.json` 固定源码/字典指纹、驱动/夹具版本和条件参数，`samples/` 每个条件与重复编号保存一份原始记录。完整写入后才产生 `.json`；中断留下的 `.pending` 保留但不计完成，续跑只执行 `missing` 中的编号。禁止覆盖历史样本或把不同版本/条件混成一批。

| 记录状态 | 含义 | 是否进入正常效果分母 |
| --- | --- | --- |
| `observed` | 夹具返回正常观察数据，仍需审查资格和观察方式 | 是 |

| `error` | 执行报错，保留原始错误观察 | 否 |
| `not_applicable` | 有依据的不适用，不能据此补成正常效果 | 否 |

## 真实驱动观察

证据保存须区分“输入哈希固定”与“源码副本”。当前 attempt 保存公开游戏源码和 LPC 夹具副本；MJS 采集器／条件模块只登记运行时 SHA，并未逐批复制工具正文。重算历史结果须取得匹配哈希的工具版本，不能从哈希恢复源码，也不能将现有系列称为可独立完整重放的全部工具快照。历史文件保全位置、两份未完整中间副本及缺失边界见[证据可用性记录](../reviews/2026-10-11-martial-evidence-availability.md#工具源码与运行输入的保存边界)。

```powershell
node tools/collect_martial_data.mjs weapons --smoke
node tools/collect_martial_data.mjs abilities --smoke
node tools/collect_martial_data.mjs abilities --smoke --case ability-recover
# 非烟雾会增加随机样本量，持续回调按原时钟等待，可能较久
node tools/collect_martial_data.mjs weapons --samples 100 --level 200
```

只在仓库外复制公开源码并启动真实驱动，通过两个回环连接建立非巫师 USER 对象。每个样本重新创建角色和装备，记录原始/有效技能、属性、资源、映射、持器、手持弹药、忙乱及临时状态。领悟等实验资格显式写入条件；这不证明角色符合线上培养、拜师或学习成本。

初始装备记录实际初始化程序、类别、特性位、重量、材质、坚硬度、耐久度、伤害和 `no_wield`；没有提供的值按原返回值保留，不从类别名推定。`weapon_details` 与 `handing_details` 分开，便于核对针、箫和暗器使用的确实是各自装备。

兵器组覆盖十二类，各用自己的初始化与代表技能；烟雾含正常施展和内力为零的拒绝条件。针保留 `pin` 身份、使用剑法映射；箫保留 `init_xsword(50)` 产生的实际伤害 45；暗器不可 wield，按 `hand` 持有并扣弹药。不存在的暗器持器普攻标为不适用，不以徒手攻击代替。

机制组单独核验回气、护体、增益、控制、致盲/弹药、缴械和学习资格。`valid_learn()` 是原接口检查，不是实际师父传授；特殊低等级/弱防御配置明确标注，不与中性对手统计混算。已知错误复现条件带 `known_issue`，保留真实错误结果，不修源码。

单次观察模式不运行自主战斗心跳，忙乱是施展当下的状态，不能据此报告忙乱自然结束时间。`start_call_out` 沿原时钟运行，新角色夹具转调原 `eval_function()`，记录回调前后状态与实际时间；不缩短持续时间、不手工调用解除函数。样本保存 `before/immediate/after`、资源账、掉落物、真实发动/拒绝及接口返回。连续交锋单独使用以下入口。

忙乱快照也不是控制触发次数。例如胡家刀法“八方藏刀势”在每次攻击前可能给对手 `start_busy(1)`，随后命中产生正伤害时，公共战斗会调用 `interrupt_me(攻击者, ...)`。对这种整数忙乱，当前公共行动实现会因中断者不是自身而清除它；同一招结束时的忙乱可能为零，即使中途施加过控制。依据见 [`cang.c:61`](../../kungfu/skill/hujia-daofa/cang.c#L61)、[`combatd.c:932`](../../adm/daemons/combatd.c#L932)、[`action.c:52`](../../mudcore/inherit/action.c#L52)。因此 `target_busy` 只表示记录时的剩余状态，不标作控制触发率；未逐次采集的中间事件保持未知，不从最终值补算。本段解释当前机制，不将其直接认定为缺陷，也不改变正在运行的探针。

仅临时副本插入命令发动/拒绝与原战斗探针；记录精确位置和前后 hash，并验证去掉探针可逐字还原。命令受理、绝招发动和命中分开；成功发动但没有伤害仍是有效观察，恢复、控制与防御不能用零 DPS 代表。

`--case` 只接受一个精确条件 ID，单独建立系列，不代表整组完成。驱动逐样本写原始 JSONL，采集器增量校验并追加到条件台账。旧固定两批基线保持原工具和参数。

### 中断续跑与错误隔离

```powershell
node tools/collect_martial_data.mjs resume --input C:/Temp/martial-series-A
node --test --test-concurrency=4 tools/tests/martial_data/*.test.mjs
# 明确启动临时驱动并主动中断/注入异常，只验证采集器

```

全套工具自检限制文件级并发，避免随机器逻辑核心数增长而同时构建过多源码快照、占用大量内存。自检通过不代表原生样本完整或全武学覆盖。历史矩阵断言使用 `historical_school_conditions.mjs` 明确排除本轮新增窗口，保持原条数、样本计划与hash；新增窗口的集成测试仍使用当前完整矩阵，不将历史视图用于实际采集或效果验收。

续跑先核对源码、驱动、字典、Node、夹具及参数指纹，再导入中断前已写完整但尚未入账的记录，只补原系列缺失编号。已记录的错误、拒绝也保留，不因重试变成成功；修改条件或修复工具后须新建系列。收齐后再次续跑不会启动驱动。并发采集器或未退出的遗留测试驱动会阻止续跑，不自动终止未知进程。

每次执行位于 `runs/attempt-*/`，保存任务编号、隔离进程身份、源码副本、原始 `log/events.jsonl`、驱动输出和退出结果。完整坏记录明确报错；未写完的尾行保留但不计样本。同编号同原文允许幂等导入，不同原文拒绝覆盖，其他运行的任务记录不能混入。

大批量任务文件可能超过驱动默认的 256 KiB 文件读取上限。采集器按实际 UTF-8 字节数和任务数，为该次**临时驱动**配置文件读取、字符串、缓冲区及数组容量（本库 JSON 解码包装会经过 UTF-8 buffer），保留小批次默认值；不修改正式服配置、采样次数、战斗时钟或公式。启动失败没有样本时不算已采集；修正工具后建立新系列，旧失败现场保留。

连续批量调用每保存 100 条样本后让出一个原生 tick，避免零延时调度链耗尽驱动上限。此时该样本的观察已结束；不缩短正在进行的战斗、持续效果和回调，也不把批间等待计入武学耗时。

单个技能发生同步异常或延迟回调异常时，保存错误样本并结束该测试驱动，剩余样本在新的隔离副本中继续。所有样本收齐但含错误时仍报告失败，不称为正常效果通过。故障注入只存在于测试夹具，并写入系列身份，不登记为游戏缺陷。原技能时钟、回调和结果不改写。

本标准档未激发特殊内功。公共普通攻击的加力分支须先取得 `query_skill_mapped("force")`，才调用该内功的 `hit_ob()`；因此这里的普攻不能代表完整门派配装的加力收益。原六门基线 A 批也已观察到两档普攻均无内力支出。直接伤害结算则另有独立的加力扣费与增伤，两条路径不可混为一谈；按各自实测总支出记录，不能只从 `jiali=50` 推算每次攻击必定扣 50。源码依据见 [`combatd.c:662`](../../adm/daemons/combatd.c#L662) 和[直接伤害路径](../../adm/daemons/combatd.c#L1088)。门派阶段须使用原有内功组合另行采集，不更改正在运行的中性基线。

`bouts` 执行原 USER 心跳，包含原生恢复、忙乱推进和战斗行为。按样本编号交替先手，首人实际完成一次心跳后才开启另一人的心跳，并保存实际先手证据。绝招策略在不忙且双方正常时尝试原命令；资源、目标、弹药或冷却不足由原代码拒绝，不能把“命令尝试”算发动。暗器绝招组允许原生徒手后续，报告须保留这一限制；暗器持器普攻仍不适用。

昏迷/死亡使用原行为后的回调确认；时限到达仍未分胜负单列未决，不计胜利。忙乱时长是按心跳后和一秒轮询采集的近似积分，不是精确事件时刻。烟雾为每条件 2 场、3 秒，只验收机制；目前已验证未决、真实昏迷路径及十二类完整固定交锋。直接死亡等特殊入口仍在后续全武学阶段核验，不将烟雾当完整交锋统计。
