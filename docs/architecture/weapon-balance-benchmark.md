# 兵器与武学隔离评测

本工具用于比较机制，不修改正式数值，不是十二类兵器排行榜，也不替代功能回归。
当前实现和验收进度见 [任务清单](../../openspec/changes/add-weapon-balance-baseline/tasks.md)。

## 运行

需要 Node.js 18+、Git、当前 mudcore 和本地 FluffOS 驱动。从仓库根目录执行：

```sh
node tools/bench_weapon_balance.mjs --help
node --test tools/tests/weapon_balance/tool.test.mjs
node tools/bench_weapon_balance.mjs --smoke
node tools/bench_weapon_balance.mjs --output C:/Temp/weapon-balance-A
node tools/bench_weapon_balance.mjs --output C:/Temp/weapon-balance-B
```

可指定 `--driver PATH`、`--samples N`、`--bouts N`、`--duration N`。完整默认每条件
100 个独立单次样本、20 场交锋、每场至多 30 秒；烟雾默认 2/2/3，仅验工具。
完整矩阵为 28 组单次条件和 12 组交锋条件，每批 3040 条记录。交锋先手交替，建议偶数场。
保留真实 1000 ms 游戏时钟和心跳，默认一批最多约两小时。不要用加速时钟缩短采样。

## 隔离与证据

仅复制公开 LPC/头文件及 `data/e2c_dict.o`；排除正式配置、玩家存档、私有 `u/`、
日志、AI 服务及驱动工程。新建临时 MUDLIB、随机回环端口和两个独立交互角色，
不通过正式登录、不连接现有服务、无外部 socket/数据库/外部命令权限。游戏源码不写回。
测试玩家不保存账号；真实死亡边界触发的守护精灵只可写临时副本的 `data/` 和 `log/`。
死亡边界自检结束后，清理它额外加载的对象和定时任务，名单写入原始记录，
避免无关任务及路人继续运行；战斗角色、已加载战斗服务和采样心跳不受此清理影响。

结果默认保存系统临时目录；指定输出必须是仓库外的新目录，符号链接及 junction
解析后仍受检查，不能覆盖既有结果。`manifest.json` 保存提交、mudcore、驱动 hash、
复制文件 hash、全部参数、探针插入位置及前后 hash；`records.json` 保存原始记录，
`summary.json` 保存统计，驱动输出和临时 MUDLIB 保留用于复核。失败也保留现场；
只有正常结束、记录完整且无编译/运行诊断时才发布汇总。无需停止正式服。

## 人工标准档

三组分别是盘古七势／撼山锤法、中平枪法／胡家刀法、打狗棒法／缠魂索。
双方经验 1000 万，先天属性各 30，基本兵器与特殊武学各 200，基本内功、轻功、
招架各 600，武学修养 200；气血和精各 10000，内力 6000。只激发本门兵器武学，
不激发额外内功、轻功、招架，不开互搏或性格加成。实际有效等级单独记录。

兵器继承各自真实初始化器，统一基础伤害 50、重量 3000，护甲加成 100；
全部实际标志和属性记录在配置中。这不是同价装备或完整可获得门派角色，学习资格
和门派贡献不计入本批，绝招发动资格仍走真实命令。每样本重建两个真实玩家对象并仅
转接本地 socket，不能继承上一样本的临时状态、伤势或技能进度。

加力 0、50 分开。缠魂单次样本另列毒技 200／白绸扩展档，不与中性档混算。
扩展是额外培养成本，不是免费类别优势。标准档下打狗“缠”比较基础轻功 600，
而攻击判定至多 299，因此无法缠中；保留真实结果，不为漂亮结果降低目标属性。

## 测量口径

- 单次普通攻击暂停自动心跳，调用真实 `do_attack`；单次绝招通过真实 `perform` 命令。
  普通攻击计数取结算的命中／招架／闪避结果，不从伤害为零反推。反击、快攻单列。
- 三组交锋分别比较纯普攻、普攻＋唯一指定绝招。正常心跳运行，不清忙乱、不补资源，
  失去武器不自动补发。不忙、持器且资源足够时才尝试绝招，打狗不重复缠已忙目标。
  每场先启用指定先行方心跳；其首个真实心跳结束后才启用另一方，后续顺序由驱动管理。
  奇偶场交换先行方，记录实际先手和双方心跳次数；不假设同时注册便会按注册顺序行动。
  截止时间在心跳及观察回调检查，不再执行截止后的攻击；结束记录可能晚一个调度粒度。
- 原生随机不替换、不固定种子；观测仅在临时副本插入旁路计数，清单列出精确位置。
  角色资源 setter 和恢复方法转调原实现；公共结算直接改 mapping 的加力另设观测点。
- 气血与有效气血分别记录，不能相加。资源总支出与恢复分开，不能用净支出冒充成本。
  零成本效率记 `null`（不适用），不是无限效率。单次忙乱是计数，不是秒数；
  交锋忙乱以 1 秒观测步长累计，占比是近似值，保留实际观测时长。
- 昏迷、死亡、时间到分别记终态；时间到仍未决的全部保留，不算胜利、不伪造击杀时间。
  发动、直接伤害入口和普通攻击采用各自分母；角色扩展、先手和模式不能混算。
- 汇总包含全部成功、拒绝与错误记录，均值、中位数、线性插值 P10/P90，以及概率的
  Wilson 95% 区间。工具异常与不利战果不同：前者失败退出，后者如实报告。

## 验收与后续

工具自检、真实烟雾、两批完整评测分别验收。两批必须同源码、驱动和参数；用清单指纹
核对，不因报告标题相同就合并。真实结果尚未完成前，不宣称已建立统计基线或兵器平衡。
现有 `node tools/test_gameplay.mjs` 不包含此长耗时工具。新发现的正式缺陷另立修复，
不边测边改公式。只有报告支持并经维护者确认后才调整玩法。
