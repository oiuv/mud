# AUCTION_D — 拍卖与结算

## 入口与持有方式

`cmds/usr/auction.c` 提供上架、竞价、查看和取消，实际记录保存在
`adm/daemons/auctiond.c` 的内存中。每名卖家同时一件拍品；**物品始终由卖家持有，不是托管**。

上架、竞价、展示和结算均复核对象存在、直接位于卖家物品栏且仍可售。
转交第三人、落地、销毁或后来标为 `no_sell/no_drop` 时撤销记录，不追回物品。
保留原来的价值、角色、货币及 `food_supply` 限制；取消只删记录，不移动拍品。

## 轮次与接口

| 接口 | 行为 |
| --- | --- |
| `add_auction(seller, goods, price)` | 检查底价、归属和当前佣金支付能力，从第一轮开始 |
| `join_auction(buyer, seller_id, price)` | 提价并重置第一轮；不能连续给自己上一口价加价 |
| `check_auction_info()` | 返回有效拍品列表，移除失效记录 |
| `cancel_auction(seller)` | 撤销该卖家记录 |

每次检查按记录各自解析买家，不能沿用上一笔。距上次叫价或报轮至少十秒时推进；
第三轮后再到期，有有效买家才尝试结算，无人竞价则撤单。
卖家退出撤单，买家退出不继续用该身份结算。
心跳间隔受驱动配置影响，不承诺精确到秒。

## 金钱、交付与失败

成交价和佣金均以文计，佣金为 `price / 25`，等价于向下取整的 4%，避免中间乘法溢出。
卖家必须自备佣金，不从预期货款抵扣；24 文成交免佣金。
`MONEY_D->query_payment()` 与 `player_pay()` 共用银票门槛、找零和溢出规则；
前者返回预检 mapping，`status == 1` 才可支付；后者返回 1 才表示付款成功，
2 也不是成功。公共付款仍拒绝非正金额。

结算顺序：

1. 复核钱物，预检原有钱币、找零、拍品及卖家货款的负重。
2. 预先准备货款和退款钱币，再支付买家货款及正数佣金。
3. 普通移动交付拍品，检查实际落点；正常同类堆叠合并只交付一次。
4. 将货款按原发钱币种规则交给卖家，完成后才广播成交。

可预见的余额或容量不足在扣款前拒绝；扣款后物品拒绝移动，恢复双方原币种和数量。
退款与货款不用强制落地替代交付。失败撤销本笔，不自动重扣；同一人作为买卖双方不结算。
任意特殊物品钩子的破坏性副作用和进程崩溃恢复不在保证范围内，不能把同步补偿当成持久交易系统。

记录保持 `goods`、`time`、`value`、`lot`、`state`、`now` 这些 mapping 字段：
`goods` 为对象，`now` 为买家 ID，其余为时间、价格、佣金和轮次。

## 验证与部署

`node tools/tests/test_commerce_audit.mjs` 在临时 MUDLIB 中运行真实驱动、货币和多角色；
`--integrity-baseline` 使用 `b85d40ff` 的旧实现作失败负对照。
原 `--baseline` 仍对应上一批 `d43c418f`。

测试覆盖部分放物、免佣金、余额不足、银票、找零超重、拒绝移动、堆叠、换主、
销毁、取消及多笔记录。测试不读正式玩家存档，不代表全库覆盖。
更新拍卖精灵前先结束或取消进行中的拍卖；记录不持久化，无存档转换或历史损失补偿。
