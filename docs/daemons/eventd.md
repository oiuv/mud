# EVENT_D — 世界活动调度

## 职责与接口

`adm/daemons/eventd.c` 在启动后延迟收集 `adm/daemons/event/*.c`，
调用各事件的 `create_event()`。登记只允许具有 `ROOT_UID` 的调用对象。
每对象保留一条 `({ year, month, day, hour, para })` 记录。

- `at_when(year, month, day, hour, para)`：直接登记游戏日期，成功返回 1。
- `at_after(year, month, day, hour, para)`：非负分量相对当前日期相加；负数分量取其绝对值。
- `query_event_list()`：查询待触发记录。
- `query_all_event()`：查询收集的事件名称。

月份从 0 到 11。零是相对增量，不表示绝对零时或一月；要明确这类日期可使用 `at_when()`。
登记过去的单次事件允许下一次检查触发一次，调度器不擅自把它改成周期事件。

## 日期进位与时钟边界

`at_after()` 将小时进到日、月份进到年，再按实际月长规范化日期。
月长取决于 `TIME_D->query_gametime()` 对应内部年份的公历，**不能拿游戏显示年份判断闰年**；
游戏纪年通过当前显示年与内部年份的偏移对应，原有 1∶60 时间速率不变。

```lpc
EVENT_D->at_after(0, 0, 1, -5, "sunrise"); // 明天五点；月底会进入下月
EVENT_D->at_after(0, 0, 0, 1, "later");   // 一小时后；二十三时会进入次日
EVENT_D->at_after(0, 1, -15, -23, "moon"); // 下月十五日二十三时
```

宿主 `adm/daemons/timed.c` 保存现实／游戏时间锚点和正纪年偏移；内部跨年时显示年递增，
重启按同一锚点计入停服经过时间，不重新取模重置日期。首次升级保留旧公式在该时刻的
初始显示日期，细节见 [TIME_D](timed.md)。mudcore 通用时间接口未改动。

## 到期与周期

心跳取得 `NATURE_D->query_localtime()`，按游戏年/月/日/时比较。
**先删除登记，再调用 `trigger_event(para)`**，避免同一条单次记录重复执行。
事件需要继续运行时自行重新登记；参数原样传递。

无量山玉壁剑舞选择严格晚于当前时间的最近一个十五日二十三时：
未到则本月，恰好到时或已经过时则下月。触发后再计算，不补发逾期月份。
奖励资格、概率和数值不变。峨眉／黄果树仍为次日五点，天池仍为次日一点，
钱塘潮仍沿用原来下一年的指定日时。

心跳设置为 60 个驱动心跳间隔，而非无条件等于 60 现实秒；
实际间隔取决于驱动配置。因此按小时检查，可能延迟，不保证整点即时触发。
单个事件异常由调度器捕获并记日志，不影响其他已登记事件。

## 验证与上线

`node tools/tests/test_world_events.mjs` 创建临时 MUDLIB，运行真实调度器和事件，
分别验证受控日历、生产宿主时钟和新驱动进程恢复；只在测试副本替换现实时间输入、
屏蔽频道，并记录奖励入口次数，不依赖随机中奖。`--integrity-baseline` 用 `b85d40ff`
的调度器、活动和宿主时钟复现旧错误。所有调时入口只存在于测试副本。

部署前备份公共数据库 `data/dbased.o`；按正常维护流程重启，使时钟恢复及活动收集顺序一致。
不补发旧奖励或扣回历史所得，也不迁移玩家存档。开发回归只写临时数据库，不操作正式服务。
