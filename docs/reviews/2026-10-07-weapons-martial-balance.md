## 结论与范围

兵器分类已经比历史状态一致，但**分类正确不等于十二类强度均衡**。当前实际差异来自装备占用、默认动作、武学选择、专属效果和学习路径；五个武器特性中，只有双手占用和副手资格形成了通用运行机制。锋刃、尖端、长度还不是通用破甲、创伤或攻击距离系统。

特别需要区分：十二种物品继承并非十二套完全独立的基本武学。针保留 `pin` 物品身份，普通战斗转换为剑法；箫直接使用 `sword`，并兼具吹奏入口。剑系内容不能简单算成“普通剑、针、箫各自独占的三份内容”。

本轮覆盖十二类初始化、装备主副手、普通攻击/绝招结算、有效技能和忙乱接口，以及下表列出的代表武学、教师与秘籍。既有修复与历史隔离验收见 [武器战斗契约](../architecture/weapon-combat.md)、[玩法审查修复记录](../architecture/gameplay-audit-fixes.md)。不将已修复的防守属性归属、盘古/撼山内力、罗汉棍阵、反击、远程加力、互搏和摄心等问题重复列为未修复。

本报告的“确认”指当前源码与调用关系可确认，不表示已在本轮重跑真实驱动复现。没有全类别对战、玩家运营数据或完整武学获得性调查，不能给出胜率排行榜或“全库平衡已通过”的结论。CodeGraph 查询出现内部 `statInode` 错误后，本轮使用 Git 检索和 UTF-8 源码复核。

| --- | --- | --- | --- | --- |

| 刀 `blade` | `blade` | `EDGED` | slash / slice / hack | 与斧共享部分动作，但刀系武学独立；没有统一刀速被动 |

| 短兵 `dagger` | `dagger` | `EDGED | SECONDARY` | slice / pierce / thrust | 可作备用副手；副手不叠加属性，也不多打一击 |

| 针 `pin` | 战斗中转为 `sword` | `EDGED` | thrust | 葵花等明确接受针；不是可单独 `enable pin` 的完整基本功体系 |

### 默认动作确有数值，但不是类别被动

`adm/daemons/weapond.c:11–69` 的动作不仅是句子：例如 hack 的 `damage=30`，thrust 的 `dodge=15/parry=-15`，pierce 的 `dodge=-30/parry=-30`，whip 的 `dodge=-20/parry=30`。需按消费者解释：

- `action.damage` 在普通攻击中按武器伤害百分比增幅，不是直接加 30 点（`combatd.c:636–642`）。
- `action.attack/dodge/parry` 写入**出招者**的 `fight` 状态，供该角色的命中或后续防守使用（`combatd.c:516–521,338–394`）。不能把动作中正 `dodge` 误读成“本击让对方更容易闪避”。
- 特殊武学映射生效时，动作由武学的 `query_action()` 返回，通常不再用默认武器动作（`feature/attack.c:391–403`）。因此默认棍杖锤的震兵回调不能宣传成所有棍杖锤招式都具有的通用效果。

## 五个特性的实际能力

| 标志 | 当前消费者与效果 | 当前没有的能力 |
| --- | --- | --- |
| `TWO_HANDED` | `feature/equip.c:94–107`、`cmds/std/hand.c:33`：双手占用，阻止主副武器及手持物品冲突 | 不自动加伤、提高命中或按重量降低攻速 |
| `SECONDARY` | `feature/equip.c:100–127,169–177`：副手资格、主副换位、主手离开后合法副手转正 | 副手不贡献 weapon_prop，不自带双持攻击 |
| `EDGED` | 初始化器记录；本轮对运行期源码检索未发现通用效果消费者 | 不自动流血或提高创伤比例 |
| `POINTED` | 初始化器记录；未发现通用效果消费者 | 不自动无视护甲、点穴或增加穿刺率 |
| `LONG` | 初始化器记录；未发现通用效果消费者 | 不自动先攻、扩大目标范围或跨房攻击 |

`include/weapon.h:8–15` 已准确注明后三项目前仅记录特征。不要为了“让每个 flag 有数字”而强加效果：前两项已经是有效的装备规则，后三项能否提升玩法需要独立设计和验证。

现有兵器碰撞是**默认动作回调**而非第六个隐藏 flag：`weapond.c:99–140` 仅在真实招架、双方武器有效时，比较武器重量/500、刚性与基础膂力；不同阈值造成脱手、震动或非自制武器损坏。`combatd.c:950–951` 传入独立结果码。损坏关系比几百分点伤害更强，后续若推广到所有钝器武学会显著扩权，不能当作无影响整理。

## 三条实际调用链

### 1. 装备到普通回合

`feature/equip.c:51` 的 `wield()` → 主手属性加入 `apply/*`（124–127）→ `feature/attack.c:368` 选择有效映射动作 → `feature/attack.c:408` 的 `attack()` → `combatd.c:1225` 的 `fight()` → `combatd.c:403` 的 `do_attack()`。

有效等级为基础技能一半、有效特殊映射等级及该项临时加成之和（`feature/skill.c:113–150`）。命中与闪避/招架还使用立方级技能力、分段战斗经验、基础膂力/身法、动作与性格修正（`combatd.c:324–394,524–603`）。正常出手机会还受双方有效膂力影响（1264）；双击来自双拳准备或特殊武学的 `double_attack()`（1246–1273），并非 `SECONDARY`。

忙乱目标的闪避与招架技能力各降为三分之一（539–540、595–596）。因此控制不仅阻止行动，还增强后续连击命中；比较“七段”和“一段”时必须计入控制窗口。

### 2. 普通攻击到最终伤害及反击

`combatd.c:636–692`：主手伤害/徒手伤害 → 动作 damage、力量及内功加力效果 → 轻功/招架/防具防御钩子（704–753）→ 攻击武学、武器或角色命中钩子（759–793）→ 属性修正与分段压缩 → `receive_damage/receive_wound`（838–866）→ 动作 `post_action`（950）→ 有条件趁隙反击（953–969）。

普通攻击的护甲主要影响创伤 `eff_qi`，不等于直接从当前气血伤害减去同额护甲；200/400 以上伤害和创伤各有压缩（838–853）。`damage_type` 在该公共路径用于伤害文案与死亡原因（873、1851），没有按“劈/刺/挫”建立通用护甲抗性矩阵。个别武学仍可自行实现条件，不应从公共机制推断全库都没有专属效果。

### 3. 主动绝招到实际结算

`cmds/skill/perform.c:101–125` → 当前有效武学 → `inherit/skill/skill.c:109–124` 解析目标并调用共享绝招对象 `perform()` → 招式检查、付费和忙乱 → 自行选择 `do_attack()` 连击、`do_damage()` 单次结算或直接角色操作。

`do_damage()` 并不重复普通攻击的 AP/DP 命中流程，是否命中由调用绝招先判定；它添加武器属性、处理招架/防具钩子、加力、属性、500/1500 阈值压缩，再按 `percent` 计算创伤（`combatd.c:980–1164`）。远程与近程的加力和抵抗也不同（1087–1111）。表面相同的 `damage=500`，走不同入口并不意味着相同结果。

## 新确认的逻辑问题

### WB-01：玉箫极意的数值冻结为首次加载者（高）

`kungfu/skill/yuxiao-jian.c:4,137–147` 在全局动作数组初始化时调用 `this_player()->query_skill()`，计算 force、attack、dodge、parry、damage。`query_action():170–176` 根据当前角色选择该共享数组，但没有按当前 `me` 重算。

因此特殊等级高于200、选中极意的使用者会共享首次加载时的数值和随机结果；低等级或高等级管理员先加载会改变之后所有使用者的该招表现。没有当前命令角色的首次加载还有空对象调用风险。黄药师已配置320级玉箫及剑法映射（`kungfu/class/taohua/huang.c:85,109`），不是只有无引用的示例文件。

依据：项目 LPC 指南 `docs/LPC_Language_FluffOS.md:80` 说明全局初始化在 create 前执行；驱动 `fluffos/docs/efun/interactive/this_player.md` 明确 this_player 是当前命令来源，不是被传入的战斗使用者。建议在本招被选中后由当前 `me` 计算，保留原公式；以两个不同等级角色和无当前玩家加载做隔离验证。本轮未执行该新复现。

### WB-02：胡家藏刀势仍能透支内力（中）

`kungfu/skill/hujia-daofa/cang.c:37` 只拒绝内力小于200，55行固定扣220。合法已领悟玩家以200–219进入时，在连击前即产生负内力；胡斐的教学入口见 `kungfu/class/hu/hufei.c:728–784`。`mudcore/inherit/dbase.c:112–121` 的 add 只累加，不代做足额检查或钳零。

建议只将发动门槛与原220成本对齐，并测试219/220/221和拒绝时零副作用；不因修复改动八连击或其他强度。

### WB-03：回风落雁剑练习可直接练至昏迷（中）

`kungfu/skill/luoyan-jian.c:116–123` 检查内力30、气血35，却扣内力50、气血40。`valid_learn():67–86` 只补充最大内力/技能要求，正常 `practice sword` 的循环在 `cmds/skill/practice.c:97–101` 直接调用该方法，没有更高资源门槛。刘正风配置并教授该武学（`kungfu/class/henshan/liu.c:42,98`）。

当气血35–39、内力30–49时检查仍通过：`feature/damage.c:42–47` 将不足的 qi 置为 -1，`inherit/char/char.c:104–109` 下一心跳对清醒角色调用昏迷；内力则可以为负。建议保持现有消费，改为足额并保留练习后清醒的检查，覆盖最低边界及连续练习。不能只提高内力门槛而漏掉气血。

### WB-04：持针时省略武功类型的绝招分发不一致（低）

普通战斗把 pin 转为 sword，但 `cmds/skill/perform.c:106–114` 直接用主武器 pin 查映射。葵花仅声明 sword 等适用类别（`kuihua-mogong.c:119–122`），`enable` 也没有 pin 项；绝招自身又明确接受剑或针（`kuihua-mogong/perform/tian.c:40–52`）。因此在其他条件相同时，持针的 `perform tian` 不会走到葵花，而 `perform sword.tian` 可以。

建议默认类型解析沿用既有针剑约定，显式类型仍保持原规则；用针、剑、空手及错误显式类别做回归，不新建一套基本针法。

## 后续最小差异化与平衡方案（建议，不是实施计划）

1. **先清除确定性错误。** 优先修玉箫首次加载污染和两处资源边界，再修针默认分发与纯文案。保留公式不变，用最小状态断言说明修复效果；不要把 BUG 修复与全武学改数值放一批。
2. **把少量代表流派放到同一可复现对照。** 先选盘古/撼山、中平/胡家、打狗/缠魂三组，设置相同基础等级、特殊等级、经验、属性、武器和防具档次，再分别测试各自真实前置与最佳合法配装。180级共同可用样本与220以上高阶样本分开；玩家对玩家和普通/强敌 NPC 分开。
3. **指标看战斗目标，不只看伤害。** 记录首次有效伤害、固定时间有效输出、耗内力、控制占比、自忙、气血与创伤、缴械/武器损失、死亡时间及结果分布。零加力与常用加力分开；禁止把随机单场、单个最高伤害或武学文件数量当强弱结论。
4. **先给斧与锤一个小而可解释的区别。** 可以比较“斧偏创伤、锤偏招架压力”方向，但须先决定与现有默认碰撞的关系及自制武器保护。初期不引入新属性系统、复杂克制表或改所有武学。先在一组代表招式里试验，再决定是否推广为类别机制。
5. **若要启用 EDGED/POINTED/LONG，逐项设计。** 例如锋刃影响创伤倾向、尖端影响一部分护甲效果、长兵影响同房首次交锋；这些只是候选，尚无数值授权。必须在普通攻击和绝招入口中定义一致边界，避免只改 do_attack 导致主力绝招绕过，也不能把 LONG 直接变成跨房攻击。
6. **保留武学承担主要战术差异。** 棍的组阵、杖的持续控制、鞭的材质/毒技联动、短兵的备用切换、针的特定剑法、箫的精神攻击、暗器的弹药成本已经是可用方向。先修真实效果和文案，不必给十二类各造一个通用被动，更不必同时统一其伤害系数。
