## 2. 原公式与真实作用

### 狂风绝技（`perform unarmed.kuang right`）

[kuang.c](../../kungfu/skill/xuanfeng-tui/kuang.c) 第 14–44 行：领悟、交战、主副手均空、原旋风扫叶腿至少 100、激发与准备正确、内力至少 300、目标仍活动。第 28–32 行的两个同值等级检查按原顺序保留；第二条并非另一个可达门槛。

第 49–70 行：基础费用 100。桃花弟子的临时 `attack += raw_lvl / 4`，`unarmed_damage += (raw_lvl / 4) / 2`，均为原整数除法，结束逐项归还；非桃花仍能调用，但加成均为 0。最多六次原普通攻击；每次先检查仍在交战，`random(3)==0` 且目标原来不忙时置忙 1。结束施术者忙乱为 `1 + random(6)`，这里的整数不是秒数。

[旋风扫叶腿本体](../../kungfu/skill/xuanfeng-tui.c) 第 126–131 行的选招是 `raw_level > action.lvl`，不是招名查询的 `>=`：100 级可用前三式，200 级尚不能抽到等级 200 的「雷动九天」，400/800 可用八式。

### 影落飞花（`perform hand.fei right`）

[fei.c](../../kungfu/skill/lanhua-shou/fei.c) 第 13–38 行：领悟、交战、主手空、兰花拂穴手至少 140、激发与准备、内力至少 300、目标活动。原空手检查只看主手，本批不构造副手状态或扩大这个缺口。

第 42–67 行：基础费用 150；`random(有效招架 + 有效手法) > 目标有效招架` 时，临时 `attack += raw_lvl / 5`，否则加成 0。**判定失败仍连击，原命令仍返回 1**，不能记作施展拒绝。单备 `hand` 的原 `keys(p)` 必为唯一 `hand`，故 `af=0`；每次原攻击前写此标记，实际攻击类别必须是 `hand`。结束忙乱为 `random(3)`，0 请求沿原 `start_busy` 早退，可保留显式 `null/0`；攻击加成归还，`action_flag` 原本没有清除，本批如实保留 0，不作修复。

本批基本招架与特殊兰花均 200 时，有效招架与手法各 300，比较范围 `random(600)`；目标基本招架 1198 的有效值 599，必不获得加成，仍应观察攻击与费用。200/400/800 正常目标下均保留原随机，不要求样本里一定出现两种判定。

[兰花本体](../../kungfu/skill/lanhua-shou.c) 第 105–128 行：特殊等级 >100、`random(10)==1`、经络学 >100 且**选招当时内力 >1000**，先扣 300，再返回独立「兰花指」动作（无 `lvl`、无 `skill_name`）；它不是 `fei` 的额外发动。普通动作也使用严格 `>`；最低 140 级只有前六式。常规初态不满足额外选招门槛；唯一高经络/高内力对照保留逐击门槛、选招与实际费用，不补款，不把抽取动作重新调用一遍。

### 攻击、忙乱与收招分账

[combatd.c](../../adm/daemons/combatd.c) 第 455–486 行从原准备键取实际攻击类别并只执行原选招；第 661–684 行仅在加力非零时进入内功附效，本矩阵加力为 0。两门武学本体没有 `hit_ob` 实现，正常命中路径的 `martial` 调用应返回实际 `null/0` 且不产生附效；不能漏记该原调用。

第 833–867 行：原先天身法可能把最终伤害变为 0，创伤还受护甲、性格、根骨与原随机影响。`RESULT_HIT` 的计数不等同实际掉血；校验保留已记录的原入参，核对原膂力/悟性加成与分段压缩后的可能实际伤害，不拿入参代替气血损失。

第 932–941 行在现有 `observe_attack` 观察点**之后**执行原 `interrupt_me` 与切磋收招。[mudcore/action.c](../../mudcore/inherit/action.c) 第 52–74 行会先清整数忙乱，因此 `kuang` 本击前置忙不保证本击后仍忙；已有 50 也可能被实际伤害打断，不能笼统要求原忙乱完整保留。利用每击原 `dodge_checks` 的两次 busy 观测和后续真实伤害区分“原来可置忙的机会”“本次置忙”“最终仍忙”。

原非致死切磋在双方实际均非追杀、本击实际伤害 >0 且目标气血不高于最大值三分之一时双方收招，下一次循环停止。低气血两条仍是活动目标与原交战，不直接失活/移场；全闪避时可能仍六击。少于六击必须有原收招、双方非追杀与结束交战证据，不强行打满、不恢复敌对关系。其余追杀样本不套用这个收招阈值；两种上下文的原创伤随机也不同，不混成同一条件。

## 3. 记录校验与统计口径

- 严格核对真实 USER 对象、初态/有效技能、单备键序、领悟、门派、装备、资源和结束身份；只容许已经确认的显式 `null/0` 原假值，缺字段或未知类型仍失败。
- 每条接受记录必须有同源发动和 1–6 次实际攻击；选招数、攻击数、每击两条闪避观察、命中/闪避/招架计数闭合。攻击类型只能原 `TYPE_REGULAR`；不允许凭空回击、直接伤害、心跳或自然回调。
- 每击取实际临时攻击/徒手伤害加成，检查整轮一致与末尾恢复；`fei` 的失败门不冒充拒绝，原标记不清除。
- 两门都是静态动作表，逐项核对原动作文本与数值、严格可用等级前缀；不新增动态首载上下文或逐样本重载。
- 原命中回调与其无效应前后快照闭合，最终伤害 0 仍可能有该回调；攻击净掉血、创伤、毛费用、恢复计数分别检查，禁止通过补款对齐净值。
- 绝招基础费用和兰花每次选招额外 300 分列。执行器已删除的 `raw.parameters` 不参与统计，必须传冻结 condition；先核外层记录、原始记录与冻结条件的 ID，以及外层/原始结果同源，再分类统计，未知/错误不当作零费用或零攻击。
- `bonus_given_accepted` 仅属于 `fei` 的门加成率；`hit_given_attack` 以实际攻击数为分母；实际掉血/创伤以接受施展为分母。`kuang` 置忙机会率和兰花合资格选招触发率各有独立分母，不将“原有忙乱”算本次控制。
- [原 perform](../../cmds/skill/perform.c) 的弱熟练增长与命中独立，低有效等级可 0/1，高有效等级按原门必 +1；技能等级不能偷升，确定拒绝不能增长。

不报告六连的长期 DPS、自然解忙时间或双备跨回合结论。`fei` 留存标记在其他准备顺序/跨回合的影响仍属于另外的未采风险，本次单备固定 0 既不能证明问题不存在，也不能确认它是设计错误。

## 命令返回值契约补正（未采样）

此前合成自检只使用成功值 `1`，遗漏了原 [force_me](../../feature/command.c#L117) 直接返回 `command()` 正执行成本的语义；成功值并不固定为 `1`。这是独立采集校验器的错误，不是武学或驱动行为错误。本次只修正单命令 `raw.command_accepted`：键必须存在、值必须为非负安全整数，以大于零表示受理，以零表示拒绝；原始成本不归一化，也不与技能资源消耗混算。NPC 闭包返回值、聚合命令字段及游戏代码均未调整。

新增两项离线自检覆盖全部固定条件：成功成本 `1/23/476`、缺键／未定义／null／错误类型／负数／非整数／非有限值／超安全整数，以及成功零成本和拒绝正成本的反例。相同原记录在三种合法成本下得到相同统计，受理分母不累计执行成本，验证及统计不回写原记录。本组现为 **18/18 通过**；七组串行合计 **122/122 通过、退出 0**，不是 122 条真实游戏样本。

原有 24 条件／1420 正式计划／48 烟雾计划和两份完整有序条件 JSON 指纹保持不变，旧准备文件已由主控另行保全。上述历史自检结果保留；当前仍未注册共享执行，也未启动驱动或采集真实样本，后续烟雾／正式门槛不变。
