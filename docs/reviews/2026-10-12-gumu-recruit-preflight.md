## 3. 原始记录契约

专属读取器与公共 `validateRecord`、后续 Gumu 原教师准备校验联合使用，不能仅靠本模块宣布原教师正确创建。

- 精确学生对象必须为真实在线非巫师玩家；全过程同一个原 NPC 克隆引用和原程序，不按名称重新找教师。每个原命令保留返回、耗时、调用墙钟及原 `receive_message` 输入，后者不是完整客户端文本。
- 每步保存原始／有效属性、技能／熟练度／映射、正邪、经验、资源、完整 family、是否存在 family 映射、姓名／职业／称号、两意向、离派／叛师记录、贡献及两份任务。前一步终态等于下一步初态，不在重复、确认或取消之间恢复资格／资源。
- 入门时间必须实际生成于该原命令时间窗口；重复请安保留它。首次加入必须观察任务删除，同派转师必须保留原任务内容；不从师父姓名推断这些副作用。
- 未设置历史、无忙乱、已删除任务可按真实 JSON 输出为 `null` 或 0；必需键缺失不能当作 0。family 必须有映射快照，并以独立 `family_present` 区分原无映射；全组没有攻击、被动、自然回调或额外资源开支。零费用不允许用等量增加／扣除的相抵账冒充。
- 统计从冻结 `condition.parameters` 校验与归类，不读取不存在的 `raw.parameters`；错误样本不进入正常效果统计。

当前自检包含明确标为合成的完整共享准备／观察记录，仅验证读取契约，不能用它声称原 NPC 已在真实驱动内构造或教学成功。

## 4. 已接入的最小共享契约

1. 在 `teaching_cases.mjs` 尾部注册本组及资格来源；`execution.mjs` 显式冻结这两份 MJS、六份共享接线文件及实际报告依赖 `teaching_report.mjs`／`statistics.mjs`。原教学矩阵前缀及完整 JSON SHA 保持不变，接入自检覆盖全局 `validateTeachingPlan`，不能只靠本组生成器通过；不回填历史系列。
2. `runner.lpc` 把 `gumu-recruit` 纳入既有 Gumu 原教师 `test_interface` 一次性准备、确切对象复用、最终自主行为检查与成功／异常清理的窄名单；不走普通学习的 enable 预载，不添加学生缺失的技能。原教师构造、配装及六动态武学的第一次加载原样执行，保留原入口／返回身份和实际加载位，中途初始化主体不能凭推断填充。
3. `teaching_observer.lpc::teaching_state` 仅对本组增加 `gender`、原始 `per`、有效 `str`／`per`；继续读取原有效 `int`／`force`。`recruitment_state` 仅本组增加 family 映射存在性、三个历史键及持久／临时 quest 原值。观察函数不建立师承、不写 pending、不代替命令，不引入新游戏探针。
4. `validateGumuTeacherPreparation` 支持本组显式嵌套的初始 family，并根据真实末态核对合法师承变化，不能继续用 `properties['family/master_id']` 的缺失值断言真实嵌套字段应为空；保留学生准备前后不变、原 NPC／蓝图／随身物回调、克隆心跳 1→0、身份与最终回收检查。NPC 初始心跳／回调诊断不能由本组语义校验覆盖掉。
5. `teaching_observation.mjs` 在旧 recruit oracle 前按精确 profile 路由本组。旧 Shaolin／Emei 的“有效悟性等于原始值、内功等于基本一半”等假设不适用于本组；不要放宽旧组或补假属性过测。所有原 `apprentice` 步骤都经已有观察器执行，不直接调用 `attempt_apprentice` 或 `recruit_apprentice`。
6. 原 runner 判终态对本组按实际新师承建立识别 observed，并与冻结预期比较；公共受理返回 1、请安或首次外派确认不算新增入门。序列保留同一学生与原教师到最后，原忙乱初态沿既有 `restore_busy`，不改原命令或自然时钟。
7. `teaching_report.mjs` 将冻结 condition 传给本组 effects，分别输出首次／转师／请安／确认／业务拒绝／公共拒绝／取消、新拜师次数、两类任务清理、贡献清理及零资源账。接入自检覆盖真实 create/open、完整共享语义校验和报告，不拿当前合成预检替代烟雾或正式原始证据。
