## 0. 更正早前虚高归因（2026-11-15）

早前报告称"727 已核验 + 0 未完成"，经诚实重验修正为 **604 已核验 + 123 未完成**。虚高原因：

1. **validatorFor 路由缺口**：145 个 school-combat 系列（gumu/emei/taohua/mingjiao 等）的专用消费者 `validateSchoolCombatRecord` 存在，但 `validatorFor` 未按 collection 类型路由，导致这些系列被误判为"不支持"→ 归入未核验。**已修复**：`collection_review.mjs` 的 `validatorFor` 现按 `collection` 类型路由（镜像 `execution.mjs` 采集时路由），并提供 `sourceContext.readSource`。
2. **v7 formal 标记不可靠**：旧 perform_entry_coverage v7 缺 `consumer_hashes`，无法证明消费者版本；且未正确路由 school-combat。v8full（当前消费者，728 hashes）+ recovered-145（routing 修复后重验）= 权威并集。
3. **契约验证是独立路径**：perform_entry_coverage 将 `variant:'probe'` 标为 discovery 不计 formal；我本轮新采集的 probe 原件由源码派生效果契约验证，单列 Path B，不与 Path A 混算。

**诚实结论**：587 Path A formal（v8full∪recovered-145）+ 17 Path B 纯契约 = 604 已核验。123 未完成条目已有明确处置（见 A1）。不得据旧"727"宣称全覆盖。
