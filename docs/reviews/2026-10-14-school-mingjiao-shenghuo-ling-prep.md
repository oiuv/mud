- 教学配置是圣火令原始220、内力修为5000、有效内功350、贡献1000、正气100000；施展本体另查当前内力400、实际剑类主手、交战及目标活性。不能把教学资格、学习资格和施展资格合为一个门槛。
- [残血令第85–114行](../../kungfu/skill/shenghuo-ling/can.c#L85)成功分支有命中加成和额外创伤；失败分支仍有最多七次普通攻击。成功的 `max_hit` 不能移给失败分支。
- 既有独立修复 `6926d0bf` 在[第100–109行](../../kungfu/skill/shenghuo-ling/can.c#L100)对整个七击循环统一增加、减少 `shenghuo-ling/hit`，防止两分支再触发内功追加。`max_hit` 仍只保留成功分支的创伤差异。修复经过的受控随机、固定命中回归见[专项记录](2026-10-11-shenghuo-combo-fix.md)，不是本页真实随机效果采集，也不单独证明当前正式服已经加载。
- 普通攻击的圣火神功追加仍是原功能，不应为保证每次七击而关闭它。之前旧实现的理论上限是七次原攻击加五十六次追加攻击，共六十三次调用；不表示每次必出，也不重新运行旧版本生成混合样本。

## 原调用与数据语义

### 内功命中回调不是每击都会调用

[公共战斗第662–665行](../../adm/daemons/combatd.c#L662)只有攻击命中，并且 `jiali != 0`、当前内力大于加力时，才调用激发内功的 `hit_ob`。因此零加力条件能观察圣火令自身命中特效，却不能证明内功追加或者残血令防重保护有效。

圣火神功[第42–76行](../../kungfu/skill/shenghuo-shengong.c#L42)使用以下数据：

| 数据或条件 | 实际语义 |
|---|---|
| 神功 `lvl` | 圣火神功原始等级；不足140早退。 |
| `damage_bonus` | 原调用输入；为0早退，不是最终普通扣血。 |
| `flvl` | `query_skill("shenghuo-ling")`，没有原始标志，也不是有效剑法。 |
| 激发与持器 | 内功激发圣火神功、剑法激发圣火令，实际主手 `skill_type == "sword"`。 |
| 保护与资源 | `shenghuo-ling/hit` 非零或当前内力不足200早退。 |
| 随机发动 | `floor(lvl/2) + random(lvl) > 目标原始基本内功`，再检查 `max_hit` 为0。 |
| 计划追加数 | `min(floor(圣火令原始等级/40), 8)`；先付每次20点内力，再检查逐次交战。 |
| 忙乱与清理 | 忙乱 `1 + random(计划追加数)`；追加期间设置 `hit`，完成后原 `delete_temp` 清理。 |

按[技能查询第135–150行](../../feature/skill.c#L135)，本组没有以特殊技能名称再激发其他技能，也没有该名称的临时加成，所以 `flvl = floor(圣火令原始等级/2)`。**原始279级的 `flvl` 是139，280级才是140**。200级普通攻击、220级残血令即使有加力，也不能发动这一内功追加。

400／800级残血令防重对照应使用加力50及充足内力：本体先付300后仍至少200。仅使用当前内力400边界时，付费后只剩100，即使没有保护也会被内功资源守卫拦下，不能拿它证明防重修复。

### 两路附伤与公共扣血分别记账

- 内功回调位于[公共战斗第665行](../../adm/daemons/combatd.c#L665)，在圣火令自身回调之前。原内功发动返回数字1，公共战斗会把这个返回值加到本击的 `damage_bonus`；不可只记录追加次数而抹去原返回值的后续参与。
- 圣火令[第163–174行](../../kungfu/skill/shenghuo-ling.c#L163)直接额外扣当前气血：输入 `damage_bonus` 加 `random(floor(神功原始等级/2))`。只有 `max_hit` 非零时，再按输入增加有效气血损失。原调用未传 `who`，不能给这两次扣血虚构公共攻击者怒气增量。
- 公共战斗随后还有自己的普通伤害、创伤随机与当前气血夹制。不得将本击 `attacks[].damage` 当作全部气血损失，或把附伤输入当作最终公共扣血。
- [伤害接口第26–84行](../../feature/damage.c#L26)分别处理当前气血、有效气血及夹制；大额、有 `who` 的公共伤害或创伤会增加怒气。应保留毛扣、恢复、净差及怒气的真实来源。
- 现有单次采集的 `fighting: true` 准备使用原双向 `kill_ob`，不是普通切磋。普通创伤条件的两次短路随机不能一律解释为三分之一；追杀关系也决定[敌人清理](../../feature/attack.c#L215)是否保留昏迷目标。需实际记录交战、追杀和预置昏迷，不能只看一个 `fighting` 配置值。

### 残血令的原范围

[施展本体](../../kungfu/skill/shenghuo-ling/can.c#L26)依次查领悟、交战、主手剑、圣火令原始220、有效内功350、最大内力5000、当前内力400、剑法激发及目标活性。扰乱判定为 `random(有效剑法) > floor(目标有效招架/3)`；成功时 `count = floor(圣火令原始等级/6)`。

原费用300，命中加成仅覆盖循环，结束收还；每次循环可能给不忙的目标请求忙乱1，最终自己忙乱1至4。目标受到正伤害可能立刻被公共战斗中断忙乱，**终态忙乱0不能反推没有控制请求**。成功后的[原命令第118–120行](../../cmds/skill/perform.c#L118)还有圣火令弱熟练增长。此处读取的是特殊技能名称，220级的实际值为110，仍有 `random(120) < 110` 的原随机熟练；400／800级实际值200／400时才必然增长。不能拿有效剑法330／600／1200替代这个弱熟练门槛。

`can.c` 第65–80行虽计算跨武学 `improve`，当前后续并未使用这个局部值；不能为本批报告额外加上并不存在的命中加成。功力、普通选招、被动、目标忙乱和最终忙乱的原随机均保持，不固定随机输入、命中或七次攻击结果。

## 首次加载与独立冷载

圣火令[第65–88行](../../kungfu/skill/shenghuo-ling.c#L65)在全局动作初始化读取 `this_player()` 的原始内功、基本剑法、轻功、招架，并计算五项随机系数。之后[第131–136行](../../kungfu/skill/shenghuo-ling.c#L131)只选择共享动作表，不按当前攻击者重算。

- 主系列建议先用真实USER原始内功／剑法200、轻功／招架200、没有映射或装备时，通过原 `enable parry shenghuo-ling` 首载。所有后续行引用同一原 `load_id`、首载身份和状态。
- 不销毁技能伪造每行冷载，不把同一主系列的400／800级解释为分别重新初始化了极意。
- 另用独立驱动，分别以原始内功／剑法400和800首载；轻功／招架仍200，与同档主系列普通条件保持其他配置一致。冷载两条各100，烟雾各2；不混入主系列均值。
- 普通原始200级的候选前缀是前六项；超过250级才包含极意，末至多六项支持不包含第一个0级动作。若要补250／251严格边界，另立有限追加，不偷偷扩大本页主矩阵。
- 这是既有[全局初始化候选](../architecture/martial-arts-data-findings.md#L1282)中的一个具体条目，不借其他五份武学的实证宣称圣火令已经采过，也不为这个候选重复分配确定BUG编号。

## 复用观察与接线风险

1. [现有首载观察](../../tools/tests/martial_data/runner.lpc#L769)可复用原 `capture_skill_loads`。新组只增加明确名单与五项缓存支持核验，不补模型或通用框架。
2. 现有[选招／回调前后探针](../../tools/tests/martial_data/execution.mjs#L325)已围住公共战斗原调用。**不能只加入新group名单**：[第1441行](../../tools/tests/martial_data/runner.lpc#L1441)假定同一路 `passive_before[route]` 不嵌套，而神功原追加会在外层force回调未返回时再进入内层force回调。后续可仅对新组保存两层LIFO前后快照并验证完全配对；不删掉内层保护返回0的证据，不改原调用顺序。现冻结工具不做这项改动。
3. 原[单次接口调度](../../tools/tests/martial_data/runner.lpc#L2301)支持固定 `hit_ob(USER0, USER1, damage, factor)`，但当前没有圣火神功名单。仅增加本组实际对象，不使用玩家输入指定任意方法。
4. 复用原资源账、已选动作、攻击／内功／武学回调。记录 `hit`、`max_hit`、`apply/attack`、当前内力及嵌套深度；按自然是否触发分开原攻击与追加，不能只从总损血推算攻击数。
5. 残血令每次扰乱结果可由原加成／标志和原消息判别，不再额外随机或调用一次判断。成功／失败必须分别报告实际出现量；目标随机请求忙乱与最终忙乱分列，现有原 `start_busy` 前后观察点可窄复用，未知触发分母不填三分之一。
6. 残血令原 `hit` 加一再减一可能留下数值0；神功原 `delete_temp` 则删除键。只按该精确原键解释语义上的无保护，保留原始序列，不要求整份临时映射字节等同，不把0键列为游戏BUG。
7. 神功联动和残血令本体没有专用异步回调；不套用上一批强化20／40秒到期。忙乱／昏迷的原框架时钟仍按真实状态观察，不提前清忙或调用移除函数。
