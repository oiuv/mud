## 原计算及分母

`B=有效指法+基本奇门五行+基本弹指神通`，`L=trunc(trunc(pow(经验*10,1/3))*4/5)`。本组 L=800。按原 `keys(query_skills())` 顺序，取前 5 门 `valid_enable("finger")` 的等级总和 S，得到 `A=B+trunc(B*(S*5/100/L))`。不能用 JSON 插入顺序或名称排序代替 LPC 顺序；快照必须另外记录原 `skill_order`。

基准 220／400／800 的 A 为 **760／1230／2310**；靶 `P=有效内功+基本招架+基本奇门五行`，基准 P=900。命中条件为 `floor(A/2)+random(A)>P`；只校验原支持区间和确定性边界，不用预期频率排除合法随机样本。

- 普通命中：原 `UNARMED_ATTACK`，入参 D 为 `[A,2A-1]`，创伤百分比 `100+random(算术/10)`，费用 `200+random(算术)`，忙乱 3。零级算术的随机值为 0；19 级创伤为 100%，20 级允许 100%／101%。
- 失手：费用 200、忙乱 2，无直伤事件；仍会执行原命令受理后的熟练增长。
- 命中且最大内力严格大于靶两倍：调用原 `die(actor)`，忙乱 2，没有 `do_damage` 和上述内力费用。死亡结算不是普通招式伤害，必须单列。
- 普通气血损伤还经过原膂力、悟性、伤害压缩；有效气血创伤还经过护甲随机及根骨减免。校验穷举原整数支持集，不加随机调用。220 级、D=760、100%、护甲随机取 0 时，独立手算普通伤害为 987 或 1065，创伤为 731 或 789；不能把输入 D 当作最终伤害。
- 原徒手 `do_damage()` 调用人物 `hit_ob()` 处理手套／毒素，并不自动调用激发武学的同名回调。本组无手套、毒素、强化和额外普通攻击。
- 原命令在受理后另有弱熟练增长：220 级可为 0 或 1，400／800 级必为 1；拒绝为 0。等级不变，失手不等于没有熟练收益。

统计分别列计划／实际、受理、拒绝、错误、命中、直接死亡、普通损伤和资源净差。命中率分母为受理样本，普通伤害分布只取非死亡命中；死亡导致的气血归 1 不混入普通伤害均值。错误和未观察入参为未知，不填 0；空分母为 `null`。即时忙乱数值不表示已经测得自然解忙秒数。

## 原死亡链的独立观察

[damage](../../feature/damage.c) → [公共奖励](../../adm/daemons/combatd.c)／[掉级](../../feature/skill.c) → [尸体](../../clone/misc/corpse.c)／[人物守护精灵](../../adm/daemons/chard.c) → [阴司入口](../../d/death/gate.c)。本组采用原死亡过程，立即取样，不能提前复活、伪造终态或关闭死亡惩罚。

在本组固定初态下，源码推导的同步结果为：

- 目标仍为相连 USER，`ghost=1/living=1`，气血／有效气血／精神／有效精神各 1，两个最大值仍 100000；当前内力仍 2000、最大内力变为 1980。经验变为 97000001，潜能变为 500。
- 新建靶的原熟练表不是 mapping，因此原死亡路径使各基本技能减 1，并删除不足 1 级项；不能只把 `query_learned() || ([])` 作为已证明此分支。靶招架 1 被删除、基本内功 2 变 1，激发与准备为空。
- 目标进入 `/d/death/gate`，原剑的同一实例进入原创建的 `/clone/misc/corpse#...`，解除装备；形制、伤害、重量、标志和耐久不变。不可用另一把剑、落在地上或销毁替代。
- 原 `dropped` 记录房间内全部非玩家对象，不只是武器。死亡分支要求其中恰好保留本次同一尸体及原名称、类型和不可持用字段；普通命中／失手／拒绝仍为空。不得过滤尸体来满足校验，也不得将尸体内的剑冒充独立地面落物。
- 原状态增加 `die_guard=6000`；施术者 PKS 增 1，未通缉计数不增。原奖励尝试受本组阅历 0 的容量限制，实战经验实际增量为 0，不能把随机奖励表达式直接当成到账数。战斗经验与实战经验分别核对。
- 双方交战关系解除；死亡原因可能调用原 `query_action()`，不把这次动作查询统计成实际攻击。死亡房间约 25 秒后开始的复活不在同步窗口内，样本后的清理须精确处理本组对象及 call_out，不清空整个房间。

以上仍是来源推导与合成校验，**等待真实烟雾核实**，尤其是原 JSON 空值、尸体对象身份、属性序列及死亡回调。现有 USER 夹具的 `save()` 不写玩家存档；不得为了本组恢复真实存档 I/O。
