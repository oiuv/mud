## 三门武学的当前机制

### 碧波与落英：容量、兼修、学练分开

- [碧波](../../kungfu/skill/bibo-shengong.c#L6)只声明内功用途。额外容量是 `L * L * 15 * 15 / 100 / 200`，`L` 为原始碧波等级，保留原整数运算次序；不是每次打坐增加这么多内力。无性且碧波超过49级拒绝学习，吹箫技法须至少100，然后才进入[基本内功至少10的继承检查](../../inherit/skill/force.c#L7)。这里读取真实技能等级，不是同名普通属性。
- [落英](../../kungfu/skill/luoying-xinfa.c#L7)只声明内功用途，学习资格仅委托上述继承检查；没有独立 `query_neili_improve`，宿主缺方法返回不能伪写成落英自己的函数实现。
- 两门 `valid_force()` 分别只接受另一门。实际[公共兼修检查](../../cmds/skill/learn.c#L190)有方向：候选没有通配许可时，问已学的每门内功是否允许候选，并跳过同名技能。不能因接口不接受自身名称就声称同一内功不能继续学习，也不等同于激发切换许可。
- [总容量](../../clone/user/user.c#L355)取已学内功候选的最大值，[当前激发容量](../../clone/user/user.c#L407)只取有效激发项；多门贡献不相加，查询不修改当前内力或 `max_neili`。原[enable](../../cmds/skill/enable.c#L119)换内功会清当前内力；本页容量查询不冒充已经执行切换命令。
- 两门的 `practice_skill()` 都拒绝，接口本身没有费用。文案“只能用学”不证明研究不可用：[research](../../cmds/skill/research.c#L53)仍通过原学习／研究资格及兼修检查，再按公共公式、精神与潜能推进。完整教师 `learn` 的认可、授课上限和付费业务不在本组。

无其他加成、基本内功与唯一特殊内功同级时，源码计算如下，**不是本次实测表**：

| 等级 | 碧波额外容量 | 碧波总／当前容量 | 落英总／当前容量 |
| ---: | ---: | ---: | ---: |
| 200 | 450 | 3450 | 3000 |
| 400 | 1800 | 7800 | 6000 |
| 800 | 7200 | 19200 | 12000 |

这些同阶容量式已分别出现在[峨嵋九阳／峨嵋心法采集](2026-10-10-school-emei-cultivation-results.md)中，不再逐级复制一遍。新增候选只保留黄药师原配功的三项原 USER 查询：基本内功340、碧波340、落英320、无修养／突破／特殊天赋加成时，总容量6400，激发碧波的当前容量6400，激发落英的当前容量4900。这是移植该技能子集到 USER 的受控查询，不是断言原 NPC 受 USER 容量约束；原 NPC 的7000内力不能因此判作错误。

### 实际运功：专用强化与公共回退

核对当前目录：`bibo-shengong/`只有 `powerup.c`；`luoying-xinfa/`不存在；公共 `force/`有11个既有入口，但没有 `powerup.c` 或 `.lpc`。缺入口应继续记录缺席，不创建替代技能。

[碧波 powerup](../../kungfu/skill/bibo-shengong/powerup.c#L9)的原流程：

1. 只作用自己；当前内力至少100；已有 `powerup` 标记拒绝。
2. 实扣100内力；`receive_damage("qi", 0)`不是气血费用。攻击、防御临时属性各加 `L / 3`，不增加 `apply/force` 或徒手伤害。
3. 通过原 [start_call_out](../../feature/action.c#L64)安排 `L` 延时的绑定解除；到期只撤回本次同量攻击／防御，再删标记。即时样本不能自称已经验证时长。
4. 交战时原忙乱请求为1—3；真实忙乱还须对照性格／互搏的[公共处理](../../feature/action.c#L7)。候选使用无互搏、无“狡黠多变”的角色，不把请求值当实测秒数。

这与[玉女心经强化](../../kungfu/skill/yunv-xinjing/powerup.c#L7)共享 `L / 3`、标记和解除结构，但后者门槛150、同样扣100。所以本轮保留碧波100／99的真实差异，不照抄玉女门槛，也不重复200／400／800的整套强化表。

[USER exert](../../cmds/skill/exert.c#L18)先运行已激发内功继承的 `do_effect()`，再试专用文件，返回假才试公共内功。碧波强化成功后的随机成长目标是碧波；公共 `recover` 成功后的成长目标是基本内功，不是落英或碧波。无修养且基本／特殊均200时，两条概率检查均必通过，但最终增长仍经[原熟练度转换](../../feature/skill.c#L255)，不等于技能升一级。[NPC 的 exert_function](../../inherit/char/npc.c#L421)不包含 USER 命令的这段熟练度流程，不能混用两类证据。

落英的 `powerup` 及其公共回退都没有文件，应拒绝且没有强化；`recover` 等公共能力仍可回退，但有文件不等于允许发动：两门都不在 [roar](../../kungfu/skill/force/roar.c#L15) 与 [shot](../../kungfu/skill/force/shot.c#L14) 的内功白名单中。这两项保留为源码拒绝事实，不复制其他门派的白名单拒绝矩阵，也不当作桃花已经实测。

两门继承的 [FORCE::hit_ob / do_effect](../../inherit/skill/force.c#L15)没有桃花专属重写：前者是公共附伤／反震，后者包含少林标记武学的佛学负担检查。无相关少林技能的本组初态不触发该负担；不重采[已完成的少林反噬矩阵](2026-10-10-school-shaolin-backlash-results.md)，也不将其与曲谱同名 `do_effect` 混为一谈。

### 暗影浮香：真实作用不止文案，但没有独立额外化解

[暗影浮香](../../kungfu/skill/anying-fuxiang.c#L14)声明 `dodge`／`move`，学习资格直接允许，闪避文字从原六条中选择。当前文件没有 `query_effect_dodge`、`valid_damage` 或专属主动入口；普通防御通过[有效技能](../../feature/skill.c#L135)及[公共闪避判定](../../adm/daemons/combatd.c#L532)使用其等级，而非由六条文字决定概率。`apply/defense`影响公共判定，不等于增加有效轻功等级。

`move`只是该接口声明；当前[玩家激发种类表](../../cmds/skill/enable.c#L7)没有独立 `move` 项，不能凭声明虚构一个可学习的基本移动武功。没有专属招式不等于暗影等级对闪避没有作用，也不由缺少独立钩子推断其综合强弱。

原练习一律先要求当前气血至少50，再按原始暗影等级扣气血：低于30扣10，30—49扣25，50及以上扣40；不扣内力。完整[practice](../../cmds/skill/practice.c#L45)还要求已激发、基本轻功严格高于暗影、可成长及合法场所，随后才增加熟练度。直接 `practice_skill` 的扣费与完整命令的成长不是同一个计数。

## 可复用协议与待接点
