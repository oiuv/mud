# 炎黄群侠传开发文档

本文档为开发者提供技术参考；实现文档以实际代码为依据，开发规范与未来设计须明确标注实施状态。

## 文档目录与查阅依据

| 目录 | 用途与边界 |
|------|------------|
| [`docs/`](./) | 本项目游戏开发文档，涵盖架构、实现与开发规范；目前覆盖不全，随开发同步完善。 |
| [`help/`](../help/) | 所有面向游戏用户的文档，包括玩法说明、命令用法与操作帮助。 |
| [`fluffos/docs/`](../fluffos/docs/)、[`fluffos/src/`](../fluffos/src/) | 当前 efun/apply 的必查依据；须对应所用驱动版本，有疑义时以实现为准。 |
| [`doc/`](../doc/README.md) | 历史 LPC、efun/apply 文档归档，仅供历史查阅，不作为当前开发依据。 |

本目录不承担完整驱动手册的维护职责。[LPC 语言指南](LPC_Language_FluffOS.md)是项目参考，使用时注意核对基线与功能支持版本；其中的 efun 摘要不能替代驱动文档或源码。

## 驱动要求

当前 MUDLIB 最低支持 **FluffOS v2026.0712.3**，不再兼容更早的驱动。新 LPC 源文件优先使用 `.lpc`；已有 `.c` 文件无需批量改名。语言参考可能包含最低版本之后新增的特性，使用前须核对其支持版本。安装与升级见[项目说明](../README.md)，开发规则见 [AGENTS.md](../AGENTS.md)。

## 权限开发规范

[简化权限规范](architecture/security-permissions.md)是后续开发依据：人员仅分玩家与管理员，新功能复用驱动 `wizardp()` 标记判断管理身份，不细分巫师等级；开发权限交给 Git 流程，UID/EUID 继续保护运行期对象和数据。不为六级巫师、个人目录授权或在线源码编辑增加兼容设计。

**旧实现保留不迁移，新功能按新规范开发。** [SECURITY_D 当前实现说明](daemons/securityd.md)用于理解现有安全入口；新代码复用有效鉴权，但不复制旧中间等级和数字比较，不另建一套权限运行时。

旧系统功能正常即可共存，不列为默认迁移任务。只有明确的安全、维护或功能接入收益足以覆盖改造成本和风险时，才单独评估迁移。

## 📋 文档编写原则

### 第一类文档（代码模块）
- ✅ **完全基于代码实现** - 不添加任何未实现的功能
- ✅ **文件名严格对应** - 确保与代码文件名一致
- ✅ **技术细节准确** - 包含实际的数据结构、接口、配置
- ✅ **工作流程清晰** - 基于实际代码逻辑编写

### 第二类文档（综合系统）
- ✅ **多模块整合** - 涉及多个相关模块的完整流程
- ✅ **实际功能整合** - 基于已实现的功能模块
- ✅ **交互逻辑清晰** - 说明模块间的调用和数据流
- ✅ **系统设计完整** - 从整体架构角度说明系统

### 第三、四类文档（技术参考与设计）
- ✅ **技术专业性** - 提供专业的技术参考和指导
- ✅ **前瞻性设计** - 为未来开发提供合理的设计方案
- ✅ **实用性导向** - 注重实际开发和维护的需要

## 📞 维护说明

- **文档更新**: 代码变更时必须同步更新对应文档
- **玩家更新说明**: 所有面向玩家的游戏更新须在同一变更中同步写入 [`help/changelog`](../help/changelog)，供玩家使用 `help changelog` 查阅。沿用日期倒序及现有游戏内显示格式，说明实际变化和必要操作；不以技术提交记录代替玩家说明，不将未开放内容写成已可用。无玩家影响的内部变更无需记入。
- **质量保证**: 实现说明必须基于实际代码；规范与规划明确区分目标行为和已实现状态
- **命名规范**: 严格保持文件名与代码文件名一致
- **维护范围**: 按本次开发涉及的模块增量完善；面向游戏用户的说明同步到 `help/`，不在本目录重复维护玩家手册
